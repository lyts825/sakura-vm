## 实施约束

- 统一治理层不替代领域锁、运行票据、namespace/cgroup清理或数据恢复日志。
- 资源申请一次原子预留所有维度；排队期间不持有部分预算。
- 取消信号不等于清理成功；只有实际退出/流关闭/协议确认后才释放相应额度。
- 任务展示历史不作为副作用执行承诺。恢复由领域handler核对回执；未知结果保留待核对状态。
- 非可信代码隔离依赖实际运行边界，类型能力接口不宣称操作系统安全沙箱。
- 每一批以真实调用路径及相应测试为完成依据，最终逐项审计全表。

## 当前验证记录

宿主 `process` 预算统计启动时已知的参与者：Native Host 包装进程与目标进程一次原子预留 2 个总额度，`process.vm` 或 `process.tool` 分类额度仍为 1；直接启动的 helper 和协议适配器占 1 个总额度。包装进程关闭与原生进程树终止回执共同决定释放，未确认清理时保留整份额度。这是已知启动参与者的并发预算，并非全部操作系统进程的硬上限：已授权 EXE 可以创建后代，后代仍受原有 Job 归属与整树清理约束，不以普通父进程退出代替清理确认。

各实施批次持续提交。最终回归修复了备份产物收集的重复写租约、双向实例包空流接收的锁循环、委托执行队列出队后的权限复核，以及操作入口的错误状态与验证顺序兼容。空输入接收端不预占设备写额度；Native Host与目标一次原子计费；正文验证、凭证与停用插件保留既有响应约定。这些修复均有对应回归。
