# Linux 图形桌面

KDE Plasma 桌面通过 noVNC 显示在浏览器内。支持 Alpine 的嵌套 KWin/Wayland 与 Debian/Ubuntu 的发行版 Plasma 入口；首次安装仍需下载系统软件包。运行中的项目工作区现在使用所选项目持久 UID/GID、独立 home、原目录描述符与网络空间，每实例保持一个 KDE 会话。先应用核对后的 [目录迁移](project-directory-migration.md)，缺失目录不自动建立。

软件包与固定系统适配器由管理员任务在清空环境、HOME=/、cwd=/ 下安装；不加载项目环境、密钥或 home 钩子。实际桌面正文和环境通过有界保护帧交给原生启动器，在降为项目 UID/GID 并关闭管理描述符后执行。Xvnc 与 Plasma、图形方式打开的终端及后代属于同一个原 UUID cgroup。

auto、x11、wayland 会话偏好和单屏/横向双屏/纵向双屏、分辨率、缩放、主题、壁纸、强调色、面板与动画设置继续可用。偏好随原项目桌面绑定保存；应用设置先确认停止旧完整运行域，再启动新 UUID 会话。显示与身份环境由桌面管理，项目不能替换 HOME、DISPLAY、Xauthority、Wayland 或运行目录。原生 Wayland 入口缺失时明确拒绝。

宿主 desktop-binding.json 第 2 版保存准确原账号、配置摘要、boot、完整 service/native 票据、保护帧摘要、构建与实际端点。状态、恢复、图形和应用准入复核原 cgroup device/inode、进程创建身份、实际 Plasma/Xvnc、UID 网络、原运行目录及 Xauthority。只读查询不安装、不重发 native 票据或启动桌面。更换项目时关闭不匹配的图形连接，须先保存工作并停止原会话。

嵌套 Wayland 会话分别核对外层 VNC 与内层 XWayland 的凭据和显示号。内层来源必须有匹配的 Xauthority cookie、原账号持有的本地监听 socket、准确内核 inode，以及属于原桌面域的 XWayland/KWin 进程；已有绑定继续固定这些身份。X11 策略应用使用实际 Plasma 环境中的显示号和认证文件。初次启动只等待尚未创建的凭据、进程或内层 socket；身份错误或已有端点变化立即回滚原会话。

Xvnc 固定监听原项目网络 127.0.0.1:5901。固定 Root 适配器在核对完整原证明后进入其网络，仅桥接该端点，连接后再次核对；只读分享沿用已运行的绑定。运行目录为 /run/sakura-desktop-uid/<uid>/<runUUID>，短路径支持实际 Wayland socket 长度。原目录和防火墙凭完整归属退休；目录内容由降权 worker 有界清理，Root 不递归遍历项目内容。

“安装中文输入法”固定提交时的项目与准确 live。先停止原桌面及匹配的注册应用，固定管理任务安装 Fcitx5 包，再由原项目 UID 在 HOME 写入自动启动与环境钩子并重启桌面；保留已有输入法 profile 和桌面偏好。任务重试恢复保存的项目，切换项目或客户机重启不会把原任务接到新实例。

X11/Wayland 策略应用均复核完整原 Desktop/native 证明及来源构建。X11 应用使用桌面项目 UID；Wayland 应用继续分配自己的 sandbox UID、home、代理和应用 cgroup。独立单应用窗口继续使用独立用户与显示器。desktopOwner/applicationOwner 分别显示来源桌面与实际应用归属，见 [X11 策略](x11-clipboard.md) 与 [Wayland 策略](wayland-clipboard.md)。

Wayland 应用现在通过自己的 mount namespace 访问原项目路径的 idmapped 目录视图。0700 项目目录及 0600 文件可由该应用账号读写，新文件在原文件系统仍归项目账号；原属主、权限与 ACL 不扩宽。私人父目录只在本次 namespace 建立必要路径，其他私人内容保持隐藏；不支持映射或与应用 home/runtime 冲突时明确拒绝。程序降权后从映射目录重新打开原 ELF，核对 inode、元数据和摘要后通过该描述符执行，关闭旧挂载中 Root 打开的原句柄。8 个自有 Linux/ext4 真实 helper 场景包含两个 0700 私有 ELF 执行场景；两个旧挂载句柄均实际返回 EACCES，映射后的同一 ELF 均成功读取 0600 文件，应用确认无管理描述符、NoNewPrivileges=1、有效 capabilities 为空。新修复的 32 项相关回归全部通过；此前目录视图的 58 项回归保留。仍需另行核对新桌面的实际端点和工具包行为。

停止、启动回滚和冷 boot 恢复按原完整票据退休匹配应用、整桌面域、native、准确运行目录与防火墙，最后释放准备租约。清理应答丢失或失败返回 503 并保留原记录及租约，明确“停止桌面”可以重试。健康桌面在宿主服务关闭或重载后保持；未知旧共享账号、旧启动脚本与第 1 版绑定只供审阅，不能自动收编。无项目工作区的显式实例管理路径仍保留原管理员入口。

正式 23 个相关测试文件 399/399 通过、零跳过，实际退出/close 为 0，对应源文件前后未变；完整类型检查通过。实际 Python 控制器函数另通过 10 个受控文件/进程模型，三个生产资产 loader 的来源与构建摘要验证通过。证明为 .data/desktop-identity-backend-4c47c412-3920-4c1b-b86a-577f07adb7ec-verification.json。没有运行新的真实 KDE/VM，不能用以下历史记录证明新 UID、端点及内核清理合约已经联测；原桌面 smoke 仍需适配。

清理失败的 Desktop 状态新增 cleanupPending，页面保留“重试停止桌面”并阻止替换安装；取消 IME 后的 503 不再停留在 installing。前后重载和取消清理的两个新增生命周期回归通过。页面已更新项目账号提示，并区分来源桌面 UID 与 Wayland 应用独立 UID。

生产构建与分发通过；真实 Chromium 在生产前端完成清理重试、跨项目拒绝和 X11/Wayland 账号展示的 4 个场景。页面使用明确 HTTP 测试数据，不能证明真实 KDE 或 Linux 内核归属。当前发布包及完整证据见 [本轮实现记录](capability-completion.md)。

## 2026-09-30 项目绑定验证

每个实例保留一个 KDE 会话，绑定启动时所选项目。切换到另一个项目时界面显示绑定不符并关闭图形连接；保存旧会话中的工作后点“停止桌面”，再为当前项目启动。运行或暂停中的桌面会阻止绑定项目修改目录与网络模式，停机修改会禁用旧自动恢复。桌面用户与偏好仍按实例共用，不提供项目文件或普通应用剪贴板的独立权限。

第 4 版启动程序先由 root 核对项目网络，再用 `setpriv` 降为桌面用户，不通过 PAM 创建处于共享网络的用户服务；项目环境与密钥只在降权后加载，HOME、DISPLAY、Xauthority 等身份由桌面管理。启动文件从上传开始即仅 root 可访问，连接按 SHA-256 复核。软件准备任务与长期系统桌面服务分开，取消、配置变更和控制服务关闭不会把旧操作接到新启动代次。已有桌面需重新安装或启动升级；未升级的旧客户机自启动不自动转换为项目绑定。

真实 Alpine、Debian、Ubuntu/QEMU 与 Chromium 验证完整安装、通过 KRunner 启动的 Konsole 及其子进程的实际网络空间、保留的显示身份、私有 VNC 监听、跨项目连接拒绝、只读连接、UI 停止与脱离会话进程清理、横向双屏、客户机与控制服务重启、停机修改配置以及项目切换。Debian/Ubuntu 安装明确包含 KWin X11 窗口管理器。重跑命令为 `npm run test:project-desktop -- alpine`，也可选择 `debian` 或 `ubuntu`；测试需要联网、2 GiB 内存和独立临时数据目录。

## 2026-09-21 连接稳定性修复

修复前，在已启动的桌面实例上进行 6 路并发 SSH 传输，重复出现 `ECONNREFUSED`，随后单次连接仍可成功。这与 [libslirp 监听实现](https://raw.githubusercontent.com/qemu/libslirp/master/src/socket.c) 中较小的连接等待队列相符，但没有据此把所有历史断连归因于它。服务端现在只对这种尚未建立 TCP 连接的短暂错误进行有限重试。

既有图形通道回归覆盖了真实 QEMU 的 VNC 握手、重启、快照恢复、连接中断自动重连，以及客户机 MSI-X 检查；这些连接层检查与桌面环境无关。Alpine 3.23 的 KDE Plasma 首次联网安装、非 root 会话、偏好应用和重启恢复已通过真实 VM 验证；Debian / Ubuntu 的软件包组合仍应在目标发行版上单独验证。新的 `SAKURA_TEST_CONNECTIONS=1` 回归通过了 300 次 SSH 传输、6 个并发客户端；已安装桌面的实例额外连续通过 3 轮相同压力测试，共 900 次。

单元测试覆盖未响应的 RFB 握手、连续失败的重试上限、认证失败、快速断连的退避、稳定会话后重置计数、离开页面释放连接，以及 SSH 重试期间取消和实例重启。

## 2026-09-24 断线恢复回归

生命周期推演确认了一个恢复缺口：SSH 和 VNC 同时失联时，`DesktopPanel` 保留最后一次 `ready` 状态，图形连接可能耗尽 5 次重试；SSH 恢复后再次返回 `ready`，不会改变原先连接 effect 的依赖，导致桌面继续停留在重试耗尽状态。现在状态轮询单独通知连接控制器客户机是否可用，由控制器暂停和恢复重连。认证失败仍需人工处理，停机、切换实例和离开桌面会释放控制器，迟到的状态响应不能重新打开旧连接。

客户机探测还会以 3 秒超时检查 `:1` 的 X 服务，避免仅凭旧的 ready 文件与残留 Plasma 进程报告就绪。新安装脚本同时监督 VNC 与 Plasma 两个子进程，任一退出都会清除 ready 文件、释放另一个进程并以失败状态退出，让 OpenRC / systemd 重启完整会话。该监督脚本在安装时写入客户机，已有实例需重新安装桌面脚本才能采用；前端恢复与状态探测改进立即生效。

回归覆盖 SSH / VNC 两种断线顺序、5 分钟失联、重试耗尽后恢复、握手期间失联、认证失败、手动重连和销毁后的迟到通知；真实本地 WebSocket / TCP 测试检查同时断线后的隧道释放与重建；POSIX shell 测试执行 Alpine / Debian / Ubuntu 生成脚本，检查失效的 X 服务以及任一子进程死亡后的清理。这里验证的是故障注入与恢复逻辑，没有复现下述 WHPX 长时间失联，也没有据此确认其根因。

本次 `npm test` 共 208 项通过，无跳过；`npm run build`（TypeScript 检查与 Vite 生产构建）通过。

## 已知限制

此前本机 WHPX 测试中曾出现 SSH 与桌面同时长时间失联：TCP 可以连接但收不到 SSH 握手，串口中的网络配置及 SSH 监听仍正常，QMP 可以正常关机；重启客户机后恢复。本轮曾在原配置上完成 4 轮重启及快照流程和约 1.6 GiB 的图像传输，没有复现这一现象。它与本轮明确复现的短暂 `ECONNREFUSED` 不同，根因仍未确认；MSI-X 配置与自动重连属于稳定性改进，不能据此保证该历史故障已被消除。因此功能仍标记为实验性。

桌面提供文本剪贴板互通和可选 Fcitx5 中文输入。停止实例后可配置 Virtio GPU/VirGL 与 QEMU HDA/DirectSound 音频；USB 摄像头和麦克风可按设备 ID 转发。noVNC 网页自身没有独立音频流，也没有 WSLg 单应用窗口集成。TCG 使用软件模拟，桌面启动和操作会明显慢于硬件加速。

可用 `SAKURA_TEST_DESKTOP=1` 配合 `npm run test:vm` 重跑联网安装、SSH 通道的 VNC 握手、重启和快照验证；追加 `SAKURA_TEST_CONNECTIONS=1` 可验证并发传输。客户机日志为 `/var/log/sakura-desktop.log`。GUI 或 SSH 长时间无法恢复时，可停止并重新启动实例。
