# Linux 图形桌面验证

本次适配范围为内置 Alpine 3.23.4 x86_64 镜像中的 Xfce / X11 桌面。桌面组件保存在实例磁盘上，使用独立的 `sakura-desktop` 普通用户；浏览器通过 noVNC 操作。不是其他 Linux 桌面发行版的镜像导入功能。

## 连接与生命周期

- 首次安装由用户在「桌面」标签触发，需要至少 1 GiB 内存，建议 2 GiB；软件包从 Alpine 官方仓库下载。
- OpenRC 管理 Xvnc 和 Xfce 会话，服务名为 `sakura-desktop`，随客户机启动。退出网页只关闭图形连接。
- Xvnc 仅监听客户机回环地址的 5901 端口。浏览器请求沿用服务令牌、同源及 Host 校验。
- Alpine Tiny Cloud 默认使用 `AllowTcpForwarding no`，因此图形流经固定命令 `exec nc 127.0.0.1 5901` 的 SSH 二进制通道传输。端点不接受自定义主机、端口或命令，也不修改 sshd 转发策略。
- 同一实例的安装请求合并执行，保留最近 16 KiB 进度日志。安装超时、失败可重试，停机取消服务端等待；客户机安装命令自身也有限时和互斥锁。

## 2026-09-20 至 21 日本机验证

环境为 Windows x64、Node.js 24.15.0、QEMU 11.1.0（本项目便携构建），桌面实例分配 2 vCPU、2048 MiB 内存、8 GiB 磁盘。使用与已有用户实例隔离的数据目录。

| 检查 | 结果 |
| --- | --- |
| TypeScript 与生产构建 | 通过，noVNC 按需加载；生产页面实际连接并显示桌面 |
| 自动化测试 | 19 项通过，含重复安装、失败重试、停机取消、二进制转发及连接释放 |
| 原有真实 VM 回归 | SSH、SFTP、NAT、重启、快照与旧配置迁移通过 |
| Xfce 首次联网安装 | 通过，磁盘实际占用约 803 MiB |
| 浏览器交互 | 鼠标打开图形终端，通过逐键输入在客户机创建文件，文件所有者为桌面用户 |
| 重连及全屏 | 通过，客户机实际分辨率随全屏变化至 1722 × 921 |
| 重启与快照恢复 | 桌面服务恢复，VNC 握手通过，恢复后新增测试文件消失 |
| HTTP / WebSocket 访问限制 | 错误令牌、跨源请求、额外路径和无效动作被拒绝 |
| 客户机服务重启 | `rc-service sakura-desktop stop` 后，网页启动动作恢复会话 |
| TCG 回退 | 可启动并显示桌面，载入较慢；未据此验证长期性能 |

## 已知限制

本机 WHPX 测试中曾出现 SSH 与桌面同时失联：串口中的网络配置及 SSH 监听仍正常，QMP 可以正常关机；重启客户机后恢复。后续也验证了持续数分钟的正常会话，但尚未确定间歇性失联的原因。因此此功能仍标记为实验性，不能据此保证长期连接稳定。

桌面不包含 GPU/3D 加速、声音转发、宿主剪贴板同步、中文输入法或 WSLg 单应用窗口集成。中文字体可显示中文内容。TCG 使用软件模拟，桌面启动和操作会明显慢于硬件加速。

可用 `SAKURA_TEST_DESKTOP=1` 配合 `npm run test:vm` 重跑联网安装、SSH 通道的 VNC 握手、重启和快照验证。客户机日志为 `/var/log/sakura-desktop.log`。GUI 或 SSH 失联时先尝试重新连接，仍无法连接时停止并重新启动实例。
