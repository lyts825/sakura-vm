# Linux X11 应用剪贴板策略

在运行中的 KDE 桌面打开「原生应用剪贴板」，安装代理后，填写完整应用路径，读取文件身份并保存规则，再从面板启动应用。此入口使用共享 KDE 的 X11 显示器，可与桌面中其他应用交换剪贴板；独立单应用窗口仍使用自己的显示器和方向规则。

应用必须是客户机当前架构的动态链接 64 位 ELF 文件，不支持静态程序、setuid/setgid 或文件能力提权程序。控制器核对规范路径及 SHA-256，用已校验的文件句柄执行程序；文件更新后必须重新读取身份、保存并重启。启动参数每行一个，以字面参数传递，不作为 shell 命令执行。

## 运行与规则

支持复制、粘贴、其他格式、敏感文本和 1 KiB 至 1 MiB 的 UTF-8 文本上限。关闭其他格式或启用敏感检测时，拒绝文件、图片、HTML 和自定义格式；仅保留允许的纯文本与必要元数据。敏感检测检查常见私钥、令牌、JWT、带凭据 URL 与凭据赋值，不能识别所有秘密。二进制格式不扫描内容，单次最多 16 MiB。

原生代理通过显式 `LD_PRELOAD` 加载，覆盖 Xlib 和 XCB 的 PRIMARY、CLIPBOARD 请求、内容属性与通知。INCR 分块传输先在私有缓冲区收齐，再检查完整 UTF-8、敏感内容、方向和大小，跨块的字符或凭据不会逐块放行；传输途中收紧的规则继续作用于完整内容。Xlib/XCB 混合访问、零长度大小查询和重复读取使用同一已检查缓存，每次读取仍核对当前规则。大小查询返回完整数据的真实格式与长度。

单次 INCR 最多等待 8 秒，单进程最多保留 32 个正文缓存及 32 MiB 预算；文本仍受已保存的 1 KiB–1 MiB 上限约束。复制端仅在完整检查后用一个原子 X11 请求发布内容，超过服务器实际最大请求大小时拒绝，不逐块发布未经完整检查的前缀。实测常规 Xvfb 的最大请求为 16,777,212 字节，因此 16 MiB 二进制 INCR 会被拒绝。受管接收可从已检查缓存读取大于服务器单次写入容量的完整内容。启用规则时仍拒绝普通属性追加及实际数据的部分读取。停用会显式放宽后续传输；已经被拒绝的 INCR 不会因停用转成原始逐块读取，代理留在进程中直到应用退出。

MULTIPLE 支持每次最多 128 个目标/属性对、最多 32 个同时存在的组，与 INCR 共用正文槽位和总预算。每个条目按原顺序独立收集和检查，单条采集时限 8 秒、全组采集时限 12 秒，完成后只发送一次父 SelectionNotify；失败条目的属性原子置为 None，其他合法条目仍可成功。这不保证所有条目作为一个事务发布。父属性必须为 ATOM_PAIR/32（兼容旧 ATOM/32），原始列表变更、奇数列表或超限会拒绝整个请求；空属性、重复子属性、父子属性冲突、嵌套 MULTIPLE 和 DELETE/INSERT_SELECTION/INSERT_PROPERTY 副作用目标按条目拒绝。缓存重读继续检查当前规则，属性复用和旧请求回执不能沿用已退休的缓存。

复合接收通过私有认证 XCB 连接，逐项向真实所有者发出单目标请求，再把已完整检查的内容提供给应用；应用的 Xlib/XCB 混合访问共用该缓存。这也避免 Qt 5 把同一请求窗口的两个 INCR 当成一条传输。连接和认证有独立的 2 秒时限，后台看守会中断卡住的协议请求并回收工作线程；协议清理另有最多 2 秒预算。只有持续泵送事件的所有者才能完成请求；同线程停止事件循环的应用会在时限内失败。

保存新规则会更新运行中会话的根用户策略文件，API 返回各会话执行状态；应用的后续操作读取当前规则。保存成功但客户机更新失败时保留已保存意图并显示错误，「刷新并应用已保存规则」可重试。关闭面板或控制服务保留当前规则；服务重载恢复同一归属，不自动重启应用。统计只保存加载状态和拒绝次数，不保存剪贴板文本或应用输出。

启动前核对 KDE 的完整原项目 Desktop/native 票据、来源构建、cgroup/boot、原运行目录、X11 凭据与实际 Plasma/Xvnc 的创建身份及网络；应用使用真实桌面项目 UID。desktopOwner 显示来源桌面的 project/run/UID，applicationOwner 显示实际应用 UID。停止桌面先按完整原证明退休匹配的注册应用域；未知或被替换的域保留原记录并拒绝清理，失败保留原准备租约供明确停止重试。应用使用绑定项目的目录与私有环境配置，私有项目的实际网络空间只有回环接口且没有路由；控制请求只传递环境摘要。配置或私密值改变后，需要重启桌面再启动应用。每个会话有独立 D-Bus，避免交给未加载代理的既有应用。

客户机需要可写的统一 cgroup v2 及 `cgroup.kill`。应用和私有 D-Bus 在降权前进入该会话专属的根用户 cgroup，普通子进程继承其归属；状态核对 PID、创建时间、UID、实际网络空间和代理映射。停止按钮强制结束此会话及子进程，请先保存内容；进程退出后会等待内核释放 cgroup，最多 5 秒，权限和其他清理错误继续显示失败。清理记录只删除已停止会话。克隆与导出/导入保留程序身份、规则和控制服务归属，不保存或重放 PID，不自动启动应用。

## 范围与验证

2026-10-03 新 Desktop/native 权限准入和清理通过正式相关回归与实际 Python 源码模型；尚未运行新控制器的真实 KDE 联测。下述 Debian/Xvfb/Qt 的实测属于此前共享桌面账号入口，不作为新 UID、端点与清理证明。

这不是内核级 DLP。已有普通应用、静态程序、卸载代理或清除加载环境的子进程、直接发送底层 X11 协议的程序不在此代理的保证范围内。原生 Wayland 使用独立入口，见 [Wayland 应用剪贴板策略](wayland-clipboard.md)。未加载代理的存活子进程会显示错误。无法撤回已经返回给应用或剪贴板管理器缓存的内容；同一 KDE 用户的家目录和显示器也不是应用之间的文件隔离边界。独立图形窗口仍提供不同用户与显示器的隔离。整体功能清单继续保持部分实现。

普通应用线程调用 `fork()` 后，代理通过 `pthread_atfork` 为子进程切换到新状态。子进程可建立新的 Xlib/XCB 连接、重建缓存并正常退出；父进程的连接和进行中的 INCR/MULTIPLE 继续工作。子进程只关闭自己继承的 broker fd 副本，不 shutdown 父连接，也不析构或等待已经不存在的后台线程。遗留且无法回收的临时分配继续占用 32 MiB 总预算，可能减少子进程可用容量；最多支持 32 层，超限子进程以 126 退出。

子进程不能继续使用继承的受管显示器指针或 socket 建立剪贴板请求，这些操作以 126 退出；继承的 `XCloseDisplay`/`xcb_disconnect` 只作无操作清理。支持范围已在 Debian 12、glibc 2.36、GCC 12 的普通线程中实测；信号处理器中的 fork、`_Fork`、`vfork`、直接系统调用、任意其他库的锁及第三方 atfork 回调不在承诺范围内。exec 重新加载代理的路径继续支持。cgroup 子进程归属不代表继承的事件循环与代理缓存可以沿用。

构建把三个生产源文件及 SHA-256 清单纳入 `.sakura-server/assets/linux-clipboard` 和运行包。安装时校验后上传，在客户机编译并保存库摘要；运行前核对固定控制器与库文件。安装依赖下载使用实例网络，应用执行使用绑定项目网络。构建入口提供 Alpine、Debian、Ubuntu 的依赖命令；本批实机验证为 Debian 12、Linux 6.1、KDE Plasma 5 和 Qt 5，其他发行版与商业应用需独立验证。

```powershell
npm run test:x11-clipboard -- debian
```

此测试创建自己的虚拟机，在独立认证 Xvfb 中测试 Xlib/XCB，再在真实 KDE 的私有项目中测试原生 API。测试不访问宿主剪贴板；检查方向收紧、文本与格式限制、敏感内容、缓存属性重读、Qt 大小查询、无效策略、服务重载、停用及会话 cgroup 清理。原生 INCR 测试覆盖双向大文本、跨块 UTF-8 和凭据、Xlib/XCB 混合访问、32 位格式的本机长整型步长、通用回复接口、空流、TARGETS 过滤、畸形流、超时、缓存预算和原子请求上限。MULTIPLE 覆盖独立成功与失败、元数据、格式和敏感内容、两个大正文、规则收紧、禁用后的属性复用、父子请求与旧 cookie、嵌套和副作用拒绝；真实 Qt/KDE 场景核对大属性和同进程事件循环。Qt 使用 BIG-REQUESTS，超过 256 KiB 不足以证明 INCR，分块证据必须观测真实 INCR 协议头。浏览器测试覆盖读取身份、保存、字面参数启动、页面重载、错误项目拒绝和手机宽度。便携包测试检查规则与归属的克隆、导入恢复。

受限请求容量的真实认证 Xvfb 实测上限为 4,194,300 字节。Qt 5 的两个同样大小的 MIME 二进制条目真实触发 INCR，CLIPBOARD、PRIMARY 各观察到 8 个 INCR 头；Xlib、XCB、混合 API 和显式 Qt 请求者均完整接收，受管复制因完整发布超出原子容量逐项拒绝。该场景启用二进制格式，仍受单条 16 MiB 与总预算限制；它不是合法文本上限超过 1 MiB 的证据。测试同时核对 2 秒认证卡住后的线程退出及两种常见失败标记的兼容读取。

fork 回归在父进程真实 INCR 进行中启动子进程和孙进程，逐一验证 Xlib/XCB/mixed 新连接、32 个正文槽、敏感与大小规则收紧、正常 C++ 退出、父进程原组及后续组继续工作；继承指针、共享 socket 与第 33 层均明确拒绝。最终完整轮未跳过原有原生、Qt/KDE、reload 或 cgroup 场景，日志为 `.data/x11-fork-final-second.log`，来源构建摘要为 `7979b7e0f7f98c1b2132dc895b70b86bb38c5e091124ad732630e9497b88be3c`。线程与 fork 的通用约束见 [POSIX fork](https://pubs.opengroup.org/onlinepubs/9799919799/functions/fork.html)。

编译版 HTTP 与生成 SDK 联测可复用前一测试自己创建并关闭的 Debian 实例。先设置 `SAKURA_KEEP_X11_SMOKE=1` 运行上面的测试，记录它输出的 `Retained owned fixture` 目录，保持同一 `TEMP`/`TMP`，再执行：

```powershell
npm run test:x11-clipboard:http -- <保留的测试目录>
```

它只接受临时目录中的单实例 `sakura-x11-*` 测试数据，临时启用桌面插件，检查桌面恢复、接口契约、非法请求拒绝、版本冲突、文件身份、保存规则，以及真实原生复制拒绝、计数和会话清理；结束后关闭实例与服务并恢复插件选择。不要同时运行另一个控制器。追加已生成的运行包目录作为第二个参数可校验包摘要后，直接测试包内编译服务；该目录需要先按安装或更新流程准备固定的 QEMU/PosixLoom 运行时。

实现依据 [ICCCM 剪贴板传输协议](https://xorg.freedesktop.org/archive/X11R7.7/doc/xorg-docs/icccm/icccm.html)、[Xlib 接口](https://xorg.freedesktop.org/archive/current/doc/libX11/libX11/libX11.html)、[Qt XCB 剪贴板实现](https://github.com/qt/qtbase/blob/5.15/src/plugins/platforms/xcb/qxcbclipboard.cpp)、[Linux cgroup v2](https://www.kernel.org/doc/html/latest/admin-guide/cgroup-v2.html) 和 [setns](https://man7.org/linux/man-pages/man2/setns.2.html)。
