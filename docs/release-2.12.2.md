# 2.12.2 · 服务装配与构建架构维护

本次从 2.12.1 升级到 2.12.2，拆分服务装配职责，补齐浏览器依赖检查，并统一发行编译入口。目录保持 486 个插件、46 个整合包，宿主插件 API 保持 5。

## 变更

`server/application-services.ts` 从 2830 行缩减至 1068 行，保留启动协调、准入状态、VM 所有权、协作端口和恢复目录。七个装配模块分别负责身份、套件、平台、项目、能力检查、开发与迁移、集成服务。工厂通过原依赖解析器取得服务，统一生命周期管理器继续持有资源。

第七批固定计算工厂生成器改为写入套件装配模块。业务模块反向引用装配阶段会触发架构错误，服务依赖声明和严格契约检查继续覆盖拆分后的模块。

依赖检查区分初始化图与完整运行图。动态导入、`require()`、目录入口及 ESM/CJS 源文件映射进入浏览器边界检查；纯类型引用仍被排除，延迟导入环不误报为初始化环。无法静态确定路径的浏览器加载表达式直接拒绝。

`scripts/build.mjs` 接替包清单中的长构建命令，保持原构建顺序、独立编译进程及失败中止行为。主构建、第七批构建和分发检查共用 `build-targets.mjs` 的 16 个入口；共享目录仅由首个入口清空。

## 验证与交付

45 项相关回归与 6 项本地专项验证通过。专项验证核对了 78 个服务声明和顺序、动态导入反例、装配模块访问限制、16 个编译入口，以及构建失败时停止后续步骤并保留退出码。固定计算工厂生成器在隔离目录重跑后，目标文件保持一致。

TypeScript、2,567 个模块的架构检查、605 个显式服务描述、486 个插件与 46 个整合包检查通过。9,316 条 HTTP 和 6 条 WebSocket 契约、繁体语言资源同步通过。

完整生产构建和分发检查通过。首屏 JS 为 624,260 字节，初始静态资源为 1,354,998 字节，与 2.12.1 一致，未提高预算。生产冒烟覆盖多组插件启动、生产 CSP、会话锁、离线监控、Webhook、本地助手、镜像路由及仓库外网络 worker。

本机验证环境为 Windows x64。未运行完整单元测试集、完整浏览器 E2E、真实 VM 套件或其他平台验收。测试脚本、夹具和报告保留在被忽略的 `artifacts/architecture-2.12.2/`。实现提交、服务契约基线和本地版本标签见 [项目状态](../PROJECT_STATUS.md)。

实现提交为 `81f31558`。113 份公开服务声明已从该提交冻结，摘要与 2.12.1 相同。本地交付由 `v2.12.2` 标签定位。

## 兼容与范围

78 个服务生命周期声明及登记顺序保持一致。公共接口、插件选择、持久数据格式、资源归属和安装文件布局保持兼容。本轮不改 VM 业务算法和原生组件实现；本地交付不代表已经推送、发布或部署。
