# 模型评测工作台

## 使用范围

`model-evaluation` 提供 10 个独立插件。你可以固定样例和提示词，导入已有输出，完成规则评分、人工量表、配对比较、审阅和报告交接。需要实际推理时，另行登记本机模型并批准具体发送计划。

本包没有工具调用、网页搜索、项目修改或自动安装模型入口。模型回答和导入输出都按普通文本显示。启用插件或打开页面不会发送样例。

## 插件与入口

| 插件                     | 保存的对象与主要操作                           |
| ------------------------ | ---------------------------------------------- |
| `evaluation-datasets`    | 原始样例、固定集合、评估或调参子集、发送许可   |
| `evaluation-prompts`     | 固定变量模板、系统文本、生成参数、展开预览     |
| `evaluation-endpoints`   | 本机地址、模型名称、秘密版本、协议检查和撤销   |
| `evaluation-runners`     | 导入输出、发送计划、逐条调用、取消与原回执核对 |
| `evaluation-scorers`     | 固定规则、单账户人工量表、独立模型判分         |
| `evaluation-comparisons` | 共同样例、缺失覆盖、设置差异和逐条分差         |
| `evaluation-reviews`     | 单账户 A/B 审阅、争议及接受或拒绝决定          |
| `evaluation-reports`     | 当前接受的审阅、固定结论、适用限制和版本差异   |
| `evaluation-exchange`    | 报告导出、隔离检查、接受导入和原接收恢复       |
| `evaluation-workbench`   | 分步页面、建议模板、分页记录和历史恢复         |

在插件管理中选择“模型评测工作台”包，打开 `model-evaluation` 页面。端点插件依赖已有的 `secrets` 插件；没有模型或秘密配置时，仍可完成导入输出评估。

## 固定材料和评估

1. 创建空间。选择建议模板，或填写 JSON 样例数组。每条记录包含唯一的 `id`、`input`、`reference`，可附带 `label` 和 `tags`。确认已审阅材料后再固定集合。
2. 选择评估集或调参集。发送许可与导出许可分别控制。拆分子集会保留父集合和原始字节引用。
3. 编译提示词。模板必须包含 `{{input}}`，另支持 `{{id}}`、`{{label}}` 和 `{{reference}}`。展开预览会显示实际文本和摘要。
4. 使用“导入结果评估”固定已有输出，或按下一节执行真实模型运行。导入项只接受 `sampleId` 和 `text`；缺少的样例保持未发送。
5. 执行规则评分或填写人工量表。规则支持与参考答案精确比较、固定字面量包含检查和 JSON 对象字段检查。未返回或截断的回答不产生确定分数。
6. 选择两次运行及各自评分，计算配对差异。输入、生成设置、重复次数或评分依据不同，会影响可比性。调参集合不会获得泛化结论。
7. 保存人工审阅决定，再封存报告。报告保留覆盖范围和限制。撤回审阅后，已有报告保留为历史，但不能继续导出。

人工评分和审阅均来自当前账户。A/B 审阅只改变页面呈现，不隐藏账户已能访问的来源，也不代表独立多人审阅。

历史区可以归档修订、预览原资源清理和核对中断发布。集合、端点和审阅的最新状态会保留到旧修订清理完毕，防止删除撤销记录后恢复旧许可。仍被报告或运行引用的材料继续受保护。

## 本机调用与独立判分

端点必须使用带明确端口的回环 HTTP 根地址，例如 `http://127.0.0.1:11434`。首版固定为本地 Ollama 文本协议，检查 `/api/show`，调用 `/api/chat`。宿主控制端口、重定向、远程模型声明、流式响应和工具响应均拒绝。

登记端点只保存地址和模型声明。主动检查连接后，才记录本地权重元数据摘要。协议未提供版本时保持未知。需要认证时，填写已有私密配置的 VM ID 和名称；端点绑定当时的秘密版本，轮换后需要重新登记和检查。

运行预览列出完整样例文本、系统文本、目标、生成参数和调用预算。批准绑定原 actor、消费者代次、具体修订和摘要。修改输入、撤销发送许可、轮换秘密或变更模型元数据后，旧计划不能继续发送。

模型判分有独立的计划和批准。它发送样例、参考答案、原回答和人工填写的量表，使用独立的受管调用入口。判分不改写原回答，也不取得宿主工具能力。返回的分数只代表模型意见；格式不符合固定量表时保持未知。

发送前先保存调用意图。断线、超时、撤权或取消发生在发送之后时，结果保持未知。重启核对只读取原回执，不重发请求。取消不能保证模型端点已经停止内部推理或删除收到的文本。

## 配额与当前限制

| 项目                       | 2.8.0 实施上限                               |
| -------------------------- | -------------------------------------------- |
| 单集合                     | 100 条样例，固定 JSON 输入最多 1 MiB         |
| 单样例输入、参考答案或输出 | 64 KiB 文本边界；实际发送另按 UTF-8 字节复核 |
| 一次生成计划               | 最多 30 次调用，重复 1 至 3 次               |
| 一次判分计划               | 最多 10 条完整回答，每条判分输出最多 8 KiB   |
| 并发与超时                 | 本体最多 2 次调用，每次最多 60 秒            |
| 批准有效期                 | 5 分钟；到期后拒绝后续发送                   |
| 一次运行保存的回答         | 最多 256 KiB                                 |
| 原调用账本                 | 最多 1,000 条、8 MiB；满额时拒绝新调用       |
| 原始材料存储               | 4 GiB，分块上传单文件最多 32 MiB             |
| 报告交接                   | 通用封套最多 16 MiB，原始材料投影最多 8 MiB  |

本次采用比设计草案更小的执行预算，以限制不可变修订与恢复记录的增长。用量未由端点提供时保持未知，不按猜测补齐 token 数。

## 交换与命令行

导出只接受当前审阅仍被接受的封存报告。引用中的原始样例必须拥有当前导出许可。导出前、保存封套时和下载时都会核对授权。撤销后恢复许可，不会恢复旧导出计划的有效性。

便携封套删除秘密引用、秘密版本、调用 ID、计划 ID 和判分调用回执。导入先进入隔离空间，再由原计划接受。外来对象始终带有 `sourceTrust: unauthenticated`、`approvalsTransferred: false` 和 `executionAllowed: false`，不能成为本地调用或批准证明。

命令行使用 `sakura evaluation <领域> <动作> [参数.json]`。动作名称采用连字符，例如：

```text
sakura evaluation datasets pin pin.json
sakura evaluation runners import-outputs outputs.json
sakura evaluation runners preview preview.json
sakura evaluation runners start approval.json
sakura evaluation scorers plan-judge judge.json
sakura evaluation scorers apply-judge approval.json
sakura evaluation comparisons compare comparison.json
sakura evaluation reports seal-report report.json
sakura evaluation download export-reference.json report.zip
sakura evaluation verify report.zip
```

批准参数是 `{workspaceId, planId, digest}`。引用是 `{domain, id, revision}`。`verify` 只读取本地文件，核对封套、原始字节、样例绑定、规则评分和配对计算；它不证明发送方身份、真实推理或模型评分的正确性。

## 验证记录

已检查固定输出评估、规则与人工评分、逐样例比较、人工审阅、报告封存、隔离导入导出和离线篡改拒绝。合成协议检查覆盖一次性提交、未知结果不重发、独立判分、发送许可撤销、秘密版本变化、输出上限、工具响应拒绝、取消、并发限制和重启核对。

按用户本轮选择，真实模型响应验收已跳过，也未下载模型。合成端点只证明协议、传输和授权实现，不计作真实模型评测完成。测试脚本、数据和详细证据保存在被 Git 忽略的 `artifacts/plugin-packs-2.8.0/`。
