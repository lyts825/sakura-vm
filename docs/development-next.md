# 工作区恢复与自动化功能

这一组功能建立在开发工作台之上，面向长期使用、多人协作前的本机工作流。所有数据仍保存在 Sakura 数据目录，实例未运行时才能执行磁盘整理或恢复等需要独占磁盘的操作。

## 会话恢复

浏览器会保存最近使用的实例、页面和实例功能标签。重新打开 Sakura 后会恢复上次工作位置；如果实例已经删除，界面会自动选择当前可用实例。终端本身继续使用 tmux 会话恢复机制，浏览器界面状态和客户机内终端状态互相独立。

## 多项目隔离

一个实例可以创建多个项目。每个项目有独立的配置、Git 操作、命令收藏、服务任务、同步配置、流水线和运行日志；实例仍共享同一块客户机磁盘。实例 → 项目可以创建、切换和重命名项目，旧版本的 `project.json` 会作为默认项目自动兼容。

备份包和克隆会携带项目目录索引及各项目配置，导入旧格式备份时仍会恢复默认项目。项目 ID 使用固定长度的小写十六进制字符串，避免把用户输入直接当作文件名。

## 文件历史与回收站

文件编辑覆盖前会保存有限版本，删除文件或目录会先移动到实例专属回收站。文件面板的“历史”可以查看、恢复和清理版本；恢复操作会再次经过版本校验，避免覆盖用户刚刚写入的新内容。历史按实例保存，单文件和总容量均有上限。

## 流水线

开发 → 流水线支持保存最多 20 个步骤的客户机命令。每一步有独立超时、退出码和日志，任务可从任务中心取消或重试。流水线可声明相对路径产物，Sakura 会在主机侧做大小限制后提供一次性下载票据；命令日志继续使用私密配置脱敏规则。

CLI 示例：

```text
npm run sakura -- pipeline my-dev list
npm run sakura -- pipeline my-dev save pipeline.json
npm run sakura -- pipeline my-dev run <pipeline-id>
```

## 远程 Git 与代码检查

Git 面板和 CLI 支持添加、删除远程仓库，以及 fetch、pull、push 和 merge。命令使用捕获原项目的持久 UID/GID、独立 home 和原网络，整项操作保持准备租约；正文及环境通过受保护输入执行。远程 URL 只接受 HTTPS，具体配置、输出与管理员文件编辑范围见 [Git 项目账号](git-project-identity.md)。

Git 面板可选择已配置的远程和目标分支，默认使用当前分支的上游；没有匹配上游时使用当前分支名。`fetch` 只更新所选远程的跟踪分支，不修改本地分支、工作区或标签。`pull` 先获取指定分支，再仅执行快进；工作区或暂存区有改动（含未跟踪文件）、历史分叉、detached HEAD、尚无提交或存在未完成的合并 / 变基时会停止，并说明恢复步骤。不会自动 stash、合并分叉或变基。`push` 将当前提交发送到所选远程分支，不执行强制推送、镜像推送或附带标签推送；远程有未整合的提交时明确报告拒绝原因。

冲突文件会单独标记。请编辑文件并点击“标记已解决（暂存）”，再完成当前操作；需要中止合并或继续 / 中止变基时使用终端。Git 面板与任务中心均可查看日志和取消运行中的任务，失败任务的 `errorCode` 也保存在历史和事件中。取消或连接失败后应先刷新检查实际结果，再决定重试；远程操作不会自动重试。

远程地址（包括 URL 重写后的地址和单独配置的推送地址）必须是无内嵌凭证的 HTTPS URL；多个目标地址会被拒绝。身份验证使用客户机已有的非交互凭证配置，任务不会等待密码输入。请求可使用 `POST /api/vms/:id/git?project=:projectId`，例如 `{"action":"pull","remote":"origin","branch":"main"}`；`branch` 对 pull/push 表示目标远程分支，省略时按上述上游规则解析。`fetch` 省略 `branch` 时获取该远程的所有分支。

文件编辑器可对当前文件执行轻量代码检查：JavaScript / TypeScript 使用 Node 或 `tsc`，Python 使用 `py_compile`，JSON 使用标准解析器。检查结果包含行列、级别和消息；工具未安装时保留实际检查错误。

轻量代码检查现使用原项目 UID/GID、独立 home 与项目网络。请求先固定项目、文件路径、配置和客户机 live 身份，环境只由捕获配置解析，命令与私密环境通过有界保护帧降权执行；单次检查时限 30 秒。准备租约保持到完整任务域与账号票据清理结束，取消等待全部后代清理，未确认的原 503 和错误码继续返回。结果发布前复核原绑定，并遮盖已解析的私密配置。具名项目标识以非枚举属性保留，不会因配置复制回落到默认项目。此入口不自动创建目录或迁移属主；独立 LSP 与 DAP 也已使用原项目账号、持续二进制保护输入和完整任务票据，功能与停止恢复见 [项目语言服务与调试器](project-protocol-streams.md)。

## 运行时版本

项目配置可选择 Node.js 与 Python 的精确三段版本。面板及 CLI `inspect` 只读取最近采样，点击“探测项目版本”或 CLI `probe` 才以项目 UID 读取声明和执行有界版本检查；未探测、过期和失败都有明确状态。选择版本经过实际 UID 验证和配置摘要检查，避免覆盖并发配置。安装需要客户机访问发行源，使用管理员安装回执；未知旧目录和半成品不能直接启用，安装失败不会修改现有选择。“清除版本选择”恢复为未指定，但不删除运行时或声明文件。详见 [项目运行时版本](runtime-versions.md)。

## 构建农场

系统设置可登记实例、项目、标签和并发槽位。构建在绑定项目账号中运行；每次准备捕获配置，子目录保留原项目身份，每个槽位独立取消并确认完整清理。结果和清理错误在刷新及重载后保留，详见 [构建农场](build-farm.md)。

## 同步删除、事件和磁盘整理

目录同步预览会报告一侧被删除的文件，执行时可以明确选择删除另一侧，或从另一侧恢复。跳过删除会保留基线，下一次预览仍会提示差异。任务中心的事件面板聚合失败、取消和中断任务，方便在多个项目之间排查问题。

停机维护中的“整理磁盘”会把 QCOW2 当前状态压缩为新的独立镜像，要求实例已停止且没有快照；转换失败会保留旧磁盘并清理临时文件。整理不会自动删除备份、历史版本或客户机内文件。

## API 与 CLI 索引

| 能力     | HTTP 入口                       | CLI          |
| -------- | ------------------------------- | ------------ |
| 项目     | `/api/vms/:id/projects`         | `projects`   |
| 文件历史 | `/api/vms/:id/history`          | `history`    |
| 流水线   | `/api/vms/:id/pipelines`        | `pipeline`   |
| 运行时   | `/api/vms/:id/runtimes`         | `runtimes`   |
| 代码检查 | `/api/vms/:id/code-diagnostics` | `code-check` |
| 任务事件 | `/api/events`                   | `events`     |
| 磁盘整理 | `/api/vms/:id/compact`          | `compact`    |

所有入口都要求 Sakura 的本机令牌。长操作返回任务对象，可从任务中心、`/api/jobs` 或 `/api/events` 查看状态与日志。
