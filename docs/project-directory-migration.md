# 项目目录与账号迁移

项目命令、初始化和普通服务使用持久的项目账号。既有 root 目录或账号尚无写权限时，先保存项目设置，在项目面板中预览目录迁移计划，核对摘要、每项属主与权限，再勾选已核对并应用。停止操作和迁移都使用已保存设置，面板草稿不会自动提交。只有管理员可访问迁移接口；即使项目成员有读取、编辑和执行权限，也不能应用目录属主变更。

## 允许的目录与变更

迁移接受已存在的 `/workspace`、其子目录，以及 `/srv/projects/` 或 `/opt/projects/` 下的项目子目录。父目录须由 root 管理、不可被组或其他用户写入，而且真实项目账号可遍历。入口不建立缺失目录，不迁移 `/root`、系统目录、其他项目的重叠目录，也不修改父目录权限。需要新目录时，管理员先通过明确的实例管理操作建立，再保存和预览。

计划保存实际设备号、inode、文件系统与 mount ID、原始属主、权限、内容摘要、链接数和修改时间。应用将已核对的目录设为项目 UID/GID 的 `0700`，普通文件设为 `0600`，保留原文件的属主执行位。符号链接、硬链接、ACL、capabilities、其他用户的文件及跨挂载项均拒绝；从允许基目录到目标的祖先 mount 跳变和项目根本身的 bind mount 都拒绝。允许基目录自身位于独立文件系统时，仍须核对目标与其他保存或原生登记目录的物理对象，防止不同路径的 bind 别名改动相邻项目。预算最多 2,000 项和 512 KiB 回执，预览会为完整完成记录、最长错误路径及最终身份预留空间，超限在任何属主变更前拒绝。

## 核对与重试

预览先确认主命令、服务、项目终端、SSH、容器及相关挂载已停止，同时恢复可准确核销的旧短任务。终端在准备返回前登记连接；尚未建立 SSH 通道的连接也阻止迁移，直到关闭或取消。新终端及共享重连在任何安装、网络或 tmux 准备前核对迁移门闩；未完成或不可核对的记录拒绝连接。账号可先保留为分配意图，尚未因此获得目录权限。应用要求原 plan ID、SHA-256、明确的 reviewed 标记和相同保存配置；文件、身份或设置改变时必须重新预览。

应用逐项以打开且核对的 FD 修改，使用持久门闩阻止新运行。中断后保留已完成项和原计划，同一计划核对原对象后继续；真实重启或绑定确认丢失也只恢复准确原身份和下一修订。即使回执已经写为 applied，最后门闩确认失败时仍显示未确认并允许重试。刷新、读取状态和重新预览不会自动应用变更。

`GET /api/vms/:vmId/project-directory-migration?project=<id>` 只读取宿主保存状态，不安装工具或创建账号。`POST` 预览请求为 `{ "action": "preview", "version": 1 }`；应用请求为 `{ "action": "apply", "version": 1, "planId": "<UUID>", "sha256": "<摘要>", "reviewed": true }`。生成 SDK 通过 `request` 发送该插件前缀路由，项目放在独立 `query` 参数中。

使用条件、真实故障回执与最终验证范围见 [项目账号](project-identities.md) 和 [功能实现记录](capability-completion.md)。普通终端及全部扩展尚未全部降权；旧 root 终端断开后自行保留的后代仍须管理员确认停止，连接登记不构成其完整运行域清理保证。
