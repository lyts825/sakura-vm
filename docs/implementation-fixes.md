# 功能审计修复记录

日期：2026-09-26。对应修复前的 [250 条目录审计](implementation-audit.md)。

本次修复公共入口、任务状态、空闲计时、应急锁定、就绪误报和 37 项工程操作协议中的实现缺陷。没有把 GPU 直通、远程集群、团队认证等尚未开发的规划功能算作完成；这些条目已明确标记并阻止伪运行。

## 缺陷处理

| 审计问题                        | 修复结果                                                                                                         |
| ------------------------------- | ---------------------------------------------------------------------------------------------------------------- |
| 37 项工程操作被 action 字段阻断 | 请求外层与操作参数分别校验，仍拒绝未知字段和非法参数；37 项公共入口均通过回归。                                  |
| 两批 200 项 configure 被阻断    | 正确解包 configure，保存配置不再遭到自身 action 字段拒绝；200 个分支逐项验证。                                   |
| 空闲关机无法累计时间            | 独立累计连续低 CPU 区间；高负载、停止、失联、陈旧或重复采样以及设置变化会重置计时；避免 tick 重入。              |
| 应急锁定只有标记                | 控制层持久化锁定，取消任务、关闭连接并停止实例；禁止重新启动及客户机访问，保留独立解除锁定接口；重启后继续生效。 |
| 无实现与缺工具误报可用          | 工具探测与功能实现分开，探测失败保留失败状态；计划条目不再生成成功任务；check 不再修改配对、锁定或策略。         |
| 工程执行器只打印或忽略参数      | 使用有界的结构化执行器实现文件、Git、质量检查、指标和命令流程，详情见下表。                                      |
| 失败退出码仍显示完成            | 检查不通过、命令失败、超时、部分步骤失败都会使任务失败；取消会清理子进程。                                       |
| 归档没有成员检查                | 全部成员先校验，拒绝路径越界、绝对路径、链接、特殊文件、重复和目录冲突，再解压到新目录。                         |
| 目录、界面、文档与测试不一致    | 目录按实现区分状态；界面允许编辑操作参数、显示日志、禁用规划项运行；更新过期 Git 文档和回归验证。                |

## 37 项工程协议

| 操作                  | 当前执行行为                                                                                               |
| --------------------- | ---------------------------------------------------------------------------------------------------------- |
| archive               | 有界 tar 创建/列出/解压；新目标目录；完整成员校验。                                                        |
| hash-manifest         | SHA-256、大小、修改时间；可写 JSON 输出；20,000 文件/512 MiB 上限。                                        |
| case-conflict-report  | 大小写冲突、Windows 保留名、非法字符和尾随空格/点。                                                        |
| task-import           | npm、Make、Just、Taskfile 静态任务发现；save 写入收藏命令，去重并检查容量。                                |
| project-onboarding    | 从锁文件、任务和 README 未完成复选项生成步骤，不执行这些步骤。                                             |
| env-schema            | 检查最终继承环境中的必填、整数、布尔、URL 与选项；报告不含变量值。                                         |
| shell-profiles        | profile 语法验证、保存、读取和显式加载执行。                                                               |
| toolchain-check       | 已安装版本与项目约束比较；不支持的复杂范围明确要求核对。                                                   |
| bootstrap-dry-run     | Shell 语法、静态工具和路径检查；动态展开不求值，标明人工检查。                                             |
| project-template-pack | 排除内部状态、依赖目录、常用秘密文件，检测私钥头部并校验归档。                                             |
| git-stash             | 正确执行 stash list/push/apply/drop，应用不隐式删除 stash。                                                |
| git-reflog            | 从提交创建新分支，检查干净工作区和分支名。                                                                 |
| git-cherry-pick       | 正确区分 pick、revert、--continue 与 --abort；保留冲突现场。                                               |
| git-bisect            | 正确传递 bad/good，要求干净工作区，支持标记和 reset。                                                      |
| git-rebase            | 只读线性历史计划；显式完整 todo；支持排序、reword、squash、fixup、drop；冲突后仍保留消息，支持继续及中止。 |
| git-policy            | 检查实际分支前缀与提交类型，错误使检查失败。                                                               |
| precommit-secrets     | 扫描暂存区并报告路径/行号/规则；Git 工作台另有提交前高置信度密钥拦截。                                     |
| code-ownership        | 常用 CODEOWNERS 路径与通配规则，最后匹配优先；明确拒绝不支持的规则。                                       |
| flaky-tests           | 重复执行并区分稳定成功、稳定失败、偶发失败，保存耗时与退出码。                                             |
| coverage-history      | Istanbul、LCOV、coverage.py 解析、持久历史和覆盖率差值。                                                   |
| benchmark-regression  | 每轮真实耗时、中位数、给定基线及阈值比较。                                                                 |
| sbom                  | npm package-lock v2/v3 转换为 CycloneDX 1.5，标准文档位于结果的 bom 字段，保留精确版本和有效完整性哈希。   |
| license-report        | 锁文件或已安装包许可证声明与 allowed 比较；未知或未允许项返回待审查。                                      |
| release-gates         | 顺序检查、首个失败后跳过后续步骤、产物存在性检查。                                                         |
| artifact-provenance   | Git 提交/脏状态、完整有界产物哈希、工具版本。                                                              |
| changelog             | 从指定提交区间生成真实 Git 日志。                                                                          |
| reproducible-build    | 同一提交导出两份工作目录，独立构建，实际比较产物内容；差异使任务失败。                                     |
| posix-acl             | getfacl/setfacl；正确区分读取、设置和移除；缺工具直接失败。                                                |
| guest-clock-policy    | 使用宿主 UTC 同步，报告同步前后偏差，偏差包含传输延迟。                                                    |
| static-routes         | IP/CIDR 与地址族检查，拒绝默认路由，显式增删目标路由。                                                     |
| process-history       | PID、启动身份、进程名、RSS 与 CPU 时间；不采集命令参数。                                                   |
| disk-io-metrics       | 一秒差分，计算吞吐、平均 I/O 延迟、在途请求与平均队列。                                                    |
| network-metrics       | 一秒差分，接口收发流量、包、错误、丢包与速率。                                                             |
| command-risk          | 实际启发式分类，包括删除、提权、下载执行和外部传输。                                                       |
| command-macros        | argv 执行、条件和超时；保留每步结果，任何失败不被后续成功掩盖。                                            |
| runbooks              | 顺序执行，首个失败后跳过后续步骤，最终状态与结果一致。                                                     |
| feature-run           | 转发到真实扩展执行器；未实现功能明确失败。                                                                 |

## 验证

- TypeScript 回归：37 个公共工程入口、200 个配置分支、非法参数、失败传播、锁定持久化、只读检查、空闲计时。
- Python 执行器回归：真实临时文件、Git 仓库和子进程，含恶意归档、Rebase 冲突继续/中止、构建差异。
- 实际 Alpine QEMU：完整执行器回归，加工程 API、收藏导入、失败状态、指标、ACL/路由、提交拦截、取消清理和应急停止链路。
- 能力中心浏览器回归：参数编辑与提交、规划按钮禁用、明确锁定与解锁。

执行命令：npm run verify、npm run test:engineering。CI 已纳入 Windows/Linux 矩阵；本机通过不等于远端 CI 已运行。

本机最终结果：260 项测试通过；6 项浏览器测试通过；实际 Alpine 虚拟机通过 19 组 Python 用例和工程调用、密钥拦截、取消清理、锁定链路。生产构建与运行包检查通过。运行包位于 release/sakura-TcXKDR，工程执行器资产与当前源码的 SHA-256 一致。
