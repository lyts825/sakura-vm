# 构建农场

在系统设置的构建农场中登记 Linux 实例、项目、标签与 1–4 个并发槽位。节点保存准确项目 ID；切换活动项目、服务重载或排队等待不会把节点改为另一个项目。标签全部匹配且节点运行、有空闲槽位时才派发；停止的节点保留队列。

## 项目账号与配置

构建使用节点项目的持久 UID/GID、独立 home 和网络模式。工具须已安装，并允许该项目账号执行；共享运行时可在运行时面板由管理员安装，再明确选择版本。已有 root 目录先在项目面板预览、审阅并应用 [目录迁移](project-directory-migration.md)，不会因提交构建自动递归改变属主或放宽权限。

每次准备构建时捕获当前项目配置与版本。随后只解析该份配置的环境、运行时和密钥，不再读取另一个版本；这不是提交队列时的配置快照。配置版本作为任务元数据持久保存，解析后的密钥不会写入队列。执行与清理期间保护原项目目录和网络模式；同节点有运行构建时也不能更换节点项目。

命令与环境通过有界受保护输入交给固定启动器。启动器核对 boot、cgroup 与项目身份后降权、清空补充组及 capabilities、设置 `no_new_privs`，再载入正文；root 参数中不携带项目命令或密钥。分段日志、完整 stdout/stderr、错误和保存的结果均遮盖项目密钥，见 [项目账号](project-identities.md)。

## 工作目录与并发

工作目录留空使用原项目目录。显式目录可位于 `/workspace`、`/opt/projects` 或 `/srv/projects` 下，路径段只能包含字母、数字、点、下划线和横线，不能使用 `.` 或 `..`，且必须处于节点项目内。子目录切换在项目账号的正文中执行，不会把项目账号绑定改为该子目录，也不会为构建额外发行一个目录身份。命令仍可按普通 shell 语义返回非零状态或执行后续语句；项目权限不等于完整文件系统沙箱。

同项目的多个槽位可同时执行，每个构建拥有独立完整 cgroup 和账号运行票据。短操作队列只串行核对、登记与核销，不锁住整个构建正文。当前进程保存准确 live、boot、owner、身份与正文摘要的活动登记，准备另一槽位时不会将其当作失联运行；目录迁移和网络核销仍受未闭合票据保护。

服务重新加载不能从磁盘记录推断一个任务仍由当前进程管理。live、boot、身份或记录不匹配时按原严格恢复处理；未知活动域不视为停止，也不按账号名称猜测并终止其他构建。

## 取消与恢复

排队构建可直接取消；已开始的构建在超时、取消或服务关闭时先清理自己的完整 cgroup，包括脱离会话的后代，确认域已移除后才核销准确账号票据。仅取消一个构建不会清理同节点另一槽位。

清理或归属确认失联时保留失败、具体错误码和原持久票据，不把它写成普通取消或服务中断。界面刷新、服务关闭及重载仍保留实际 error/cancelled/done 结果。检查原实例和归属后再重试；新构建只有在原未确认记录能正常恢复后才可执行，重新排队不会清除旧记录。客户机每 boot 仍有 1,024 张保留票据限制，没有无重启归档。

## API 与验证

`GET /api/build-farm` 读取节点与任务；加 `?vmId=<id>` 读取该实例的项目列表。`POST` 支持 `save-node`、`remove-node`、`submit`、`retry`、`cancel`，任务命令最多 4,096 字符，超时为 5–1,800 秒。重试产生新任务并保留 `retryOf`，不会重放原 run ID。

单元测试位于 `tests/build-farm.test.ts`、`tests/project-run-scope.test.ts` 和 `tests/project-terminals.test.ts`，浏览器场景位于 `e2e/plugin-surfaces.spec.ts`。实机检查使用脚本登记的已停止自有实例、独立新队列和证明，不接受任意用户实例；实际通过范围及源码归属见 [功能实现记录](capability-completion.md)。
