# 目录同步合并驱动

在实例“同步”页保存 Windows 与 Linux 目录后，展开“按路径设置冲突合并驱动”。规则从上到下匹配，支持与同步忽略规则相同的 `*`、`**` 路径模式。只有双向同步中两端都修改了同一文件时才使用驱动；单向同步、删除确认和路径只读策略仍按原有规则处理。规则保存在当前实例与项目的同步配置中，后台自动同步也会应用。

可选方式：

- **手动处理**：保留两端文件，等待单文件决策。
- **两端都保留**：另存 Linux 版本为带唯一后缀的冲突副本，并同步到两端；原路径采用 Windows 版本。适用于二进制文件。
- **保留 Windows / Linux 版本**：将选定一端覆盖到另一端。建议同时启用同步回滚点。
- **尝试三方文本合并**：须先启用“保存共同文本版本”，并完成一次同步建立基线。仅合并不重叠的 UTF-8 修改；缺少基线、文件超过 1 MiB、含二进制内容或修改重叠时保留两端原文件供手动处理。

“预览双向同步”会显示每个冲突命中的驱动和将采用的决策。可以在该次预览中改选单文件决策，覆盖驱动规则；预览令牌包含配置与两端文件摘要，规则或文件变化后旧预览不能执行。路径方向策略优先于合并驱动，禁止的上传、下载或合并不会执行。驱动只处理已经识别为普通文件的冲突，不处理符号链接。

自动化验证覆盖规则优先顺序、二进制副本、两端优先、单文件覆盖、配置变化后的旧预览拒绝，以及文本合并成功与保留冲突。真实 Alpine/QEMU 双向同步脚本还验证从预览到客户机文件覆盖的完整路径。
