# 启动性能验证

2026-09-20，在同一台 Windows 11 x64 主机上，以 Alpine 3.23.4、QEMU 11.1.0、2 vCPU、512 MiB 内存、8 GiB 增量磁盘验证。从调用实例启动开始计时，直到 SSH 可以执行命令且 Tiny Cloud 初始化完成；不含控制服务自身的启动时间。

| 配置                          | 首次初始化       | 后续启动                                        |
| ----------------------------- | ---------------- | ----------------------------------------------- |
| 修改前默认 TCG（`8439b7d`）   | 61.91 秒         | 测试遇到 IO-APIC 定时器内核崩溃，未取得有效对照 |
| 新默认自动模式，本机选择 WHPX | 24.59 / 30.40 秒 | 13.16–14.76 秒，共 4 次                         |
| Windows TCG 兼容回退          | 70.67 秒         | 44.93 / 49.56 秒                                |

本机使用 WHPX 时，首次启动比这次旧默认配置基线缩短约 51%–60%。这是少量本机测量，包含首次主机密钥生成及宿主负载波动，不代表所有电脑的固定耗时。两轮 WHPX 测试均包含首次初始化、正常停机后再次启动、恢复离线磁盘快照后启动。

Windows TCG 回退优先处理本机复现的早期定时器崩溃，使用自动指令时钟及单线程模拟；首次启动耗时和多核计算吞吐量存在代价。它不是这次主要提速来源。自动模式只在探测到可用的 WHPX 后选用硬件加速，手动选择 TCG 或 WHPX 的配置会保留。

配套改动包括静态 NAT 配置、将后续引导菜单等待缩短至 1 秒、精简默认设备、提供 VirtIO 随机数设备、等待初始化真正完成后开放终端，以及即时推送运行状态。旧实例仅迁移仍为官方默认值的配置，保留备份，支持 `/etc/sakura/keep-boot-config` 退出迁移。

验证已覆盖：

- 14 项单元测试，包括自动加速选择、取消启动、初始化就绪判断、内核崩溃识别和 SSH 超时。
- TypeScript 检查及生产构建。
- WHPX 与 TCG 的真实 Linux 启动、SSH 命令、SFTP、DNS 和 HTTPS 联网、本机 TCP 转发。
- 文件重启持久化、离线快照恢复、旧默认配置迁移、自定义配置保留及退出迁移。
- WebSocket 状态通知及未授权订阅的拒绝。

可重复执行：

```powershell
npm test
npm run build
$env:SAKURA_TEST_ACCELERATOR = 'auto'
$env:SAKURA_TEST_NETWORK = '1'
npm run test:vm
```

`SAKURA_TEST_NETWORK` 可省略以离线验证；指定 `SAKURA_TEST_ACCELERATOR=tcg` 可验证软件回退。最新一轮结果保存在 `artifacts/boot-timings.json`，TCG 测量另存于本机的 `artifacts/boot-timings-tcg.json`。测试实例使用独立临时目录，结束后清理。

启用新版需要重新启动 Sakura 服务并刷新页面；已有实例停机后在「配置」中选择「自动」，即可使用可用的硬件加速。旧实例的默认网络和引导配置会在一次成功启动后迁移，下一次启动生效。
