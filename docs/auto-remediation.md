# 自动修复 Runbook

在“系统设置 → 事件自动化规则”中选择“自动修复 Runbook”，为任务完成或新告警事件设置实例、项目、标签和状态条件，然后添加最多 8 个有名称、Shell 命令与超时时间的步骤。命令在匹配实例的项目目录内依次执行；步骤超时最多 120 秒，总超时最多 600 秒。任一步骤失败时停止后续步骤，执行记录仅保存步骤名称与退出码。

新建和编辑 Runbook 时只能先保存为预览规则。点击“预览最近事件”可以检查匹配目标与**实际保存的全部命令**；点击“批准并启用自动修复”后，服务器校验一次性审批令牌与已审阅的规则版本、筛选条件和步骤完全一致，才允许执行。修改规则必须重新保存、预览和批准；服务重启也会使旧审批令牌失效。实例处于应急锁定或数据目录维护时不执行。

自动修复沿用事件自动化的持久去重、最少 60 秒冷却、每日 25 次操作上限和执行历史。触发前会检查实例存在且未锁定；服务关闭会取消运行中的 Runbook。任务或告警事件若没有实例 ID，仅记录跳过。适合明确、可重复执行的本机修复命令；请在规则中设置精确的事件条件与实例范围。

`npm run test:auto-remediation` 使用真实 Alpine/QEMU 客户机验证预览后批准、按顺序执行、第一步失败时终止以及事件去重。浏览器测试覆盖步骤编辑、审阅、批准和执行结果。
