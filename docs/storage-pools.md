# 本机存储池

在“创建实例”中选择存储池，可将新实例的磁盘、启动种子、密钥和项目随附文件放在指定本机目录。Sakura 的控制记录、镜像缓存、备份和任务数据仍位于主数据目录。默认池沿用现有 `machines` 目录。

创建外部池时，先准备一个已存在、可写的绝对目录，再从创建实例窗口的“新增本机存储池”填写名称和路径，或在能力中心执行 `storage-pools` 的 `create` 操作。Sakura 在目录下创建 `sakura-machines` 和所有权标记；一个池最多可注册八个，池目录不得与数据目录或其他池重叠，也不能经过符号链接或目录联接。能力中心的 `list` 返回每个池的可用容量、磁盘已分配字节数和实例列表；不可用目录会显示为不可用。

已有实例须先停止，再在能力中心选择“迁移到此池”并提交。迁移复制实例目录中的全部普通文件，逐文件验证 SHA-256，并在目标目录就绪后切换持久实例记录。运行中实例、含特殊文件的目录、已有同标识目标目录以及上次迁移尚有待清理副本时都会拒绝迁移。迁移期间需有足够的目标可用空间容纳实际文件；新旧副本会短时并存。断电或旧目录删除失败后，`pendingCleanup` 记录使“清理”操作按当前实例记录识别并删除过期副本。若断电恰好发生在登记清理记录之前，目标目录可能作为未登记数据保留，需要检查后人工处理。不要手工修改所有权标记或已登记实例目录。

删除池前必须迁出全部实例并完成待清理操作；若池目录还有未登记文件，删除会拒绝。删除只移除 Sakura 创建的空 `sakura-machines` 目录及标记，不删除作为池根的用户目录。

迁移整个 Sakura 数据目录前，须将外部池中的实例迁回默认池；数据目录迁移也不能以已注册存储池内部或其上级目录为目标。这样可避免外部池中的磁盘继续引用旧数据目录内的基础镜像。

核心接口：`GET /api/storage-pools` 查询；`POST /api/storage-pools` 传入 `mode` 为 `create`、`move`、`remove` 或 `cleanup`，迁移时同时传入 `vmId` 和目标 `poolId`。接口要求本机控制凭证。例：`{"mode":"move","vmId":"<实例 UUID>","poolId":"default"}`。

验证：`npx tsx --test tests/storage-pools.test.ts` 覆盖持久注册、分配、迁移、重启恢复、清理及拒绝条件；`npm run test:storage-pools` 使用真实 Alpine/QEMU 客户机，在三次启动和双向迁移之间验证同一客户机文件。
