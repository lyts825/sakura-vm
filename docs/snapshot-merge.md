# 快照分支合并

在已停止的实例上创建快照，然后从该快照克隆分支。Sakura 为明文快照分支额外保存一份独立的基线 QCOW2 磁盘，并在实例记录中保存来源实例和快照 ID。基线占用额外存储空间；普通当前状态克隆和加密实例不建立合并分支。分支保留明文基线期间不能转换为磁盘加密实例。

停止分支与来源实例后，在分支的“快照分支合并”面板选择客户机路径和分区。预览读取基线、分支当前磁盘、来源实例当前磁盘的普通文件与符号链接清单，比较 SHA-256 和链接目标。若双方相对基线修改同一路径且内容不同，就报告冲突；相同修改记为已存在。预览只读复制来源磁盘，不修改任何实例。

执行合并时先克隆来源实例，再在隔离救援系统中重新计算三方差异。没有冲突才将分支的文件新增、修改和删除应用到新克隆的磁盘；原实例与分支均保持不变。新实例记录分支、来源、快照、路径、时间和文件数。冲突时删除本次克隆并返回冲突清单。执行失败或取消也会清理本次克隆；若宿主进程在克隆之后异常退出，可能留下一个未标记合并来源的普通克隆，请核对任务历史和实例列表后手动处理。

自动挂载支持 ext2、ext3、ext4。一次最多扫描每盘 5000 个普通文件或符号链接，应用至多 200 项、64 MiB。仅合并指定路径中的文件内容及符号链接，不合并目录属性、特殊文件、磁盘分区、项目设置、快照历史或内存状态。新增目录由救援系统创建，不复制目录属主和权限。加密磁盘和仍在运行的实例会被拒绝。

```text
GET  /api/vms/:vmId/snapshot-merge
POST /api/vms/:vmId/snapshot-merge
     {"mode":"preview","path":"/workspace","partition":0}
     {"mode":"apply","name":"merged-copy","path":"/workspace","partition":0}
```

`POST` 返回后台任务。通过任务列表或 `/api/jobs/:jobId/result` 获取 `applied`、`already`、`conflicts`、`mergedVmId` 和来源信息。`npm run test:snapshot-merge` 使用真实 QEMU/Alpine 验证冲突预览、冲突执行的回滚、新实例启动与文件内容、原盘不变。
