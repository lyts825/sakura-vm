# 受管存储与恢复

`server/storage-runtime.ts` 把宿主文件操作的异步并发、显式缓冲、文件句柄和暂存空间交给同一个 `hostRuntime`。它不是 OS 文件系统沙箱：操作系统页缓存、V8 领域索引对象、密码派生的原生工作内存、QEMU 自身内存、第三方任意文件调用及用户在宿主上的操作不由这些额度限制。

## 准入和空间

默认宿主额度为 8 个 I/O 操作、64 MiB 显式缓冲和 128 个文件句柄；其中为控制工作保留 2 个操作、4 MiB 和 8 个句柄。一个操作同时申请所有宿主、设备和任务分区，等待期间不占用部分额度。每任务一个操作，每设备总计两个操作、普通写一个、普通读最多两个。设备身份由已存在祖先的真实路径、设备号和 Windows 卷根确定；不同路径指向同一设备时共享容量。

网络外发流另有每宿主一个、每设备一个 `outbound` 通道，同时占用设备总额度。实例包外发使用 20 MiB / 8 个句柄，内容块下载使用 36 MiB / 4 个句柄；上限给同宿主的实例包接收保留至少 24 MiB 缓冲和 I/O 准入，避免相向迁移因远端背压互等。普通文件下载使用同一外发通道。写入本地备份或黄金镜像不占这个网络通道。

已知输出按实际格式和阶段预留：QCOW2 使用 `qemu-img measure` 的 `required`，原生 LUKS 加密盘的测量与转换使用同一组选项，历史快照也使用同一快照标识。转换中间盘、实例包、密文、明文解密文件和目标副本按同时存在的阶段取峰值；不按虚拟容量乘固定倍数。测量和转换间保持同一 VM 锁。128 GiB 稀疏普通盘及加密盘均有使用真实 `qemu-img`、64 MiB 模拟剩余空间的回归。

未知长度的 HTTP 导入、同步下载和镜像下载先登记设备，再由 `storageGrowth` 在写出每个增长块之前增量预留。`ResourceLease.resize()` 原子检查宿主统一分区，容量不足立即拒绝，不在已持有 I/O 时再次排队。设备总容量约束和 `statfs` 可用空间检查同时生效；已经写出的、由同一租约跟踪的字节只扣一次可用空间。流本身仍执行各自的长度上限、内容哈希与格式校验。

暂存预留直到文件删除、实际关闭或明确转交给已发布的领域记录后才释放。取消只是停止准入与工作信号；不会提前归还仍有流、句柄或远端分片清理未确认的预算。`STORAGE_CLEANUP_PENDING` 在宿主资源诊断中保留原租约和故障；普通校验失败在成功清理后正常释放。

## 已接入的路径

- 备份导出、加密、去重物化、校验、恢复与删除；独立实例包导入/导出、克隆、历史快照复制和冷迁移的共享入口。
- 同步的宿主扫描/哈希/文本读取、临时文件写入、已有恢复点的原文捕获和回滚；保留 `sync-history` 的原有回执格式。
- 云镜像下载、OVA 提取与格式转换、磁盘导入、`Machines.adopt` / `importDisk` 的目标副本、黄金镜像制作与实例化。
- 存储池的目录复制和校验、现有 `pendingCleanup` 恢复；数据目录迁移的复制、重定位和核对。
- S3 下载、远端哈希、导入和分片上传。上传最多两个 8 MiB 分片工作者，等待两者真实结束以及远端清理回执。
- 本地 HTTP 文件流入口 `streamStoredFile` 和内容块下载；沙箱产物流式收集与受限读取；去重块检查与回收。

嵌套调用显式传递 `StorageLease`，例如备份恢复 → 解密 → Bundle 解包 → VM adopt。不得根据相同 VM ID 推断可借用租约。VM 或领域锁先取得，随后申请 I/O；持有 I/O 的导入调用只尝试现有立即拒绝冲突的 `Machines.locked`，不排队等待 VM 锁。不可把这个领域锁改成等待队列而不重新审查顺序。去重块维持原来的串行队列，I/O 准入在队列之前；没有拆分哈希、暂存和 GC 的读保护。

## 发布与恢复

`MetadataStore` 以规范化文件名串行执行完整读改写、替换、移除和 flush，revision 是内容哈希，不向现有 JSON 添加外壳。替换在调用时捕获快照；冲突会明确拒绝。失败写入不会毒化后续纠正操作，但 flush 会报告尚未修复的失败。它处理进程内路径别名，不替代目录归属，也不是跨进程数据库锁。

每 VM 的 `backups/<VM>/publication.json` 是小型发布日志：先登记受控暂存身份，再在发布前持久化已验证记录，之后发布文件或块清单、更新索引、记录并清理旧备份。重启首次访问会核对精确长度和哈希；已发布但尚未入索引的副本补入索引，未发布的暂存文件被清理，已记录删除完成收尾。内容不符时保留原文件和日志并报告 `BACKUP_RECOVERY_REQUIRED`，不重新导出、不自动覆盖。保留期在恢复清理时重新检查。日志不替换同步历史、存储池清理票据或远端复制回执。

存储池删除失败保留原租约，并绑定已有 `pendingCleanup`；原清理入口确认删除及票据持久化后才释放。数据目录迁移在创建 stage 之前取得 `DataDirectoryOwner` 的目标归属，取得后再次确认目标不存在，持有至发布完成或安全失败处置结束。stage 清理未确认时保留归属与 I/O。已经 rename 出来的迁移目标继续遵循原迁移回执/激活流程，来源数据不删除。

普通备份、同步、对象镜像补传和存储分层周期工作已经登记 `Scheduler`。同步的短暂文件事件防抖仍为事件合并；协议截止时间与 HA 心跳不在这批迁移范围内。
