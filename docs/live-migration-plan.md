# 在线迁移检查与执行

能力中心的“虚拟机在线迁移”检查读取运行中实例的 QEMU 状态、版本和迁移任务状态，并刷新已配对主机的资源评分。没有指定目标主机时选择一个合格同伴；也可在 `POST /api/vms/:vmId/next-features` 的 `check` 请求中传入 `options.targetHostId`。检查结果包含候选主机、逐项阻断原因及迁移步骤，不会修改实例或发送数据。通过检查后可向同一接口提交 `{ "action": "run", "featureId": "live-migration", "options": { "targetHostId": "已配对主机 UUID", "targetName": "可选目标名称" } }`，服务创建后台任务并记录迁移标识、目标实例及日志。目标端需要授予该来源导入和启动权限。

底层 QEMU 传输模块已将 `blockdev-mirror` 的 NBD 磁盘在线镜像与 RAM 预复制组合：先等待磁盘追平，QEMU 在 `pre-switchover` 暂停来源后再次等待最后的脏块追平，取消镜像并关闭 NBD，持久来源栅栏成功后才允许目标继续运行。栅栏前的预复制错误会取消迁移，且仅在确认迁移取消、目标未运行时恢复来源；栅栏结果不确定时维持两端停机以避免双写。独立的 [真实 QEMU 冒烟脚本](../scripts/smoke-qemu-live-migration.ts)使用临时合成磁盘，在 Windows QEMU 11.1 和 WSL Linux QEMU 10.2 上验证正常切换、磁盘内容一致、预复制中断、栅栏失败与磁盘容量不匹配。Windows 可运行 `npm run test:live-migration-transport`；WSL 内可运行 `node --experimental-transform-types scripts/smoke-qemu-live-migration.ts`，并追加 `--interrupt-precopy`、`--fail-fence`、`--different-size` 或 `--remote-endpoint` 验证失败路径。传输模块拒绝非回环端口。加 `--peer-tunnel` 后，Windows 与 WSL 上的真实 QEMU NBD 和内存迁移流及受限目标 QMP 控制也通过配对主机的证书指纹锁定 TLS、短期会话和权限校验；再加 `--legacy-drive` 可使用与正式实例相同的 `-drive` 写法，并从 QMP 读取自动生成的磁盘节点；测试仍在单机上模拟两个主机，栅栏为测试回调，且没有启动完整客户机系统。目标通道可在撤销同伴权限时断开；来源实例另有持久迁移栅栏，服务重启后仍拒绝原主机启动。目标运行时增加 `-incoming defer` 暂停接收模式，接收期间不会执行普通客户机就绪探测，也不能通过手动恢复启动；迁移完成且 QEMU 确认运行后才转入就绪探测。

来源任务现在串联目标准备、两条证书指纹锁定的 TLS 转发、NBD 磁盘镜像、RAM 预复制、持久来源栅栏、目标完成确认及客户机就绪轮询。只有目标客户机就绪后才强制停止来源 QEMU；来源记录保留，且持久栅栏禁止再次启动。若栅栏建立前失败，任务仅在 QMP 确认来源仍运行时请求目标撤销；目标只在身份、会话、迁移记录及 QEMU 暂停状态均吻合时删除。栅栏后或状态不确定时保留目标与来源供人工核对，不能自动恢复来源。QMP 客户端对尚未建立连接时的短暂拒绝进行有限重试，避免连续命令关闭前一连接时误判来源失联。Windows 可运行 `npm run test:live-migration-target` 和 `npm run test:live-migration-runner`；后一脚本启动真实 Alpine 客户机，经配对 TLS 完成磁盘与内存迁移，并在目标 SSH 中读取切换前写入的标记。测试在一台宿主模拟两个控制服务，尚未覆盖独立物理主机的网络故障与断电恢复。当前执行范围限同平台、同架构、TCG、BIOS、无磁盘加密、无快照及无特殊硬件的实例；Sakura 项目配置等宿主元数据尚未迁移。因此目录继续标为“部分实现”。跨主机移动也可使用已有的[冷迁移队列](cold-migration.md)，但需要先停止源实例。底层顺序依据 [QEMU 在线块操作](https://www.qemu.org/docs/master/interop/live-block-operations)和 [QMP 迁移命令](https://www.qemu.org/docs/master/interop/qemu-qmp-ref.html)。
