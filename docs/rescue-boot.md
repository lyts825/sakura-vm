# 只读救援

启用“磁盘快照”插件，在停止实例的“快照 → 只读救援”中提交命令。Sakura 创建独立 Alpine 临时系统，启动后只读连接源磁盘，执行结束后停止并删除临时系统。无需源系统能够正常启动。

源实例在整个过程中保持停止并被锁定，不能同时启动、删除、恢复快照或修改磁盘。临时系统使用 512 MiB 内存、1 vCPU、4 GiB 临时 COW 根盘，计入 4 台同时运行、32 台保留实例的限制；需先准备本机 Alpine 镜像。网络隔离，仅保留控制器 SSH 通道。

## 操作

1. 选择分区。默认 `0` 表示整盘文件系统，适用于 Sakura 默认 Alpine 镜像；其他镜像可能使用 `1` 或其他分区编号。布局不明确时取消“自动只读挂载源文件系统”，先执行 `cat /proc/partitions` 与 `blkid`。
2. 自动挂载支持 ext2/ext3/ext4，挂载点为 `/mnt/source`。ext3/ext4 使用 `ro,noload`，不重放文件系统日志。未知格式、加密卷、LVM、缺少驱动或无法挂载的损坏文件系统不会被自动修复。
3. 命令在临时系统的 `/workspace` 执行。实际源设备路径保存在 `/run/sakura-source-device`，可用于只读诊断。命令及产物收集期限为 1–1800 秒，不包含启动和挂载时间；整个救援系统另有 35 分钟期限。
4. 将需要保存的普通文件复制到 `/workspace`，在产物框列出相对路径。最多 8 个文件、合计 8 MiB，禁止 `..`、绝对路径及指向工作目录外的链接。完成后下载产物或导出执行记录。

例如恢复源实例中的项目说明：

```sh
cp /mnt/source/workspace/README.md /workspace/recovered-README.md
```

产物填写 `recovered-README.md`。恢复文件保存在宿主数据目录，并通过 SHA-256 校验下载；不会覆盖源文件或其他实例中的文件。任务失败时已经成功保存的产物仍可下载；取消或超时不会继续提取文件。请在删除源实例之前下载所需产物。

## 生命周期与边界

QEMU 块设备与底层文件均以只读模式打开，并检查 QMP 返回的只读状态。临时系统启动完成后才接入源盘，避免与基础镜像相同的文件系统 UUID 干扰启动。客户机挂载前还检查块设备只读标志，普通文件写入及原始块写入均应失败。

关闭网页或锁定控制面不会取消已经提交的后台任务；使用“取消救援”或任务中心取消。取消、超时、应急锁定和正常服务关闭均终止整个临时虚拟机，确认 QEMU 退出后释放源实例锁。故障启动的尾部日志保留在任务记录。重启后遗留的救援实例会清理，不自动恢复命令或磁盘连接。

此入口用于只读检查和提取，不执行写入修复。它不绕过 QCOW2 损坏、文件系统不一致或加密保护；挂载失败会明确报错。跳过日志重放可能看到未完成事务之前的状态。产物及任务记录位于本机，沿用任务历史保留规则，不提供额外加密。

依据：[QEMU 块设备参数](https://www.qemu.org/docs/master/system/invocation.html)、[Linux ext4 只读与日志重放说明](https://docs.kernel.org/admin-guide/ext4.html)。验证命令为 `npm run test:rescue`，使用隔离数据目录和真实 Alpine/QEMU 验证挂载、写入拒绝、提取、取消、超时及清理。
