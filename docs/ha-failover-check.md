# 故障接管策略与健康检查

第三批能力中心的“故障接管策略与健康检查”可保存目标、故障阈值和副本最长时效，并持续观察本机主实例的运行状态。API 使用 `POST /api/vms/:vmId/next-features` 的 `configure`，设置 `featureId: "ha-failover"`、`enabled: true` 和 `options.targetHostId`（已配对主机的主机 ID），可选设置 `failureThreshold`（2–10，默认 3）、`maxReplicaAgeMinutes`（1–10080，默认 1440）和 `autoProcessFailover`（默认 `false`）。`check` 结果包含主实例状态、目标资源和平台观测、最近已校验快照副本的实时回执与数据时效；开启本机进程故障接管后还会验证目标启动权限与停机状态。`localProcessReady` 仅在本次服务已观察过来源进程运行、故障达到阈值且其余预检均通过时才为真；检查本身不会启动副本。

启用并选定目标后，主实例首次进入 `running` 时监测器开始计数；每 15 秒采样一次，连续 `failureThreshold` 次处于 `error` 或 `stopped` 则标记为疑似故障。恢复运行会清零；通过 Sakura 主动停止或暂停时会撤销监测。进程异常退出与故障计数写入 `ha-failure-monitor.json`，服务异常终止后重启可继续观察；正常关闭服务会撤销监测，避免计划关机触发误报。`GET /api/vms/:vmId/next-features` 的 `haFailoverMonitor` 和手动 `check` 结果的 `monitor` 显示采样状态。

要启用本机进程故障接管，先用[跨主机快照复制](snapshot-replications.md)创建停机副本，在目标主机的入站配对中分别授予“实例包导入”和“故障副本接管”，再勾选“本机 QEMU 进程退出后自动接管”。来源本次服务运行期间必须实际见过该 QEMU 运行；旧监测记录或服务重启后未托管的进程不构成退出证据。达到故障阈值后，Sakura 重新检查目标容量、平台、回执、快照时效和目标停机状态，在本机持久保存来源启动栅栏，然后请求目标启动。来源启动会返回 `HA_SOURCE_FENCED`；目标启动失败时保留栅栏并重试。目标仅返回“正在启动”时来源继续封锁、接管状态不记为已接受；目标客户机真正进入 `running` 后才记为已接受。

已导入的快照副本不能通过普通实例启动入口启动。目标仅接受已配对来源主机的故障副本接管请求，并再次核对来源主机、复制任务、来源实例、快照及磁盘校验值；这样手动启动备用实例不会绕过接管栅栏。

本机进程接管与宿主失联接管可同时启用。已登记见证的来源在保存本机接管栅栏前，必须先取得见证撤防确认；正在进行的慢速副本检查会先完成，再串行撤防，并在发布计划前重新核对来源运行状态、栅栏和策略。撤防确认返回后，本机再次核对来源故障、服务可用和当前目标策略，才持久保存栅栏；待完成的本机接管重试也必须重新确认撤防并复核同一目标。撤防回调缺失、见证不可达、见证已进入隔离阶段，或等待期间策略关闭/服务停止时，本机不自动启动其他副本。

退出接管须先在目标主机停止副本，并回迁目标运行期间的新写入，或明确接受丢失这些写入。来源实例面板需勾选数据确认后才能点“目标停机后退出接管”；API 使用同一路径的 `run`，传入 `{ "mode": "rejoin", "dataReconciled": true }`。来源经认证请求目标把该副本持久标记为不可重启，收到确认后才解除自身栅栏。目标仍运行、不可访问或权限撤销时，来源保持封锁；若目标已封锁但响应丢失，重复操作仍可完成。退出后旧副本不可再用于接管，需要重新复制快照。

## 独立见证节点接管宿主失联

第三节点配置模板、服务托管及真实故障演练步骤见 [独立第三节点部署与真实故障演练](ha-external-drill.md)。`ha:witness` 新增只读 `--drill-plan` 和 `--observe`：计划绑定实际来源硬件、目标和精确副本；观察需先记录来源基线，再确认关机、目标健康、流量指向及来源启动拒绝。报告不含认证资料，也不能凭软件接口自行证明节点在物理上独立。

见证状态现由进程独占锁保护；本机旧进程异常退出后核实 PID 才自动恢复锁。已确认的来源关闭状态在每次接管推进、目标重启及切流前都重新核对 Redfish UUID 和 `Off`。已接管目标退出后可重启同一副本，保留目标写入；流量已指向该副本时不重复提交切流。`fencing`、`fenced` 和 `promoted` 都可在数据核对、目标停机和持久退役后受控退出；成功退出回执支持心跳和见证重启后的重复请求。持久写入失败时见证封锁来源授权，Linux 同步状态目录，Windows 对短暂共享冲突进行有限重试。

仓库现在提供独立 HTTPS 见证程序（`npm run ha:witness`）。它每 15 秒接收来源 Sakura 的已校验副本心跳；连续 `failureThreshold` 次心跳缺失后，先持久记录隔离阶段，再通过 Redfish `ForceOff` 关闭**来源宿主**，直到该系统资源明确返回 `PowerState: "Off"`。关机前及确认时都要求 Redfish 系统 UUID 与已登记的来源宿主硬件 UUID 相同；身份不符时不发送关机请求，也不启动目标。隔离失败或结果不明确时，绝不启动目标。隔离确认后，见证程序使用来源与目标的已配对令牌复核并启动精确的快照副本；目标进入 `running`、应用健康接口确认、流量接口确认目标实例后，才记录接管完成。不同来源实例的外部隔离、健康检查和流量操作独立执行；某台 BMC 响应缓慢不会阻塞其他实例的心跳持久化。故障中断后会从持久状态重试，不重新允许来源启动。后台接管不依赖目标网页会话保持解锁；实例应急锁与数据目录维护状态仍会阻止操作。

来源实例一旦启用宿主失联接管，就把见证登记持久写入 `machines.json`。每次启动都必须先获得见证节点授权；见证不可达、状态文件损坏、HA 插件未加载时均拒绝启动。目标快照副本也不能从普通“启动实例”入口手动启动。启用或修改见证目标与阈值前须停止来源实例；关闭策略会先取得见证节点的撤防确认，再清除本机登记。删除来源实例前须先撤防。

见证程序要部署在独立于来源与目标的第三节点，并使用持久存储。`npm run build` 会生成 `.sakura-witness/ha-witness.js`，运行包也包含它。在首次部署、**确认目标副本未运行且没有历史接管记录之后**，执行 `npm run ha:witness -- --initialize <witness-config.json>` 创建状态文件；随后执行 `npm run ha:witness -- --preflight <witness-config.json>` 检查部署，再用 `npm run ha:witness -- <witness-config.json>` 启动。预检只读取见证状态、监听证书和外部状态：向 BMC 查询电源状态，查询目标主机身份，若已有布防计划则调用目标的只读副本预检和应用健康接口，并查询流量当前指向；它不会关机、启动副本或切流。报告只输出实例 ID、阶段和检查结果，不输出令牌或密码；任一检查失败时进程返回非零状态。无布防计划时无法验证精确副本及目标应用接口，应在布防后再跑一次预检。见证服务收到正常关闭信号后会等待正在执行的隔离与持久化操作结束。状态文件丢失或损坏时，程序拒绝自动初始化；应先核实源、目标和流量的实际状态，再人工恢复或初始化，不能把空状态当作安全的来源授权。

第 2 版运行包清单覆盖见证程序。更新暂存、启用及回滚会保留并切换见证代码；所有 `ha:witness` 命令都读取活动版本，并保持调用目录和相对配置路径。文件完整性失败会拒绝运行，不自动运行历史见证代码，升级兼容范围见 [自更新说明](self-update.md)。

见证配置 JSON 包含 `version: 1`、`listen`（`host`、`port`、TLS `certFile`、`keyFile`）、`stateFile`，以及每个实例的 `vms` 项。仅有一个来源宿主时可使用 64 位十六进制 `sourceToken`；多个来源宿主必须改用 `sourceTokens`，以来源宿主 UUID 为键、各自不同的 64 位十六进制令牌为值，且键须完整覆盖配置中的来源宿主。见证服务会把令牌绑定到请求中的 `sourceHostId`，一个来源不能替另一个来源续报心跳、撤防或退出接管。持久状态使用版本 4，绑定来源宿主、来源实例、目标宿主、故障阈值、Redfish 系统 UUID，以及启用自动回切时的来源健康/流量端点与证书指纹摘要。服务拒绝自动修改绑定或升级旧状态；第 2/3 版升级、更换配置和损坏状态恢复使用 [受控见证维护](ha-witness-maintenance.md)。每项填写 `sourceHostId`、`sourceVmId`、`targetHostId`、`failureThreshold`，并配置：

| 字段 | 内容 |
| --- | --- |
| `redfish` | 来源宿主 BMC 的 HTTPS `baseUrl`、`systemPath`（如 `/redfish/v1/Systems/1`）、`systemUuid`（该资源返回的 `UUID`，应与来源宿主硬件清单核对）、`username`、`password`，以及 `caFile` 或 SHA-256 证书 `fingerprint` 二选一。见证程序按 [DMTF ComputerSystem Reset](https://redfish.dmtf.org/schemas/DSP2046_2025.1.html) 发 `ForceOff` 并轮询 `PowerState`，每次读取均校验 `UUID`。|
| `target` | 目标 Sakura 主机的配对 HTTPS `baseUrl`、证书 `fingerprint`、来源主机在 `host-peers.json` 中保存的该目标配对 `token`。目标入站配对必须授予导入和故障接管权限。|
| `application` | 应用健康 HTTPS `url`、64 位十六进制 `token`，可选证书 `fingerprint`。`GET <url>?vmId=<目标实例 UUID>` 须返回 `{ "ready": true, "vmId": "<目标实例 UUID>" }`。|
| `traffic` | 流量控制 HTTPS `baseUrl`、64 位十六进制 `token`，可选证书 `fingerprint`。`POST /activate` 接收 `{ "sourceVmId": "...", "targetVmId": "..." }`，须幂等返回 `{ "accepted": true, "activeVmId": "<目标实例 UUID>" }`；`GET /status?sourceVmId=...` 须返回同一 `activeVmId`。|
| `failback` | 可选自动回切。`application` 使用与应用健康相同的配置结构；`GET <url>?vmId=<来源实例 UUID>` 必须返回该来源 ID 与布尔 `ready`。同一 `traffic` 还须支持幂等 `POST /restore`，接收 `{ "sourceVmId": "...", "retiredVmId": "<已退役副本 UUID>" }`，返回 `{ "accepted": true, "activeVmId": "<来源实例 UUID>" }`。|

来源 Sakura 的 `SAKURA_HA_WITNESS_CONFIG_FILE` 环境变量指向另一个仅包含 `version: 1`、见证节点根 `url`、其证书 `fingerprint` 和本来源宿主对应的 `token` 的 JSON 文件。配置后重启来源服务，在实例的故障接管面板选定目标，启用“独立见证节点确认宿主隔离后自动接管”，并保持见证配置中的阈值一致。更换目标、阈值或启用回切接口时，先关闭策略并获得撤防确认，再通过 `--reconfigure` 提交新绑定、停止来源实例并重新启用。来源只在目标容量、平台、快照时效、复制回执和目标停机状态均通过时发送布防计划；不满足时发送撤防心跳。慢速预检期间的存活心跳独立续报，不会先清除上一次仍在有效期内的已校验计划；预检确认为不可用或计划过期时撤防。检查结果包含见证状态，只有来源计划与见证布防均就绪才报告 `ready: true`。

宿主失联后的回切先停止目标、回迁目标期间的新写入或明确接受丢失，在来源面板确认后执行“目标停机后退出接管”。见证收到精确副本的持久退役确认后才允许来源启动。配置 `failback` 时，完整退役身份和 `pending` 回切状态一起持久提交；来源启动并通过认证健康检查后，见证复核退役、幂等调用 `/restore`，再以 `/status` 确认来源，记为 `completed`。未知流量目标、错来源健康响应、退役不一致或接口失败均保持待回切。成功响应丢失、见证重启均可恢复；已指向来源时不会再次写流量配置。关闭接管策略只撤销后续接管，已有 `pending` 回切仍继续：来源服务在启动时读取见证记录，对运行来源仅续报 `plan: null`，不会重新布防。`haHostFailover.failback` 和见证 `failback` 状态可分别显示策略布防与既有回切；未配置 `failback` 时仍须在来源健康后自行恢复流量。恢复封锁状态则显示 `recoveryHeld: true`，禁止启动和自动推进。

独立 HTTPS 协议测试覆盖 Redfish、配对目标、应用健康和流量接口，以及见证重启/失败路径；只读预检覆盖证书、BMC 系统 UUID、目标身份、布防副本和外部接口契约。

`npm run build` 后运行 `npm run test:ha-failover -- alpine`（也可选 `debian` 或 `ubuntu`），会创建独立临时数据目录，在不同服务进程间复制真实客户机的历史快照，再由编译版见证进程启动真实备用虚拟机。目标采用与生产服务相同的实例包接收器；锁定目标网页会话后继续验证自动接管。客户机开机运行真实 HTTP 应用，健康适配器读取该应用响应；本地流量测试入口随后转发请求到目标应用，并检查历史快照数据。

此联测还验证错误 BMC UUID 不发送关机命令、确认来源关机后才启动副本、应用未就绪及切流拒绝时保持来源封锁、见证重启后的持久状态、目标运行时拒绝退出接管、停机退役后拒绝再次接管，以及来源恢复启动。测试需要已下载对应镜像及 QEMU；只操作其自身创建的临时实例。**这里的 BMC 是本地模拟服务，ForceOff 实际停止测试来源 QEMU，并未关闭物理宿主；来源、目标及见证进程运行在同一台测试电脑，流量适配器也只用于联测。尚未在用户的真实第三节点、BMC、应用健康端点与流量控制系统上完成故障演练**，目录仍标为部分实现。已移除源实例的[冷迁移](cold-migration.md)可单独授权目标启动。
