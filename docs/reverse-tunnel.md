# 临时反向隧道

在能力中心选择运行中的实例和工作项目，选择“临时反向隧道”，将参数设为 `{"mode":"open","guestPort":8765,"durationSeconds":300}`。客户机需有 Python 3.9+，目标 TCP 服务应监听该项目网络空间的 `127.0.0.1:guestPort`。任务完成后返回宿主机上的 `127.0.0.1:localPort`，以及绑定的项目 ID、目录和网络模式；可用本机浏览器或 TCP 客户端连接。入口只绑定宿主机回环地址，不向局域网开放，每个入口最多允许四个并发连接。

每个项目可独立开启一个入口；切换项目后，`status` 和 `close` 只查询或关闭当前项目的入口。Python 探测和 broker 使用原项目持久 UID/GID、独立 home、捕获配置/live 和原网络；环境只解析一次，正文、环境和随机连接凭据通过原生保护帧运输，原生目录描述符固定 cwd。既有 root 目录须明确应用 [目录迁移](project-directory-migration.md)，缺失目录不自动建立。私有模式只允许回环，不新增接口或路由；每次连接核对原完整账号、boot、cgroup/network、PID 创建时间和 UID 监听 inode。固定管理员桥接只连接经过凭据核对的 UID broker，用户指定目标由 broker 连接。共享模式使用客户机共享回环，目标应自行区分调用者。

时限可设为 10–600 秒，到期、实例停止或暂停、应急锁定、客户机运行会话变化或 Sakura 服务关闭时先撤销监听和所有连接。客户机独立期限守护清理整个原 cgroup，包括脱离终端的后代；原全域、保护帧及准确 native 票据核销后才释放准备租约和删除宿主记录。启动前持久保存原 UUID/账号/正文及配置摘要；broker 已启动但回执丢失、宿主监听尚未建立时也保留原准备租约。失联或清理失败返回 503，原记录阻止重复启动及目录/网络修改，明确关闭可重试；暂停须先恢复实例或按准确旧 boot 证明退休。服务关闭取消并等待准备操作。创建完成后的请求取消不改变入口期限。隧道不为本机客户端增加身份认证，本机其他进程在有效期内也能访问，敏感服务应继续使用自身认证。

宿主服务重载后，同步 `status` 保持不活跃，明确 `check` 核对已知原完整票据并恢复原宿主端口，不启动新 broker 或发行新 native 运行。恢复先只读核对旧票据，再取仅核对原目录/网络的准备租约，不安装软件包或修复网络。过期、变更、未知及旧 root 记录保留，不自动接管或按标签杀进程。独立元数据位于 `/run/sakura-reverse-tunnels/<projectId>`，不占用用户服务名。

此实现通过 Sakura 控制的 SSH 命令通道转发字节，不要求启用客户机 SSH TCP forwarding，不修改客户机 SSH 配置。中继支持二进制、背压和 TCP 半关闭；输入 EOF 后仍可接收延迟响应，空闲连接不受最初连接超时限制。

本批正式七个相关测试文件共 196 项通过，完整类型检查通过；包含真实宿主 journal、原域/租约失败模型，以及实际宿主 Python 和回环流的二进制、背压及半关闭测试。证明为 `.data/reverse-identity-backend-74d05060-4dbf-4b5f-b57f-2e2b50498abb-verification.json`。本批未启动 VM，不能据此声明真实 Linux UID、cgroup、私有网络描述符及到期后代清理已验证。既有 `npm run test:reverse-tunnels -- alpine`、`debian`、`ubuntu` 冒烟脚本仍需适配明确目录迁移及完整 UID 运行证明；旧管理员中继结果不替代新实现验证。
