# 临时反向隧道

在能力中心选择运行中的实例和工作项目，选择“临时反向隧道”，将参数设为 `{"mode":"open","guestPort":8765,"durationSeconds":300}`。客户机需有 Python 3.9+，目标 TCP 服务应监听该项目网络空间的 `127.0.0.1:guestPort`。任务完成后返回宿主机上的 `127.0.0.1:localPort`，以及绑定的项目 ID、目录和网络模式；可用本机浏览器或 TCP 客户端连接。入口只绑定宿主机回环地址，不向局域网开放，每个入口最多允许四个并发连接。

每个项目可独立开启一个入口；切换项目后，`status` 和 `close` 只查询或关闭当前项目的入口。私有项目经 SSH 命令连接自身网络命名空间，不新增接口或路由，每次连接复核项目绑定与实际网络；共享模式使用客户机的共享回环地址。开启时可准备项目目录和私有网络空间，运行中的入口会阻止修改该项目目录或网络模式，需先关闭。中继使用系统环境，不加载项目环境或密钥。

时限可设为 10–600 秒，到期、实例停止或暂停、应急锁定、客户机运行会话变化或 Sakura 服务关闭时都会关闭监听并断开现有连接。服务关闭还会取消并等待尚未完成的准备操作。创建任务完成后，入口按自己的时限运行；取消已完成的请求不改变它的生命周期。入口及流量不持久保存，服务重启后需要重新开启。隧道本身不增加身份认证，本机其他进程在有效期内也能访问该端口，敏感服务应继续使用自身认证。

此实现通过 Sakura 控制的 SSH 命令通道转发字节，不要求启用客户机的 SSH TCP forwarding，也不会修改客户机 SSH 配置。中继支持二进制数据和 TCP 半关闭，空闲连接不会因客户机连接时的五秒超时而提前断开。`npm run test:reverse-tunnels -- alpine` 验证三个项目网络使用相同客户机端口的实际分离、能力任务上下文、配置保护、完整二进制响应、空闲连接、额外路由拒绝、请求与入口生命周期、到期和暂停撤销，也支持 `debian`、`ubuntu`。
