# 本机流程工作台

`flow-studio` 是 2.8.0 的 10 插件包。它将固定材料、人工核对、条件分支、绝对时间等待及原服务动作组成有向无环图。原服务动作目前支持接口验证和本机知识发布；每个阶段单独预览和批准。

## 插件与入口

| 插件               | 功能                                        |
| ------------------ | ------------------------------------------- |
| `flow-definitions` | 空间、固定图、拓扑和环检查                  |
| `flow-inputs`      | JSON 来源、人工审阅、固定标量绑定和导出许可 |
| `flow-connectors`  | 两个静态原服务适配器及可用性检查            |
| `flow-plans`       | 整图就绪检查、阶段计划及失效处理            |
| `flow-approvals`   | 当前账户的阶段批准、撤销和一次性消费        |
| `flow-journal`     | 顺序事件、摘要链和原回执记录                |
| `flow-runs`        | 按固定依赖推进、取消及原结果核对            |
| `flow-timers`      | 持久等待、到期查询、显式释放和取消登记      |
| `flow-exchange`    | 历史快照导出、离线核验和隔离接收            |
| `flow-workbench`   | 图编辑、批准弹窗、时间线、维护和恢复        |

页面 ID 为 `flow-studio`。默认模板包括“材料审阅与等待”“接口验证后人工放行”“文稿批准后本机发布”，另有标量条件分支示例。原服务模板中的占位引用必须换成用户选定的真实固定对象。

所有操作通过本机身份与原服务准入。可选的 `integration-runners` 或 `knowledge-publish` 缺席时，页面仍可编辑图和固定材料；相关动作不能执行。接口验证的真实结果须同时满足原断言和资源清理确认。

## 操作顺序

1. 创建空间，上传最多 1 MiB 的 JSON 标量对象。审阅后固定输入；最多 100 个变量，不解释脚本、表达式或模板代码。
2. 编辑并固定图。节点为 `material`、`approval`、`condition`、`wait` 或 `provider`，边按 `success`、`failure`、`always` 选择后继。条件未选中的分支保留为取消状态。
3. 预览图，确认固定输入和原服务均就绪，再创建运行。此时没有原服务写动作。
4. 选择已就绪节点，预览固定参数、依赖回执、原提供者范围和有效期。填写理由并批准后，只推进这个阶段。
5. 对运行中的原动作执行“核对原回执”。等待节点先登记，再显式释放到期等待；后续原动作仍需要新的批准。
6. 导出运行的固定快照及引用图，或隔离接收别人的流程历史。接收的对象没有执行与批准能力。

CLI 使用统一的参数文件入口；HTTP 方法为 `POST`，动作采用短横线命名。例如：

```sh
sakura flow definitions compile graph.json
sakura flow inputs bind inputs.json
sakura flow plans preview-flow preview.json
sakura flow runs start start.json
sakura flow runs preview-step step.json
sakura flow approvals approve approval.json
sakura flow runs advance advance.json
sakura flow runs reconcile original.json
sakura flow timers due scope.json
sakura flow timers release timer.json
sakura flow verify flow-history.zip
```

作用域为 `{workspaceId}`；固定引用为 `{domain,id,revision}`。`runs advance` 还需要 `id`、`nodeId`、`approval` 和当前运行的 `expectedRevision`。`runs preview-step` 是对外阶段入口；计划回调、批准消费、事件追加、原动作派发和等待唤醒只供固定内部消费者调用。

## 批准与恢复边界

批准绑定当前账户、原阶段计划、固定输入和运行代次。新预览、撤销、失效或重启会使旧批准无法继续使用。并发提交同一批准只执行一次；重复提交返回原运行状态。审批仅代表本机单账户核对。

流程先保存意图再派发原提供者票据。发送后失联或落盘不确定时，节点保留 `unknown`，阻止后继节点，且不能自动重发。接口验证按原计划 ID、摘要、运行 ID 和创建时间核对与清理；知识发布只接受原发布返回的精确 ID，不通过“最新发布”猜测成功。推进后继前再次核对原依赖，已撤回的知识发布不能继续放行。

取消停止未来阶段，并对支持停止的原运行请求取消。知识发布完成后不会因流程取消而撤回；补偿须显式创建新的阶段计划并重新批准。历史成功记录和未知回执始终保留。归档当前状态前须先清理不再受保护的旧修订，防止旧批准或旧运行状态复活。

等待和事件持久化后可在重启后查询。到期不会后台执行原服务动作。发布中断可通过“原发布与引用核对”确认已经落盘的对象或释放未发布对象自己的保护引用，恢复不重新派发业务动作。

## 预算与交接

当前实现采用比早期设计更小的边界：每空间最多 200 个未归档定义；每图 24 节点、50 条边；每空间 1 个活动流程、每账户最多 8 个。仍有进行中或未知节点的已取消运行继续占用活动名额。最长等待 30 天，空间控制材料和字节总预算 1 GiB。每运行保留最多 100 个事件引用；第 85 个修订起拒绝新增阶段预览，为核对和取消预留控制修订。原 VM 和请求预算继续由原提供者限制。

交接封套最多 16 MiB，其中来源材料最多 12 MiB。导出和每次下载都会重新核对来源许可及固定摘要。投影删除原派发票据、运行代次和可执行回执，保留脱敏的结果摘要与事件摘要；原审批仅作为来源声明。离线核验检查封套、字节、修订、固定输入、拓扑、计划和事件链，**不证明原提供者真实执行，也不转移批准**。

## 验证记录

已通过固定图、分支、并发一次推进、撤销、等待释放、内部入口拒绝、隔离交接和导出许可撤销验证；页面通过批准门禁、文本转义、取消、明确推进及会话锁定检查。故障协议检查覆盖发送后未知、账户错配、并发消费及重启不重放。真实插件重启后旧批准失效，等待到期查询不会自动推进。

真实服务代理验收已经完成两个原提供者闭环：知识服务确实生成一次本机发布，重复推进没有再次发布，撤回后前序依赖检查拒绝后继；接口验证确实创建隔离 VM、完成 3 次请求且全部断言满足，原运行确认清理后才放行后继，结束时没有运行中或登记中的 VM。纯 Node 离线入口核验了 23 个对象和 10 个事件组成的交接包。协议夹具和界面夹具均单独标记，不作为原服务执行证据。

测试脚本、交接样本、截图和详细回执只保存在被忽略的 `artifacts/plugin-packs-2.8.0/`，不纳入正式交付内容。
