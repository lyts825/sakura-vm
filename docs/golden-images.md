# 黄金镜像库

启用“磁盘快照”插件后，进入实例 → 快照 → 黄金镜像库。也启用“发行版镜像”时，可以在侧栏“镜像库”统一管理模板，包括源实例已经删除的模板。

1. 在源实例内准备所需的软件、工具链和文件，并清理不应复制的凭据与个人数据，然后正常停止实例。
2. 填写模板名称及备注，确认已经检查源实例内容，点击“保存黄金镜像”。
3. 模板完成后可单独校验 SHA-256，填写新的实例名称并创建。实例默认停止，需要在工作空间主动启动。
4. 删除模板需要确认；已有实例使用独立磁盘，删除模板或源实例不会删除它们。

制作通过现有 Sakura 实例包流程把当前 QCOW2 磁盘展平为独立副本，包含当前磁盘、Sakura 控制连接身份、初始化种子及项目配置。原快照历史不复制；没有基础镜像依赖，也不是共享可写磁盘。模板保存在数据目录下的 `golden-images/<模板标识>/`，单个包最多 32 GiB，最多 16 个、总共 128 GiB。制作前要求宿主剩余空间至少为源虚拟磁盘容量的两倍再加 64 MiB，以覆盖转换副本和实例包。空间检查是预检，操作过程中其他程序仍可能消耗空间。

模板是已经准备好的磁盘副本，不会自动清理整个系统。磁盘中的应用账户、私钥、SSH 主机密钥、机器标识、令牌及文件都会随模板复制。首次启动沿用 Sakura 克隆的身份更新流程：生成新控制密钥，把 `/root/.ssh/authorized_keys` 替换为新控制公钥，并更新 Linux 主机名；不声明为通用 Linux 系统清理工具。若工作负载需要独立机器标识或其他主机密钥，应在制作前加入适合该发行版的首次启动初始化流程。

创建新实例前重新校验完整实例包 SHA-256，随后验证包内磁盘摘要、QCOW2 头、外部依赖和连接身份。端口转发默认清空；项目环境值与磁盘中的数据按现有实例包规则保留，Sakura 宿主密钥库本身不复制。模板未加密，本机有数据目录访问权限的人能够读取包内容。

服务每次只执行一个镜像库操作，操作会出现在任务中心，支持取消。停止、取消和请求断连会清理尚未发布的临时模板；服务被强制结束时留下的目录会在列表中标为未完成，可明确移除。提交完成瞬间的断连可能已创建模板或实例，因此恢复页面后先刷新检查，再决定是否重试。服务不会自动重试实例创建，避免重复实例。

目录和文件拒绝链接、联接及多重硬链接。移除只删除本功能认识的普通文件，再移除空目录，遇到其他文件会停止并保留它们。源实例应急锁定会阻止制作、校验与从其模板创建，创建新实例前再次检查锁定状态；沙箱不能制作模板。正常删除源实例后，独立模板仍然可用。数据目录迁移和服务关闭遵循原有操作排空流程。

接口为 `GET /api/golden-images` 和 `POST /api/golden-images`，写入动作有 `create`、`verify`、`instantiate`、`delete`。两个操作已声明类型并纳入 OpenAPI 和生成 SDK；SDK 操作名为 `snapshots.golden-list`、`snapshots.golden-action`。插件关闭时端点拒绝访问。

验证包括真实 Alpine/QEMU 启动：制作模板后删除源实例，再从模板创建两台实例，检查两台都能读取原始标记、控制密钥各不相同、一台的写入不影响另一台，以及删除模板后第二台仍可启动。`npm run test:golden-images` 使用独立临时数据目录，结果写入 `artifacts/golden-images-smoke.log`。其他回归覆盖损坏和取消清理、目录边界、未完成目录恢复、并发拒绝、应急锁定复查、浏览器持久化管理与手机布局。
