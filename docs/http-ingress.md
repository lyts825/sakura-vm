# 本机 HTTP 服务入口

在实例的“服务与端口”页，先把 Linux 服务端口转发到 Windows 端口，再创建 HTTP 入口。入口监听 `127.0.0.1` 的指定端口，按最长路径前缀匹配，将请求转发到所选实例已经声明的 Windows 转发端口。路径匹配按段进行，例如 `/app` 不会匹配 `/apple`；可以保留或移除前缀。查询参数、请求体和 WebSocket 升级一并转发，健康检查直接访问上游指定路径。

入口规则最多 24 条、监听端口最多 4 个。监听端口不能与 Sakura 控制端口或任何实例端口转发重叠；保存前先绑定新端口，失败时保留旧规则。重启后从网络插件的数据文件恢复监听；被其他程序占用的端口会在页面显示错误。删除最后一条使用某端口的规则后，该监听端口立即释放。

当实例停止、被删除或上游端口转发被移除时，入口返回 HTTP 503。找不到匹配路由返回 404，上游连接失败返回 502。入口只在本机开放明文 HTTP，并拒绝非本机 `Host` 或 `Origin`；需要 HTTPS、本地域名或外部访问时，应另行配置可信的入口层。可用 `GET /api/ingress` 查看规则、健康状态和监听错误，使用 `POST /api/ingress` 的 `save`、`delete`、`check` 操作管理；两者沿用 Sakura 控制 API 的本机认证。

自动化验证包括 HTTP 路由、最长前缀、WebSocket、健康状态、端口冲突、配置恢复及删除释放；`npm run test:http-ingress` 使用真实 QEMU 和客户机 HTTP 服务验证 NAT 端到端转发。
