# 本机 HTTP/HTTPS 服务入口

在实例的“服务与端口”页，先把 Linux 服务端口转发到 Windows 端口，再创建 HTTP 或 HTTPS 入口。入口监听 `127.0.0.1` 的指定端口，按最长路径前缀匹配，将请求转发到所选实例已经声明的 Windows 转发端口。路径匹配按段进行，例如 `/app` 不会匹配 `/apple`；可以保留或移除前缀。查询参数、请求体和 WebSocket 升级一并转发，健康检查直接访问上游指定路径。

入口规则最多 24 条、监听端口最多 4 个。同一端口只能使用一种协议；切换现有端口的 HTTP/HTTPS 协议时先删除该端口的旧入口，或使用新端口。监听端口不能与 Sakura 控制端口或任何实例端口转发重叠；保存前先绑定新端口，失败时保留旧规则。重启后从网络插件的数据文件恢复监听；被其他程序占用的端口会在页面显示错误。删除最后一条使用某端口的规则后，该监听端口立即释放。

当实例停止、被删除或上游端口转发被移除时，入口返回 503。找不到匹配路由返回 404，上游连接失败返回 502。入口只在本机开放，并拒绝非本机 `Host` 或 `Origin`。HTTPS 入口首次创建时生成带 `localhost` 和 `127.0.0.1` 标识的自签名证书；可以下载公钥证书并自行加入信任，未信任前浏览器会显示警告。私钥仅写入本机网络插件数据文件，不通过 API 返回。证书默认在到期前 30 天自动轮换，也可在页面调整策略或立即轮换；轮换时现有 HTTPS 监听器立即采用新证书，新连接需要信任新的公钥证书。自动轮换关闭时不安排下次轮换，过期证书会阻止 HTTPS 入口启动。当前不生成或解析自定义本地域名，也不提供外部网络访问。

可用 `GET /api/ingress` 查看规则、健康状态和监听错误，使用 `POST /api/ingress` 的 `save`、`delete`、`check` 操作管理。`GET /api/ingress-certificate` 返回公钥证书、指纹、有效期和策略；`POST /api/ingress-certificate` 支持 `configure` 和 `rotate`。这些接口沿用 Sakura 控制 API 的本机认证。

自动化验证包括 HTTP/HTTPS 路由、证书校验和热轮换、WebSocket、健康状态、端口冲突、配置恢复及删除释放；`npm run test:http-ingress` 使用真实 QEMU 和客户机 HTTP 服务验证 NAT 端到端转发。
