# 主机维护排空

两台 Sakura 主机先完成[配对与导入授权](cold-migration.md)。在源主机停止所有实例，在任意一个实例的“能力中心 → 主机维护排空”填写目标主机的迁移目标 ID，先执行 `confirmSourceRemoval: false`。默认在目标沿用实例名称；若有名称冲突，或源实例在复制后变化，可通过 `targetNames` 按源实例 ID 指定新目标名。Sakura 逐台通过固定证书的 TLS 通道传输校验包，使用持久迁移标识避免失败重试产生重复实例。若某台传输失败，已复制的源实例仍保留；用同一目标 ID 和目标名称重试即可继续。

在目标主机逐台检查并启动导入的实例。确认所有实例可用后，以相同目标 ID 再次检查排空计划，并执行 `confirmSourceRemoval: true`。确认阶段要求当前每台源实例都有匹配的队列记录和目标回执；任何一台缺失或已变化，都会阻止批次开始移除。执行时每台还会重新核对源磁盘、实例记录、项目配置和目标回执。单台失败时后续实例保留，可修复后重试。排空结果列出每台目标 ID 和本机剩余实例数；迁移队列也会持续显示各实例状态。

此流程不会自动关闭运行中的实例，也不会迁移历史快照或原主机端口映射。排空期间若创建了新实例或更改了源实例，需重新检查并处理。目标主机仍需具备启动这些实例所需的运行条件。
