# 数据与实验工作台插件包设计

## 设计状态与交付目标

设计版本为 `1.0.0`，日期为 2026-10-23。应用基线为 Sakura `2.5.0`（`6fb9115`）。本文是待实施提案，不代表已有插件、接口或验证结果；本轮不修改应用版本。

`data-lab` 将数据导入、版本固定、分析、实验和结果交接组成一个完整工作流。用户能够从本地文件或受限数据库读取数据，生成有摘要的版本，运行 SQL 和 Python Notebook，比较结果，再交付可离线核验的资料包。

首版服务于单机、有界的表格分析。它不承担在线数据库管理、持续同步、分布式查询、模型训练调度或生产推理。原 `lab` 包保持原有实验性扩展定位，两个包使用不同 ID。

验收入口是“只有 `data-lab` 及其必需依赖”的新项目。必须完成本地文件到离线交接的全过程；数据库来源是同一流程的另一入口，缺少凭据服务时显示不可用原因。

## 首版数据范围与预算

| 项目 | 首版约束 |
| --- | --- |
| 文件格式 | UTF-8 CSV、逐行对象的扁平 JSONL、标量列 Parquet；拒绝压缩包、嵌套对象、嵌套列、任意插件格式和静默转换 |
| 类型 | 布尔、整数、浮点、定点十进制、字符串、日期、带明确时区规则的时间戳；精度、空值和异常值处理均写入 schema |
| 文件解释 | 固定 CSV 分隔符/引号/表头/空值标记，固定 JSONL 编码和数字策略；首轮推断需审阅，后续按固定 schema 解析 |
| 数据版本 | 最多 128 个分区、合计 512 MiB；记录每分区摘要、字节数、解析行数和顺序，不依赖可变目录 glob |
| 单次计算 | 输入合计最多 1 GiB，输出最多 256 MiB，临时空间最多 4 GiB；引擎默认 2 个 CPU、2 GiB 内存 |
| 时间与并发 | 默认 300 秒，最长 1800 秒；每项目 2 个运行、全局 4 个运行；矩阵最多 32 个组合，默认逐个执行 |
| 预览与输出 | 表格最多 100 行、1 MiB；Notebook 最多 500 个单元、单元输出 1 MiB、总输出 32 MiB；超限标记截断，不能形成完整证据 |
| 存储与交接 | 项目数据预算默认 5 GiB；单个交接包最多 1 GiB，包含全部文件、目录信息和描述；遵守现有制品文件 1 GiB 上限 |

预算同时计算上传、已保留版本、并发暂存和待核销材料。准入前预留预算，写入时持续计数；空间不足时停止并保留恢复记录。超过限制必须明确拒绝或让用户另建显式分区版本，不能只处理前半部分后报告成功。

## 插件成员、职责与独立价值

完整包新增以下 10 个插件。每个插件均提供自己的页面或面板、类型化服务与命令入口；统一工作台负责导航，不保存第二套业务状态。

| 插件 | 用户动作与输入 → 输出 | 单独启用后的用途 | 自有资源关闭行为 |
| --- | --- | --- | --- |
| `data-runtime` 数据计算环境 | 选择固定镜像和预算，准备/启动/取消/恢复；输入清单与运行描述 → 运行票据、日志、产物与清理回执 | 执行受管数据任务并核对环境 | 撤销准入，取消自有任务，核销 VM/cgroup/挂载/传输；不明归属保留 |
| `data-sources` 数据来源 | 登记来源、预览、捕获、撤销连接；文件或表选择 → 已捕获原始清单与一致性证明 | 安全导入文件或数据库表 | 关闭有界连接和游标，回滚只读事务，清除内存凭据，保留未完成捕获记录 |
| `data-datasets` 数据版本 | 审阅 schema、封存、对比 schema、生成脱敏副本、归档；来源清单 → 不可变版本及派生关系 | 管理表格版本和可共享副本 | 停止解析任务，撤销预览令牌；已封存版本与引用继续保留 |
| `data-transforms` SQL 变换 | 预览 SQL、运行、取消、重跑；版本与 SQL/参数 → 新版本、计划、运行证据 | 在固定数据上查询和生成新表 | 取消所持运行句柄，等待运行域回执，保留未确认任务 |
| `data-quality` 数据画像与质量 | 创建规则修订、抽样画像、全量检查、比较；版本与规则 → 覆盖范围明确的证据 | 检查空值、类型、范围、唯一键、重复行和引用关系 | 取消检查任务，释放临时读取；完整证据和所需输入引用保留 |
| `data-notebooks` Notebook 分析 | 从模板新建、打开、停止、封存、批执行；数据版本与 `.ipynb` → 草稿会话或密封结果 | 交互探索和单次可追踪分析 | 先关入口，再停止准确会话和全部内核后代；不触碰平台原有会话 |
| `data-experiments` 参数实验 | 预览矩阵、执行、取消、选择失败项重跑；Notebook/SQL 修订与参数 → 独立运行和指标 | 按相同输入执行有限参数组合 | 停止调度，取消自有运行，保留每组合的真实状态与清理状态 |
| `data-lineage` 血缘与比较 | 展开祖先、审查完整性、比较两次结果；不可变记录 → 关系图与有条件的差异报告 | 查清结果来自哪些输入和代码 | 取消索引与比较读取，释放下载租约；索引可重建，源记录不能改写 |
| `data-exchange` 离线交接 | 预览导出、导出、校验、隔离导入、接收；闭合证据图 → 文件包或本地接收记录 | 不依赖原 VM 核验并接收资料 | 终止传输，关闭读租约，保留隔离材料和恢复偏移 |
| `data-workbench` 数据工作台 | 选择项目并沿来源、版本、分析、实验、交接操作 | 提供全过程入口与缺失依赖说明 | 中止页面请求与临时预览，不因离开页面终止已确认的后台任务 |

所有 `data-*` 服务名采用对应的 `dataRuntime/dataSources/...` 前缀，避免覆盖现有通用键。依赖清单固定到本次应用插件版本，公共接口独立版本化。

| 插件 | 直接 `required` 插件 | 直接 `optional` 插件 |
| --- | --- | --- |
| `data-runtime` | `projects`、`delivery-artifacts` | 无；可导入经过本地核验的镜像摘要，不依赖其他新包 |
| `data-sources` | `projects`、`delivery-artifacts`、`data-runtime` | `secrets`，仅数据库凭据引用使用 |
| `data-datasets` | `delivery-artifacts`、`data-runtime`、`data-sources` | 无 |
| `data-transforms` | `delivery-artifacts`、`data-runtime`、`data-datasets` | 无 |
| `data-quality` | `delivery-artifacts`、`data-datasets`、`data-transforms` | 无 |
| `data-notebooks` | `projects`、`delivery-artifacts`、`data-runtime`、`data-datasets` | 无；显式声明 Notebook 系统服务依赖 |
| `data-experiments` | `delivery-artifacts`、`data-datasets`、`data-transforms`、`data-quality`、`data-notebooks` | 无 |
| `data-lineage` | `data-datasets`、`data-transforms`、`data-quality`、`data-notebooks`、`data-experiments` | 无 |
| `data-exchange` | `delivery-artifacts`、`data-datasets`、`data-lineage` | 无 |
| `data-workbench` | 上述 9 个 `data-*` 插件 | 无 |

按表格从上到下可拓扑排序。`data-notebooks` 与 `data-quality` 可并行装配；全部边只指向较早的提供者。服务不通过反向回调读取使用方。包成员只有这 10 个新插件，选择器展开 `projects` 和 `delivery-artifacts`，不启用完整 `delivery` 包。

与 `foundry` 的衔接采用镜像摘要与准备回执，与 `app-runtime` 的衔接采用显式导出后的静态结果。两个新包只提供可选的资料交换。与交付工作台的结果互通走制品清单；数据报告不自动变成可部署候选，也不继承交付发布的信任。

## 完整用户流程

1. 选择项目和本地计算镜像，核对工具版本、资源预算和离线可用性。缺少依赖时先展示准备计划，用户单独确认下载；准备完成不自动运行数据代码。
2. 上传本地文件，或选择项目内文件。预览固定路径、摘要、分区顺序、格式和预计规模；捕获前再次核对身份。数据库入口先确认目标、表、列、过滤条件和凭据版本。
3. 查看 schema 与脱敏样本，修订列类型和异常值策略后封存版本。生成脱敏副本时新建版本，保留原始版本的摘要及脱敏规则修订。
4. 在固定版本上预览并执行 SQL，保存新数据版本。选择质量规则运行全量检查；抽样画像单独展示，不能替代全量质量结果。
5. 绑定输入版本并打开 Jupyter 草稿。保存 Notebook 后封存代码与环境，选择“干净内核执行”；已有交互输出只作为探索记录。
6. 从 SQL 或 Notebook 选择参数矩阵，审阅组合数、输入、预计预算和错误处理。每个组合生成独立运行；失败项重跑保留旧证据。
7. 比较结果，先确认输入、代码、环境、指标定义和覆盖范围是否可比；展开血缘，检查是否有未知清理、缺失输出或非确定性说明。
8. 导出完整资料包，展示包含的原始数据、脱敏副本和代码。接收方离线核验摘要和图关系，确认命名空间后接收；重新执行还需另行确认并满足环境条件。

首版附带“销售 CSV 汇总”“JSONL 事件质量”“Parquet 参数分析”三个无外部服务模板。模板的数据和代码仅作示例，不能预填质量通过或实验成功。

## 数据权威、版本与隐私

`SourceRevision` 保存来源类型、配置修订、捕获时间、准入主体、连接目标指纹和捕获事实。文件来源记录内容摘要，路径只是位置提示；数据库来源记录实际读取事务信息、表列选择和输出摘要，数据库地址或事务 ID 不能代替内容版本。

先封存不含输出的 `ExecutionDefinition`，其摘要覆盖输入版本、代码/SQL、参数、环境与固定规则。`DatasetVersion` 摘要覆盖格式版本、分区顺序及摘要、schema、解析规则、时区、空值策略、父版本和这个执行定义摘要。版本不引用最终运行结果摘要。完成后的 `RunReceipt` 再引用执行定义和输出版本，形成单向关系；各对象自身 digest、可变状态、展示名称和时间均不参与内容摘要，避免循环自引用。

文件捕获拒绝符号链接、目录联接、越界路径、重复路径和捕获时变化的内容。浏览器上传使用实际字节摘要；项目文件经原项目身份读取。采集失败只生成不完整记录，不能封存为可运行版本。

schema 推断记录扫描范围。抽样推断仅是建议；封存前全量解析验证所有分区，异常行按固定策略拒绝或进入独立拒收清单。采用拒收策略的版本保留原行数、拒收数和阈值，不能把拒收行从质量分母中隐去。

抽样记录方法、种子、已扫描行数与总行数是否已知。预览默认隐藏字符串内容，只展示类型和长度；用户选择列级删除、常量替换、分桶或截断后才生成可见样本。首版不提供可逆伪匿名标识，也不声称自动发现全部敏感数据。

脱敏操作始终产生副本，不覆盖来源。系统日志和错误仅记录元数据；异常样例单独按敏感数据管理。Notebook 默认只绑定用户审阅后的脱敏副本。用户显式选择原始输入后，任意 Python 的文本、图像和文件输出都继承原始输入的敏感级别，预览和导出分别授权。系统不承诺自动识别或消除任意程序输出中的敏感内容；衍生聚合也不能自动宣称匿名。

血缘由生产者在封存时写入，只能新增后继记录。最小关系为 `源捕获 → 数据版本 → 变换/检查/Notebook → 实验结果 → 比较/交接`。每条边保存角色和内容摘要；来源自行声明的信息标记为 `declared`，本地运行和校验事实分别标记为 `executed`、`verified`。

## SQL、数据库与计算隔离

本地 SQL 只访问本次绑定的逻辑表。服务在可信准备阶段导入数据，再关闭外部文件、网络、扩展加载和配置修改能力。用户 SQL 仅允许解析后的单个查询表达式和受限内建函数，不接收任意 `COPY/ATTACH/INSTALL/LOAD/PRAGMA`。输出由可信收集器写入新清单。

SQL 文本仍按可执行代码管理：用户明确启动，运行在无外网、无来源凭据的自有临时 VM 内。输入只读，输出只允许独占目录。语法树检查、引擎限制、资源限制和 VM 边界共同验收；关键词过滤或只读数据库标志都不构成独立保证。

`data-runtime` 使用独立分析账号、home 和临时工作目录，显式传入最小公开环境，不继承来源项目密钥。镜像只读基线及工具摘要在启动和收集时复核；准备工具所需联网和数据计算分为两个阶段，运行时不得自动安装依赖或回退为联网模式。

镜像持有、独立运行磁盘和实例创建采用三个新包共用的拟增本体 `ImageAssetsV1`。本包只消费公开资产引用，不读取工坊目录；未启用工坊时也能从本体登记镜像准备环境。镜像能力和完整清理证明不满足时，环境保持未就绪。

数据库首版只提供 PostgreSQL 18 普通表的只读捕获。拒绝视图、外部表、继承/分区、行级安全策略、生成列、自定义类型及自由 SQL；客户端不提供函数调用入口。使用固定查询结构、准确引用的标识符及绑定参数；过滤只允许受支持标量列的比较和空值判断，结果完整落为本地版本后才能做后续 SQL。

捕获事务内复核关系种类、列定义及策略，无法核实则拒绝，不修改数据库安全设置。[PostgreSQL 行级安全文档](https://www.postgresql.org/docs/18/ddl-rowsecurity.html)说明策略表达式参与查询，[生成列文档](https://www.postgresql.org/docs/18/ddl-generated-columns.html)说明虚拟列在读取时计算。上述范围约束减少隐式执行，但外部数据库的管理员、扩展、访问方法和服务端日志仍在服务器信任边界内；Sakura 不保证远端零副作用或证明服务端实现无恶意。

远程连接需要当前操作者确认计划，绑定主机、端口、解析地址集合、数据库、TLS 证书校验规则、凭据修订、表列与预算。目标或凭据变化使确认失效。拒绝未批准目标、跳转代理、弱化证书校验和隐式扩大网络范围；不得自行开通远程数据库或更改权限。

使用专门的低权限账号，验证所需表权限与连接配置。在一个 `REPEATABLE READ READ ONLY` 事务内捕获，设置语句和事务时限；断线后重新捕获，不拼接两个事务的半份输出。数据库仍可能写日志或临时文件，只读事务也须配合权限边界，见 [PostgreSQL 事务说明](https://www.postgresql.org/docs/current/sql-set-transaction.html)。

数据库凭据只使用 `secrets` 引用，由受控连接器临时取得，经保护通道传递；不写入 URI、日志、制品或 Notebook。计划所需的强修订核验使用共享拟增的秘密引用版本接口，不能把现有读值方法或更新时间当作凭据版本。该接口由秘密服务提供，不依赖应用包。停止时取消准确连接的查询、回滚并关闭。回执不明时保留 `cleanup-unknown`，等待服务端时限或显式恢复核对，不向同名新连接发送旧取消。

Notebook 首版选择 Jupyter 和 Python 3；Marimo 继续由现有入口管理，不承诺批执行兼容。导入 `.ipynb` 时忽略旧内核地址与连接信息；HTML/JavaScript/小部件输出不直接执行，工作台只渲染有界文本、表格和核验后的图片。

交互会话属于专门分析工作目录，不能读到其他项目或未绑定数据。正式实验使用新内核和密封代码，每组合重新创建运行域，参数以严格 JSON 文件输入，禁止代码字符串替换。Python 随机种子只作为记录，不保证库、硬件或并行计算确定性。

## 公开拟增契约与状态机

所有名称均为拟增接口。公共 DTO 写入 `shared/contracts/`，独立服务接口写入 `server/service-contracts/`，实现必须通过 `serviceRef` 声明引用；不向插件暴露数据库连接、VM 内部对象或可变存储对象。

| 接口 | 主要方法与结果 |
| --- | --- |
| `DataRuntimeV1` | `inspectEnvironment/prepareEnvironment/plan/start/get/cancel/reconcile`；返回环境摘要、运行 ID、输出清单、清理状态 |
| `DataSourcesV1` | `save/preview/capture/get/archive`；返回来源修订、一次性计划和捕获记录 |
| `DataDatasetsV1` | `inspectSchema/seal/deriveRedacted/list/get/compareSchema/archive`；返回版本、拒收清单和修订冲突 |
| `DataTransformsV1` | `save/preview/run/get/cancel`；返回 SQL 修订、计划、数据版本与真实执行结果 |
| `DataQualityV1` | `saveRules/profile/check/get/compare`；返回范围、分母、失败数、异常样例的脱敏版本 |
| `DataNotebooksV1` | `createDraft/open/stop/seal/execute/get/reconcile`；返回自有会话 ID、密封 Notebook 和单元状态 |
| `DataExperimentsV1` | `plan/start/get/cancel/retryFailed`；返回组合清单和逐组合尝试历史 |
| `DataLineageV1` | `graph/verify/compare`；返回闭合范围、缺失节点、比较条件和差异 |
| `DataExchangeV1` | `planExport/export/verify/importPreview/accept`；返回传输记录、隔离清单和本地接收记录 |
| `DataWorkbenchV1` | `view/templates`；只聚合可用入口、阶段和当前授权下的摘要 |

本体新增 `BoundedDatabaseReadsV1`：只接受带准入证明的目标、固定读取计划和秘密引用，提供捕获、取消、核对与关闭。它受统一网络层约束；现有 HTTP 通道不能直接充当 PostgreSQL 连接。实现前先审定该能力的出站地址、凭据和连接归属规则。

本体新增显式作用域的 `NotebookEnvironmentsV2` 入口，接受 `{vmId, projectId, ownerId, expectedSessionId}` 及环境准备计划；`ownerId` 由宿主的插件身份派生，不接受客户端自报。入口固定原项目、原 boot 和会话，V1 行为保持兼容。新入口需支持只停止调用方拥有的会话，不能用当前活动项目或同名端口推断所有权。

| 对象 | 状态与约束 |
| --- | --- |
| 捕获 | `draft → planned → capturing → sealed`；变化、取消、断线进入 `failed/cancelled/incomplete`，重试创建新捕获 |
| 计算/检查 | `queued → preparing → running → collecting → succeeded/failed/cancelled`；另设 `cleanup: pending/confirmed/unknown`，只有输出完整且清理确认才可作成功证据 |
| 交互会话 | `starting → active → stopping → stopped`；身份或清理不明进入 `review`，禁止重新占用原资源 |
| 实验 | `planned → running → finished/partial/failed/cancelled`；`finished` 要求全部必需组合成功，取消的组合不能跳过后算完成 |
| 质量结论 | `pass/fail/unknown/not-applicable`；样本范围独立字段，缺失数据、超时或截断一律不能产生全量 `pass` |
| 交接导入 | `uploaded → verified → quarantined → accepted`；摘要不符为 `rejected`，旧质量结论只保留为来源声明 |

所有修改绑定固定 `{vmId, projectId}`、修订、请求幂等键和当次授权检查。预览令牌默认 10 分钟且单次消费，覆盖所有有副作用的输入；配置变化后返回冲突并重做预览。取消、接收和关闭重复提交返回已有事实，不重复执行。

幂等键绑定完整请求摘要，同键不同正文返回 409。权限拒绝返回 403，预算或体积超限返回 413，并发已满返回 429，资源清理未确认返回 503；错误包含稳定错误码、对象 ID 和恢复动作，不包含数据行或凭据。

## 比较、交接与引用回收

结果比较先给出 `comparable/conditional/incomparable`。固定输入、代码/SQL、schema、单位、指标定义、环境和重复次数一致才默认可比；若故意比较参数或算法变化，必须登记允许变化的字段，其余差异逐项列出。缺失值不能补成零。

表格逐行比较要求显式、经全量验证的唯一键；无唯一键时只给出带定义的多重集或聚合差异，不按随机行序配对。浮点比较必须保存绝对/相对容差。性能结果记录预热、硬件和运行负载，首版不给出未经统计设计的显著性结论。

实验指标采用有版本的 JSON，字段包括名称、有限数值或明确缺失、单位、计算定义摘要和期望方向。收集器核对运行 ID、代码摘要和所有必需指标；未知字段、重复名称和非有限数值拒绝封存。Notebook 中自行打印的“成功”不构成执行或质量证据。

资料包包含版本描述、分区清单、实际数据、schema、规则、代码、环境指纹、运行结果与血缘索引。默认只选择用户指定的脱敏版本与结果；额外包含原始数据和代码须在导出计划中明确选中。计划列出敏感内容与缺失祖先，删除连接地址、凭据引用和本机绝对路径。资料不齐时只能导出明确标记的“仅供查看”包，不能标记可重现。

导出只含脱敏版本时，声明该版本为交接数据起点，以摘要占位记录未交付的原始祖先，明确“上游不可复核”。可以核验包内图及从该起点开始的执行，不能声称原始数据到脱敏过程可重现。闭合性检查不得为补齐祖先自动带出原数据；完整程度分为包内完整、上游缺失和重新执行条件不足。

容器固定 `type: sakura-data-study-v1`、`schemaVersion: 1`，根描述文件为 `study.json`，与交付制品的容器及解析器分离。两个接收器先检查各自类型和严格 schema，错误容器拒绝接收；不得仅凭 ZIP 后缀判断。首版不签名，也不接受来源声明的签名作为信任依据；后续签名需要独立域分隔和可信发布者设计。

首版使用无脚本的目录清单和受限 STORE ZIP，禁止链接、绝对路径、路径碰撞与超限解包；逐文件验证字节数和摘要，再验证关系图。摘要只证明所持内容一致，不证明发布者可信。离线 CLI 无需账户、VM 或网络即可核验；重新执行仍要求匹配的本地环境和明确授权。

接收先进入隔离区，不连接原地址、不执行 SQL、不加载 Notebook 输出脚本。用户确认新命名空间及包含内容后，创建本地接收记录；保留来源摘要，不覆盖同名版本。导入的 `pass` 不变成本地验收，重新检查产生新的证据。

各版本、运行和交接记录持有 `data:<kind>:<id>` 的业务引用。先保留制品，再提交业务记录；失败产生可恢复待补偿项。归档只隐藏，不释放引用。删除预览列出依赖者，经确认后先移除合法叶节点引用，最后交由 `delivery-artifacts` 的精确清理执行。

下载遵守既有 `openRead/closeRead` 租约，并在 `finally` 关闭；长任务另持业务引用，不依赖 15 分钟下载租约。血缘索引是派生数据，索引损坏不能触发 GC。原 VM 停止或删除后，已封存清单仍可查看、比较和导出。

## UI、API、CLI 与权限

工作台分为“环境、来源、版本、SQL、质量、Notebook、实验、血缘、交接”。侧栏显示当前项目和预算，详情页固定展示版本摘要、范围、执行状态和清理状态；390 px 宽度下改为纵向列表，表格在自身容器滚动。

错误给出具体对象与恢复动作：来源变化重做捕获，schema 冲突修订规则，环境缺失打开准备计划，资源清理不明进入恢复页。离开页面只停止前端请求；关闭后台运行需明确操作。活动项目切换清除页面草稿选择和确认令牌，晚到响应不得进入新项目。

API 采用既有插件前缀约束，如 `GET/POST /api/data-datasets`，作用域在查询中显式给出。请求按动作使用严格联合 schema，响应进入生成契约；长任务返回运行 ID，进度沿现有 jobs 系统，声明 `jobs/job-retry` 贡献，重试需新计划。取消和恢复不能伪造成功状态。

拟增 CLI 为 `sakura data`，覆盖 `source preview/capture`、`dataset seal/mask`、`sql run`、`quality check`、`notebook execute`、`experiment plan/run`、`lineage compare`、`bundle export/verify/import/accept`。默认 JSON 可机读输出，日志走 stderr；退出码区分业务失败、输入/权限错误、资源清理未知，敏感值不接收在命令行参数中。

首版沿用交付插件的 owner 控制权限，所有成员与查看者入口明确拒绝。运行前、取凭据前、连接后和提交结果前复核授权；插件撤销后停止新增工作。宿主范围的归档读取仍复核原项目归属，不能以“VM 已删除”为由跳过授权。CLI、HTTP 和 UI 共用同一准入逻辑。

## 停用、重启和数据迁移

停用按逆依赖顺序撤销入口、停止调度、关闭来源连接和 Notebook 桥接，再等待自有计算域清理。记录包含 VM 创建身份、boot、项目账号、运行票据及资源标识，禁止只凭 PID、名字或端口杀进程。已封存内容保留，禁用包不等于删除数据。

服务重启先核对未终结记录。原运行仍存在时只能恢复准确句柄；原 boot 消失时登记退休原因；身份不符则保持 `review`。首版不自动恢复内核状态、不自动重放查询或远程捕获，用户通过新计划重跑。清理确认前不能把旧尝试覆盖为新尝试。

元数据采用严格 schema、显式格式版本与原子修订写入。迁移前只读预检并保留备份，迁移引用和记录必须一起核对；中断后可恢复到旧格式，不改原内容摘要。遇到未来格式或损坏记录只读隔离，不以空数组替代。旧 Notebook 会话不自动归入本包。

## 实施里程碑与验收

| 里程碑 | 优先级、依赖与负责人角色 | 可验收交付 |
| --- | --- | --- |
| M0 契约与准备 | P0；无前置；本体/插件契约维护者 | 选定并固定引擎版本和来源；镜像资产引用、有界数据库连接、秘密引用版本、Notebook V2、插件 DAG、存储预算评审通过；拒绝未准备环境 |
| M1 来源与版本 | P0；M0；来源/存储实现者 | CSV、JSONL、Parquet 三条全量封存路径；PostgreSQL 固定事务捕获；schema、拒收记录、脱敏副本和引用恢复 |
| M2 SQL 与质量 | P0；M1；执行/质量实现者 | 隔离 SQL、规则修订、全量质量和采样标识；超限、取消、未知清理不误报成功 |
| M3 Notebook 与实验 | P0；M1、M2；Notebook/实验实现者 | 显式会话所有权、干净内核、32 组合边界、失败项独立重跑、真实结果比较 |
| M4 血缘与交接 | P0；M1～M3；资料交接实现者 | 可追溯图、离线校验器、隔离接收、缺失材料标识、无原 VM 的导出与再核验 |
| M5 界面与版本验收 | P0；M0～M4；界面/集成验收者 | 单包全流程、最小依赖启停、API/CLI 一致性、390 px 布局；冻结服务契约后才可标记实现完成 |

必要验收用例必须保留可复核结果：

- 三种格式具有一致内容时按约定类型得到相同汇总；CSV 引号、JSONL 大整数、Parquet 定点数、时区和空值不发生静默损失；坏行计入拒收和质量分母。
- 文件捕获中修改、分区替换、链接越界和超额预算均拒绝；脱敏副本不改变原摘要，默认预览、日志和导出不泄漏未选原始列。
- PostgreSQL 写权限、未批准地址、证书错误、凭据轮换、查询超时和连接中断都有明确失败；RLS、生成列和其他超范围表拒绝；捕获时并发修改不会混合事务快照，服务不提交写语句。
- SQL 尝试读取额外文件、安装扩展、外连和突破预算时受阻；Notebook 取消后包括 fork/脱离终端的内核后代全部核销，回执丢失保持未知。
- 抽样通过但全量有坏行时不得显示全量通过；缺失指标、代码变化、单位变化、无唯一键和非确定性条件分别得到正确比较结论。
- 重启、停用、项目切换、来源 VM 删除和原会话替换不误接管资源；旧结果仍能离线读取。GC 不能移除活动运行、下载或祖先仍引用的内容。
- 无其他新包与完整 `delivery` 的环境中完成捕获、质量、Notebook、参数实验、导出；另一离线目录核验成功，篡改、缺分区、越界路径和超限资料包失败；错投 delivery 容器拒绝，缺失原始祖先仅核验声明起点后的范围。
- HTTP、CLI 和界面执行相同权限与状态规则；成员越权、确认后撤权和并发修订冲突均失败。测试材料按仓库约定留在忽略目录，Git 只保留简短验证结论。

当前验证仅限基线源码核对、设计依赖审查和外部官方资料核实。以上功能实现、资源预算实测、数据库联测与 UI 验收均为待开始。
