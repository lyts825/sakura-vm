# NAT 回流验证

在实例“服务与端口”中先建立 TCP 端口转发，再到“能力中心 → 第三批能力 → NAT 回流验证”选择 `nat-hairpin`。`status` 列出当前实例的转发端口；`verify` 可指定 `hostPort`，只有一条转发时可省略。验证会从运行中的客户机连接 `10.0.2.2:<hostPort>`，这是 Sakura 当前 QEMU 用户网络的宿主网关地址。连接成功表明客户机可经宿主入口回到该转发服务。客户机需要 Python 3。

此能力使用已有 QEMU TCP 转发，不创建新的开放监听，也不修改宿主防火墙。它仅覆盖本机 QEMU 用户网络中的 TCP 回流，不代表从局域网、公网地址或其他虚拟机回流；UDP 尚不支持。真实 Alpine/QEMU 测试除 TCP 连通外，还读取了经回流路径返回的 SSH banner，并验证转发可在线撤销及重加。
