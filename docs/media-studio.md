# 媒体资源制作插件包

`media-studio` 是 2.8.0 的实验性插件包，包含 9 个插件。它处理明确选择的本地文件，记录来源、固定配方、实际工具结果、派生文件和人工审核。

| 插件 | 负责内容 |
| --- | --- |
| `media-sources` | 分块上传、来源许可、派生关系和共享容量 |
| `media-inspect` | 在独立副本探测并完整解码输入 |
| `media-recipes` | 校验尺寸、时间、格式和固定操作 |
| `media-workers` | 转换、输出复核、发布、取消及原副本核销 |
| `media-captions` | 手工 SRT、实际输出时长及重叠检查 |
| `media-collections` | 固定资源集合、文件名映射及版本比较 |
| `media-reviews` | 人工接受、拒绝、撤回和修订检查 |
| `media-exchange` | 导出完整引用图、离线核验和隔离导入 |
| `media-workbench` | 五步制作页面和三个固定配方示例 |

## 准备与输入

先准备包含 FFmpeg 8.0.1、ffprobe 8.0.1 和 Python 3.12 的镜像，再把镜像登记为本体资产。页面要求填写固定资产 ID 和 SHA-256。工具准备阶段可以明确联网；探测和转换副本使用隔离网络，执行过程中不下载编解码器。

本版在 Alpine 3.23 的 `ffmpeg=8.0.1-r1` 和 `python3=3.12.15-r0` 上验证。准备镜像应使用新建的专用实例。封存前清除 `/var/lib/cloud`，并重新启用四个 `tiny-cloud-*` 服务，使新副本读取自己的启动身份。不要直接改变用户原镜像或已有实例。

上传支持 PNG、JPEG、WebP、PCM WAV 和 H.264/AAC MP4。固定来源时填写许可说明，并明确确认已检查文件。本说明记录人工声明，不认证版权。原材料和派生文件默认禁止导出。

文件扩展名只用于选择待核验格式。专用副本还检查文件头、实际编码、尺寸、时长、帧率和音频参数，并完整解码。未知编码、辅助轨道、损坏输入和超预算媒体会失败。文件路径、工具路径、过滤表达式、脚本和外部 URL 都不能作为配方输入。

## 三种制作流程

### 多尺寸图片

上传并固定图片后，预览媒体探测并批准。读取探测结果，选择通过的项目，再选择“多尺寸图片”。配方可以包含一至三个尺寸：

```json
{
  "kind": "image",
  "sizes": [{ "width": 320, "height": 240 }, { "width": 640, "height": 480 }],
  "fit": "contain",
  "stripMetadata": true
}
```

`contain` 保持比例并补透明边，`cover` 保持比例后居中裁切。输出统一为 PNG。工具应用 JPEG EXIF 方向和受支持的旋转信息，再归一化输出方向。RGBA 输出保留透明度。

首版把无 ICC 的静态图片按 sRGB 处理，明确拒绝嵌入 ICC 档案。它不提供任意色彩管理或印刷色彩转换。视频只接受工具支持的有限颜色空间；输出事实记录颜色声明，不能据此承诺所有显示设备的视觉一致性。

### 演示视频片段

上传 MP4，完成探测后选择“演示视频片段”。设置起点、持续时间和偶数输出尺寸。首版输出 H.264/AAC MP4，固定为 12 帧/秒，可同时生成一张 PNG 缩略图。

```json
{
  "kind": "video",
  "width": 640,
  "height": 360,
  "startMs": 500,
  "durationMs": 2000,
  "fps": 12,
  "thumbnail": true,
  "stripMetadata": true
}
```

起点与持续时间不能超出实际输入。时间以毫秒声明，视频输出以 12 帧/秒离散化。工具重新探测输出，持续时间偏差超过 90 毫秒时失败；该误差边界同时包含帧舍入和封装时间。

### 音频与手工字幕

上传 WAV 或带音轨的 MP4，选择“音频与手工字幕”。固定配方剪取明确时间段，使用 FFmpeg `loudnorm` 单遍处理，再输出 16 kHz、单声道 PCM WAV。响度目标为 −16 LUFS，真峰值目标为 −1.5 dBTP，动态范围目标为 11 LU。处理目标不等于保证所有输入都恰好达到该响度。

音频重新解码后，持续时间偏差不能超过 2 毫秒。发布输出后，在字幕页面选择实际文件并填写 SRT：

```text
1
00:00:00,000 --> 00:00:01,000
第一句手工字幕
```

字幕要求连续编号、明确毫秒时间和纯文本。重叠、结束早于起点、超出实际输出时长及标签文本都会失败。字幕作为单独的 SRT 文件交付；首版不识别语音，也不烧录字幕。

## 发布、审核与交接

探测和转换各支持最多三项的页面批次。编译配方后，预览转换任务并批准。每次任务使用新建的专用副本，工具以 UID/GID 65534 运行。输出必须重新解码，并检查尺寸、方向、实际帧数、持续时间、字节数和摘要。静态图片要求实际解码为单帧。工具退出码为零仍不足以发布。

读取任务后，点击“发布已验证输出”。发布要求完整工具回执和原副本清理确认。批次存在失败项时，已验证项目仍可单独发布；失败项没有可交付文件。重复点击不会重新启动转换，也不会重复创建同一派生文件。

在字幕与集合页面打开实际图片、音频或视频，填写安全文件名并加入集合。文件名不能包含路径，不能重复，扩展名须匹配已验证格式。集合只接受已发布输出和经过时间检查的字幕文件。

审核页要求人工填写观察，并确认已经打开实际输出。接受集合后，逐项批准原始材料和派生材料的导出许可。导出从已接受审核开始，携带完整引用图和获准字节。撤回审核、后续审核修订及来源撤权会使旧下载失效。

交接移除执行计划、会话 ID、虚拟机及进程凭据。接收端生成新对象身份，材料默认保留在隔离空间。外来核验和审核只作来源声明，不授予本机执行权限。

离线核验检查封套、字节摘要、引用闭合、配方与探测关联、输出映射、PNG 尺寸、字幕时间及审核条件。它不启动 FFmpeg，也不认证发送方实际执行过工具。需要重新处理时，应明确检查接收材料并创建新的本地流程。

## 取消、撤权与清理

取消只停止原任务。核销只追踪原副本、进程身份和清理回执，不重新提交转换。结果缺失或清理未知时，页面保留原状态，禁止发布。原工具输出在归档清理前保留，可继续读取和核销。

关闭未批准的探测或转换预览，会释放输入预留额度。来源许可、工作区许可和原消费者代次在运行中持续复核。失去许可后，执行底座撤销短租约并停止原进程组。

删除前先归档记录。存在保护引用时拒绝清理。最后一个任务修订清理时，才释放原任务的持久输入和输出；未确认清理的副本保留容量占用。

## 实际容量

| 对象 | 首版上限 |
| --- | --- |
| 单份材料、单批输入总量 | 4 MiB |
| 单任务输入数量 | 3 项 |
| 单任务派生文件总量 | 4 MiB |
| 静态图片 | 4,000,000 像素，单边不超过 4,096 像素 |
| 图片输出 | 每项最多 3 个尺寸，单边不超过 1,024 像素 |
| 视频输入 | 1,280 × 720、30 帧/秒、30 秒 |
| 视频片段输出 | 640 × 360、12 帧/秒、15 秒 |
| 音频输入 | 60 秒、双声道、48 kHz |
| 音频输出 | 30 秒、单声道、16 kHz |
| 字幕 | 200 条、单条 1,000 字符 |
| 集合 | 24 项 |
| 专用副本 | 2 vCPU、2 GiB 内存、最长 600 秒 |

字节通过有界分块传输，控制协议和结果各受 8 MiB 上限约束。材料、镜像、虚拟磁盘和执行输出同时计入包及本体共享容量。首版收紧了设计稿的容量设想；本体默认容量不足时拒绝启动，由用户在容量设置中明确调整。

## HTTP 与 CLI

HTTP 为认证后的 `POST /api/media-<领域>/<动作>`，动作采用短横线，例如 `validate-timing`、`export-text`、`confirm-reconcile`。请求和响应由 `shared/contracts/media-http.ts` 严格校验。内部派生材料发布端口不对 HTTP 开放。

```text
sakura media help
sakura media sources pin 参数.json
sakura media inspect preview 参数.json
sakura media inspect inspect 批准.json
sakura media inspect poll 参数.json
sakura media recipes compile 参数.json
sakura media workers preview 参数.json
sakura media workers start 批准.json
sakura media workers poll 参数.json
sakura media workers publish 参数.json
sakura media captions import-text 参数.json
sakura media collections assemble 参数.json
sakura media reviews decide 参数.json
sakura media verify 交接.sakura
```

批准对象包含 `workspaceId`、`planId` 和 `digest`。固定引用包含 `domain`、`id` 和 `revision`。CLI 对失败、不确定以及未确认清理分别返回退出码 1、3 和 4。

## 验证结论

真实 FFmpeg 验证覆盖三种模板、透明 PNG 的实际颜色与 Alpha、JPEG EXIF 方向、片段时间、缩略图、音频输出、批次部分失败、损坏文件及像素、帧数和颜色档案限制。3,840,044 字节音频输入及 960,078 字节输出通过真实分块传输验证。

真实服务代理验收贯通九个插件、隔离工具、派生发布、字幕集合和审核交接，并验证运行取消、来源撤权及原副本清理。撤销原始材料许可后，原已接受审核的导出下载仍会拒绝。领域验收另外覆盖并发批准、重复发布、字幕越界、集合命名、审核撤回和隔离导入。浏览器验收覆盖三个示例、显式批准、预览取消、撤权清屏及迟到响应隔离。

本地验证脚本、素材、输出与报告保存在被 Git 忽略的 `artifacts/plugin-packs-2.8.0/`。正式仓库只保留实现和简短结论。
