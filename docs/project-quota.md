# 项目磁盘配额

在实例的能力中心选择“项目磁盘配额”。`status` 查看当前项目目录的上限、用量和挂载状态；`apply` 输入 `limitMiB` 创建配额；`grow` 提高上限；`clear` 将文件迁回普通目录并清除限制。最小上限为 64 MiB。上限包括 ext4 元数据，因此文件可用空间会略小于设置值。

配额作用于当前项目的 `directory`，要求目录位于 `/workspace`，路径部分仅使用字母、数字、点、下划线或连字符。其他项目不能使用相同或相互包含的目录。执行迁移和清除前，先停止项目服务。操作会先复制现有内容，再切换挂载；原始目录备份和清除后的镜像归档保留在客户机 `/var/lib/sakura/project-quotas`，需要按实际空间情况自行检查和整理。

配额使用固定容量 ext4 镜像，并写入客户机 `/etc/fstab`，重启后自动挂载。挂载点底层设为不可修改；挂载失败时，Sakura 会拒绝启动该项目，目录写入也会失败。`status` 若显示记录与挂载状态不一致，应先检查客户机磁盘和挂载情况。配额依赖客户机提供 `mkfs.ext4`、`chattr`、`losetup`，扩容还需要 `resize2fs`。

`clear` 会复制当前内容到普通目录，因此客户机磁盘需要有足够的临时可用空间。配额不限制原始备份、镜像归档或项目目录之外的其他写入，也不会缩减客户机虚拟磁盘容量。真实 Alpine 和 Debian/QEMU 测试验证了迁移、写满拒绝、扩容、重启挂载、清除和挂载缺失时的拒绝写入。
