# 新插件包的宿主持久容量

本文适用于 2.8.0 的第三批十个插件包。各包根账本、五种固定 VM 会话及共享镜像账本均已接入；此额度尚未覆盖所有历史插件的数据目录。

## 总额与预留

默认共同总额为 8 GiB，其中 256 MiB 留作撤权、取消、确认和恢复。各包自身的额度继续生效，不能因为宿主还有容量而超过单包上限。

总量来自各包已经落盘的根账本，包含已提交容量、未核销预留和控制预算。停用插件、关闭页面或更换插件代次不会释放这些占用。未知上传、隔离接收和未确认的清理继续计费；普通新增写入不能使用宿主恢复预留。

当前每包的 32 MiB 控制预算也覆盖两个材料存储者的上传及读取租约账本；每个此类账本限 8 MiB。普通根账本限 31 MiB，另留 1 MiB 供控制更新，根账本整体限 32 MiB。领域元数据的原有上限继续生效。

工作台同时显示本包容量及新插件包的共同容量。CLI 使用 `supply sources host-capacity`、`locale catalogs host-capacity` 或 `incident cases host-capacity` 查询，输入文件包含 `workspaceId`。事件包的根账本与证据字节分属两个原服务，字节服务不能冒充根账本。汇总不返回其他空间的标识或正文。

五种固定执行另按完整虚拟磁盘容量预留，不能用稀疏文件当前大小替代。镜像物理字节按摘要共享计费；删除实际镜像后才从原镜像库存核对释放。输入、输出、复制暂存和未知资源继续占用额度，具体规则见[固定工具执行](suite-execution.md)。

## 提交与中断

根账本替换共享宿主串行准入。提交前重新读取所有已登记包的原账本，核对当前数据、容量预留和元数据替换峰值，再由原提供者执行带预期修订的替换。不同包并发申请不能分别使用同一份剩余额度。

根账本的原子写入暂存按实际字节保留计费，读取容量不会删除暂存。账本损坏、身份无法确认，或根账本缺失而材料仍在时，拒绝无法核对的新增写入；不会根据空缓存或缺失文件把原占用归零。需要由原领域恢复账本后重试。

恢复预留允许控制元数据更新，不允许借此增加材料或 VM 磁盘预留。控制更新仍须满足实际磁盘空间和替换峰值要求；恢复预算不足时保留原回执。

## 调整总额

管理员可在启动服务前设置 `SAKURA_SUITE_CAPACITY_BYTES`，范围为 512 MiB 到 1 TiB，使用整数字节数。示例保持默认 8 GiB：

```powershell
$env:SAKURA_SUITE_CAPACITY_BYTES = '8589934592'
npm start
```

修改后重启服务生效。降低总额不会清理既有材料；低于当前占用时，操作仍须满足峰值要求，可能需要先恢复原总额才能完成核销。非法配置会明确拒绝相关插件的容量装配，不改写原账本。

此准入队列约束一个控制器内各包的持久申请。当前不支持多个独立控制器并发管理同一数据目录；启动前应停止使用该目录的其他控制器。
