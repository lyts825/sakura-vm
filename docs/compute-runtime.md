# 有界计算运行时

`ComputeRuntime` 将计算额度纳入同一 `HostRuntime`，使用 Node.js 工作线程；不拆成独立业务服务。全宿主最多 4 个工作线程、512 MiB 声明内存预算（其中 32 MiB 保留给控制通道）。每个任务按需启动线程，处理一次后退出，没有常驻空闲池。工作线程资源限制与输入/解压边界同时保留，内存额度用于并发准入，不宣称能限制整个 Node 进程的 RSS。

实际接入包括：

- 文件预览：大于 256 KiB 的完整预览和所有 gzip/TAR 压缩预览在工作线程解析。最多同时两个预览，每项声明 192 MiB，包含有界输入、64 MiB 解压及解压拼接峰值。先取得预算再读入文件；跨线程传递独立字节数组，读取长度变化会拒绝。小预览和超大文件的 4 KiB 十六进制摘要保持直接处理。
- 社区 WASM 插件：签名和信任复核后在现有无宿主导入的 WASM 边界执行，每项 48 MiB、1 秒期限；全局额度与文件预览共享，每插件最多两项。输入先序列化为固定快照，卸载和关闭同时取消等待与活动任务。
- 工程执行器：固定源码的压缩结果按原文精确匹配缓存一份，不缓存含私密信息的任务请求。客户机 UID、正文大小和哈希验证不变。

任务结果、取消或超时都先终止线程，收到实际 `exit` 后才释放计算额度。终止失败保留原线程及 `cleanup-pending` 记录，关闭重试同一个线程。取消排队任务不读取输入。工作线程不持有 VM、SFTP 或存储发布能力；结果回到父进程后，仍由原领域检查身份并发布。

## 测量

运行 `node --import tsx scripts/measure-compute.ts` 可复现对比。Windows/Node 24 本次合法 64 MiB TAR（131072 个空成员，gzip 输入约 273 KiB）测得同步预览约 1188 ms，事件循环心跳同样延迟 1188 ms；线程预览整体约 1320 ms，主线程心跳约 3 ms。连续 16 次工程正文封装由缓存前约 107 ms 降至约 12 ms。数据是本机样本，不是硬实时保证；工作线程改善主线程响应，不保证单项任务更快。

发布构建单独打包 `compute-task.js`，复制固定 bootstrap，并记录源码与发布文件 SHA-256。`dist:check` 校验资产且实际运行无 TypeScript loader 的发布线程。生命周期、取消、超时、终止失败保留及原格式预览有独立测试。
