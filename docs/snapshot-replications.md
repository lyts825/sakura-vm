# 跨主机快照复制

两台主机都启用“平台”和“快照与实例包”插件，按[主机配对说明](host-peers.md)核对 TLS 指纹并完成单向配对。目标主机还需为来源主机单独开启“允许导入”。

在来源主机停止实例，打开“快照”页，找到要复制的历史快照 ID。到同一实例的能力中心选择“跨主机快照复制”，填写已配对主机的目标 ID、快照 ID 和新实例名称后提交。目标会创建一个独立的、可启动的实例；来源实例与快照保持不变。快照 ID 和目标 ID 分别显示在快照页及“系统设置 → 主机配对与多主机状态”。

导出器通过 QEMU 的 `convert -l` 选择指定历史快照磁盘，读取该快照保存的实例身份、磁盘大小及文件系统扩容状态。新建的停机 TPM 快照也携带对应的安全启动 NVRAM 与 TPM 状态；旧快照缺少该状态时拒绝用当前身份代替。传输包携带当前实例配置和项目配置；目标清空端口转发，原有快照历史不随包复制。目标按普通实例包导入流程检查磁盘格式、完整性和 SHA-256，再把来源实例、快照和磁盘摘要写入实例记录。来源端校对目标回执的来源标识与摘要。配对证书固定，包内含控制身份私钥，应只授权可信目标主机。

复制队列存于来源数据目录，显示等待、传输中、已复制或需复核状态，以及目标实例 ID 和 SHA-256。重启时未完成的传输会变成“需复核”；以相同参数重试会先查询目标回执，避免再次创建实例。目标回执与来源、快照或已记录校验值不一致时拒绝完成，需检查目标并用新的目标名称重新复制。若源快照、身份或相关实例配置变化，也需使用新名称。可通过受本机控制凭证保护的 `GET /api/snapshot-replications` 查看队列；请求结构在 OpenAPI/SDK 中。

传输上限为 32 GiB，最长 30 分钟；目标需有足够 CPU 与空闲内存，并与来源平台、架构相同。目标还需具备实际启动所需的 QEMU、固件和其他运行条件。完成后请在目标主机验证新实例能启动并读取预期历史数据。
