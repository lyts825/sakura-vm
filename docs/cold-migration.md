# 跨主机冷迁移

两台主机均启用“平台”和“快照与实例包”插件，完成证书指纹核对与短码配对。目标主机在“系统设置 → 主机配对与多主机状态”的入站主机列表中，为来源主机单独开启“允许导入”。如需在移除源实例后自动请求目标启动，还需开启独立的“允许目标启动”。默认只有只读资源状态权限。

在来源主机停止实例，打开该实例的“能力中心 → 跨主机冷迁移”。从系统设置复制目标主机的“迁移目标 ID”，填写目标实例名称，首次保持 `confirmSourceRemoval: false` 并提交。任务将经过证书固定的 TLS 通道流式发送校验后的实例包，目标使用原有包导入校验流程发布新实例，返回目标实例 ID。确认目标副本已导入后，以相同目标 ID 和名称重试并设置 `confirmSourceRemoval: true`，才会移除源实例。可选设置 `startTarget: true`：此选项要求此前已完成一次保留源实例的复制；先重新核对目标导入回执中的磁盘校验值与启动权限，再删除未变化的源实例，最后向目标发起启动请求。`startTarget` 不能单独使用，且默认关闭。

迁移队列和传输标识持久保存。网络中断或回执丢失时，重试会按来源主机与传输标识查询目标已导入的实例，避免重复导入。删除源实例前，Sakura 再次核对磁盘大小、修改时间、实例记录和目标回执；若源实例变化或目标不可达，会保留源实例。目标名称冲突、资源不足、平台或架构不同也会阻止初次传输。若源实例已移除而目标启动请求失败，队列会保留“已移除源实例”与启动错误；此时应到目标主机复核并启动，不要把失败当作来源仍存在。

迁移传输上限为 32 GiB，连接最长 30 分钟。当前迁移的是停止时的活动磁盘、实例配置与项目配置；历史快照和原主机端口映射不会随包迁移。远端启动回执只表示目标接受请求，客户机健康及服务入口仍需单独检查。目标主机仍需具备启动该实例所需的 QEMU、固件与其他运行条件；若不能接受启动后才发现目标不可用的风险，先在目标主机验证，再移除源实例。
