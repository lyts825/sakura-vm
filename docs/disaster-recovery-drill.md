# 灾备演练

在已启用备份、快照实例包和平台插件的实例“能力中心”选择“灾备演练”。先以 `status` 列出该实例已有备份，再选择一份提交 `run`。演练对备份文件及独立磁盘做完整性校验，恢复为随机命名的临时实例，实际启动客户机，并检查 `/workspace` 路径存在。可指定 `probePath` 检查其他路径；同时提供 `expectedSha256` 时，将在恢复的客户机内计算该文件的 SHA-256 并比对。例：`{"mode":"run","backupId":"<备份 UUID>","probePath":"/workspace/proof.txt","expectedSha256":"<64 位 SHA-256>"}`。

结果记录备份标识、临时实例、恢复耗时、启动耗时、总耗时与探测结果。无论成功、探测失败、取消或超时，服务都会尝试强制停止并删除临时实例；如果清理失败，报告会保留临时实例名称和标识，供用户检查和删除。任务的日志与结果由 Sakura 的持久任务记录保存。单次演练最多六分钟，不会覆盖原实例或备份。

加密备份需要先在备份策略中保存可用的密码密钥；演练接口不接收临时明文密码。客户机启动和路径检查证明该备份在当前主机上可恢复到指定检查点，并不等于已验证业务服务、外部依赖或跨主机故障切换。临时恢复会占用额外磁盘、内存和一个可运行实例名额。

验证：`npx tsx --test tests/disaster-recovery-drill.test.ts` 覆盖成功、文件哈希不符、参数拒绝与清理；`npm run test:disaster-recovery` 从真实 Alpine/QEMU 客户机生成备份，再临时恢复、启动、核对客户机文件哈希并清理。
