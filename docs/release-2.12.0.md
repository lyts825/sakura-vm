# 2.12.0 · 第七批二十个完整插件包

本次从检出的 2.8.1 升级到 2.12.0，新增 20 包、285 个内部插件及独立领域服务。完整目录为 486 插件、46 包；默认选择为空，宿主 API 保持 5。各包成员、功能、页面、HTTP、CLI 和容量见[使用指南](seventh-plugin-packs.md)，工具镜像见[准备指南](seventh-tool-images.md)。

## 变更

数据质量、血缘、实体归并、时间、地理、图分析和实验提供固定算法与可复查证据。特征、训练、求解、提取、设计系统、表单和通知形成完整创作流程。调度、扩展、依赖、协议、副本和多服务分别提供模型判断、真实固定工具或客户机执行。

285 个插件分别拥有材料、定义、计算、审阅、版本和交换数据，通过显式依赖调用原提供者。新包互无必需依赖；22 个本体固定计算或执行接口逐项登记。旧五类执行服务继续使用冻结 DTO，新增四类使用独立接口。

工作台包含结构编辑、显式字段投影、固定计划、材料续传、结果分页、取消和恢复。地理与图结果提供离线 SVG，设计产物采用无脚本和网络权限的静态 iframe；表单试填通过原领域端口保存回答、计算值及导航判断。身份、空间或代次变化会撤销旧请求和私有缓存。完整扩展目录的侧栏现在可以滚动访问。

原生工具随 Windows x64 运行包交付，固定 Python、11 个包、Tesseract 和语言资源；辅助程序使用 AppContainer、原子 Job 归属及持久原进程身份。原任务结果先保存并关联固定证据，再确认删除暂存和核销预留。恢复只处理原资源，重复批准返回原结果。

四类工程 VM 从显式镜像创建断网副本，记录真实工具、准确 VM、输出摘要及清理。业务完成和资源核销分别记录。每个档案最多一个活动或未核销会话，额度不足会拒绝执行；验证环境显式配置 32 GiB 总套件预留，产品默认仍为 8 GiB。

交接支持 64 MiB、多材料拥有者和完整引用子图。离线 CLI 直接运行编译 JavaScript，不依赖源码、TypeScript 或宿主。导入生成新空间，外来结果与意见保持参考身份，批准、活动会话及凭据不迁移。

接口文档继续保存完整模式；宿主改用约 1.4 MB 的去重运行索引，避免直接解析约 80 MB 文档的类型字面量。完整目录在实际编译态激活时未报告插件错误。

## 验证与交付状态

整版运行验收通过。完整构建、2,559 模块架构检查、605 个显式服务描述、9,316 条完整 HTTP、6 条 WebSocket 及语言包同步均通过。完整目录实际激活 486 个插件且错误为空，关闭后原监听器归零；生产 CSP、独立网络入口和既有生产烟雾检查通过。

60/60 HTTP 模板、20/20 CLI 代表及 20 包完整交接通过；交接包含 420 个实际 HTTP 请求，另验证约 62 MiB 多拥有者材料和纯 Node 离线核验。四类客户机的 8 次真实运行分别核对原会话、实际工具与输出和资源清理。领域验证覆盖真实训练与预测、MILP 独立约束验证、PDF/OCR、地理布尔运算、时间与精确十进制，以及领域反例。原生取消、独立截止、慢探针与持久结果交接窗口另作定向验证。

正式候选在仓库外的系统临时目录完成生产安装验收。无依赖时 20 个纯 Node CLI 帮助可用；安装 17 个生产依赖后审计为 0，应用无法解析 TypeScript、tsx、Vite 或 Playwright。18 包代表实际执行、2 包固定 VM 计划、真实训练模型及指标、MILP、CLI 镜像导入和真实调度 VM 均通过；20 个工作台正常点击、各 3 个模板、请求前缀归属、默认关闭状态和无页面错误通过。三个测试宿主均实际关闭，端口和所记录进程全部退出，安装前后 5,583 个发行文件的内容指纹一致。

安装验收复用四个预备 PosixLoom 文件及已有 QEMU，作为明确的系统前置；本轮未重做它们的联网下载和 Rust 编译。工具客户机镜像从外部 qcow2 经正式 CLI 显式导入，不随运行包交付。浏览器驱动首次按错误的模块形状读取导致验收中断，原失败报告完整保留；修复测试驱动后，在同一安装目录只续跑剩余导航、默认状态和完整性步骤，没有重跑已通过的算法或修改生产代码。

最终版本说明在验收后补齐；封装时逐文件核对最终包与已验收候选，要求仅本说明变化，运行代码及资产字节一致。源码仓库的 `PROJECT_STATUS.md` 记录候选、最终包指纹及必要的验证证据，原始测试材料保留在被忽略的本地目录。

已发现并修复编译 worker 相邻路径、页面重复 `/api` 前缀、VM 完成与清理之间的窗口、原型字段静默丢弃、原生准备失败时覆盖原错误，以及业务 `close` 与宿主销毁冲突。宿主使用独立销毁符号，业务方法仍经过严格模式。根账本的双重载用单个可调用属性表达以通过严格契约冻结，输入与返回保持相同；前后转译的运行字节一致。原失败记录保留，复验按受影响范围执行。

已有 CI 夹具补齐第二个快照服务和本轮 22 个必需提供者，全部原断言保留。插件管理三项、相关契约与运行域十八项、目录与表面查询回归，以及完整包启停定向检查通过；没有通过删除断言缩短验收。运行包没有增加开发依赖。
