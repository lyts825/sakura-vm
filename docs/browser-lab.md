# 浏览器验收工作台

## 用途与插件

`browser-lab` 面向固定样站的本地验收。十个插件分别管理目标、合成数据、旅程、运行、断言、视觉基线、可访问性、报告、交接和工作台。包保持实验性，默认不启用。

运行器使用本体 `BrowserSessionsV1`。每次执行创建独立 VM，运行固定 Python 工具和真实 Chromium。网页脚本只能访问本次只读站点，不能取得宿主命令、用户浏览器或真实登录会话。

## 首次运行

1. 启用 `browser-lab`，按插件页提示重启服务。
2. 通过现有镜像资产流程准备 Alpine x86_64 镜像，安装 `python3`、`chromium` 和字体。运行步骤不会自动下载依赖。
3. 核对总容量。每个 VM 至少预留 8 GiB 虚拟磁盘，另计镜像、输入、输出及恢复预留。默认 8 GiB 总额不足以启动此类任务，需要按[容量说明](suite-capacity.md)明确配置。
4. 在工作台选择镜像，创建“表单提交”“响应式导航”或“视觉基线”样例。模板只生成输入，创建空间不会运行浏览器。
5. 核对合成数据、步骤、断言、视口和时区，预览并批准运行。页面查询只更新原回执，不重放步骤。
6. 等待原资源清理确认为 `confirmed`，生成三类评估，完成人工检查并封存报告。

CLI 入口为 `npm run browser -- help`。领域方法通过 `browser <领域> <动作> <输入文件.json>` 调用；具体拼写以帮助输出为准。全部 HTTP 方法位于 `/api/browser-<领域>/<动作>`，使用 `POST` 和固定输入模式。

## 站点和旅程

站点材料采用 `sakura-browser-site/1`：`entry` 指向普通相对路径，`files` 保存路径、`utf8` 或 `base64` 编码及内容。拒绝父目录、重复路径、大小写冲突和未支持类型。页面上传上限为 2 MiB；分块材料接口允许更大的站点输入。

旅程支持导航、点击、输入、选择、等待元素和截图。可选条件只判断指定元素是否存在。输入值可以引用合成字段，例如 `{{name}}`；课程式任意脚本和宿主命令没有执行入口。

实际首版上限为 100 个站点文件、8 MiB 解码内容、50 个步骤、100 条断言、10 张截图、单图 4 MiB、输出总帧 8 MiB。视口最大 1920 × 1080，单步等待最多 10 秒，运行最多 15 分钟，VM 为 2 vCPU / 2 GiB。完整交接包最多 16 MiB。这些是实施上限，设计文档中的更大数值不代表本版能力。

## 证据和判定

步骤记录来自实际浏览器，包括耗时、DOM 摘要、页面地址、断言和截图。失败时尽力捕获当前页面；捕获失败会明确保留原因。浏览器未完成、证据缺失或清理未知时，不把未观察的检查计为通过。

视觉检查使用运行前固定的容差和遮罩。首次运行没有基线时，视觉结论为不确定。候选截图经人工接受后成为新的基线修订；接受时核对原活动基线，防止并发覆盖。旧基线历史和旧报告保持原结论。

只有镜像、工具、浏览器、字体、视口、时区和旅程均匹配，才能直接比较基线。像素比较另有解码尺寸、内存和时间限制。动画、动态时间等仍可能造成变化。

可访问性自动检查覆盖文档标题、图片名称、控件名称和标题层级四种规则。人工检查单单独保存，不能修改自动发现。报告按运行前选定的检查形成总体结论，未选内容明确列为未覆盖，不作完整无障碍认证。

## 取消、恢复与交接

运行前先持久化意图，再启动原会话。重复批准返回原运行，不创建第二台 VM。取消、到期、撤权和插件停用会停止续租；客户机守护进程与宿主看门狗负责原进程的停止。重启后保留中断状态和预算，需显式核销原资源，不恢复执行。

交接只接受已封存报告及完整引用图，原运行必须已清理，站点和截图必须有当前导出许可。每次下载重新检查许可。接收在隔离空间内生成新对象；来源声明没有本机执行权限，也不能成为直接可用的本机运行证据。

`browser verify <交接包>` 在完整安装包中离线核验封套、字节摘要、对象关联和可重算断言。它不证明发送者实际运行过浏览器，也不重新执行浏览器或重新计算像素。导入的通过记录仅供参考。

物理清理前保留仍被报告、基线或运行引用的材料。预览取消会释放未执行输入；清理最后一个运行修订后，才释放相应本体输入、输出额度。活动基线及其历史暂不提供物理删除，避免旧修订重新成为活动基线。
