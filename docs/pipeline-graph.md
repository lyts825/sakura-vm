# 流水线依赖与局部重跑

## 配置步骤

项目流水线插件支持有向无环依赖图。每条流水线最多 20 个步骤，并发上限为 1～4，默认值为 1。在项目的流水线页面可以编辑步骤、查看依赖图，并设置输入和产物文件。

步骤的 `id` 必须以英文字母开头，只能包含英文字母、数字、连字符和下划线，最长 64 个字符。`dependsOn` 填写前置步骤的标识。前置步骤全部成功后，当前步骤才会执行。显式填写空数组，表示步骤可以独立执行。

旧配置无需迁移。步骤省略 `id` 时，系统按位置使用 `step-1`、`step-2` 等标识。省略 `dependsOn` 时，默认依赖前一个步骤，保持原来的执行顺序。重复标识、重复依赖、未知依赖和循环依赖都会在保存时拒绝。运行期间不能修改或删除流水线配置。

```json
{
  "name": "前后端检查",
  "maxConcurrency": 2,
  "inputs": ["package-lock.json"],
  "steps": [
    {
      "id": "frontend",
      "name": "前端测试",
      "command": "npm run test:frontend",
      "dependsOn": [],
      "rerunnable": true
    },
    {
      "id": "backend",
      "name": "后端测试",
      "command": "npm run test:backend",
      "dependsOn": [],
      "rerunnable": true
    },
    {
      "id": "build",
      "name": "构建",
      "command": "npm run build",
      "dependsOn": ["frontend", "backend"],
      "rerunnable": true
    }
  ],
  "artifacts": []
}
```

任一步骤失败时，系统阻断它的后继，继续执行不受影响的独立分支。运行记录保留每一步的状态、日志、退出码和阻断原因。未执行步骤保留 `pending` 状态，并附带原因。取消会停止新步骤调度，等所有已启动任务完成清理后，再释放原项目租约。清理未确认时，整次运行保留错误状态。

## 选择局部重跑

在历史运行中勾选步骤。页面会显示实际执行集合：所选步骤、它们的下游，以及这些步骤需要的全部祖先。确认集合后，点击“重跑所选分支及依赖”。没有选入集合的独立分支不会执行，也不会标为成功。

执行集合中的每一步都必须显式声明 `rerunnable: true`。这个声明表示你已确认命令可以重复执行，而且没有部署、数据库迁移等外部副作用。声明默认关闭；系统不会根据命令文本推测安全性。运行中断、取消、清理未确认或已启动却没有退出码的步骤，不能作为局部重跑依据。普通任务中心的“重试”入口会引导你返回流水线页面核对。

局部重跑要求原运行存在指纹。配置中包含可重跑步骤时，完整运行会通过原项目账户读取以下证据，保存 SHA-256 摘要：

- 干净 Git 工作区的 `HEAD`。已跟踪修改、未跟踪文件和子模块修改都会使指纹不可用。
- 流水线定义、已解析项目配置和项目配置版本。环境值参与摘要，但不会以明文写入运行记录。
- 客户机、项目标识、捕获的运行代次、客户机启动标识和账户 UID。
- `inputs` 声明文件的内容摘要。路径相对项目目录，必须指向可读取的文件。

开始重跑前，系统重新计算指纹。代码、配置、声明输入或身份变化时，系统拒绝重跑，要求重新完整运行。工作区不干净或输入文件不可读时，普通完整运行仍可继续，但此次运行不能提供重跑依据。指纹读取本身发生身份或清理错误时，运行失败。

局部重跑会真实执行所需祖先，不复用旧命令结果。首版不缓存产物，局部运行也不发布整条流水线的产物。需要完整交付物时，请完整运行流水线。

## 使用边界

指纹只核对 Git 代码、项目配置和显式声明的输入。它不冻结工作目录，也不追踪未声明的忽略文件、远端服务内容或可变软件源。执行期间修改代码仍可能影响命令。涉及这些输入的步骤，应补充输入文件或关闭可重跑声明。

步骤共用原项目目录和账户。并发步骤需要避免写入同一路径；系统不为每一步创建独立文件系统。运行与取消沿用项目账户任务执行器的身份检查、资源租约和清理回执。
