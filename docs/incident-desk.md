# 事件响应与复盘

目标版本为 2.8.0，当前仍在实施阶段。`incident-desk` 由十个实验插件组成：案例、证据、时间线、假设、步骤、处置、审阅、报告、交接和工作台。材料到交接的页面、HTTP 和 CLI 流程已通过验收，版本整体尚未发布，完整进度见[项目状态](../PROJECT_STATUS.md)。启用插件包并重启后，从“事件响应与复盘”进入。

## 从材料到报告

1. 选择“应用启动失败”“容量耗尽”或“演练中断”，核对案例名称、影响、严重程度和关联对象。模板仅提供建议，不生成证据或执行动作。
2. 上传文本或 JSON 日志，记录人工观察，或预览并批准原指标、健康服务的一次只读采集。上传相同内容仍是外来声明。
3. 对需要交接的证据生成脱敏副本，读取完整副本后记录人工审阅理由并批准导出许可。默认交接不会直接导出原始证据。
4. 选择固定证据整理时间线，通过事件窗口查看原时间和采集时间。人工时钟偏差只是显示注释；跨来源顺序保持不确定，不据此自动认定因果。
5. 提出假设，读取该假设后，从对应固定时间线关联支持或相反事件。切换假设或时间线会清空索引草稿，需要重新读取。固定步骤可以记录查询、人工操作或两种原提供者动作，每个在线动作单独预览和批准。
6. 解决案例时公开未决项。对选定时间线、完整证据窗口、假设和处置逐项审阅，填写事实、推断、措施、后续工作四栏，生成并封存报告。

审阅只覆盖明确选定的窗口。案例关闭、原函数返回和资源释放分别记录，不能互相替代。空事件窗口不能作为完成的复盘依据。报告草稿不能导出。

## 原提供者与未知结果

采集范围见[只读采集](incident-capture.md)。在线处置仅支持维护清理和演练原运行核销，规则见[固定动作委派](delegated-actions.md)。缺少可选提供者时，上传、人工观察、时间线、人工处置及复盘仍可使用。

原回执查询不会重发业务。未知结果可由原账户填写核对说明，回执状态和结果保持原样；核对不代表成功、停止或资源已释放。已压缩或提供者暂时缺席的回执只显示本地保存的历史，当前资源状态保持未知。权限、账户、票据身份或撤权错误会继续拒绝访问。

## 脱敏与交接

派生材料保留本地强引用、原摘要、规则摘要及人工审阅许可版本。原生采集凭据在生成副本时强制遮盖，副本不再携带可使用的采集绑定，按派生声明审阅。未知秘密仍需人工全文核对；工具不声称发现全部敏感信息。

默认导出只选择封存报告，包含其人审脱敏材料和便携历史声明。私有原始证据、原采集凭据、动作票据和执行输入留在本机。导出不改写已经审阅过的材料字节；发现凭据残留时拒绝导出，要求重新脱敏和审阅。

导出预览、生成和每次下载都会核对本地完整原图、来源许可及最新人工决定。审阅被后续决定替代后，旧报告不能继续生成或下载交接包。撤销来源后再恢复读取，也不会复活原下载批准。封存报告可随案例后续调查继续作为固定历史声明交接，不因此取得新的本地审阅批准。

接收时先隔离核验，再创建新空间和新 ID。外来报告、时间线、假设、审阅及动作均为未经身份认证的来源声明，不能充当本机采集、执行或批准证明；接收材料默认不允许再次导出。离线核验检查摘要、引用闭包、事件索引和报告/审阅的一致性，不认证作者或来源，也不重算原事件分析或原审阅摘要。

## CLI 与容量

使用 `npm run incident -- help` 查看十个领域的固定命令。所有在线输入文件均为 JSON 对象；账户模式使用既有 `SAKURA_TOKEN`。示例：

```powershell
npm run incident -- workbench templates
npm run incident -- cases open case.json
npm run incident -- upload <workspaceId> incident.log
npm run incident -- timeline events window.json
npm run incident -- exchange preview-export report-selection.json
npm run incident -- exchange export approval.json
npm run incident -- download export-reference.json incident.zip
npm run incident -- verify incident.zip
```

`upload` 分块传输后自动固定证据。`window.json` 含 `workspaceId`、固定 `timeline: {domain,id,revision}`、`cursor` 和 `limit`；单次最多 200 个事件。工作台使用紧凑时间线摘要，不一次返回全部事件。`verify` 使用固定编译工具和可终止工作线程，纯 Node 离线运行。

当前控制请求文本最多 1 MiB，分块材料最多 32 MiB，一次整理原文总额最多 32 MiB、100,000 条事件，每例最多 500 个证据对象。交接包沿用共享安全格式，整体最多 16 MiB，单项材料或对象最多 8 MiB、最多 1,000 个对象；超过限制须明确缩小所选范围，不静默截掉事件。以上为当前实现边界，设计中的 256 MiB 交接预算尚未实现。

本包总额为 4 GiB，另受[宿主持久容量](suite-capacity.md)约束。清理前预览原保护引用及实际对象；隔离、上传中断和未知占用继续计费，不自动删除。

当前本地已接受或拒绝的人工审阅及其来源强引用必须保留，不能归档或物理清理；执行时也会拒绝旧清理批准和恢复入口，避免删除后让更早批准重新生效。待决定审阅和接收的来源声明仍可按原清理规则核销。决定历史继续占用容量，这是当前保守实现的限制。
