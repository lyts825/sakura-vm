# 安全清理中心

## 使用方法

清理中心位于“磁盘与诊断”的“空间管理”区域，仅所有者可用。选择备份块或任务日志后，页面列出来源、归属、具体候选、保留理由和预计释放空间。检查清单并勾选确认后，再执行本次清理。

预览有效期为 5 分钟。同一提供者的新预览会替换旧预览。令牌只能使用一次，执行失败、取消或状态变化后都需重新预览。关闭插件会撤销预览并取消在途工作，随后等待已开始的清理退出。

## 清理范围

| 提供者 | 可以清理 | 保留内容 |
| --- | --- | --- |
| 未引用备份块 | 全部备份清单验证通过后的孤儿块 | 清单引用的块、保留锁对应备份、未知目录、临时块和清单本身 |
| 已完成任务日志 | 已成功结束且超过现有期限或容量的日志正文 | 活动任务、失败或中断证据、未释放的恢复资源、任务结果和审计记录 |

日志清理沿用当前策略的天数和容量，但不会开启自动清理。日志空间估计按 UTF-8 正文计算，实际文件系统释放空间可能不同。各提供者单独执行，失败前已经完成的删除不会自动恢复。

## 实现与接口

维护插件负责入口、提供者注册和确认流程。本体保留日志策略、存储权限和领域锁。清理中心不接收文件路径，也不扫描任意宿主目录。

`GET /api/cleanup` 返回提供者。`POST /api/cleanup/preview` 接收 `provider`；`POST /api/cleanup/execute` 接收 `provider` 和预览返回的 `token`。提供者标识为 `backup-blocks` 或 `job-logs`。全部接口使用已有会话与所有者权限。

备份块在原串行锁内核验清单、块大小和缺失引用。引用或块元数据与预览不一致时，执行返回冲突并停止删除。写入和下载也使用这把锁。

日志提供者在原保留队列内重新计算候选，复核策略与任务日志版本。底层日志清理函数再次检查任务状态、恢复资源和正文签名。清理只修改日志正文，任务元数据和结果保持可查询。
