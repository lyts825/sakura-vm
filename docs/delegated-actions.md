# 固定动作委派

目标版本为 2.8.0。当前为实施阶段：本体接口和两个原提供者适配已实现，事件处置领域已接线；事件包已登记为实验功能，材料到报告交接的页面、HTTP 和 CLI 流程已通过验收。原演练委派的实机验证边界见文末。

`DelegatedActionsV1` 只接受维护清理和演练运行核销。它通过服务代理找到实际执行消费者声明的可选依赖，继续使用原提供者的权限、代次、对象检查和资源锁。首批消费者限定为 `incident-actions` 与 `flow-connectors`。

| 适配器 | 具体输入 | 原执行入口 |
| --- | --- | --- |
| `maintenance-cleanup` | `backup-blocks` 或 `job-logs` | 维护插件持有的 `CleanupPlans`；原一次令牌和清理器保持生效 |
| `resilience-reconcile` | 原工作空间和运行 ID | 原 `ResilienceRuns`；不按 VM ID 停止或释放替代实例 |

## 计划和批准

提供者将完整输入、资源摘要、实际 owner、消费插件及双方代次保存到自己的账本，返回五分钟票据。清理计划显示全部候选，最多 1,000 项；超过范围或大小上限时拒绝委派，要求回原功能页面核对。原清理令牌留在提供者内部。

提交先消费票据，再调用消费者的意图记录回调。回调必须持久保存意图并返回摘要；服务代理会恢复实际消费者权限。原执行器在业务开始前再次检查截止、取消、权限及对象摘要。回调不能通过修改计划对象替换实际目标。重新预览清理会按原有规则使同一提供者的旧清理令牌失效。

| 状态 | 可以据此确认的事实 |
| --- | --- |
| `ready` | 计划已保存，尚未消费 |
| `consumed` | 一次票据已消费，不能再次提交 |
| `dispatching` | 已保存派发边界；实际结果仍待原提供者确认 |
| `returned` | 原执行函数已经返回，结果随回执保存；仍须查看结果中的核销状态 |
| `rejected` | 本次没有跨过派发边界 |
| `unknown` | 已跨过派发边界或恢复时无法确认结果，禁止自动重发 |
| `expired` | 提供者重启或计划到期，必须重新预览 |

运行核销返回原运行的 containment、cleanup 和 outcome，不将函数返回解释为演练通过或资源已释放。失败消息只保存固定错误代码，避免复制原日志或密钥。

## 中断和案例记录

提供者重启后，旧 `ready` 票据失效，原 `consumed/dispatching` 变为 `unknown`。结果提交前后发生持久化故障时，以账本实际落盘状态为准。查询允许同一 owner、同一消费插件的新代次核对旧票据，旧代次的写批准不能沿用。

事件动作先保存可查询的原票据，再在案例执行窗口内保存意图和提交。案例范围改变或来源撤权会拒绝新动作；结案等待当前窗口结束。请求已经失效时，原提供者只能继续保存本次回执，不能借此发出新业务。新会话可查询原回执；案例结果写入失败不会触发重放。

人工处置始终标记 `systemExecution: false`。动作返回不自动结案，结案也不证明原资源已经核销。

`acknowledge(ticket, reason)` 允许原账户、原消费插件在新代次核对已结束或未知的旧回执，保存核对人、时间和理由。相同理由重复调用返回原记录，不同理由拒绝覆盖；`ready/consumed/dispatching` 不能核对。核对保持原状态及结果，未知仍是未知，不释放资源、不重发业务。事件领域另以预期修订保存新的动作记录；已结案案例仍可补充此类核对。

原提供者缺席或原回执已压缩时，查询可以返回已披露的本地历史回执，当前资源状态保持未知。权限、账户、消费者及票据身份错误不能降级为可读历史。

## 容量和当前验收边界

每个原提供者的动作账本最多 8 MiB，并为待返回结果及未知核对元数据预留空间；每份计划和结果均有大小限制。按数量和实际字节保留最近至多 1,000 份可压缩终态，核对过的未知记录也可参与压缩；未核对的未知及活动记录不自动删除。没有足够可核销空间时拒绝新计划。旧账本若完全填满且只有未核对的未知记录，补充核对也可能明确容量拒绝，原文件保持不变；不会提高预算或自动丢弃这些记录。

本阶段验证覆盖真实服务代理、真实元数据、维护插件激活、实际日志正文清理、重复提交、旧代次、过期、撤权、案例结案顺序和回执写入故障。演练委派另通过真实 VM 验收：原运行在基线采集时中断控制器，重启后由事件处置调用原提供者核销，复核同一运行、原副本、镜像引用和监管账本释放，重复提交不重放。原演练结果保持 `inconclusive`；这证明中断后的核销路径，不代表完成了故障注入或全部演练场景。
