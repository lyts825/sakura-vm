# 离线软件包缓存

运行中的 Alpine、Debian 和 Ubuntu 实例可在“工作空间 → 软件包”预取软件包，之后从实例内缓存安装。预取需要联网；离线安装分别使用 `apk --no-network` 和 APT `--no-download`，不向包源下载。缓存保存在该实例的 `/var/cache/sakura/packages/<软件包名>`，不会在实例之间自动共享。

1. 选择“预取软件包及依赖”，输入不含版本约束的软件包名称，提交任务并等待完成。预取会更新软件包索引、下载软件包及当前环境需要的依赖，记录文件 SHA-256。
2. 选择“查看离线缓存”。任务日志逐行显示缓存名称、软件包文件数和字节数；列表不需要填写名称。
3. 选择“从缓存离线安装”并输入同名软件包。安装前会校验缓存中的每个文件，校验失败会拒绝安装。
4. 不再需要时，选择“移除指定软件包缓存”并输入名称。清理只影响这一项缓存。

项目依赖可在“工作空间 → 开发任务”选择“预取项目依赖到离线缓存”或“从缓存离线安装项目依赖”，并选择类型：

- npm：需要 `package.json` 和 `package-lock.json` 或 `npm-shrinkwrap.json`。预取在临时目录执行不运行安装脚本的 `npm ci`，不改动项目的 `node_modules`；离线安装校验两个清单文件并使用 npm 的 `--offline --ignore-scripts`。
- Python：需要只含固定版本普通 PyPI 包的 `requirements.txt`（例如 `idna==3.10`），不接受 URL、路径或索引覆盖。预取解析并下载所有二进制 wheel，记录 SHA-256；离线安装校验依赖文件和 wheel 后，用 `--no-index` 安装到项目的 `.sakura/venv`。需要客户机已安装 `python3`、`pip` 和 `venv`。

项目缓存按实例和项目隔离，保存在客户机的 `/var/cache/sakura/project-deps`。修改锁文件或依赖文件后需重新预取。npm 不运行安装脚本；依赖脚本或仅提供源码包的 Python 项目可能无法使用此离线入口。

系统软件包缓存基于预取时客户机的发行版、架构和包索引。若客户机升级、切换软件源或依赖发生变化，应重新预取；缺少依赖时离线安装会失败并保留缓存。缓存属于客户机磁盘，计入实例占用空间。

真实 Alpine 与 Debian/QEMU 测试覆盖系统包预取、离线安装、缓存列举；Alpine 测试还覆盖文件篡改拒绝和定向清理。`npm run test:package-cache` 可重测。项目依赖由 `npm run test:project-cache` 在真实 Alpine/QEMU 中验证 npm、pip 预取、离线安装和依赖文件漂移拒绝。
