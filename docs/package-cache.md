# 离线软件包缓存

运行中的 Alpine、Debian 和 Ubuntu 实例可在“工作空间 → 软件包”预取软件包，之后从实例内缓存安装。预取需要联网；离线安装分别使用 `apk --no-network` 和 APT `--no-download`，不向包源下载。缓存保存在该实例的 `/var/cache/sakura/packages/<软件包名>`，不会在实例之间自动共享。

1. 选择“预取软件包及依赖”，输入不含版本约束的软件包名称，提交任务并等待完成。预取会更新软件包索引、下载软件包及当前环境需要的依赖，记录文件 SHA-256。
2. 选择“查看离线缓存”。任务日志逐行显示缓存名称、软件包文件数和字节数；列表不需要填写名称。
3. 选择“从缓存离线安装”并输入同名软件包。安装前会校验缓存中的每个文件，校验失败会拒绝安装。
4. 不再需要时，选择“移除指定软件包缓存”并输入名称。清理只影响这一项缓存。

项目依赖可在“工作空间 → 开发任务”选择“预取项目依赖到离线缓存”或“从缓存离线安装项目依赖”，并选择类型：

- npm：需要 `package.json` 和 `package-lock.json` 或 `npm-shrinkwrap.json`。预取在临时目录执行不运行安装脚本的 `npm ci`，不改动项目的 `node_modules`；离线安装校验两个清单文件并使用 npm 的 `--offline --ignore-scripts`。
- Python：需要只含固定版本普通 PyPI 包的 `requirements.txt`（例如 `idna==3.10`），不接受 URL、路径或索引覆盖。预取解析并下载所有二进制 wheel，记录 SHA-256；离线安装校验依赖文件和 wheel 后，用 `--no-index` 安装到项目的 `.sakura/venv`。需要客户机已安装 `python3`、`pip` 和 `venv`。

项目缓存按实例和项目隔离，保存在客户机的 `/var/cache/sakura/project-deps`。修改锁文件或依赖文件后需重新预取。npm 不运行安装脚本；依赖脚本或仅提供源码包的 Python 项目可能无法使用此离线入口。

需要认证的仓库可在“开发设置 → 网络配置”的“项目依赖认证预取”设置 npm、pip 各自的下载端点、Bearer 令牌或用户名密码方式，以及私密配置名称。先在“私密配置”保存只读凭证，再预览并应用网络档案；只保存档案而未应用时，不会启用认证。这里引用的下载凭证与项目环境/私密引用分开，预取仍不解析项目密钥、npmrc、pip.conf 或导入钩子。认证下载需要系统 Python 3，npm 需要完整的第 2 或第 3 版锁文件；pip 需要支持 HTML Simple API 的索引及二进制 wheel。

凭证由 Windows 用户保护的存储解密，通过 SFTP 写入客户机独占的 `0700` 临时目录与 `0600` 文件，下载代理读入后立即删除凭证文件，结束或取消时清理本次临时目录。清理使用独立 SSH 连接重试，持续失联时报告未确认，不宣称已清理；不会处理重新启动的实例中的同名路径。凭证不放入命令参数、进程环境或 npm/pip 配置。包管理器只连接临时回环镜像，代理只在端点的准确协议、域名、端口与目录范围内发送认证；已认证请求向其他范围重定向会拒绝，双重百分号编码、路径穿越及含控制字符的地址也拒绝。索引引用的其他公共 HTTPS wheel 可以无凭证下载，之后照常在项目的私有网络中离线安装。上游需使用 HTTPS，HTTP 仅接受客户机回环测试地址；系统代理配置仍适用于上游请求。

npm 默认 registry 锁文件地址按已配置认证端点重映射，带摘要的 tarball 收入本项目缓存，离线安装仍校验原始锁文件与内容摘要。认证 npm 不接受第 1 版锁文件，普通无认证预取保持既有支持。下载索引最大 8 MiB、单个包最大 256 MiB、每次任务上游正文总计最大 2 GiB，最多 8 个并发请求；未知长度的包先完整收齐再交给包管理器。需要交互登录、客户端证书、Git prepare、源码构建或额外可执行下载配置的来源不能通过此入口使用。

`npm run test:project-auth-cache -- alpine|debian|ubuntu` 使用独立真实客户机、只读测试凭证和回环 registry/index 验证认证预取、跨端点拒绝、公共传递 wheel 不带凭证、下载取消清理、原缓存保留、私有离线安装及导入钩子所在网络。证据保存在所属数据目录的 `authenticated-prefetch-evidence.json`，不调用外部私有仓库。

`npm run test:project-auth-cache:http -- <已停止的所属目录> <已准备的运行包>` 通过包内编译服务、HTTP 和生成 SDK 验证 npm/pip 认证预取与私有离线安装。运行包内不能有开发源码副本，测试核对代理来自已校验的分发资产；结束后停止所属实例、恢复原插件选择并再次校验包摘要。先按安装流程准备该包的固定 QEMU/PosixLoom 运行时，禁止同时运行其他控制器。证据保存为 `authenticated-prefetch-http-evidence.json`。

pip 先在本次独占暂存目录下载和校验完整 wheels、摘要及原依赖文件，再用 Linux `renameat2` 发布：首次使用 `RENAME_NOREPLACE`，已有缓存使用 `RENAME_EXCHANGE`。当前 `pip` 目录始终指向完整旧缓存或完整新缓存；取消恰好发生在交换后可以保留完整新缓存，不承诺回滚。内核、文件系统或架构不支持原子操作时明确拒绝，不回退到先移走旧目录的两步替换。这个保证不涵盖断电后的文件持久性，也不表示多个独立文件读取构成事务。

npm、pip 的暂存路径由宿主预先选定并单独登记。超时、取消或 SSH 中断后，先核对客户机启动身份和任务锚点，确认本次进程组停止，再重试清理本次暂存；归属或停止未确认时保留记录并报告错误。`npm run test:project-cache:atomic -- <所属 Alpine 数据目录>` 验证首次和替换发布前后的真实 TERM/KILL、不支持操作、并发首次发布、连续交换及认证/公共下载取消。`npm run test:guest-task -- <所属 Debian 数据目录>` 验证清理 SSH 失败重试、身份不匹配拒绝、延迟登记取消及 BusyBox launcher 的实际退出码。两者只接受认证测试生成的、当前已停止的单实例目录。

系统软件包缓存基于预取时客户机的发行版、架构和包索引。若客户机升级、切换软件源或依赖发生变化，应重新预取；缺少依赖时离线安装会失败并保留缓存。缓存属于客户机磁盘，计入实例占用空间。

真实 Alpine 与 Debian/QEMU 测试覆盖系统包预取、离线安装、缓存列举；Alpine 测试还覆盖文件篡改拒绝和定向清理。`npm run test:package-cache` 可重测。项目依赖由 `npm run test:project-cache` 在真实 Alpine/QEMU 中验证 npm、pip 预取、离线安装和依赖文件漂移拒绝。
