# 项目终端与只读分享

Sakura 的普通网页终端按当前工作项目的保存配置打开：进入项目目录，使用共享客户机网络或仅回环的项目网络空间。未显式传入项目时，服务端读取保存的活动项目；停用项目插件后也遵守该配置。界面的网络标签来自服务端完成检查后的结果。

启用“多终端工作区”后，tmux 会话、标签、选中项及分屏布局分别按实例和项目保存。首次连接可准备 tmux、iproute2、目录及私有网络空间；系统包下载使用客户机共享网络，不加载项目环境变量。切换项目后原有 tmux 会话继续运行，返回原项目可恢复历史。普通新建 tmux 窗口、分屏继承项目启动命令；刷新和断线恢复会核对所有窗格进程的实际网络空间。

服务端保存会话的项目、目录与网络模式指纹。指纹或任何窗格网络空间不符、私有空间出现额外接口或路由时拒绝连接。已经打开的网页 shell 以及断开后仍运行的项目 tmux 会话会阻止该项目修改目录或网络模式；暂停中的实例需先恢复，再检查和清理。

“停止项目终端”先断开网页连接并保存停止状态，再结束此项目的后台 tmux 会话，保留标签与布局。刷新页面不会自动重建这些会话，点击“打开终端”后重新创建。停止失败会显示错误，并保留断开状态供重试。其他项目的会话不受此操作影响。未启用多终端时，工具栏的“断开项目终端”可断开普通交互 shell。

管理员可向有该实例权限的只读账户共享一个运行中的会话。授权同时绑定项目和该次会话的随机唯一标识：修改活动项目、在其他项目建立同名会话，或停止后重建同名会话，都不会把旧授权转移到新会话。新会话需管理员重新共享。只读连接仍在服务端拒绝输入和尺寸调整；撤销或续签授权会关闭旧连接。旧版本未绑定项目或运行会话的授权可保留在目录中，但不能连接，需重新共享。

CLI `shell` 同样默认打开活动项目，可用 `--project` 指定项目；基础命令执行 API、SDK 和 CLI `exec` 的范围与取消规则见 [项目命令执行](project-execution.md)。这些终端仍以客户机 root 运行。客户机管理员可以自行改变网络或启动自定义 tmux 命令；该功能不限制独立 SSH、显式实例管理命令或自行启动的进程，也不提供文件系统隔离。网络隔离的其他覆盖范围见 [项目网络隔离](project-network-isolation.md)。

`npm run test:project-terminals -- alpine` 使用编译后的 HTTP/WebSocket 服务和真实 QEMU 客户机验证项目目录与实际网络空间、历史分离、断线恢复、默认分屏继承、错误窗格及路由拒绝、只读输入拒绝、撤销、同名重建授权、按项目停止、暂停保护和项目插件停用后的控制器重启。将 `alpine` 改为 `debian` 或 `ubuntu` 可验证另外两个发行版。浏览器场景额外验证停止状态、项目布局切换和手机宽度。
