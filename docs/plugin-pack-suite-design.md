# 第三批十个完整插件包设计

## 1. 版本与交付范围

设计系列：**2.0.0 → 3.0.0**。日期：2026-10-24。代码基线：应用 **2.7.0 / 912287a**，宿主插件 API 5。读者为产品维护者、插件实现者和验收人员。

原设计交付于 2026-10-24，共 10 包、101 个插件。2.8.0 已完成实现和本轮约定的整版验收，当前目录为 201 个插件、26 个包。本文保留原设计依据；实际接口和收紧后的预算见各包使用指南及[版本说明](release-2.8.0.md)。默认空选择保持。

每个包都必须完成输入、编排或编辑、执行或审阅、结果保存、离线交接和原资源清理。只完成页面、目录项或单次命令，不能作为完整包验收。通用规则由本文定义，领域对象、限制和验收见各包详情。

## 4. 插件拆分和依赖约定

详情表中每行是一个独立插件，拥有自己的对象、服务与生命周期。表内短依赖名补上该表统一前缀；`@id` 指向现有插件。`—` 表示无依赖，`*` 仅表示同表其余插件，在实施清单中必须展开成精确 ID 和版本。

每个工作台只聚合公开服务。exchange 插件通过各对象所属服务的导出和接收接口交换材料，不读取其他插件的数据目录。它们不能修改运行器的结果。未来清单沿用 [PluginManifest](../shared/plugin-protocol.ts) 和 `ServiceRef`，必需依赖与可选依赖分别声明。

每行服务名后的方法是首版业务操作集。定义型服务还须具备 `list/get/save/seal/archive`，采用预期修订更新；结果型服务必须提供固定版本读取。所有存储者提供引用查询与清理预览，清理只能删除本插件拥有且无人保护的内容。内部字节租约、容量预留和执行证据提交不开放为 HTTP 写入口。

## 5. 数据、权限与版本

工作空间由实际认证主体创建。服务端绑定 actor、插件实例和 generation，不接受客户端指定 owner。仅拥有 workspaceId 不授予访问权限。首版按现有 owner 权限开放；“审阅人”“学员”等业务标签不构成新的访问角色。单人多阶段审阅必须如实标注。

每个固定对象至少记录 `workspaceId/id/revision/contentDigest/createdAt/schemaVersion`。内容修订、来源许可、工具版本和审核决定分别保存。关系引用固定 ID 与修订，不追随“最新”。原始字节与派生内容都具有保护引用；归档不等于删除历史。

跨服务提交采用有界预留、暂存、发布和确认回执。仅原存储者发布字节；协调者持有提交意图。中断恢复按意图及原回执核对，不能凭内存推断成功。未完成接收的新空间不可读取，并继续计费。事务与恢复账本必须有独立预留，不能在磁盘满时丢弃未确认的资源。

会话锁定或撤权后，页面卸载私有内容，取消读取及订阅。服务在读取前、外部动作前和输出提交前复核授权。后台计算即使已完成，也不能向失去权限的调用者返回结果。UI 缓存按账号、工作空间和插件 generation 隔离。

## 6. 执行与接口共同约定

拟议路径为 `POST /api/<插件ID>/<方法>`，每个方法单独登记严格请求、响应和操作策略。查询也须鉴权；上传和下载另用显式二进制路由。CLI 为 `sakura <包别名> <领域> <动作>`，各详情注明别名。没有任意服务名、命令、URL 或动态方法分发入口。

计划固定输入、目标、工具摘要、作用域、预算、权限修订及截止。默认有效期 5 分钟，批准绑定原计划和摘要。修改输入或目标必须重新预览。执行响应返回 `operationId/jobId/runId` 及查询入口，提交成功不等于业务通过。

列表采用分页，大正文通过受控读租约分段查看。预览显示完整条目总数、摘要和未展开范围，不能用第一页冒充全部输入。用户批准绑定服务端保存的完整计划，提交时不得补入未列明的材料。

| 层次 | 状态与语义 |
| --- | --- |
| 定义 | draft → sealed → archived，封存版本不再覆盖 |
| 计划 | ready → consumed；也可 expired、invalidated，同计划重复提交查询原回执 |
| 任务 | queued → preparing → running → finalizing → completed；失败、取消或 interrupted 单独记录 |
| 结果 | passed、failed、inconclusive、not-supported，不把缺样本判为通过 |
| 清理 | pending、confirmed、unknown，与任务和结果分别显示 |

有副作用的动作先持久化意图，再交给原执行者。请求断开、主进程退出或服务重载都不自动重放。安全收尾只能处理原租约、原进程和原磁盘，不能新建资源或延长业务授权。晚到结果不得把已释放状态改回占用。

所有 VM 操作核对创建回执、运行寿命、boot、项目身份和配置摘要。专用副本默认无外部网络、宿主目录挂载或公开端口；需要的内部通道在固定工具档案中逐项声明。取消先撤销新调度，再等待原执行域退出。宿主定时器本身不能证明硬截止，新增工具须提供独立截止机制或拒绝对应执行模式。

UI 提供空状态、模板、缺项准备、固定计划确认、进度、原任务恢复、结果和清理入口。打开页面及启用插件不下载依赖、不扫描目录、不运行示例。窄屏和夜间主题复用现有组件与语义色；错误保留稳定 code、关联 ID 及恢复动作。

CLI 统一约定：0 为当前操作完成；1 为已知业务失败；2 为输入或传输失败；3 为不确定或不支持；4 为清理待确认。异步 submit 的 0 仅代表接收；`watch --until-terminal` 按最终结果退出。离线 `verify` 不启动宿主或联网，也不依赖 TypeScript 或 tsx。

## 8. 交换、容量与清理

拟定格式为 `sakura-<包ID>/1`。首版采用有界 ZIP STORE 封套，禁止压缩、ZIP64、链接、设备条目、路径穿越、重复路径和大小写碰撞。路径采用 NFC 且使用 `/`。每包详情可收紧支持的条目集合与大小。

清单包含格式、对象模式、条目路径、长度和摘要。清单摘要覆盖规范化清单正文，排除摘要及签名字段本身。原始字节摘要与脱敏派生摘要分开记录；导出预览列出准确材料，不自动携带引用祖先、秘密、浏览器登录状态或活动票据。

导入依次校验大小、结构、字节摘要和对象引用，再隔离审阅并显式接受。接收生成新 ID；旧账号、路径、PID、计划、人工审批和运行权限均不生效。外来证据只作为来源声明，不能成为本地真实执行回执。先完成完整对象图再开放读取。

离线核验分别输出字节完整性、来源认证、可重算范围和缺项。没有配置并验证发布者签名时，来源保持未认证；摘要一致不证明业务结论。下载后的材料无法远程撤回。

详情中的数值均为拟定硬上限，实施可根据实测收紧。必须同时限制单对象、运行、包和宿主总量，不能把十个包的额度直接相加。共享资产物理字节只计一次，专用副本、暂存和派生字节单独计费。

创建 VM 前按其声明的虚拟磁盘容量预留额度，同时报告实际分配字节。稀疏文件当前占用较小不能用于绕过预算。固定镜像与输入字节也计入总量；新镜像、检查点和导出暂存超限时必须拒绝新任务。

每包预留 32 MiB 控制账本，计入总容量，用于取消、撤权和恢复。上传分块默认 512 KiB，控制 JSON 默认 1 MiB；大材料走流式传输。临时读租约最长 15 分钟，需显式释放，到期撤销访问并终止未完成传输。未知任务、活动导出和受引用历史阻止清理。

停止插件先撤销准入，后关闭自己创建的资源，再确认账本。停用保留正式材料。到期只生成清理候选；清理须预览原对象和保护引用，并按原修订提交。失败记录与来源不明的文件不得自动删除。
