# 独立第三节点部署与真实故障演练

本流程用于已有真实来源宿主、独立目标宿主、第三节点、Redfish BMC、应用健康和流量控制接口的部署。`ha:witness` 的演练命令仅生成计划或观察接口，故障注入由已获得具体对象授权的操作者执行。一个来源宿主的 `ForceOff` 会影响该宿主上全部实例，须按资产清单审查整个宿主的影响。

仓库的 [配置模板](ha-witness-config.example.json) 中所有 `REPLACE_...` 和 `.invalid` 地址都必须替换；模板不能直接启动。填入真实 Sakura 宿主/实例 UUID、Redfish 系统 UUID、HTTPS 端点和认证资料，并按 [接口契约](ha-failover-check.md) 接入健康及流量系统。来源与目标宿主 ID 必须不同。TLS 证书指纹需经可信通道核对，BMC 系统 UUID 需与来源硬件资产清单核对。目标配对令牌应来自已建立的来源到目标配对，目标入站配对需授予导入及故障副本接管权限。

## 部署见证

第三节点支持 Windows 或 Linux，需 Node.js 22.12+ 和随 Sakura 运行包提供的运行依赖；见证不启动 QEMU，也不需要下载客户机镜像。将已校验运行包放在固定安装目录，用 `npm ci --omit=dev` 安装其运行依赖。见证配置、TLS 私钥及状态目录使用只允许服务账户读取的权限；所有路径建议填写绝对路径。状态文件放在第三节点的持久本地文件系统中，不要把同一状态文件交给跨宿主、容器或多个独立命名空间共同运行的见证副本。它不是多节点共识服务。

首次部署时，先确认目标副本停止且不存在历史接管，再执行初始化和只读预检：

```sh
npm run ha:witness -- --initialize /etc/sakura-ha/witness.json
npm run ha:witness -- --preflight /etc/sakura-ha/witness.json
npm run ha:witness -- /etc/sakura-ha/witness.json
```

初始化命令拒绝覆盖已有状态。缺失、损坏或绑定不匹配的状态必须先核对来源、目标及流量真实情况再恢复；不能通过删除状态文件重新获取来源授权。Linux 持久提交包含状态文件和父目录同步；Windows 对短暂共享冲突进行有限重试。持久写入仍失败时，当前见证进程拒绝新心跳和来源启动授权，应恢复存储并重启核对状态。

状态版本 4 保留完整退役、自动回切和恢复封锁记录。旧见证程序会拒绝读取；回滚须保留兼容版本，不能删回执或重建空状态。第 2/3 版迁移、配置更换和损坏状态恢复使用 [受控见证维护](ha-witness-maintenance.md) 的 `--migrate`、`--reconfigure`、`--recover` 命令；恢复先封锁全部来源，经完整历史副本核对与退役后才解除。

Linux 可按 [systemd 示例](../scripts/ha-witness.service.example) 建立 `sakura-ha` 服务账户，并按实际 Node、安装目录和配置目录修改 `ExecStart`。先完成初始化，再由该服务启动。`StateDirectory` 保留见证状态，普通停止会等待正在进行的隔离操作；不要把 TLS 私钥放在公共可读目录。该示例包含本地 Unix IPC 所需的 `AF_UNIX`。Windows 可用运行包命令由既有服务管理器托管；保持相同服务账户、安装目录、配置和持久状态文件。

见证按状态文件的规范路径持有 [Node.js IPC](https://nodejs.org/download/release/v22.21.0/docs/api/net.html#ipc-support) 内核独占锁，并保存旁侧 `.lock` 的宿主和 PID。Windows 命名管道和 Linux 抽象 socket 防止两个活进程同时成为见证；即使活进程的 `.lock` 文件被误删，第二个进程也无法获得授权。正常退出会释放锁；异常终止后，只有取得本机内核锁且确认原本机 PID 已不存在，才自动回收旧记录。PID 存活、权限不明、损坏记录或其他宿主的记录均拒绝自动回收。不要删除活见证的锁文件，也不要跨主机复制锁文件来启动第二个见证。若需移动见证节点，应停用旧服务，核对接管状态和目标，再迁移状态并受控处理旧锁。

来源服务的 `SAKURA_HA_WITNESS_CONFIG_FILE` 指向独立客户端配置：

```json
{
  "version": 1,
  "url": "https://replace-witness-host.invalid:9443/",
  "fingerprint": "REPLACE_WITH_WITNESS_SHA256_CERTIFICATE_FINGERPRINT",
  "token": "REPLACE_WITH_THIS_SOURCE_HOST_WITNESS_TOKEN_64_HEX"
}
```

重启来源服务，完成目标配对和已校验快照复制，在来源实例停止时启用宿主失联接管，再启动来源。等待见证状态为 `source`、`armed: true`，目标副本为 `stopped`。初始化后无布防计划的预检不能证明副本链路就绪；布防后应再执行预检。健康适配器在副本停止时须返回该副本 ID 和 `ready: false`，流量接口的初始 `activeVmId` 须为来源实例 ID。

## 准备与观察演练

在第三节点生成绑定实际副本和端点的计划。命令同时检查来源通电、近期心跳、快照时效、目标停机、健康为 false、流量当前指向来源及真实见证启动授权：

```sh
npm run ha:witness -- --drill-plan /etc/sakura-ha/witness.json SOURCE_VM_UUID --output /var/lib/sakura-ha/drill-plan.json
npm run ha:witness -- --observe /etc/sakura-ha/witness.json --plan /var/lib/sakura-ha/drill-plan.json --output /var/lib/sakura-ha/drill-observations.jsonl --timeout-seconds 600
```

这两个命令拒绝覆盖已有输出。计划及观察记录不包含令牌、用户名、密码或应用 URL 查询参数。计划固定来源/目标/硬件身份、证书绑定和精确快照副本；BMC CA 文件的路径和内容摘要也绑定到计划。配置或证书绑定改变、计划撤销后须重新生成。工具默认连接监听地址，`0.0.0.0` 和 `::` 分别使用本机回环；需经过真实可达见证地址时，可为两个命令一致追加 `--witness-url https://实际见证地址:端口/`。

观察器先取得一条完整 `source` 基线，再等待操作者执行已审查的来源宿主失联动作。若来源服务收到正常关闭信号，它会撤防；这种计划关闭不会验证宿主失联自动接管。演练应使已选定来源宿主的心跳真正中断，并保留见证、BMC、目标及流量控制的通信。不得把同一电脑上暂停一个 Node 进程或本地 BMC 适配器的结果当作第三节点及硬件隔离证据。

观察器读取 Redfish UUID/电源、目标主机与精确副本、应用健康、流量状态，并调用见证的只读来源启动授权接口。只有实际认证接口返回 409 才记为来源被拒绝；超时或 TLS 失败不能当作隔离成功。外部读取不是同一个原子事务，采样期间阶段或副本变化会记为 `stable: false` 并继续观察。初始基线缺失、稳定样本出现提前启动、来源复电仍在接管、来源授权泄漏或计划变化时返回失败。观察两次稳定 `promoted`，且来源关机、精确目标运行、应用健康、流量指向目标、来源启动明确被拒绝全部成立，才记录 `promotionObserved: true` 并返回零退出码。Ctrl+C 保存停止结果；它不会关机、启动、退役副本或修改流量。

演练结束应另附：三节点的实际资产身份及独立性、BMC 真实关机日志、来源心跳中断证据、目标应用读写与流量请求结果、见证进程异常终止后重启的来源启动拒绝结果。可在目标停机后复核见证只重启同一个已接管副本，磁盘中接管期间的新写入仍存在。`physicalNodeIndependenceVerified` 始终为 `false`：软件观察工具无法凭接口自行证明三台物理机器互相独立，不能用该记录单独宣称真实三节点演练已经完成。

## 失败处理与回归

`fencing` 表示尚未确认来源关闭；`fenced` 表示来源确认关闭，但目标/健康/流量仍可能未就绪；`promoted` 表示目标已取得接管权。见证会从前两种阶段重试；后续推进、目标再次启动及切流前都只读复核 BMC UUID 和 `Off`。来源意外复电会保留来源封锁并记录错误，不会根据历史关机确认继续启动目标，也不会再次盲目关闭正在恢复的来源宿主。已接管目标退出时，见证确认来源仍关闭后可重启同一副本，保留其新写入；流量已经指向目标时不会重复提交切流。应用或流量失败保留接管权和错误，不会自动放行来源。

退出已完成或中断的隔离接管，都须使来源宿主系统可访问但保持来源实例停止，完成数据回迁或明确的数据取舍，停止目标并提交 `dataReconciled: true`。见证经已配对认证请求目标持久退役；目标仍运行、不可访问、身份不符或权限撤销时拒绝释放来源。成功退役回执在撤防心跳和见证重启后保留，使丢失的成功响应可以重试。新的已校验计划才清除旧回执。配置 `failback.application` 时，来源恢复并通过精确身份健康检查后，见证复核退役、调用流量 `/restore` 并读取 `/status` 确认来源，完成持久 `pending` → `completed` 回切。未知路由不会被后台覆盖；关闭接管策略后仍继续已有回切，服务重启会恢复只续报 `plan: null` 的来源心跳。没有配置该接口的部署须自行回切。旧副本已退役，下一次接管须重新复制。

当前仓库已验证独立服务进程、真实 Linux 副本和 HTTP 应用，但已有 BMC/流量适配器仍运行在同一测试电脑。2026-10-01 检查当前工作区配置和进程/用户/系统环境变量，未找到可接入的实际见证/BMC/健康/流量配置，已登记主机列表也为空。本流程和工具提供可直接填写真实配置的验证入口；实际第三节点、带外硬件与生产流量故障演练仍需要真实环境。
