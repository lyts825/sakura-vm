# 环境变更预览与受控应用

## 使用入口

在项目面板打开“分享与导入项目环境”，粘贴或读取 `sakura.json`，点击“预览环境变更”。预览列出当前配置、目标声明和处理方式。应用前检查项目命令和服务配置。

只有全部差异都允许保存，界面才开放应用按钮。配置没有差异时，确认操作不写入项目文件。每次应用消费当前预览，无论成功还是失败，再次操作都需要重新预览。

## 变更范围

| 字段 | 处理方式 |
| --- | --- |
| 项目命令、环境、服务、端口和 Node/Python 版本声明 | 保存项目配置。相关服务可能停止，需要按需准备环境或启动服务。 |
| 项目目录 | 在项目配置中完成目录迁移，再重新预览。 |
| CPU、内存、加速器和磁盘扩容 | 在实例资源面板停机后执行，再重新预览。 |
| 端口转发 | 在端口转发面板核对占用并修改，再重新预览。 |
| 发行版和实例模板 | 使用“从 sakura.json 创建环境”新建实例。 |
| 磁盘缩容 | 当前不支持。创建新实例并迁移数据。 |

配方只比较显式声明的资源字段。项目配置沿用配方原有的完整替换语义，省略的项目字段使用配置默认值。预览会显示这些变化。

资源差异会阻止整份配方应用，不会只保存项目部分。这样可以避免界面报告成功后，资源仍与声明不符。

## 核对实际环境

预览中的 Node/Python 版本是配置声明。保存版本声明不会安装运行时。展开“核对实际 Node/Python 运行时”，使用已有运行时插件安装所需版本，点击“探测项目版本”核对实际结果。插件尚未启用时，界面提示先在插件中心启用“运行时版本”。

配置摘要只用于识别配置内容，不证明镜像或依赖已经复现。预览不读取客户机，不探测实际版本，也不计算镜像文件和依赖锁文件的摘要。API 将三类验证状态明确标为 `not-probed`。

需要依赖核对时，使用工程任务已有的“校验环境锁文件”操作。需要依赖安装时，使用“按锁文件安装依赖”。这些独立任务的结果不属于本次配置预览的验收结果。

## 过期与并发保护

预览保留 10 分钟。服务最多保存 128 份预览，超限时淘汰最早的记录；服务重启或插件重载后，旧令牌失效。

预览绑定实例持久标识和创建时间、实例记录、运行状态、当前项目标识、项目配置版本和配方输入摘要。应用时再次核对，保存项目配置时继续使用已有的版本比较及提交前检查。实例重建、项目切换或配置变化会使旧预览失效。

令牌只允许发起一次应用。保存前或提交前核对失败会拒绝配置覆盖。项目保存可能先停止受影响的服务；此时需要检查服务状态，再重新预览。

## 接口与兼容性

`POST /api/vms/{vmId}/recipe/plan` 接收原有配方对象，返回差异、配置摘要、过期时间和令牌。该接口只生成预览，不执行客户机操作。

`POST /api/vms/{vmId}/recipe/apply-plan` 接收 `{ "token": "预览令牌" }`，返回原有项目视图。两条路由都沿用实例及项目权限范围，应用路由要求实例未锁定。

原有导入、导出和创建接口保留。旧 `PUT /api/vms/{vmId}/recipe` 仍沿用仅保存项目配置的行为；新界面统一使用预览流程。
