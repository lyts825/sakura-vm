# 持久项目账号与固定启动器

`server/project-identity.ts` 提供持久项目账号、固定启动器与客户机运行票据；`server/project-run-scope.ts` 保存宿主预期身份和核销记录。默认项目 `/exec`、项目初始化、主命令、普通服务、就绪与命令式健康检查、运行时版本的显式探测和选择验证，以及构建农场、收藏命令、流水线步骤和单次 SSH/GPG Agent 命令使用固定项目 UID/GID。普通网页终端与可恢复 tmux 会话也通过固定启动器使用项目账号、原网络和独立运行票据，规则见 [项目终端](project-terminals.md)。收藏命令和流水线的配置捕获、步骤时限、取消及持久错误见 [项目命令任务](project-command-tasks.md)。专属项目 SSH 的 Shell、命令、SFTP 与编辑器入口已接通同一持久 UID/GID、独立 home、原服务 cgroup 和固定启动器，二进制 stdin 与 PTY 使用独立描述符，完整 daemon/boot/inode 票据在启动前登记并在停止全域后核销，规则见 [项目 SSH](project-ssh.md)。浏览器 IDE、集成终端与扩展宿主也已使用项目账号、独立 home、受保护 stdin 和完整原服务票据；原账号持有的监听核对后才开放回环桥接，客户机到期清理覆盖全部后代，规则见 [浏览器 IDE](browser-ide.md)。工程扩展的工作区、Git、测试、命令宏和 Runbook，以及平台分片、跨实例矩阵子任务与环境指纹也已使用原项目账号、捕获配置和有界保护帧；可信源码在降权后解压校验，直接操作结果保存及任务导入保持原准备租约，见 [工程操作](engineering-project-identity.md)。轻量 Node/tsc/Python/JSON 代码诊断也使用捕获配置、原 live 身份、项目账号与保护帧，准备租约保持到整域清理，结果继续脱敏；见 [代码检查](development-next.md)。Notebook 的安装、Jupyter/Marimo 与内核也已接通持久项目账号、独立 home、捕获配置和完整服务票据。固定管理入口下载不可变 wheels，项目账号离线创建虚拟环境；共享与私有模式均核对原 UID 监听后开放回环桥接，停止确认全域及准确资源清理后核销，规则见 [Notebook 环境](notebook-environments.md)。客户机系统 SSH、cron、用户管理器、独立语言服务和调试适配器等其余入口仍有未迁移范围，网络隔离总功能保持部分实现。运行时面板读取宿主缓存，安装共享运行时仍属于实例管理员操作，见 [运行时版本](runtime-versions.md)；构建配置捕获、并发和取消见 [构建农场](build-farm.md)；命令确认、独立入口与撤销见 [SSH Agent 转发](ssh-agent-forward.md) 和 [GPG Agent 转发](gpg-agent-forward.md)。

项目 [首次 Git 检出](project-repository.md) 使用系统固定代理下载对象，项目 UID 在原目录和原网络内验证摘要并检出；项目环境、Git 配置和下载认证不会进入系统 Git。检出入场同时固定 live 与原 boot，取消或失败保留未确认的准确资源。

## 账号与目录

客户机在 root 管理的 `/var/lib/sakura/project-identities` 保存登记表。每个项目固定一组 UID/GID、账号、身份 UUID 和修订号，先持久保留分配意图，再建立系统账号与独立 home。分配中断后复用已保留的身份，UID 不分配给另一个项目。登记同时核对 passwd、group、补充组、home 以及目录设备号和 inode，不接管同名但已替换的账号或目录。

home 位于 `/var/lib/sakura-project-homes/<identityId>`，叶目录为该账号所有且权限 `0700`，父目录由 root 管理。控制器用真实项目 UID 核对父目录可遍历和项目目录的读、写、执行权限；不足时返回 `PROJECT_IDENTITY_DIRECTORY_MIGRATION_REQUIRED`。在项目面板预览保存的目录迁移计划，核对所有文件的属主与权限变更后明确应用，再重试原操作。入口不会自动递归改属主、放宽 `/root` 或建立缺失的项目目录，见 [目录迁移](project-directory-migration.md)。

`ensure` 携带宿主保存的登记表、身份 UUID、UID/GID、home inode 与修订号；预期身份不符时拒绝。`rebind` 必须提供当前身份，确认旧运行全部停止后，才将新目录或网络模式发布为下一修订。宿主先持久保存绑定意图，丢失确认后仅接受原身份的准确下一修订。目录迁移中的持久门闩阻止其他入口准备新运行，最后的绑定和门闩确认失败仍保留同一计划供重试。

## 运行归属

独立运行准备专属 `sakura-identity-<runId>` cgroup v2，固定当前 boot ID、网络命名空间和 cgroup 的设备号及 inode。私有网络只允许本项目派生的 `sk-<projectId>`，核对仅回环接口和无路由。准备回执丢失可用相同 run ID 重试；关闭的票据不能再次开放。

`inheritedInput` 用于已经进入 Sakura 短任务、主命令或服务 cgroup 的 root 启动器。控制器从自身真实 cgroup 成员关系取得上层归属，调用者不能传入任意 cgroup 路径；C 启动器核对固定域后保持成员关系，不把项目命令移出原有清理范围。宿主在发送正文前保存准确的 boot、run、域 inode、身份和正文摘要。上层先清理全域并确认不存在，再核销对应账号票据；回执丢失保留原记录，下次操作只重试原归属。

固定 C 启动器读取 root 管理的二进制记录，不以项目提供的 JSON、UID、命名空间路径或 FD 编号决定权限。非 root 调用按真实 UID 查找唯一项目登记，不能选择另一个账号。进入已核对的网络与 cgroup 后，设置固定账号的 UID/GID、清空补充组、丢弃 capabilities、设置 `no_new_privs`，关闭 root 控制 FD，然后才载入项目环境并执行命令。项目环境不能替换 `HOME`、`USER` 或 `LOGNAME`。

命令与环境编码为最多 128 KiB 的二进制正文，通过 SSH 标准输入或 root `0700` 运行目录内的独占 `0600` 帧运输。root 启动参数只包含固定归属、大小与 SHA-256，不包含正文。降权后检查完整 EOF、摘要、UTF-8、NUL 与字段限制，写入只读并加完整 seals 的 memfd，以 `/bin/sh /proc/self/fd/3` 执行；不使用携带内联正文的 shell `-c`。旧 argv 正文 API 明确拒绝。主命令与服务的帧还固定文件设备号、inode、boot 和原运行，不能把同路径替换文件当作原正文。该运输不能阻止同一项目账号读取自己的环境，也不能限制客户机管理员。

独立停止先关闭票据，再清理准确的 cgroup，确认空域和移除；回执丢失可重试。身份替换、控制连接失败或清理未确认时保留记录并报告错误，不按账号名称或目录猜测并终止其他进程。冷重启后仅在两次准确 boot/旧域不存在核对通过时保存宿主退休记录，不伪造客户机停止回执，也不向新开机进程发送信号。只读运行查询不安装工具或推进回执。

客户机热目录最多保留 1,024 张票据，每个项目同时最多 32 个活动运行。满额时，固定控制器在账号独占锁下每批归档最多 512 张本次 boot 已关闭、准确任务域不存在或无进程的完整原回执，使新任务无需因此重启实例。活动票据、仍有后代的关闭票据、旧 boot 与替换后的任务域不被退休。

归档保存在 `/run/sakura-project-identities/archives/<UUID 前两位>/<run ID>.bin`，目录 root/0700、记录 root/0600；每桶最多 4,096 项，临时残留也占容量。控制器不跟随链接，先独占写入临时文件、同步完整 1,024 字节，用 Linux `renameat2(RENAME_NOREPLACE)` 发布，同步归档目录并读回核对后，再核对原父目录、票据文件身份及任务域，最后删除准确热票据并同步原目录。缺少 libc 包装入口时，仅在已核对的原生 64 位 x86-64 或 AArch64 ABI 上调用同一个内核原子接口；未知 ABI 或内核不支持则拒绝。归档冲突、替换、权限不符、容量或写入核对失败保留原回执和具体错误，不覆盖未知归档或扫除旧临时文件。

满额准备复用同一次独占锁内已验证的最多 1,024 条回执快照；每张候选在退休前仍重新核对原字节、文件身份及任务域。SDK 的任务准备控制有三分钟独立时限，普通查询及准确停止仍使用原时限；取消信号继续传入控制连接。

归档的 run ID 拒绝再次 prepare 或继承执行；即使中断留下同字节的热票据副本，也不恢复授权。正常 run/status、只读查询与重复停止可读取完整关闭回执，重复停止不把它写回热目录。只读入口不建立目录、安装或触发归档。本次 boot 的热票据与客户机归档仍在真实重启后随 `/run` 清空。宿主日志到达 1,024 条时，继续先将最早 512 条已关闭完整回执逐项持久归档并读回核对，再压缩日志；宿主归档的 run ID 永久禁止复用。旧构建存在活动或已关闭但仍有进程的热票据时，升级拒绝继续；归档不得用来绕过该核对。

`npm run test:project-identity:archive -- --describe` 只显示测试合同。实测需明确指定 `--run-new <alpine|debian|ubuntu>`，从只读缓存复制基础镜像，在全新目录和实例中生成新 SSH 身份，不复用旧实例。默认逐条实际 prepare/stop；可追加 `--seed-closed-capacity`，以一张实际关闭票据生成 1,022 张明确标注的关闭回执夹具。夹具模式不证明完成了 1,023 次内核任务运行；满额后的归档、正常项目命令、旧 ID 拒绝、私有记录访问、真实原子发布冲突和邻居任务取消仍执行生产接口。目录同步故障明确标为测试注入。

外层短任务的控制记录位于 `/run/sakura-guest-tasks/<runId>`：父目录与每次调用目录为 root `0700`，记录为非链接、单链接的 root `0600` 普通文件。每个调用还固定独立 nonce 与 boot；启动、停止确认和核销均重新核对，不接管同 UUID 的已有调用。完整任务 cgroup 停止且账号核销回调完成后才删除该调用记录；账号核销回调失败时，恢复账号票据不代表这一独立控制目录也已退休。核销确认丢失可以重试；无法确认时保留记录并报告清理失败。原第 2 版完整 UUID/cgroup 回执格式和输入运输保持一致。

构建的同项目槽位各自登记完整运行。当前进程只为本次原子入场保存准确 live、boot、账号、owner、正文摘要与已观察票据的活动归属，短队列串行核对和核销，正文可并行；新的槽位不会回收仍受本进程管理的准确运行。重新加载、记录变化或实例替换后不能从磁盘恢复这份活动豁免；目录变更、迁移与网络核销始终仍受全部未闭合票据保护。

单次 SSH Agent 在原任务记录上同时固定 lease ID、broker 摘要和时限；活动豁免还核对这份不可变资源。原 SSH 监听维持 root 私有权限，固定 broker 在外层任务域中为项目发布独立入口；每次直接连接及协议请求核对 UID/GID、进程创建身份、boot 和完整域。上层域停止后先撤销本次宿主流并核对准确入口清理，再核销账号票据；失败保留资源及原 host owner 供正常恢复，不关闭邻居任务或宿主守护进程。

单次 GPG Agent 还固定原生宿主来源和 helper 摘要；项目 intent 写入前先持久保存宿主未启动回执，helper 在读取 nonce 前保存准确进程回执。每次运行有独立项目 GNUPGHOME 和 Assuan broker，账号票据不能先于域、宿主连接和准确临时资源关闭。控制服务重载按原持久回执核对 helper 进程身份，不能将丢失的内存登记当作已关闭；客户机重启后清理固定当前 live，旧 owner 仍只授权原宿主资源的回收。

## 私有网络核销

私有网络固定命名空间设备号、inode、boot ID 与随机 generation。停止整个项目先保存固定 release ID 并冻结本代入口，再清理所有上层运行和账号票据，最后按同一代次核销命名空间。已发出的启动票据也受冻结检查；清理失联、删除失败或确认丢失时保留 pending/deleting 状态，只能重试同一请求。下一次启动建立新 generation；即使内核复用同一 inode，旧请求也不能删除新代。仅停止一个命名服务不会核销整个项目网络。

客户机 root 仍能修改这些设施；显式实例命令及未迁移扩展仍保留管理员路径，不能据此承诺所有 Linux 入口均有跨项目权限边界。普通网页终端使用独立项目账号、PTY 和完整运行票据，具体连接、恢复和清理规则见 [项目终端](project-terminals.md)。

## 分发与验证

生产资产包含 `protocol.h`、`launcher.c`、`controller.py` 与第 1 版清单。构建、运行时安装及分发检查核对每项大小、SHA-256 和整体摘要；运行时只读随包资产，不回退到开发源码。客户机安装使用干净环境，在受保护版本目录编译固定启动器。

客户机需要 Python 3、C 编译器、iproute2 和发行版 shadow 账号工具。Alpine 用官方 `shadow` 软件包的固定命令，三发行版都采用显式 UID/GID 的 system account 建立方式，不依赖某个版本才支持的 login.defs 设置。运行准备在 Alpine 启动原生 cgroups 服务，并核对实际 cgroup v2 挂载，不以测试目录或普通文件代替。

单元入口为 `tests/project-identity.test.ts` 与 `tests/project-run-scope.test.ts`；三发行版固定启动器实测入口为 `npm run test:project-identity -- alpine|debian|ubuntu`。产品接入、目录迁移与打包 HTTP 烟测只接受脚本明确登记并已释放的自有 fixture，不接受任意用户实例。具体通过范围、源摘要和回执见 [功能实现记录](capability-completion.md)。
