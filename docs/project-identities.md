# 持久项目账号与固定启动器

`server/project-identity.ts` 提供持久项目账号、固定启动器与客户机运行票据；`server/project-run-scope.ts` 保存宿主预期身份和核销记录。默认项目 `/exec`、项目初始化、主命令、普通服务、就绪与命令式健康检查，以及运行时版本的显式探测和选择验证使用固定项目 UID/GID。普通终端、系统 SSH、cron、用户管理器和全部扩展入口尚未完成账号迁移，网络隔离总功能仍为部分实现。运行时面板读取宿主缓存，安装共享运行时仍属于实例管理员操作，见 [运行时版本](runtime-versions.md)。

## 账号与目录

客户机在 root 管理的 `/var/lib/sakura/project-identities` 保存登记表。每个项目固定一组 UID/GID、账号、身份 UUID 和修订号，先持久保留分配意图，再建立系统账号与独立 home。分配中断后复用已保留的身份，UID 不分配给另一个项目。登记同时核对 passwd、group、补充组、home 以及目录设备号和 inode，不接管同名但已替换的账号或目录。

home 位于 `/var/lib/sakura-project-homes/<identityId>`，叶目录为该账号所有且权限 `0700`，父目录由 root 管理。控制器用真实项目 UID 核对父目录可遍历和项目目录的读、写、执行权限；不足时返回 `PROJECT_IDENTITY_DIRECTORY_MIGRATION_REQUIRED`。在项目面板预览保存的目录迁移计划，核对所有文件的属主与权限变更后明确应用，再重试原操作。入口不会自动递归改属主、放宽 `/root` 或建立缺失的项目目录，见 [目录迁移](project-directory-migration.md)。

`ensure` 携带宿主保存的登记表、身份 UUID、UID/GID、home inode 与修订号；预期身份不符时拒绝。`rebind` 必须提供当前身份，确认旧运行全部停止后，才将新目录或网络模式发布为下一修订。宿主先持久保存绑定意图，丢失确认后仅接受原身份的准确下一修订。目录迁移中的持久门闩阻止其他入口准备新运行，最后的绑定和门闩确认失败仍保留同一计划供重试。

## 运行归属

独立运行准备专属 `sakura-identity-<runId>` cgroup v2，固定当前 boot ID、网络命名空间和 cgroup 的设备号及 inode。私有网络只允许本项目派生的 `sk-<projectId>`，核对仅回环接口和无路由。准备回执丢失可用相同 run ID 重试；关闭的票据不能再次开放。

`inheritedInput` 用于已经进入 Sakura 短任务、主命令或服务 cgroup 的 root 启动器。控制器从自身真实 cgroup 成员关系取得上层归属，调用者不能传入任意 cgroup 路径；C 启动器核对固定域后保持成员关系，不把项目命令移出原有清理范围。宿主在发送正文前保存准确的 boot、run、域 inode、身份和正文摘要。上层先清理全域并确认不存在，再核销对应账号票据；回执丢失保留原记录，下次操作只重试原归属。

固定 C 启动器读取 root 管理的二进制记录，不以项目提供的 JSON、UID、命名空间路径或 FD 编号决定权限。非 root 调用按真实 UID 查找唯一项目登记，不能选择另一个账号。进入已核对的网络与 cgroup 后，设置固定账号的 UID/GID、清空补充组、丢弃 capabilities、设置 `no_new_privs`，关闭 root 控制 FD，然后才载入项目环境并执行命令。项目环境不能替换 `HOME`、`USER` 或 `LOGNAME`。

命令与环境编码为最多 128 KiB 的二进制正文，通过 SSH 标准输入或 root `0700` 运行目录内的独占 `0600` 帧运输。root 启动参数只包含固定归属、大小与 SHA-256，不包含正文。降权后检查完整 EOF、摘要、UTF-8、NUL 与字段限制，写入只读并加完整 seals 的 memfd，以 `/bin/sh /proc/self/fd/3` 执行；不使用携带内联正文的 shell `-c`。旧 argv 正文 API 明确拒绝。主命令与服务的帧还固定文件设备号、inode、boot 和原运行，不能把同路径替换文件当作原正文。该运输不能阻止同一项目账号读取自己的环境，也不能限制客户机管理员。

独立停止先关闭票据，再清理准确的 cgroup，确认空域和移除；回执丢失可重试。身份替换、控制连接失败或清理未确认时保留记录并报告错误，不按账号名称或目录猜测并终止其他进程。冷重启后仅在两次准确 boot/旧域不存在核对通过时保存宿主退休记录，不伪造客户机停止回执，也不向新开机进程发送信号。只读运行查询不安装工具或推进回执。

每次 boot 最多保留 1,024 张客户机票据，同时最多 32 个活动运行；关闭票据仍作为禁止重放的记录，直至 `/run` 随实际重启清空。宿主活跃日志到达 1,024 条时，只将最早 512 条已关闭完整回执逐项持久归档并读回核对，再压缩日志；归档的 run ID 永久禁止复用。这不解除客户机的每 boot 限制。旧构建存在活动或已关闭但仍有进程的票据时，升级拒绝继续；不通过删除旧票据或放宽旧启动器来升级。

外层短任务的控制记录位于 `/run/sakura-guest-tasks/<runId>`：父目录与每次调用目录为 root `0700`，记录为非链接、单链接的 root `0600` 普通文件。每个调用还固定独立 nonce 与 boot；启动、停止确认和核销均重新核对，不接管同 UUID 的已有调用。完整任务 cgroup 停止后才删除该调用记录，核销确认丢失可以重试；无法确认时保留记录并报告清理失败。原第 2 版完整 UUID/cgroup 回执格式和输入运输保持一致。

## 私有网络核销

私有网络固定命名空间设备号、inode、boot ID 与随机 generation。停止整个项目先保存固定 release ID 并冻结本代入口，再清理所有上层运行和账号票据，最后按同一代次核销命名空间。已发出的启动票据也受冻结检查；清理失联、删除失败或确认丢失时保留 pending/deleting 状态，只能重试同一请求。下一次启动建立新 generation；即使内核复用同一 inode，旧请求也不能删除新代。仅停止一个命名服务不会核销整个项目网络。

客户机 root 仍能修改这些设施；显式实例命令、普通终端及未迁移扩展仍保留管理员路径，不能据此承诺所有 Linux 入口均有跨项目权限边界。

## 分发与验证

生产资产包含 `protocol.h`、`launcher.c`、`controller.py` 与第 1 版清单。构建、运行时安装及分发检查核对每项大小、SHA-256 和整体摘要；运行时只读随包资产，不回退到开发源码。客户机安装使用干净环境，在受保护版本目录编译固定启动器。

客户机需要 Python 3、C 编译器、iproute2 和发行版 shadow 账号工具。Alpine 用官方 `shadow` 软件包的固定命令，三发行版都采用显式 UID/GID 的 system account 建立方式，不依赖某个版本才支持的 login.defs 设置。运行准备在 Alpine 启动原生 cgroups 服务，并核对实际 cgroup v2 挂载，不以测试目录或普通文件代替。

单元入口为 `tests/project-identity.test.ts` 与 `tests/project-run-scope.test.ts`；三发行版固定启动器实测入口为 `npm run test:project-identity -- alpine|debian|ubuntu`。产品接入、目录迁移与打包 HTTP 烟测只接受脚本明确登记并已释放的自有 fixture，不接受任意用户实例。具体通过范围、源摘要和回执见 [功能实现记录](capability-completion.md)。
