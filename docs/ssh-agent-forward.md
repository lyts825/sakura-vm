# 单次 SSH Agent 转发

能力中心的 `ssh-agent-forward` 为一条明确提交的项目命令提供宿主 SSH Agent。宿主需要运行 Agent 并装载所需密钥；客户机需要 OpenSSH 客户端。Windows 默认使用 OpenSSH Agent 管道，其他宿主使用服务进程的 `SSH_AUTH_SOCK`；需要指定入口时，在启动 Sakura 前设置该变量。

在第二批能力中心选择“SSH Agent 转发”，填写命令、`confirmed: true` 和 1–300 秒时限，再明确提交。检查入口只报告宿主连接与客户机工具是否可用，不执行项目命令。命令与确认属于这次提交，不能保存为功能默认配置，也不会沿用旧版本保存的确认。

```json
{
  "command": "ssh-add -L",
  "confirmed": true,
  "timeoutSeconds": 60
}
```

CLI 可读取这个 JSON 文件执行：

```text
npm run sakura -- extended <实例名> run ssh-agent-forward agent-command.json
npm run sakura -- task <任务ID> result
```

项目账号运行命令，使用固定 UID/GID、独立 home、原项目目录和已保存的网络模式。准备捕获项目配置与准确运行实例，后续环境、运行时与密钥只由该份配置解析。已有 root 目录需要所有者先预览、审阅并应用 [目录迁移](project-directory-migration.md)。命令与环境使用 [项目账号](project-identities.md) 的受保护输入，分段输出、完整结果和错误继续遮盖项目密钥；项目配置中的 `SSH_AUTH_SOCK` 不会替换本次转发入口。

Agent 可以为客户机请求的数据签名，提交前须确认命令及其依赖可信。私钥文件不复制到客户机；转发不会建立私有项目的外网接口或路由，也不会为其他命令开放通道。

## 并发、取消与恢复

每次命令拥有独立账号运行票据、完整 cgroup、Agent 入口及宿主转发连接。直接连接入口时核对项目 UID/GID、boot、进程创建身份与完整任务域，同项目另一任务的直接连接也拒绝。已授权进程仍可能主动转交自己的连接 FD 或代理请求；这不是防止同 UID 主动串通的边界。

命令结束、超时或取消后，撤销本次宿主转发并清理完整任务域，包括脱离会话的后代。确认原域停止及准确 Agent 资源清理后，才核销账号票据；取消一条命令不会关闭宿主 Agent 守护进程或另一任务的连接。执行与清理期间保护原目录及网络绑定，共享终端服务关闭会取消并等待这些任务。

清理或归属未确认时返回 503 并保留具体错误码；Agent 资源或账号核销失败使用 `PROJECT_IDENTITY_CLEANUP_FAILED`。原资源记录和账号票据保留，任务界面显示错误码。刷新、服务重载及重新提交不会删除原记录或重放旧 run ID。后续准备先按原完整身份恢复清理；未知对象或身份变化继续拒绝，不能凭路径、账号名称或旧磁盘记录推断当前进程仍持有任务。

## 资产与范围

运行包包含固定 Python broker 与单文件大小、SHA-256 清单；客户机只执行校验过的 root 私有版本。原 SSH 监听保持原权限，项目仅获得本次入口；每条连接和协议帧都有数量、大小与时间预算。客户机需要真实 cgroup v2 和 Linux pidfd，缺少必要能力时在项目正文执行前拒绝。

本入口只处理能力中心的单次 SSH Agent 命令。专属项目 SSH、普通 PTY 与 GPG 转发仍有各自迁移范围；系统管理员也能改动客户机设施。实际验证条件、失败记录与当前完成范围见 [功能实现记录](capability-completion.md)。
