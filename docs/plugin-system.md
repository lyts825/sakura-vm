# 统一插件管理实施记录

基础版本迭代（2026-10-04）：应用 `0.1.0 → 1.0.0`，内置插件及整合包 `0.3.0 → 1.0.0`，宿主插件 API `3 → 4`。删除原始上下文和字符串服务引用属于不兼容变更；可信插件必须更新声明和能力调用。用户选择格式仍为 3，已有整合包选择和领域元数据按原迁移入口保留。版本由根包清单、共享应用版本及插件协议声明同步维护。

契约基础迭代为应用与内置包 `1.0.0 → 2.0.0`，宿主插件 API `4 → 5`（2026-10-05）。显式操作策略和独立服务引用要求可信源码插件迁移，因此采用主版本迭代。保留现有 HTTP 路径、用户配置，并向前读取旧领域票据；操作策略和启动依赖不再隐含在实现中。

当前迭代为 `2.3.1 / 7620ee1 → 2.3.2`（2026-10-06），复核历史 86 项 HTTP 请求声明，补齐上传条件正文及生成/解析一致性；宿主插件 API 5 和公共服务 V1 保持兼容。分版本验收与兼容边界见文末。

运行链路为：入口 → OperationGateway → PluginManager / PluginDirectory → ServiceBroker → 实例能力 → 现有统一运行时 → HostRuntime。可信官方模块和签名社区 WASM 保持各自执行方式，共享实例、状态、贡献与清理责任。

## 管理与身份

`PluginManager` 保存选择与整合包意图，协调官方运行时和社区适配器；`PluginDirectory` 是实际运行状态的唯一来源。原 `Features` 作为 `PluginRuntime` 的组合入口保留。应用装配的领域服务登记为 `system:` 必需提供者，官方与社区分别使用 `official:`、`community:` 命名空间。

每次激活固定插件 ID、版本、SHA-256 产物摘要、代次、权限、取消信号和资源范围。开发摘要包含宿主和插件源文件，生产摘要包含服务器入口、插件分块及随包交付的执行资源；文件路径、长度和内容均参与摘要。状态包括 activating、running、draining、inactive、failed、skipped 和 cleanup-pending；配置变化需重启的官方插件明确显示 restartRequired。历史选择、旧聚合插件到整合包的迁移和领域元数据继续保留。

激活期间创建资源立即归属本实例，但贡献只有激活成功后才发布。运行中的动态注册、注销和权限变化推进目录版本。操作目录、OpenAPI、SDK 和界面从同一运行贡献目录读取。前端按代次取消请求、失效缓存并忽略旧响应。

## 调用与资源

插件上下文是独立冻结对象，提供实例绑定的 VM、执行、存储、网络、Jobs、会话、不透明元数据以及明确声明的系统服务。`compat.machines`、原始 Machines、全局可写槽位、数据路径接口和字符串服务引用已删除。迁移覆盖领域实现中的 Jobs、网络范围、周期任务和 VM 事件监听器。

公共服务通过绑定契约 ID 的 `ServiceRef` 声明。独立 `service-contracts/v1.ts` 定义接口，描述符生成脚本仅读取这些契约；实现类的新增公开方法或类名变化不会改变公共成员。消费者无法读取私有依赖、原始管理器或关闭提供者。ServiceBroker 在调用时和资源出队时复核消费者、提供者、权限和原代次。转发已经受控的服务句柄时保留其公共成员与原调用检查，不把它误当成普通数据复制。缓存句柄不会自动连接到新实例。可选发现不形成必需卸载依赖；实际异步借用被原消费者与提供者共同观察。

提供者长期资源归属提供者，调用保留账户、VM、项目和最初调用者身份。嵌套执行通过合法委托复用预算，后台触发恢复创建实例的权限并清除旧请求身份。HostRuntime 的资源视图包含 pluginInstanceId、pluginGeneration、operationId、vmId 和 projectId。共享网络与计算进程池继续使用全局上限和实例归属。

VM 端口只暴露明确方法和只读记录。缓存 SSH/SFTP 端口在每次新命令时检查原 VM 身份与权限，内部 socket 和协议对象不可访问。清理只允许原句柄的关闭、注销以及原独占创建临时文件的删除回执。

Node 流保留 pipeline、取消及错误完成语义；SSH/SFTP 回调恢复原实例、账户、VM 和项目身份，不能获得新的业务或清理授权。待决 SSH 连接的原拒绝回执在撤权后仍可完成一次，接受新连接继续检查准入。

基础终端、插件终端和共享观看共用 `TerminalBackend`，各自取得独立子句柄。文件替换、VM 启动、项目配置和可信启动使用带注销回执的受管拦截器。平台、工程和自动化聚合类拆为领域服务；原 API 与能力中心继续组合这些服务。应用的业务 `set*` 装配改为构造依赖及显式延迟解析契约。

## 退出与恢复

退出顺序为：标记 draining → 阻止新调用 → 撤销后台触发、排队工作和原代连接 → 等待在途工作与物理清理 → 注销贡献 → 完成安装记录变化。WS 登记插件代次、账户、VM 与项目，只关闭退出实例所属连接。

激活失败和关闭超时均保留原实例责任。cleanup-pending 保留预算、产物身份和恢复回执，不能被重新安装覆盖。清理回执由宿主标记，撤权后仍可重试原清理；业务调用继续被拒绝。常驻项目会话同时登记到原插件实例与 VM 生命周期；退出和 VM 状态切换使用原完整回执清理，不重新申请已关闭的业务执行准入。清理失败保留会话配额与插件恢复记录，确认原资源回收后才核销。社区卸载和升级在计算工作实际退出并确认恢复后才删除安装记录与产物。社区 UI 仍只渲染签名声明的有限表单，WASM 仍无宿主导入并受原内存与计算限制。

## 2.1.0 契约与恢复补全（2026-10-05）

基线为 `2.0.0 / a73247e`，实现提交为 `d4a2587`，交付版本由本地 `v2.1.0` 标签定位，未推送、发布或部署。应用及内置包升级到 `2.1.0`，宿主插件 API 保持 5。操作与服务声明、初始化依赖、插件错误边界、资源所有者和恢复目录沿用 2.0.0 的治理机制。

298 个 HTTP 操作均已声明响应：142 个核心、156 个插件，HTTP 的 `partial` 为零。独立 DTO 位于 `shared/contracts/core-dtos.ts`、`core-responses.ts` 与 `plugin-route-responses.ts`；动态外部协议数据使用明确的 JSON 值类型，固定字段和枚举保留精确结构。实现不能通过私有 validator 扩大公共输出，缺契约或处理器无法通过登记与生成门禁。所有 298 项生成响应类型及其递归引用均不含 `any / unknown`；无 Schema 的请求体仍如实为 `unknown`，6 项 WS 的帧协议仍为 `partial`，不混入 HTTP 覆盖率。

统一响应边界校验实际序列化结果，JSON 结构、成功状态或媒体类型不匹配时，在发送响应头前拒绝；错误只报告字段位置，不返回字段值。绕过 JSON helper 的原始写入也不能发出未验证成功响应。GraphQL 的协议错误、多成功状态、SSO HTML、下载二进制和 204 空响应各自表达。OpenAPI 与 TypeScript 客户端使用同一份传输描述；公开、客户机、扩展和下载入口不自动附加控制凭证，调用方可显式提供其专用凭证。取消单个请求不会中断其他请求共享的凭证获取，账户代次变化继续中断旧请求。

OpenAPI/SDK 只缓存已严格验证、序列化后不可变的私有字节，按目录版本、启用插件集合和端口失效，最多保留当前目录的两份文档。每次发送继续核对操作、契约、Schema、状态和媒体身份并通过原响应门禁；普通业务响应仍逐次校验。缓存不能被复制或伪造，也不能跨操作使用。

在线迁移提前协商 `completionProtocol: 1`，来源持久栅栏绑定原进程、配对宿主、会话、transfer、项目摘要及原插件代次。只有原 QEMU 的 native 退出回执与目标原会话的运行核验一致，且完成证明保存成功，恢复目录才确认完成。完成后保留来源栅栏，不能重新启动来源；保存失败可在原回执仍有效时重试。目录不把内存中的临时写入、记录消失或票据替换当成完成。旧票据及重启前未能持久化原退出回执的票据保持待核验，没有解除栅栏或凭空核销预算的动作。

证明端口不属于公共 V1 描述符，也不提供公开获取函数；协调器以 JavaScript 私有字段持有原域闭包。插件上下文不能创建、注册或注入端口，只能调用保留权限检查的高层流程。依赖门禁覆盖插件辅助文件、静态与动态导入、加载器别名和规范化路径，并拒绝无法静态核查的模块路径。合法平台调用、原代撤权、权限负例和删除失败保留回执均有定向验证。

旧来源可继续向新目标使用原协议；新来源遇到不支持完成证明的旧目标，会在来源暂停前拒绝切换。原领域票据仍是权威。2.1.0 可读取旧数据，但新可选证明字段可能被旧版严格校验器拒绝；回退应先处理待恢复票据并保存交接副本，不承诺携带新票据的任意降级。

## 2.2.0 故障恢复与契约门禁（2026-10-05）

基线为 `2.1.0 / 9a92f1a`。本轮实施与验收状态以根目录 `PROJECT_STATUS.md` 为准；本节描述恢复行为及操作约定，本地标签不代表发布。

迁移栅栏覆盖启动、暂停、恢复、停止和内存快照入口。已封锁来源的普通停止直接安全终止，不能先发送 QMP `cont`；迁移失败回退的 `cont` 也在原实例锁内核对栅栏及原进程身份。继续迁移只经过原领域的进程和会话核验。来源在发起准备前持久记录 transfer 和请求摘要，丢失准备响应后用原 transfer 幂等取回同一目标及 session。切换后的重入核对原会话与来源 native 退出回执；两端正常关闭后可恢复目标冷启动，来源继续封锁。突然失联或强制结束而缺少原退出证据时，保留待核验状态，不推断已经退出。

HTTP 变更在进入业务前持久登记关联 ID 和执行准入标志；业务结果、响应结构校验、审计记录和响应发送分别保存。业务异常仍是主异常，审计结束失败作为附加诊断。有限响应在结束审计及结果保存后发送，之后失败不把已知业务成功改成业务失败。错误 DTO 和客户端保留 HTTP 状态、稳定错误码及关联 ID，不直接公开内部异常消息。写操作、网络失败及执行结果不明的请求均不自动重放；浏览器仅在本机共享凭证模式下，对首次 401 且 DTO 明确为 `outcome: failed / executed: false` 的无请求体 GET 刷新凭证并重试一次，还要求 `UNAUTHORIZED` 错误码与内外关联 ID 匹配；账户模式仍要求重新登录，生成 SDK 不自动重放请求。可查询的结果使用 `GET /api/operation-results/{correlationId}`，只允许原账户或原本机管理边界读取；未能建立账户身份的匿名请求不提供通用查询权。`executed` 表示业务入口已获准进入，`unknown` 不能解释为成功或失败；`delivery: sent` 只代表服务端已经结束写响应，不证明客户端收到。结果目录保留未确认记录，容量不足时在新业务开始前拒绝，不能为腾出空间丢弃未确认操作。

300 个 HTTP 操作统一声明无请求体、JSON、表单或二进制传输，以及实际 query/header 字段。生成 SDK 与类型客户端使用同一编码函数，SAML 回调按表单发送。终端、事件、日志和分享连接声明 JSON 消息方向与结构，桌面声明 RFB 二进制字节流；六个 WebSocket 契约均有明确方向、编码和尺寸界限。输入、响应与版本化服务契约由生成和兼容门禁共同约束。

恢复目录的读取与写入共用 8 MiB UTF-8 上限和 4096 条记录上限，写前按 `writeStore` 实际缩进格式计量。只保留最近 256 条已完成记录；未完成记录不会为腾出容量而被删除。新增或扩大记录超过容量时保留最后一个可重读文件，目录进入只读降级状态，仍允许 HTTP 启动和管理员诊断。

`GET /api/recoveries` 返回 `diagnostics`，包括容量、只读原因、无法读取的原领域和比较修订。管理面板提供“保留原文件并重建目录”：`POST /api/recoveries/rebuild` 携带刚读取的 `revision`，先完整发现原领域票据，再将原目录复制到同目录 `recovery-directory.json.quarantine-<UUID>`，核对副本一致后原子发布新索引。修订过期、领域发现失败、路径并非普通文件或存储写入失败都会拒绝发布。重建期间须保持其他控制器和外部文件写入者停止。磁盘满时应先恢复可写空间；不要删除迁移栅栏或清理票据来恢复目录。隔离副本保留供人工检查，不自动删除。

重建只处理索引，不调用原领域恢复动作，也不因记录缺失解除预算或来源迁移封锁。真正恢复继续匹配原票据、进程和会话；原域不能确认的记录保持待处理。来源或清理资源的存在与否都不能单独证明任务完成。

性能诊断在固定的 HTTP、任务、计算、资源四类来源下记录六个阶段，使用最近 60 秒、每序列最多 1024 个样本的窗口 p95/p99。`resource-lifetime` 表示已准入资源到释放的存活时间，`execution` 表示实际业务回调或计算任务的耗时；旧资源字段 `executionMs` 保留兼容，其含义仍是清理前持有资源的时间。阶段可能嵌套，不可相加推断 CPU 使用率。首屏发布门禁遍历 Vite 静态导入图并去重，主窗口和独立应用窗口分别要求静态 JavaScript 总量不超过 950000 字节；入口继续保留 450000 字节限制，动态按需模块不计入首屏。HTML 中的脚本、预载、样式和图标以及静态图中的字体等资源同时计入 1650000 字节的总量预算；这一预算按首次完整测量约 1.57 MB 留出约 5% 余量，不能视为已经缩减资源体积。
