# Windows 工作区集成

在系统设置 → 管理 Windows 集成中启用右键菜单，选择宿主编辑器，或为扩展名指定项目。需要启用 `projects`、`files`、`sync` 插件，并先在项目的目录同步页保存有效的 Windows ↔ Linux 映射。安装为当前 Windows 用户生效，不需要管理员权限。

资源管理器的目录、目录背景和文件菜单提供“在 Sakura 工作区中打开”（Windows 11 通常在“显示更多选项”）。选择的路径经运行中的本机控制服务验证后，打开浏览器并定位正确的实例、项目、目录或文件；暂停、停止的实例需要先启动。此操作不启动实例、不传输文件，文件需先同步到 Linux。同一目录映射到多个项目时，使用扩展名关联明确选择；嵌套目录优先选择最深的映射。

扩展名关联写入 `HKCU\Software\Classes` 的独立 ProgID 和 `OpenWithProgids`。在 Windows 的“打开方式”中选择 Sakura，或通过 Windows 设置默认应用。Sakura 不改写扩展名默认值或 `UserChoice`；只能打开指定项目同步根目录内的该类文件，目录外的文件会说明如何配置。这个流程遵循微软的 [Open With 注册说明](https://learn.microsoft.com/en-us/windows/win32/shell/how-to-include-an-application-on-the-open-with-dialog-box) 和 [快捷菜单文档](https://learn.microsoft.com/en-us/windows/win32/shell/context)。

文件面板提供“在资源管理器中打开”和“用宿主编辑器打开”。基于当前文件或目录映射到 Windows 副本；资源管理器选中文件，记事本打开文件，VS Code 用户/系统标准安装支持文件和目录。程序使用固定可执行路径及独立参数启动，不经过命令解释器；不会把未保存的浏览器草稿写入本机。编辑后通过项目同步传回 Linux。

菜单和关联默认关闭。移除按钮只清理本安装拥有且值仍匹配的注册值，保留其他程序的数据。如果写入中断，配置文件保留预写恢复记录，重启后点击“修复 Windows 注册”继续；其他程序修改了相同值时报告冲突，不覆盖。服务关闭或升级不会自动卸载注册项，移动安装目录后重新保存以更新打开助手路径；迁移数据目录会保留设置。安装路径不能含 `%` 或引号。助手随运行包发布，菜单依赖 Node.js 和 Sakura 服务仍位于配置时的位置。未启动服务会由浏览器显示连接失败；锁定时解锁后从资源管理器重试。

路径限制为本机普通文件与目录，拒绝 UNC/设备路径、备用数据流、符号链接、目录联接、硬链接和目录越界。每次操作重新读取映射并验证文件；宿主机拥有文件写入权限的其他进程仍可能在验证与操作之间改变文件，这不是抵抗恶意本机管理员的安全边界。应急锁定的实例和临时沙箱不提供映射。

所有接口使用同源、控制令牌和会话锁保护。`POST /api/native-integration` 提供 `configure`、`repair`、`receive`、`resolve` 和 `open` 操作，详见 OpenAPI。浏览器链接仅含短期随机请求号，不包含宿主路径或控制凭证；请求保存在内存、5 分钟到期，锁定、设置变化和重启使其失效。同时保留最多 64 个请求。读取同一请求可重试，但不自动重放打开程序或注册表写入。

可从 PowerShell 手动验证定位，不打开浏览器：

```powershell
node scripts/native-open.mjs --port 7337 --print-url -- 'D:\Projects\demo\README.txt'
```

该命令使用已启用的右键入口；指定 `--extension .txt` 则使用保存的扩展名关联。返回的链接需在 5 分钟内打开。
