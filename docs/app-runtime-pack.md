# 应用运行包

## 适用范围

`app-runtime` 把本地运行文件安装到专用 VM。每个应用固定一个 VM 和一个项目。应用文件、配置修订、持久数据、运行记录和备份分别保存。启用完整包会同时启用 9 个插件及其必需依赖。

| 插件            | 直接操作                                               |
| --------------- | ------------------------------------------------------ |
| `app-targets`   | 创建或接管目标、核验身份、审阅有限出站、清理未登记目标 |
| `app-packages`  | 分块上传、核验摘要、封存启动定义、归档制品             |
| `app-config`    | 保存环境变量、绑定秘密引用版本、验证修订               |
| `app-data`      | 创建数据目录、容量预检、迁移、审阅删除                 |
| `app-observe`   | 持续健康探测、查看当前日志、保存人工记录               |
| `app-routes`    | 独立回环入口、按修订切换、撤销入口                     |
| `app-recovery`  | 关闭 VM 冷备、验证备份、恢复新实例、交接目标           |
| `app-deploy`    | 预览不可变计划、批准、执行、取消、核销                 |
| `app-workbench` | 汇总上述记录和表单                                     |

包可独立使用，无需启用 `foundry`、`delivery` 或 `data-lab`。从“运行目标”选择本体登记的固定摘要镜像，可复用镜像构建包产物。应用包不把任意 URL 当成可信镜像来源。

启用可选的 `delivery-releases` 与 `delivery-artifacts` 后，可按来源 VM、项目、版本标识和核心摘要导入。复制前后核验当前规则、运行成功、清理完成及来源信任。实际文件分块复制到应用库，保留来源回执。后续部署再次检查撤回与吊销状态；来源插件停用时，此类制品暂停部署，本地审阅制品仍可使用。

首版用于单宿主专用 VM。升级有停止窗口。固定入口保留原地址，窗口内拒绝流量。持久 VM 不受临时沙箱到期清理影响。应用停用后保留磁盘和数据；入口、进程和临时秘密文件须关闭或核销。

## 安装第一个应用

1. 在插件管理中启用 `app-runtime`，打开导航中的“应用运行”页面。没有 VM 时也可进入；已有 VM 的开发页仍保留应用工作台。所有写操作要求宿主所有者会话。
2. 在“运行目标”选择已登记镜像，填写内存、CPU 对应计划和磁盘预算，审阅后创建目标。创建失败的 VM 清理结果仍可按回执查看。
3. 在“安装制品”上传实际文件，选择静态站点、持续服务或一次性命令。静态站点必须包含指定目录内的 `index.html`。持续服务填写启动命令、端口及健康路径。
4. 在“应用配置”保存环境变量和秘密引用。秘密引用填写 `ENV_KEY=引用名`，值由私密配置插件保存。
5. 在“持久数据”创建目录。应用通过 `APP_DATA_DIR/<目录名>` 访问。容量限制是执行前的实际占用预检，不是客户机磁盘硬配额。
6. 在“安装与变更”选择制品和配置，生成计划。核对目标身份、摘要、数据变化和停机影响，批准后执行。
7. 持续服务须通过实际 HTTP 或命令探针及 60 秒稳定窗口。任务成功后从“应用入口”打开地址。

也可先点击“新应用标识”，上传并封存本地制品，再创建运行目标。创建时会沿用这个尚未登记目标的应用标识，保留已上传制品的归属。接管 VM 或导入交付版本时，须填写真实来源标识；页面不会补造 VM。

运行镜像需要 Python 3、tmux、C 编译器、libc 与 Linux 头文件、iproute2、OpenSSL、shadow 账户工具和 nftables。Alpine 可在镜像构建阶段安装 `python3 tmux gcc musl-dev linux-headers iproute2 openssl shadow nftables`。有限出站另外需要 `iptables` 与 `ip6tables`。应用目标默认隔离，安装时不会临时联网补装缺失依赖。

接管只接受已运行、持久隔离的单项目专用实例。项目须使用 `none` 模板，且没有服务、仓库、准备命令、运行时或环境配置。已有应用占用、目录冲突或多项目实例会拒绝接管。接管后，在项目页修改目录或上述配置会使应用操作拒绝执行。

## 配置与变更

配置修订保存公开变量和秘密引用的强版本。保存后修改秘密值，会使引用旧版本的计划失效。重新保存配置并生成计划即可使用新版本。服务执行时才解析秘密，计划、制品和检查点元数据不保存秘密明文。

计划绑定 VM 创建身份、磁盘身份、启动身份、目标修订、制品摘要、配置摘要、数据目录版本及入口修订。计划有效期为 10 分钟，批准后只能消费一次。目标或数据发生变化时，重新预览并批准。

升级先停止旧进程，再写入新的独立版本目录。健康检查失败时，只有数据尚未迁移且旧配置仍可验证，才会重新启动旧版本并恢复原入口。应用健康与资源清理分别记录。`cleanup=unknown` 需要核销，不能据此宣称旧进程或租约已清理。

应用运行期间每 30 秒采样一次健康状态。变更租约或启动交接期间暂停采样；无法核验目标时记录未知。日志按请求读取，不作为健康证据保存。

数据迁移要求已验证的冷备。迁移命令使用项目账户执行，验证命令成功后才更新数据模式版本。发生写入后，流量回退不会撤销数据变化；旧代码与当前数据模式不兼容时，必须恢复检查点到新目标。

迁移失败并留下租约时，先在冷备页恢复独立副本，再在失败操作中选择检查点，执行“核销原进程并交接恢复副本”。系统核验原磁盘、停止原进程并转移变更租约，恢复新目标的数据目录记录。原数据保留在停止的原 VM，恢复结果需重新安装和健康检查。

“停止”保留制品、版本目录、配置和数据。“卸载”移除当前安装目录，并保留数据。删除持久数据需另行生成短时删除计划并审阅；应用运行或存在变更租约时会拒绝删除。

上传中断后，可先预览清理范围，再清理未完成上传和未引用文件。已封存制品及历史版本引用的文件会保留。

## 网络授权

默认 VM 出站隔离。有限出站按 IPv4 字面地址、TCP/UDP 和端口授权。域名和 IPv6 会拒绝；访问 DNS 需要明确授权 DNS 服务器的 IPv4 和端口。

先填写目标及到期时间生成网络计划，再审阅固定摘要并授权。有效期限为 10 秒到 24 小时。规则先安装，再接通网络；内核时间规则阻断到期后的连接。观察动作读取实际规则和隔离状态，撤回动作关闭授权。重启后保持隔离，不自动重放旧授权。

普通 NAT 开关不构成有限联网授权。缺少过滤工具、客户机时钟偏差超过 3 秒，或不能核验执行身份时，网络计划会拒绝执行。

## 冷备与恢复

冷备依次停止应用、撤销流量、清除临时秘密文件、记录关机意图、关闭 VM、生成备份并校验完整性，最后重启 VM。原 VM 创建身份及磁盘身份须保持不变。新启动身份通过预登记回执交接，并换发执行租约。没有登记的重启视为漂移。

单独点击冷备后，VM 重启但应用保持停止。可生成安装或升级计划恢复服务。部署计划内的冷备由同一变更流程接续安装和健康验收。

定时策略按 1～168 小时执行。仅当应用已停止、VM 已运行且没有变更租约时触发。业务运行中跳过；失败后暂停策略，保留原记录待核销。控制器重启后加载持久策略，错过的周期最多补做一次。

恢复先创建新的停止实例，并固化持久隔离。确认副本后点击“交接恢复副本”，停止旧目标、核验恢复目录，再将应用固定到新 VM。原磁盘保留。重新选择有效配置并生成安装计划，通过健康检查后才开放流量。原 VM 的秘密引用版本不能直接授权新 VM；存在秘密引用时，先在新目标配置秘密并保存新配置修订。

控制器中断后，正在执行的操作标记为未知。先检查检查点、目标、入口和操作记录，再执行核销。迁移结果未知时不会自动解锁，也不会把未确认的数据状态当成成功。

核销必须持有原操作标识和计划摘要匹配的租约。已成功的操作，以及已释放租约的失败操作，都不能再次关闭当前入口、停止项目或修改安装记录。同一 VM 启动周期内升级到新版本，也受此限制保护。

普通宿主或 VM 重启后，先启动原 VM，再打开“普通重启后重新绑定”。预览会固定原 VM 创建身份、磁盘和新启动身份，批准有效期为 5 分钟。确认后关闭旧入口、停止项目并清除临时秘密文件，然后提交新基线。应用保持停止；重新预览部署并通过健康检查后才能开放入口。旧计划和旧操作不能作用于新基线。

重新绑定拒绝任何未核销的部署租约、迁移或冷备转换。执行中断时保留本次重新绑定租约，可对同一计划再次执行清理；不会借此解锁其他操作。审阅后再次重启的目标会拒绝继续，需要核对原记录。

## CLI 与 HTTP

CLI 使用编译后随运行包提供的受管网络入口。源码目录先构建；帮助命令无需构建。令牌建议通过 `SAKURA_TOKEN` 环境变量传入。

```powershell
node scripts/app-runtime.mjs help
node scripts/app-runtime.mjs view --app <应用UUID>
node scripts/app-runtime.mjs upload --app <应用UUID> --directory ./site --file ./startup.json --name site-v1 --reviewed
node scripts/app-runtime.mjs preview --app <应用UUID> --file ./plan.json
node scripts/app-runtime.mjs approve --app <应用UUID> --id <计划UUID> --digest <计划摘要> --reviewed
node scripts/app-runtime.mjs apply --app <应用UUID> --id <计划UUID>
node scripts/app-runtime.mjs status --app <应用UUID> --id <操作UUID>
```

静态站点的 `startup.json`：

```json
{ "kind": "static", "directory": "public", "port": 8080, "healthPath": "/", "timeoutSeconds": 60 }
```

目录包含 `public/index.html`。计划文件填写 `{"kind":"install","packageId":"…","configId":"…","checkpoint":false}`。CLI 的 `act --section <领域> --file <动作.json>` 对应领域 API 的公开动作。

每个插件分别提供 `GET/POST /api/app-<领域>?appId=<UUID>`，响应使用 `AppView`。例如 `GET /api/app-workbench` 汇总记录，`POST /api/app-config` 保存配置修订。请求、响应和领域类型分别在 `shared/contracts/app-http.ts` 与 `shared/contracts/app-runtime.ts` 定义。

内部租约、启动交接、迁移、探针和入口切换动作不开放给 HTTP 客户端。这些操作只能由拥有明确依赖的领域服务在对应流程中调用。

## 验证范围

已在 Windows 宿主与 Alpine x86_64 客户机完成实际安装、60 秒健康验收、原入口回退、关机冷备、独立实例恢复、迁移失败恢复、定时冷备和有限出站验证。普通 VM 重启后的重新绑定、旧操作重放隔离和并发核销也已通过实机验证。CLI 分块上传、配置版本冲突、来源信任撤回和上传清理已通过专项验证。其他客户机系统与宿主异常断电后的恢复尚未验证。
