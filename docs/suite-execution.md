# 固定工具执行底座

## 服务与平台

2.8.0 为五类工具提供独立服务：`BrowserSessionsV1`、`DatabaseRehearsalV1`、`EventSessionsV1`、`MediaTasksV1` 和 `LearningToolSessionsV1`。本体固定消费者、输入契约、worker、依赖探针及资源档案。调用方不能传入工具名、命令、脚本或替换探针。

首版受管宿主执行只支持通过本机探针的 Windows 与 x86_64 客户机。宿主原生监管不可用时，服务拒绝执行并返回缺口。镜像必须预先准备依赖；执行不会下载依赖，也不会获得外网、宿主共享目录或端口映射。

浏览器档案使用真实 Chromium，数据库档案固定 PostgreSQL 17.11，事件档案使用 SQLite WAL 与独立消费者，媒体档案执行固定 FFmpeg 操作，学习档案执行固定文件操作和临时本机 HTTP 请求。各领域只声明自己的操作，由对应服务解析。

## 批准与运行

`preview` 固定 actor、消费者实例与代次、空间、镜像、工具摘要、输入摘要、期限和预算。输入保存为不可覆盖的本体文件。预览有效期为 5 分钟，提交前再次验证原声明。

`start` 先持久消费批准，再要求领域提交原意图，随后创建独立虚拟机。相同批准返回同一会话，不重复提交领域意图。回执记录原虚拟机创建时间、宿主 QEMU 的 PID 与 FILETIME、客户机 boot ID、依赖探针，以及固定 worker 的 PID、启动时钟和 UID/GID 65534。

领域授权、原镜像提供者和虚拟机提供者在执行期间持续受检。客户机监管器每 750 ms 获得一次短租约，租约 3 秒后失效。授权撤回、取消或期限到达时，监管器停止原 worker 进程组。本机独立监管程序持有原 QEMU 的准确身份，控制器退出或硬截止到达后停止原进程。

回执期限包含最多 180 秒启动预算和本次工具期限。客户机实际工具期限从准备完成后计算，并受回执总期限约束。控制器冻结时，客户机短租约先失效；宿主监管仍受原回执硬截止约束。

## 有界文件运输

公共机器接口继续保持原有 128 KiB stdin 和 1 MiB 输出限额。固定工具使用本体私有路径 `/var/lib/sakura-suite/<session UUID>/`，按 64 KiB 分块写入固定的 `worker.py`、`guardian.py` 和 `input.json`。

每块检查当前授权、原普通文件身份、偏移和长度，完成后检查完整摘要。工具与输入文件由 root 持有，非 root worker 只从标准输入接收内容。调用方不能选择路径或文件名。

监管器将完整结果写入 root 持有的只读 `output.json`，标准输出只返回一个小回执。本体分块读取时核对 inode、修改时间、大小、权限及完整摘要，避免原 stdout 限额截断结果。运输帧上限为 8 MiB，各档案可设置更低限制；元数据记录仍使用独立的结构预算。

## 原身份清理与恢复

普通 `ImageAssetsV1` 权限不变。本体装配额外提供一个窄清理工厂，只有固定服务可以使用。工厂验证原 profile、固定消费者、actor、代次、原会话账本、镜像声明和原提供者对象，返回零参数的原资源清理闭包。

闭包再次核对原 owner、VM token、VM ID 和创建时间，只能停止、删除并释放既有资源。业务授权已撤销时仍可回收原资源，但无法创建新资源、恢复普通业务权限或处理其他会话。

`inspect` 读取当前历史；`cancel` 停止原会话；`reconcile` 只核销原资源。控制器重启把未结束记录标为 `interrupted`，清理保留 `unknown`，等待显式核销。新消费者代次可以读取同一主体的原历史，不能重新批准旧执行。无法确认原进程、VM 或磁盘已消失时，额度继续保留。

`release` 只释放已经确认清理的原输入和输出材料。历史保留摘要，后续材料读取明确拒绝。尚未提交的预览通过 `discardPreview` 释放。启动及下一次工具查询、预览还会清扫已过期且从未消费的原输入，避免领域写计划失败或崩溃遗留材料。文件身份不明时保留额度；活动运行的材料不能提前释放。

## 容量账本

五个执行域与共享镜像域使用 `DATA/suite-execution/<profile>/state.json`。所有准入都进入同一个 `SuiteCapacity` 串行入口，按实际保留量和预留量合并判断。

共享镜像按实际摘要计费一次。每台虚拟机按 `max(8 GiB, ceil(virtualBytes / GiB) × GiB)` 预留磁盘，另计输入、输出和临时材料。只有原资源消失得到确认后才释放额度；镜像删除也必须经过原缓存清单确认。

默认宿主总预算保持 8 GiB，其中 256 MiB 用于恢复。默认额度不足以容纳一台至少 8 GiB 的工具 VM 及镜像，执行会明确拒绝。管理员应在准备阶段设置足够的 `SAKURA_SUITE_CAPACITY_BYTES`，产品不会自动提高预算。
