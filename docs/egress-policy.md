# 客户机出站目标白名单

在“能力中心 → 扩展能力 → 客户机出站目标白名单”选择 `egress-policy`。`status` 读取现有规则，`apply` 设置 `allowedDestinations`，`clear` 撤销。目标是 IPv4 地址或 CIDR 网段，例如 `10.0.2.2/32`、`192.0.2.0/24`；最多 64 个。需要运行中的 Linux 客户机具备 `iptables`、`ip6tables`、连接跟踪和管理员网络权限。

规则挂在所选网卡的 OUTPUT 链，只允许新发往白名单 IPv4 目标的流量；新建 IPv6 出站连接会被拒绝，避免绕过 IPv4 白名单。已建立连接、相关流量和 DHCP 更新可继续；这也避免中断 Sakura 的现有 SSH 管理连接。需要通过 DNS 域名访问时，请把客户机使用的 DNS 服务器地址也加入白名单。地址变化后需要更新 CIDR；这里不按域名做动态解析。

每次应用先建立新的 IPv4/IPv6 链，双栈都就绪后再接入 OUTPUT，最后清理旧链。构建或接入失败会回滚新链；清除只移除 Sakura 标记的链，不修改客户机其他防火墙规则。当前连接可能在关闭前继续通信。规则由客户机内核管理，客户机管理员可自行修改；它不构成宿主侧网络隔离。Linux 防火墙规则在客户机重启后消失，需再次应用。真实 QEMU 测试覆盖允许与拒绝、在线替换、清除及恢复普通联网。
