# 项目交付工作台

`delivery` 是 2.5.0 的完整交付插件包。它将源码和定义固定为输入快照，在新 VM 中执行，再把制品、报告、规则判定、预览和本地版本关联起来。交付包可带源码附件，也可仅交接可运行制品；接收端的验证不会冒充源码重建。

## 启用与组成

在插件管理中启用“项目交付工作台”整合包，按提示重新加载插件。默认选择仍为空；AI 修复会话和私密配置不自动启用。包内直接包含下列 8 个插件及命令面板，其他依赖由解析器去重。

| 插件 | 职责 |
| --- | --- |
| `delivery-workbench` | 定义、模板、复制、归档和完整流程界面 |
| `delivery-inputs` | 固定 Git 提交或已审阅草稿，记录环境和镜像摘要 |
| `delivery-artifacts` | 分块传输、不可变文件清单、引用保留和清理 |
| `delivery-runners` | 新 VM 矩阵、DAG 步骤、取消和原身份回收 |
| `delivery-reports` | 测试、覆盖率、诊断与基准报告 |
| `delivery-gates` | 不可变规则修订和候选判定 |
| `delivery-previews` | 实际制品预览、独立入口、健康及绝对到期 |
| `delivery-releases` | 本地版本、通道、签名信任和离线交接 |

首版所有交付 API 仅供宿主所有者使用。档案查询使用显式 `vmId`、`projectId`；读取制品不要求运行实例存活。源码捕获和新执行仍核对实际项目身份。停用插件保留元数据；重启后未确认的执行标为中断或待核销，不自动重放。

## 准备运行环境

源项目须在运行的 Linux 实例中，并具有 Git、Python 3。提交模式读取固定 Git 对象，不检出或改写用户分支。草稿捕获显示实际文件和改动，确认后复核内容，变化会拒绝旧计划。链接、特殊文件、未物化 LFS 指针及子模块明确拒绝。

执行实例另行创建。断网镜像须预装项目用户隔离所需工具和项目依赖；缺少工具时返回明确就绪错误。需要联网安装时，必须在定义中显式选择 NAT，再捕获新输入。不会把断网配置临时改为联网。声明的 Node、Python 和基础镜像摘要会与实际环境核对；未核实的环境不能冒充验证通过。

模板包含静态站点、Node、Python 命令行和自定义流程。模板命令需要按项目调整，例如 Node 模板要求项目自身输出 `junit.xml`。语法检查与文件存在检查不等于测试；静态和 Python 示例未声明实际测试。

## 完成一次交付

1. 在“交付定义”选择模板，设置源码引用、命令、依赖、输出、报告、矩阵和启动方式。保存定义会检查修订冲突；复制生成新身份，归档保留记录。
2. 在“输入快照”预览真实文件，审阅后固定。快照记录定义、实际源码字节及基础镜像摘要。之后编辑定义不会改变既有快照。
3. 在“隔离执行”选择快照，审阅命令和外网权限后启动。每个矩阵单元使用新 VM，步骤在同一单元内执行。日志、退出码、实际环境和回收结果分别展示。
4. 运行结束后，在“本地版本”选择真实输出清单，创建候选。候选摘要不包含门禁判定，因而后续添加证据不会改变制品身份。
5. 在“验证报告”选择同一候选、运行及报告清单，解析报告。缺失、空测试、格式错误、截断和未知执行不会显示为通过。HTML 只作为文件下载。
6. 在“交付规则”保存规则修订，选择同一候选的本机证据并执行核对。构建规则使用 `build`；接收端使用 `import-acceptance`。默认要求真实测试和环境证据；不适用的规则须明确调整并留下新修订。
7. 按需启动候选预览，再刷新健康证据。预览运行已经封存的制品，独立随机 `*.localhost` 入口不转发管理端 Cookie、Authorization 等凭据。入口有效期不会因暂停或重启延长。
8. 选择候选、有效判定和命名空间，登记语义版本。候选、正式通道按修订条件更新；正式通道拒绝豁免判定和不符合来源要求的版本。回退只改变通道指向，不回滚用户业务数据。
9. 导出 `.sakura-delivery.zip`，按需包含源码和签名。内容核心摘要与 ZIP 文件摘要分别记录；同一命名空间、版本不能绑定不同核心内容。

工作台每个阶段都有完整记录。单独启用某个插件时，可用候选描述传递已经封存的身份；服务端会重新核对摘要和实际引用，不信任客户端自报的通过状态。

启用可选的 AI 修复插件后，失败报告可打开修复草稿。先填写源项目中的目标文件，界面将文件和报告摘要带入修复会话。打开草稿不会发送给模型；仍须预览发送内容、确认生成、审阅补丁并隔离验证。应用后重新捕获输入和创建候选，旧证据保持不变。

## 离线交接与签名

导入先验证 ZIP 目录、路径、大小、CRC 和 SHA-256，再检查候选、报告和交付核心。外部候选、运行和判定 ID 只保留为来源信息，导入记录和制品使用新的本地身份。导入不会自动执行。

接收时填写来源命名空间并审阅信任状态。未签名或未知发布者内容须明确允许；无效签名直接拒绝。接收后对原制品执行 `validate-artifact`，使用新 VM 和本机结果评估 `import-acceptance` 规则。没有源码附件时不声称已重建源码；要求本地测试的规则仍须提供对应证据。

签名仅用于 `sakura-delivery`，与应用更新签名无关。启用可选的私密配置插件，在源实例保存一个 JSON 私密值，例如：

```json
{
  "keyId": "project-release",
  "publisher": "项目维护者",
  "privateKey": "-----BEGIN PRIVATE KEY-----\n……\n-----END PRIVATE KEY-----"
}
```

私密引用名称须与 `keyId` 一致。在交付发布者列表登记对应 Ed25519 公钥，再在导出界面填写引用名称。私钥只在服务端用于签名，不进入包、报告、元数据和响应。撤销公钥后，后续接收、登记与通道更新重新检查信任。

## 恢复、保留与边界

构建执行结束与清理完成是两项独立证据。取消会等待受管任务收尾；身份冲突、控制器重启或不确定结果必须先核销原实例。恢复只处理记录中的原身份，不自动重放未知外部写入。

预览具有宿主入口到期关闭和客户机到期管理。客户机请求停止不等于宿主已经证明资源回收；若宿主中断，记录保持待核销。已确认健康但仍活动的预览不要求提前清理，停止后的清理失败会阻断相关交付。

制品不随构建 VM 或普通任务历史删除。输入、候选、报告、预览和版本保留自己的引用。清理先显示具体对象、保护引用及未完成上传，再凭短时计划执行并复核；版本归档不会隐式解除制品保护。

当前范围是本机 VM 矩阵和离线交接，不包含云部署、远程集群或用户业务数据回滚。单个制品文件和完整交付包最多 1 GiB，输入默认最多 100 MiB / 10,000 个文件；报告解析默认最多 2 MiB。交付 ZIP 使用逐块校验的 STORE 格式，不支持压缩条目或 ZIP64。浏览器支持文件系统保存时直接分块落盘；其他浏览器对下载使用 64 MiB 内存上限，大文件通过 [交付 CLI](delivery-cli.md) 保存。下载具有 15 分钟绝对保护租约，超时重新发起。

接口模式由 [HTTP 请求契约](http-request-contracts.md) 和生成的 API 文档维护。总体设计见 [插件包设计](delivery-pack-design.md)，实际验收结论见 [项目状态](../PROJECT_STATUS.md)。

页面关闭或权限撤销后，客户端可能无法提交下载租约关闭请求。此时保护保留到原 15 分钟期限，随后清理计划可重新核对；不会为清理而绕过已撤销权限。
