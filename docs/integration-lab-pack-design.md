# 接口集成验证插件包设计

## 1. 版本、读者与交付结果

设计版本：**2.0.0**。核对日期：2026-10-23。应用版本保持 **2.6.0**，基线提交 `86f589a`，宿主插件 API 为 `5`。本包运行实现状态为**待开始**。

本文面向插件实现者、接口开发者和验收人员，定义 `integration-lab` 包及其 11 个插件。用户可以固定接口契约、环境和测试数据，建立受管模拟服务，运行请求场景，检查响应语义，比较有限负载结果，最后交接可离线核验的证据包。

本文件属于[第二批插件包设计](plugin-pack-expansion-design.md)。文中的新插件、服务、页面、HTTP 路径和命令均为拟议接口，当前版本不能调用。当前运行目录仍为 69 个插件和 13 个整合包；本次设计不改插件选择、生成契约和应用版本。

## 2. 使用范围与产品边界

首版面向本机开发者自有的接口测试环境。完整流程涵盖模板、契约、数据、模拟、功能请求、断言、有限负载、报告和离线交换。首次打开页面不需要虚拟机（VM），可以编辑、检查和交换定义。用户明确执行后，才创建专用测试 VM；该 VM 内同时运行固定请求工具和模拟服务。

| 现有能力 | 继续由现有插件负责 | 本包增加的内容 |
| --- | --- | --- |
| `delivery` | 固定源码、通用构建、报告导入、交付门禁与版本签名 | 精确请求意图、接口语义、模拟状态、请求级副作用记录和可比性判定 |
| `app-runtime` | 长期应用目标、部署、入口、观测与恢复 | 对明确测试目标运行一次受限场景；读取目标身份不授予压测权限 |
| `data-lab` | 数据集、变换、质量、Notebook 和实验谱系 | 请求输入及响应契约；测试数据不会自动变成数据实验的已验证输入 |
| `network` | 端口、代理、配置与网络诊断 | 每次运行的目的地址、方法、请求数和截止时间；底层继续复用本体网络统管 |
| `code-checks`、`pipelines` | 开发诊断和项目任务编排 | 独立持久化的接口场景、断言证据和未知副作用处理 |

首版请求协议限定为 HTTP/1.1 的 HTTP 和 HTTPS。WebSocket、gRPC、浏览器脚本、任意 JavaScript 钩子、宿主脚本和自动发现接口均不在首版执行范围。接口契约使用包内完整定义的 `sakura-http-contract/1`；OpenAPI 导入适配另行设计，不能将未识别字段静默丢弃后标为兼容。

负载测试仅允许本次专用 VM 内由本包创建的模拟服务。外部私网测试端点只支持功能验证。首版不向公共互联网、真实生产目标或用户填写的任意地址开放压测。启用本包只加载页面和服务，不下载镜像、不安装工具、不发请求、不启动任务。

## 3. 插件组成与依赖

每个插件拥有独立持久对象、修订和操作授权。表内服务全部为拟议 V1；表内系统能力未列为插件依赖。直接调用服务必须声明直接依赖，不能借工作台的依赖间接取得句柄。

| 插件 ID | 责任与独立持久对象 | 拟议公共服务 | 必需插件依赖 | 可选插件依赖 |
| --- | --- | --- | --- | --- |
| `integration-specs` | 工作空间登记与 owner 授权、契约文档、不可变契约修订、操作标识、兼容差异记录 | `IntegrationSpecsV1` | 无 | 无 |
| `integration-environments` | 测试环境修订、目标登记、凭据槽位、使用范围确认与撤销记录 | `IntegrationEnvironmentsV1` | `integration-specs`、`secrets` | `app-targets` |
| `integration-fixtures` | 不可变测试数据集、生成种子、脱敏规则、数据快照和引用账本 | `IntegrationFixturesV1` | `integration-specs` | 无 |
| `integration-mocks` | 模拟规则修订、初始状态、有限状态转换、故障配置和编译产物 | `IntegrationMocksV1` | `integration-specs`、`integration-fixtures` | 无 |
| `integration-scenarios` | 请求场景修订、分支图、数据绑定、提取变量和场景编译记录 | `IntegrationScenariosV1` | `integration-specs`、`integration-fixtures`、`integration-environments` | 无 |
| `integration-assertions` | 断言集修订、断言执行记录、证据定位和不适用原因 | `IntegrationAssertionsV1` | `integration-specs`、`integration-scenarios` | 无 |
| `integration-runners` | 运行计划、审批回执、专用 VM 与工具会话回执、请求意图和收尾记录 | `IntegrationRunnersV1` | `integration-specs`、`integration-scenarios`、`integration-mocks`、`integration-environments`、`integration-fixtures`、`integration-assertions`、`projects` | 无 |
| `integration-load` | 负载配置修订、负载批准记录、调度账本、采样窗口与可比性记录 | `IntegrationLoadV1` | `integration-specs`、`integration-runners`、`integration-scenarios`、`integration-environments` | 无 |
| `integration-reports` | 封存报告、证据索引、比较记录、保留策略与删除计划 | `IntegrationReportsV1` | `integration-specs`、`integration-assertions`、`integration-load`、`integration-runners` | 无 |
| `integration-exchange` | 离线交换清单、分块传输、隔离导入、审阅和本地重绑定记录 | `IntegrationExchangeV1` | `integration-specs`、`integration-environments`、`integration-fixtures`、`integration-mocks`、`integration-scenarios`、`integration-assertions`、`integration-reports` | 无 |
| `integration-workbench` | 引导状态、命名模板、组合操作记录和最近查看位置 | `IntegrationWorkbenchV1` | `integration-specs`、`integration-environments`、`integration-fixtures`、`integration-mocks`、`integration-scenarios`、`integration-runners`、`integration-assertions`、`integration-load`、`integration-reports`、`integration-exchange` | 无 |

`integration-mocks` 管理规则，活动模拟进程统一归 `integration-runners` 所有。独立启动模拟会话也通过运行计划执行；停止操作需要原会话回执。这样模拟规则可单独维护，运行器和模拟插件也不会形成循环依赖。

报告封存时，由运行器提供实际使用的模拟规则和场景快照。交换插件从报告取得该依赖闭包。单独导出尚未运行的定义时，交换插件按其直接依赖收集固定修订。接受导入时仍逐项调用原领域服务，不能直接写其他插件的元数据。

本包只需额外启用 `projects` 和 `secrets` 两个已有插件，不要求启用整个交付、镜像工坊、应用运行或数据实验包。`app-targets` 缺席时隐藏目标选择适配；手工登记私网测试端点和本包模拟流程仍可使用。配置变化沿用现有“保存选择后重启服务”的流程。

## 4. 对象、内容与编译规则

### 4.1 工作空间与内容修订

工作空间具有 `workspaceId`、真实宿主 owner 身份和修订，由 `integration-specs` 登记，独立于 VM 存在。首版只对当前宿主 owner 开放，不新增自建多账户权限体系。工作台只组合页面和操作，不拥有核心授权。契约、环境、数据、模拟、场景和断言采用“可编辑草稿 → 校验 → 不可变修订 → 归档”的状态；执行只引用不可变修订。

拟议 `IntegrationSpecsV1.createWorkspace()` 从宿主授权上下文捕获 owner，不能接受客户端指定所有者。`assertWorkspace({ workspaceId, expectedRevision? })` 核对当前 owner、登记状态及原修订，返回只读范围回执。其他 10 个插件都直接依赖 specs，读写时核对范围，并校验各输入引用属于同一工作空间；对象 ID 或内容摘要相同不代替授权。回执必须保留原插件消费者和请求身份，不可跨请求重用。

specs 同时拥有本包容量账本，提供拟议内部操作 `reserveCapacity`、`commitCapacity` 和 `releaseCapacity`。各领域在写入前按对象数、修订数和峰值字节预留，以原分配回执确认实际占用或释放；不能只统计自己的目录。账本不代理其他领域的业务写入，也不把临时文件排除在总量之外。

修订包含对象标识、父修订、格式版本、内容摘要、创建时间和创建账户。更新请求携带 `expectedRevision`，冲突返回 `REVISION_CONFLICT`。两个页面不能互相覆盖；归档也不能删除运行、报告或交换清单仍在引用的内容。

`integration-specs` 和 `integration-fixtures` 使用自身的受管元数据与内容目录。它们不调用 `delivery-artifacts` 服务。可复用现有分块存储、摘要、路径检查和原子发布的实现模式，但必须提供真实工作空间授权。现有 `ArtifactStore` 接受 VM/项目作用域，不能捏造 VM ID 来冒充兼容；实施时应提取受管内部存储辅助层，或在本领域实现等效的作用域适配。

### 4.2 首版契约格式

`sakura-http-contract/1` 使用严格 JSON。操作具有稳定的 `operationId`、HTTP 方法、路径模板、路径及查询参数、请求体模式、预期状态码、响应体模式和副作用声明。模式支持对象、数组、字符串、布尔值、整数、数字、空值、枚举、必填字段、长度或数值范围，以及显式的额外属性策略。

引用只能指向同一冻结文档内的具名模式。拒绝远程引用、递归引用、任意表达式、自定义代码和未识别字段。兼容比较返回逐操作的 `compatible`、`breaking` 或 `undetermined`，记录比较方向和规则版本；不能把没有覆盖到的协议语义标为兼容。

例如，旧客户端需要的响应字段被删除，按已有客户端消费新服务的方向判为破坏；新增可选响应字段是否允许，取决于旧响应模式的额外属性策略。未知媒体类型、模式范围外的约束或不一致的操作匹配返回 `undetermined`，由用户修订契约后重新比较。

### 4.3 数据、模拟与场景

测试数据支持用户选择的 JSON 和 UTF-8 CSV 文件，以及固定种子的包内生成器。生成器只产生虚构字段，不采集浏览器、项目环境变量或数据库。解析后固定类型和内容摘要；用户修改源文件不影响已封存数据。

模拟规则按方法和完整路径模板匹配，响应来自常量或已固定数据。状态转换只能更新本次会话内的有限状态值，禁止读取宿主文件、执行代码或访问其他 URL。故障配置支持固定延迟、指定状态码、截断响应和断开连接；规则的选择顺序及随机种子写入报告。

场景使用有向无环图。每个节点包含操作引用、绑定参数、输入行、输出槽位和依赖条件。断言集引用固定场景中的节点，由运行器在预览时合并校验。JSON Pointer 提取变量只用于后续路径参数、查询值或声明的请求体字段，不能改目标主机、端口、凭据槽位或请求方法。每项绑定必须声明来源节点及字段、允许写入的位置、类型、长度和数值范围或枚举；预览固定这些规则的摘要，不预言尚未返回的值。固定次数的数据驱动展开由编译器展开为有界节点；首版不执行动态循环。

同一会话默认串行请求。图式并发只允许编译器证明变量和模拟状态没有写冲突的分支；否则用户必须指定先后顺序。写请求必须有明确副作用分类，缺失分类按写请求处理。方法名和服务器返回的幂等键都不能单独证明重试安全。

断言支持状态码、选定响应头、类型及范围、JSON Pointer 值、集合成员、跨步骤值关系和单次时限。断言不得包含正则表达式或任意脚本。断言结果为 `satisfied`、`violated` 或 `unevaluated`，每项携带证据字节范围、规则修订和未求值原因。

断言服务接收运行器提交的有界证据快照，核对调用者、运行身份和已冻结断言修订后求值。这个内部动作不开放 HTTP，客户端不能直接提交“通过”或自造运行证据。断言服务不反向调用运行器；运行器负责固定证据，报告服务同时读取原运行记录和断言记录交叉核对。

## 5. 用户流程与首次使用

顶层页面拟定为 `/integration-lab`。页面按“工作空间 → 契约与数据 → 场景 → 运行 → 报告与交接”组织；环境、模拟和有限负载作为对应步骤的专门编辑页。每一步显示缺失输入、实际状态和可执行动作。页面显示任务已提交时，不能同时显示验证通过。

| 步骤 | 用户动作 | 产生的结果 | 首次使用缺项处理 |
| --- | --- | --- | --- |
| 创建工作空间 | 选择“订单接口演练”模板 | 原生契约、虚构数据、初始模拟、串行场景和断言草稿 | 无 VM 也能创建，模板不会发请求 |
| 固定输入 | 检查差异并封存各修订 | 输入清单及摘要 | 缺失字段直接定位；未支持字段不被忽略 |
| 准备执行环境 | 选择已导入的准备好镜像；确认专用 VM 配额 | 镜像引用、工具校验和资源计划 | 无镜像时停在可继续编辑的准备页；显式选择本地导入或独立下载准备步骤 |
| 预览运行 | 查看目标、请求、写操作、凭据槽位、时限和清理范围 | 一次性计划及摘要 | 工具不全、环境撤销或容量不足时拒绝执行 |
| 执行 | 批准计划后创建隔离 VM | 本次模拟会话和功能请求运行 | 默认只连接 VM 内模拟端口，无外部出站 |
| 检查与修订 | 查看逐步断言；修改模拟故障后重跑 | 不同修订的两份独立证据 | 原运行不被覆盖，失败也能生成报告 |
| 有限负载 | 对同一 VM 内新建模拟会话批准负载计划 | 请求计数、延迟分布、调度缺口和有效性结论 | 不接受外部目标和复用生产目标 |
| 交接 | 选择定义、虚构数据与报告，预览导出清单 | 可离线核验的 ZIP 和摘要 | 凭据、批准、环境地址和执行权限不会随包迁移 |

“订单接口演练”固定 2 条虚构商品，依次查询商品、向模拟服务创建订单、查询订单，再检查总价与商品明细。第二个模板固定为“分页与限流”，验证分页边界、指定错误状态和响应格式。第三个模板固定为“契约变更检查”，在不运行 VM 的情况下比较两份契约并生成差异报告。

完整首次使用验收必须覆盖从零 VM 开始的订单演练。镜像内固定工具缺失时返回 `RUNTIME_NOT_PREPARED`，不能在运行计划背后安装依赖。准备镜像需要联网时，单独显示来源、下载摘要与联网许可；没有可用来源时允许用户导入已准备镜像。

## 6. 公共操作及三个调用入口

网页、HTTP 和命令行界面（CLI）调用同一公共领域服务。所有写动作均声明明确操作策略，继续经过当前操作网关、账户授权、来源校验和插件代次检查。不能根据 HTTP 方法推断业务权限，也不能在浏览器直接向目标服务发请求。

下面是拟议操作映射，路径和命令尚未实现。CLI 前缀为 `sakura integration`，`--json` 返回与 HTTP 一致的业务结果。

| 领域动作 | HTTP | CLI 子命令 | 返回内容 |
| --- | --- | --- | --- |
| 工作空间和模板 | `POST /api/integration/workspaces` | `workspace create --template order-demo` | 工作空间及草稿引用 |
| 导入与冻结契约 | `POST /api/integration/specs/import`、`POST /api/integration/specs/{id}/seal` | `spec import`、`spec seal` | 严格校验结果及固定修订 |
| 兼容差异 | `POST /api/integration/spec-comparisons` | `spec compare` | 方向、规则版本和逐项证据 |
| 固定数据与模拟 | `POST /api/integration/fixtures`、`POST /api/integration/mocks` | `fixture import`、`mock save` | 数据摘要、规则校验与修订 |
| 环境与凭据槽位 | `POST /api/integration/environments` | `environment save` | 地址与版本化引用，永不返回密钥 |
| 编译场景和断言 | `POST /api/integration/scenarios/{id}/compile`、`POST /api/integration/assertions` | `scenario compile`、`assertion save` | 固定执行图、断言修订与错误位置 |
| 预览与批准运行 | `POST /api/integration/run-plans`、`POST /api/integration/run-plans/{id}/apply` | `run preview`、`run apply --plan-id … --digest …` | 不可变计划或运行回执 |
| 查看、取消和收尾 | `GET /api/integration/runs/{id}`、`POST /api/integration/runs/{id}/cancel`、`POST /api/integration/runs/{id}/recover` | `run inspect`、`run cancel`、`run recover` | 原运行状态与清理证明 |
| 有限负载 | `POST /api/integration/load-plans`、`POST /api/integration/load-plans/{id}/apply` | `load preview`、`load apply` | 专用模拟目标与调度计划 |
| 报告与比较 | `GET /api/integration/reports/{id}`、`POST /api/integration/report-comparisons` | `report inspect`、`report compare` | 证据、可比性和拒绝原因 |
| 交换 | `POST /api/integration/exports`、`POST /api/integration/imports`、`POST /api/integration/imports/{id}/accept` | `export`、`import`、`import accept` | 清单、隔离结果和定义重绑定记录 |

新增 DTO 必须使用严格字段校验，未知字段拒绝；流式导入使用明确的大小、内容类型、偏移和最终摘要。异步动作返回运行 ID 与状态查询地址，不能用 HTTP 200 代替业务成功。CLI 功能失败、断言未求值、清理待处理和输入错误分别返回稳定的非零退出码，JSON 中保留具体业务错误码。

## 7. 已有能力与本体缺口

### 7.1 可以复用的真实入口

| 现有入口 | 本包的使用方式 | 不可推导的能力 |
| --- | --- | --- |
| [插件契约](plugin-design-contract.md)中的 `use`、`optional`、元数据、存储、Jobs 和 execution capability | 直接依赖、归属、修订、取消、预算和恢复记录 | 不提供任意进程沙箱，不允许直接取得 `Machines` |
| [ImageAssetsV1](../server/service-contracts/image-assets.ts) | 保留固定镜像，创建隔离的自有 VM，以原回执销毁 | 镜像存在不证明请求工具或防火墙已经安装 |
| [WorkspacesV1](../server/service-contracts/v1.ts) 的 `save`、`readCommittedConfig`、`runPrepared` | 建立本包专用项目，固定配置并运行准备好的工具 | `runPrepared` 不安装工具，不接受隐式仓库下载或 setup |
| [EgressRulesV1](../server/service-contracts/egress-rules.ts) | 私网功能测试的精确 IPv4、端口和截止时间 | 没有域名自动解析授权，也不限制 HTTP 方法、请求数或副作用 |
| [SecretsV1](../server/service-contracts/v1.ts) 的 `references`、`resolveVersioned` | 预览固定全部引用版本，执行前按同一集合解密 | 当前秘密按 VM 作用域管理，不存在工作空间级通用密钥仓库 |
| [AppTargetsV1](../server/service-contracts/app-runtime.ts) 的 `view` | 可选读取应用目标身份供用户登记测试环境 | 读取目标不授予请求、写操作、出站或负载测试权限 |
| [网络统管](network-runtime.md)和原会话生命周期 | 复用原网络代次、进程回执、关闭与收尾证明 | 通用网络 scope 不是任意地址的出站访问控制列表 |

环境里的秘密引用必须携带实际 `sourceVmId`、名称及不透明版本。零 VM 时可保存未绑定槽位；执行带凭据的请求前必须选择真实作用域并校验授权。首版秘密能力沿用当前 Windows 账户保护限制；其他宿主仍可运行无凭据模拟流程，不能悄悄退回明文存储。

### 7.2 需要本体增加的窄接口

当前接口不能证明固定客户机 HTTP 工具在主进程暂停时仍遵守请求总数、速率、截止时间及真实收尾。拟增加 `PreparedWorkerSessionsV1`，封装准备好项目中的固定工具会话。它是新的系统服务提案，不能在文档阶段登记进现有公共契约。

下面仅展示接口轮廓，所有类型和方法均未实现。工具标识由宿主审核的注册表选择，本包只使用拟议的 `integration-http-v1`。插件不得传任意命令、可执行路径、宿主地址代理或自定义加载模块。

```ts
// 拟议系统接口；不是当前 SDK。
interface PreparedWorkerSessionsV1 {
  preview(input: {
    ownedVmReceipt: OwnedImageVm;
    projectId: string;
    configRevision: string;
    toolId: 'integration-http-v1';
    toolDigest: string;
    inputManifestDigest: string;
    destinationGrantDigest: string;
    mode: 'functional' | 'load' | 'mock-only';
    maxRequests: number;
    maxRequestsPerSecond: number;
    minRequestIntervalMs: number;
    maxConcurrent: number;
    maxBytes: number;
    deadline: string;
  }): Promise<PreparedWorkerPlan>;
  start(planId: string, digest: string): Promise<PreparedWorkerReceipt>;
  inspect(receipt: PreparedWorkerReceipt): Promise<PreparedWorkerObservation>;
  stop(receipt: PreparedWorkerReceipt): Promise<PreparedWorkerCleanupProof>;
}
```

系统服务负责真实消费者身份、项目执行范围、固定工具完整性、原进程组与监听回执、控制通道和截止终止。工具内部实现本地预算，控制通道失联时关闭请求发起端和模拟监听；本体只接受实际关闭证明。请求解析、模拟规则、断言、报告和兼容判断仍由本包负责。

本地预算不能代替逐请求授权。功能请求必须使用新增的内部“请求单次许可”协议：工具经已绑定原会话的控制通道提交具体请求，运行器复核工作空间、来源修订、秘密版本、目标身份和最终绑定结果，持久化发送意图后，本体才能确认并下发一次许可。协议不提供客户端 HTTP 入口，也不允许插件从其他会话转交许可。

| 内部阶段 | 受管消息与责任 | 发请求的前提 |
| --- | --- | --- |
| `request-permit` | 工具提交运行 ID、节点及尝试序号、随机挑战、前序响应记录摘要、最终请求摘要和当前会话身份 | 尚未取得许可，禁止连接或写请求数据 |
| `commit-intent` | 运行器按原修订验证绑定与当前授权，将最终方法、目标、路径、请求体摘要、来源与凭据版本、时限写入意图账本 | 存储层确认持久化；提交失败或回执未知时不发许可 |
| `grant-once` | 本体核对原会话、已提交意图回执及真实消费者，先持久化许可签发记录，再发出绑定该请求摘要、目标、全部来源版本、挑战和短期截止的单次许可 | 工具核对摘要与本地预算，只消费一次；许可不能用于改写后的请求 |
| `request-result` | 工具返回已消费序号、派发与响应观察；运行器追加记录 | 无结果时保留未知，不能靠重新取许可重放同一请求 |

普通请求头、路径和正文在确定序列化形式后计算最终请求摘要。秘密请求头使用不透明引用版本绑定，明文不进入意图或公共摘要输入。工具核对本次短期注入的秘密版本，不能在获准后换值。每个执行分支同时最多持有一个未消费许可，禁止预取下一请求许可或把许可存入导出物。

短期许可的拟定有效期为 2 s，从工具创建原挑战的单调时刻计算，不从许可到达时重新计时，并同时检查运行及出站绝对截止。控制器冻结但套接字仍连接时，未获得新许可的工具不能发送下一请求。冻结前已获准的请求最多在这段有效期内派发；正在传输或对端已收到的请求不能撤回，缺少完整结果仍记为 `effect-unknown`。权限撤销阻止后续发放，不能追溯撤回已派发请求；页面和报告必须保留这一边界。

`mode` 决定不可扩大的工具预算和可用目标。`load` 只接受本次原模拟监听回执；`mock-only` 不允许主动请求。服务端根据模式校验请求频率、最短发起间隔、总数、并发、字节与截止时间的组合，客户端传入更大数值不会放宽首版上限。

本地模拟负载允许一次批准完整的固定请求账本。运行前展开全部请求及最终摘要，整体持久化后才发放绑定原模拟会话的批次许可；该模式不接受前序响应决定后续请求内容的动态绑定。需要动态绑定时改用逐请求许可的功能运行。工具逐项消费账本，保留消费序号和实际派发记录；崩溃后缺少完整记录的项标为未知，不重新发起。

批次许可仍要求受管授权心跳，拟定每 1 s 核对一次当前授权，确认有效期最多 2 s，从本次心跳挑战的工具单调时刻计算。没有新确认就停止派发，即使控制套接字仍连接。许可发出后到下一次核对之间，权限撤销可能尚未被工具观察；最多可继续到旧确认截止或更早的取消送达。报告记录最后授权确认及撤销观察时刻，不宣称零延迟撤权。该例外仅用于同一 VM 内原模拟服务，不适用于外部请求。

工具输入是一份已核验的只读清单。工具启动时同时固定单调时钟预算和绝对截止时间，采用限制更严者。宿主暂停期间仍执行本地预算；VM 暂停后恢复时先检查截止时间再发下一次请求。不能用宿主定时器或环境变量代替请求侧限额。插件以普通项目账户运行，不将客户机 root 攻击者列入过滤保证。

首版外部私网测试使用已准备的隔离 VM 和有限出站；地址、端口、TLS 名称及信任材料同时固定。拒绝 DNS 查询、重定向、代理环境变量、回环及宿主管理地址、元数据地址、IPv6 和地址别名绕过。VM 内模拟连接仅使用本次原监听回执允许的回环端口，不把这个例外扩展为宿主回环访问。

现有应用目标使用宿主回环入口，不能直接套用有限出站。若目标缺少允许的私网测试地址，适配只显示 `TARGET_TRANSPORT_UNAVAILABLE`。未来可增加持有目标原回执的窄桥接服务；首版不通过裸宿主回环转发绕过隔离。

## 8. 计划、身份、并发与副作用

### 8.1 运行计划

计划绑定 `workspaceId`、账户、插件实例和代次、契约/数据/模拟/场景/断言修订、目标修订、镜像摘要、工具摘要、资源上限、凭据全部版本、目的端点、请求图和批准截止时间。创建后不可编辑；任何一项变化都需要新计划。

批准使用一次性计划令牌和摘要。服务端在出队后、创建 VM 前、建立会话前及每次功能请求的单次许可发放前检查当前授权与目标状态；本地模拟负载按第 7.2 节的固定账本和短期确认执行。同一令牌的重复提交返回同一个运行，不能再次发送请求。资源锁定顺序为工作空间运行槽、目标操作锁、专用 VM、项目会话、网络和内容引用。无法一次获得所需资源时释放已确认的预留，不带锁无界等待。

运行创建后补充并固定 `vmCreatedAt`、`vmProcessId`、`executionGeneration`、`bootId`、网络代次、项目配置修订、原工具会话和原出站回执。相同 VM ID、端口号或 PID 不能替代原身份。计划过期、秘密轮换、目标重启、契约撤回、配置变化和权限撤销均阻止新的许可或确认。已发许可的消费和撤销边界按第 7.2 节记录，不能宣称在途请求未发生。

写请求计划逐项列出目标、方法、路径模板、请求体模板、固定输入摘要、动态绑定规则及值域摘要、数量和预期副作用。没有动态输入时可同时固定最终请求体摘要；依赖前序响应时，预览不能声称已知最终正文。

发送前根据已记录的前序响应求值，逐项检查来源、写入位置、类型和值域。运行器固定规范序列化后的 `finalBodyDigest` 和最终请求摘要，再完成意图持久化与单次许可。值超出批准规则时返回 `BINDING_OUT_OF_SCOPE`，不发送请求；用户修改规则后须生成新计划。默认只在本包模拟服务运行写请求；私网测试环境需要用户明确确认“测试用途”和本次写操作范围。声明无副作用不代表服务端确实只读，所有发出的请求仍记入意图账本。

### 8.2 状态机与请求账本

| 对象 | 主要状态 | 终态或恢复条件 |
| --- | --- | --- |
| 运行计划 | `draft → validated → approved → consumed`；另有 `expired`、`invalidated` | 一次使用后不再批准；失效原因保留 |
| 运行 | `queued → preparing → running → evaluating → cleanup → completed` | 断言失败可以完成收尾，但报告 verdict 为失败 |
| 异常运行 | `cancelling`、`interrupted`、`effect-unknown`、`cleanup-pending` | 业务副作用与资源清理分别确认，不能合并成一个成功状态 |
| 请求 | `planned → binding-validated → intent-durable → permitted → dispatching → response-recorded` | 无法确定是否到达目标时转 `effect-unknown`；仅当原签发账本能证明未签发且原工具消费记录完整时，才确认未发送 |
| 会话资源 | `reserved → starting → active → stopping → released` | 只有原进程、监听、出站和 VM 的真实证明才能转 `released` |
| 报告 | `collecting → sealed → archived` | 封存后只追加撤销或补充记录，不改原断言证据 |

发送前先持久化请求 ID、序号、计划摘要、来源版本、绑定验证结果和最终请求摘要，收到持久化确认后才发单次许可。外部功能请求不能仅将意图留在客户机缓存。网络错误不能说明对端没有执行；连接断开、响应丢失、进程崩溃或取消中的已许可请求都保留未知副作用。自动恢复只处理清理和证据整理，不重放请求，包含 GET 和声明幂等的写请求。

同一外部环境默认只允许一个写场景活动，读取场景也计入该目标的统一请求预算。变量依赖、秘密版本和访问授权不能由其他并发场景修改。模拟状态按会话隔离，负载会话总是从明确的初始状态重新创建。

未知副作用只能追加外部核验记录，包括核验账户、时间、证据附件摘要和结论。该记录不把历史请求改写为已知成功。用户选择新运行时必须使用新计划，看到原未知请求和可能重复的操作；对端提供的幂等机制只能作为证据，不触发自动重放。

### 8.3 取消、重启和停用

取消首先停止调度新请求，再关闭原连接、模拟监听和固定工具。随后撤销出站，确认原 VM 销毁，最后释放内容引用和资源额度。响应读取可以短暂保留以记录结果，但不能派发后续节点。超时、取消和插件停用走同一条收尾流程。

主进程重启后先核对原会话、VM 和网络身份，关闭未确认的原资源。活动运行转 `interrupted`；已发请求中缺少完整响应的转 `effect-unknown`。重建页面和报告不恢复业务执行，也不根据元数据中的“完成”字样归还额度。

无法确认关闭时保留 `cleanup-pending`、原租约和恢复票据。恢复入口只操作原回执；VM 已替换时，不对新 VM、复用端口或复用 PID 执行停止。停用插件不删除审计和报告，不让其他插件替它宣称资源已清理。

## 9. 网络、凭据与内容保护

本包的工作空间操作首版限定为当前宿主 owner，沿用本体已鉴权身份与操作网关。各插件先调用 specs 核对工作空间；涉及现有 VM、项目或秘密时，再通过原领域核对相应授权。计划分别记录运行、写请求、保留内容和导出的具体许可范围。首版不提供多人工作空间或自建角色权限映射，不能用“页面可见”代替 owner 校验。

预览只读取秘密的引用版本。执行时环境服务解析同一完整集合，交给本次工具会话的受保护短期通道；明文不得写入命令行、常规环境转储、元数据、日志或报告。轮换后排队计划失效；在途请求可能已使用旧凭据，报告记录版本而不显示值。

禁止将秘密插入 URL、路径、查询字符串、文件名或模拟规则。首版只允许批准端点的具名请求头；不能由响应变量覆盖认证头。客户端不接受关闭证书验证的选项，TLS 校验失败终止请求。

响应可能反射凭据或业务数据。默认只保留状态、允许列表中的响应头、大小、摘要及断言结果；正文在内存中完成有界断言后丢弃。用户需要保存正文时，必须选择字段允许列表并预览脱敏结果，再固化到计划。脱敏不足时拒绝正文导出，不能以“已脱敏”标签保证任意内容不含秘密。

断言提取值、差异片段和失败消息同样受字段允许列表约束，不能从断言侧绕过正文保留策略。默认断言结果只保存布尔结论、规则引用和不含实际值的原因码。报告逐项声明 `evidenceCoverage`：`record-only`、`selected-fields` 或 `recomputable`，同时列出不可重算原因。正文丢弃或字段不足时，离线核验只能证明包完整性和记录关联，不能独立重算相应业务断言。

报告和离线 HTML 中的接口描述、错误信息及响应片段都作为文本显示。禁止执行输入 HTML、脚本、远程样式和远程资源，确保离线查看不会向外部目标发请求。

## 10. 首版配额、保留与清理

以下均为**首版拟定硬上限，实施前资源实测可收紧，不是当前性能保证**。实际运行还受宿主更严格的现有资源预算限制；降低上限后，旧定义可以查看，超限定义必须修订后才能再次执行。

| 项目 | 拟定值 | 达到上限时的行为 |
| --- | --- | --- |
| 工作空间 | 全包最多 32 个，归档与待接受导入占位也计入 | 拒绝新建或导入占位，不以归档规避上限 |
| 领域对象与修订 | 全包最多 10,000 个领域对象、50,000 份修订；每对象最多 100 份修订 | 拒绝新增对象或修订，允许读取与审阅清理；运行请求项计入所属运行元数据大小 |
| 元数据 | 全包业务元数据合计 256 MiB，另预留 32 MiB 控制记录空间 | 业务写入拒绝；取消、撤权、原资源清理和完成证明可使用保留空间 |
| 全包持久与暂存字节 | 合计 32 GiB；包含材料、元数据、报告、日志、隔离区、交换文件、临时上传、本包镜像引用和自有 VM 磁盘 | 写入前按峰值预留，容量不足返回 `PACKAGE_CAPACITY_EXCEEDED`，不能删除受保护材料腾位 |
| 单契约 | 5 MiB、500 个操作、模式深度 16 | 导入失败，临时分块进入可清理列表 |
| 单数据集 | 50 MiB、10,000 行；单单元格 64 KiB | 停止解析，不发布部分数据集 |
| 场景 | 100 个展开节点、同时最多 4 个无冲突分支 | 编译失败，不截断场景 |
| 功能运行 | 200 次请求、10 min、并发 4；单请求 15 s | 停止新请求并记录未运行节点 |
| 单请求 | 请求体 1 MiB、响应体 2 MiB、响应头 32 KiB | 超限终止读取；相关断言标为未求值 |
| VM 与任务 | 每工作空间 1 个活动 VM，宿主最多 2 个本包 VM；单镜像和每 VM 虚拟磁盘最多 8 GiB | 明确排队或拒绝，不增加隐藏 VM；镜像保留和 VM 磁盘同时计入本包总量 |
| 模拟服务 | 每会话 500 条规则、最多 8 个状态、最长独立会话 30 min | 编译或计划失败；截止后停止监听 |
| 有限负载 | 同一 VM 内模拟目标；100 次/秒、并发 16、最长 60 s、总数 6000 | 任一限额先到即停止新请求 |
| 运行输出 | 总计 64 MiB；日志 4 MiB | 留摘要和明确截断标记，不把缺失证据算通过 |
| 离线包 | 压缩包 256 MiB、展开后 512 MiB、2000 个条目 | 在隔离区拒绝，不发布部分导入 |
| 计划有效期 | 5 min；执行截止另行固定 | 批准过期计划返回 `PLAN_EXPIRED` |
| 请求许可与授权确认 | 功能请求单次许可最长 2 s；本地模拟负载每 1 s 核对，确认有效期最长 2 s | 无新许可不发请求；过期、冻结或缺少确认时停止后续派发 |
| 保留 | 默认保留报告 30 天；临时上传 24 h | 生成待清理计划，不直接删除仍有引用内容 |

负载报告同时列出计划发起数、实际发起数、完成数、错误数、取消数、未发起数，以及实际调度间隔。延迟只统计定义清楚的完成样本，超时另列。达到客户端资源上限、调度缺口过大、采样不足或目标身份变化时标为 `inconclusive`，不得宣称目标吞吐或容量已经达标。

请求速率由工具端令牌桶约束，桶容量为 1，初始为空，按单调时钟补充令牌；上限 100 次/秒对应两次发起至少间隔 10 ms。排队延迟不积累突发额度，恢复后不追赶错过的请求。功能运行的 10 min/200 次与负载运行的 60 s/6000 次分别计量；两种运行都另受 64 MiB 输出预算约束，字节预算不能代替请求、并发或时间预算。

总字节计额按保守的逻辑大小预留，不因共享去重或稀疏磁盘而降低准入。上传原件、解析暂存、待发布副本、压缩包和解包目录同时存在时全部计入峰值；原子发布成功并确认旧临时资源消失后才核减。宿主整体磁盘预算仍可施加更低限制，其他包共用镜像也不能让本包获得无上限引用。

固定报告、历史修订和活动引用继续占用字节及对象额度，固定操作不能扩容。开始运行前同时预留最坏情况下的意图、结果与收尾记录空间；保留空间不允许写新报告正文、普通日志或追加业务修订。容量不足先拒绝新业务，取消、权限撤销和原资源清理仍保持可用。若连已预留控制记录也无法写入，例如宿主磁盘故障，则立即禁止新许可并执行原受管停止，保留外部资源账本中的未知责任，恢复后再核销，不伪造持久化成功。

报告比较必须固定场景、契约、数据、模拟规则、工具、镜像、资源配额、负载曲线、采样窗口和计时方式。任一不一致时返回不可比原因，并允许用户并排阅读原始报告，不输出伪精确的性能提升百分比。

删除先生成包含对象修订、摘要和仍被引用内容的清理计划。执行前再次核对引用；活动会话、未确认收尾、隔离导入和保留报告保护相关内容。删除文件后确认真实结果，元数据不能先声明删除成功。清理测试产生的材料时，只操作本次工作空间拥有且已确认无引用的路径。

## 11. 离线交换与信任

交换包采用 `sakura-integration-bundle/1` 清单，列出包格式、各领域格式、工具要求、逻辑引用、相对路径、字节数和内容摘要。定义、模拟规则、允许的数据、断言、报告和可比性说明可选择导出。对未运行定义的导出仍需完整依赖闭包，缺少任一固定对象则拒绝封存。

首版交换包提供完整性核验，不宣称发布者身份认证。它不会复用 delivery 的签名权限，导入后也不生成已通过门禁。外部报告始终标为“导入证据”，只能供阅读和比较；在本机运行后才能生成新的本机证据。

导出不包含秘密值、秘密源 VM ID、真实环境地址、信任私钥、运行批准令牌、活动资源回执或可重用会话令牌。凭据和目标改为逻辑槽位。报告保留必要的运行身份摘要及时间，但不能让接收者凭其操作原资源。

导入流程为“上传 → 隔离校验 → 审阅内容 → 接受定义 → 本地重新绑定 → 重新预览”。接受时由 exchange 调用 specs 创建新的本机工作空间和真实 owner 登记，再通过各领域服务逐项写入带新本地 ID 的定义；外部 owner 和工作空间 ID 只作为来源信息保存。导入事务未全部发布时不开放运行，失败后可按导入 ID 继续完成定义写入。接受定义不会联网或执行。格式更新于本机支持范围时，保留隔离记录并说明缺少的版本；不能自动降级解析。

解包前检查展开大小和条目数；逐条拒绝绝对路径、父目录穿越、符号链接、硬链接、设备条目、大小写别名、重复路径和文件目录重叠。只发布摘要完整的对象。离线核验器不连接 Sakura 服务，不加载插件代码，不替导入报告授予执行权限。

## 12. 里程碑与实施顺序

优先级只表示依赖顺序，不代表删减完整包。11 个插件及完整流程都通过后，才能把本包标为已完成。负责人采用职责划分，具体人员由实施时分配；本设计不虚构工期。

| 里程碑 | 优先级 | 责任角色 | 依赖 | 交付与退出条件 |
| --- | --- | --- | --- | --- |
| M1：契约与存储 | P0 | 契约及存储负责人 | 当前 API 5、受管元数据/存储 | 完成工作空间授权、严格格式、修订、数据与模拟编译；无 VM 模板可创建，非法输入全部拒绝 |
| M2：执行边界 | P0 | 本体运行时负责人 | M1、已有 ImageAssets/Egress/项目执行 | 固定工具会话、原身份、限额、截止、取消和恢复通过真实 VM 验证；不提供任意宿主网络代理 |
| M3：功能场景 | P0 | 集成运行负责人 | M2、环境及秘密版本绑定 | 订单演练、写请求批准、断言、未知副作用和收尾证据均可通过 UI、HTTP、CLI 复现 |
| M4：负载与报告 | P1 | 验证与报告负责人 | M3 的固定会话及请求账本 | 仅自有模拟压测，调度缺口可解释；不完整证据不能通过，错误比较被拒绝 |
| M5：交接与包交付 | P1 | 交换及工作台负责人 | M1～M4 | 完整离线导出、隔离导入和本地重绑定；只启用本包及必需单插件即可完成全流程 |

实施时新增服务应按仓库流程编写独立契约、生成描述符、操作及 HTTP 请求声明、类型客户端、CLI、页面和使用说明。新增工具资产纳入运行包摘要与独立分发验证。兼容新增优先沿用 API 5；若公共身份或生命周期协议必须改变，先提出版本迁移方案，不能仅改数字绕过兼容验收。

## 13. 成功与故障验收

下表是未来实施的验收要求，当前尚未执行。测试脚本、数据、截图和报告只保留在精确忽略的本地测试目录；Git 中记录简短结论及必要实现，不提交专用测试材料。

| 场景 | 可观察的合格结果 |
| --- | --- |
| 零 VM 首次启用 | 页面可打开，3 个模板可编辑；没有网络、VM 或后台任务；准备好镜像后订单演练完整运行并清理 |
| 独立包启用 | 仅本包和 `projects`、`secrets` 启用时，全流程可用；其他两套新设计包及现有完整包均非前提 |
| 契约变化 | 删除必需响应字段得到有方向的破坏记录；未知约束拒绝或标未判定，不产生假兼容结论 |
| 输入冻结 | 批准后修改原数据文件不改变执行；替换固定内容摘要失败；旧修订仍能读取 |
| 修订与重复提交 | 两个编辑者竞争保存时只有一个成功；重复批准返回同一运行且无重复请求 |
| 写请求批准与动态绑定 | 未批准写范围的场景不发请求；改变方法、模板、绑定规则或值域后旧批准失效；规则内动态值在发送前固定最终摘要，越界值被拒绝 |
| 单次许可与持久化 | 意图持久化未确认时没有许可、没有请求；许可跨请求、会话或代次重用被拒绝；响应丢失后不重复发许可派发 |
| 请求断连 | 对端已写入但响应丢失时显示 `effect-unknown`；重启和恢复不重复创建订单 |
| 秘密轮换 | 预览后旋转一个引用使整个集合失效；日志、命令、报告及 ZIP 不出现秘密值 |
| 网络绕过 | 重定向、DNS、宿主回环、管理地址、代理变量、IPv6、私网目标换址及非批准端口全部拒绝 |
| 原身份替换 | VM 重建、boot 改变、端口或 PID 复用后旧运行失效；恢复不能停止新实例 |
| 主进程暂停及 VM 暂停 | 保持控制套接字连接后冻结主进程，未获得新许可的外部请求不会发出；已获许可的有限窗口与在途未知明确记录；恢复后不补发 |
| 取消及插件停用 | 停止新请求，原监听和出站关闭；未完成写请求保留未知结论；未确认资源不归还预算 |
| 模拟隔离 | 两个会话不共享订单状态；故障注入只影响指定规则；没有未声明的外部请求 |
| 负载边界 | 只能选本次模拟回执；超过速率、并发、时限和总数任一约束均停止；不能选择应用生产目标 |
| 模拟批次撤权 | 固定账本不能添加或修改请求；授权确认过期后不再派发；撤权发生到工具观察之间的窗口可核对，不宣称即时停止 |
| 客户端饱和 | 计划数和发起数存在缺口时报告为不确定；不将丢失请求排除后宣称通过 |
| 大响应及残缺证据 | 超限读取有明确错误；相关断言未求值；不能用截断结果判通过 |
| 导出与导入 | 脱敏清单可审阅，离线可核验；导入不执行、不连旧地址，也不继承批准或信任 |
| 恶意归档 | 穿越、链接、别名、重复路径和展开超限均停在隔离区；没有写出工作空间 |
| 总容量与控制预留 | 工作空间、对象、修订或字节额度满时拒绝新增业务；导入峰值计入，固定引用不扩容；取消、撤权和清理记录仍可提交 |
| 依赖缺席及撤权 | 可选应用适配缺席时主流程可用；运行中撤权阻止新许可或确认，按短期许可边界停止派发并保留合法收尾能力 |
| 独立运行包 | 无源码、无开发依赖的运行包能完成模板、运行、负载、报告、离线核验及清理 |

## 14. 设计状态与未决实施事项

本包设计确定 11 个独立插件、依赖方向、受限协议范围、固定输入、请求副作用账本、资源恢复责任和验收边界。运行实现仍待开始；本次不声称上述验收已通过。

实施前必须解决并记录 3 个具体缺口：固定工具会话的原资源证明；独立工作空间内容存储的真实授权；受管工具与已准备镜像在独立运行包中的提供方式。这些缺口对应 M1 和 M2，不得用任意命令执行、伪 VM ID 或隐式安装代替。

外部报告进入交付门禁需要另行定义候选、运行、清理和证据归属的适配。当前 [DeliveryGatesV1](../server/service-contracts/delivery-quality.ts) 没有通用第三方报告接收语义，本设计仅交接可核验证据，不预设现有门禁会接受它。
