# 单应用 Linux 窗口

运行中的 Alpine、Debian 或 Ubuntu 实例可在“桌面 → 单应用窗口”输入客户机里的程序名及参数，启动独立的浏览器弹窗。每个应用使用专属 Xvnc 显示器和 Openbox，会话与普通 KDE 桌面分开；首次使用会通过 `apk` 或 `apt` 安装所需图形组件。默认程序 `xterm` 可用于检查。参数每行一个，程序需已安装在客户机中。

窗口沿用启动时所在项目的网络设置。私有项目中的 Xvnc、窗口管理器、图形程序及其子进程都进入仅回环的项目网络命名空间；浏览器连接通过已有 SSH 通道进入同一命名空间，不增加 QEMU 转发、网卡或路由。每次连接都会复核网络，当前项目切换不改变已有窗口的归属。窗口运行或实例暂停时，必须先恢复实例并停止窗口，再修改该项目目录或网络模式。此入口需要 `projects` 插件。

每个窗口使用独立、密码锁定且不回收复用的 Linux 用户，应用数据保存在面板显示的专属主目录中；其他窗口不能读取其中的 VNC 密码或受保护的 X11 凭据。Xvnc 要求随机密码认证，密码仅通过已有认证接口和同源窗口消息传递，不写入网址、浏览器存储或长期运行进程的命令行。客户机 IPv4/IPv6 防火墙还按用户限制回环地址的 `5900–5999` TCP 端口，仅允许连接自己的窗口，避免访问共享 KDE 桌面或其他受管窗口；其他出站流量仍遵守项目网络设置。防火墙组件不可用或已有同名规则时启动失败，安装失败会回滚本次规则，不覆盖其他规则。

停止窗口会终止该独立用户的全部进程，包括脱离父进程的子进程，并移除本窗口的防火墙规则；应用正常退出也执行清理。主目录和用户账户保留，避免删除应用保存的数据或把旧文件权限交给另一窗口。每次新建窗口使用新的主目录；项目目录继续保留原有 Linux 文件权限，不会自动授予新用户写入权限。需要写入的文件可保存到窗口自己的数据目录，再由管理员整理。

每台实例最多四个会话，可从桌面页重新打开或停止。应用退出、实例停止或 Sakura 服务关闭时会话终止，最长运行四小时。关闭弹窗只断开观看，可从会话列表重新打开。弹窗加载独立页面，取得连接令牌后不再依赖主控制页保持打开；令牌不写入弹窗网址。图形数据经已有实例 SSH 通道和有权限校验的 WebSocket 转发；客户机 RFB 仅监听环回。

启动时可分别关闭“复制到宿主”和“粘贴到应用”。Sakura 将限制写入此应用专属 Xvnc 会话的剪贴板收发与 PRIMARY 选区参数，并禁止会话内用 `vncconfig` 放宽这些参数；重开窗口仍沿用会话设置，更改需要停止并重新启动应用。网页中的敏感文本检测和大小限制仍额外生效。这只约束该图形会话与 VNC 客户端之间的剪贴板传递，不阻止客户机管理员在其他进程或显示器中访问数据。

这是独立的**浏览器窗口**，不是 Windows 原生单应用窗口；应用界面仍显示在自己的虚拟屏幕上，可能带有 Openbox 背景和窗口边框。重启 Sakura 服务后未保留会话索引，也不提供跨窗口剪贴板同步、音频或文件拖放。浏览器必须允许弹窗。目录的“可用”表示可以启动、操作、重开和停止每个独立应用窗口，不表示具备宿主窗口管理器级的无缝集成。

接口：`GET /api/vms/:vmId/single-app` 查看会话；`POST` 使用 `{ "action": "start", "program": "xterm", "args": [], "resolution": "1024x768", "clipboard": { "copy": false, "paste": true } }` 启动，或 `{ "action": "stop", "id": "..." }` 停止。省略 `clipboard` 时双向均允许。图形 WebSocket 为 `/ws/:vmId/desktop?app=:sessionId&token=:ownerToken`，仅实例拥有者可连接。

`npm run test:single-app-windows` 在真实 Alpine 虚拟机内验证启动、独立用户和凭据权限、正确及错误的 VNC 密码、IPv4/IPv6 用户防火墙、第三方规则保留、失败回滚、剪贴板规则收紧、配置变更保护、子进程清理和数据保留；设置 `SAKURA_TEST_DISTRO=debian` 或 `ubuntu` 可验证对应发行版。设置 `SAKURA_SINGLE_APP_PRIVATE=1` 验证真实图形程序所在的网络命名空间；再设置 `SAKURA_SINGLE_APP_BROWSER=1` 验证真实 Chromium 弹窗的 noVNC 认证和剪贴板控件。
