# AI 修复会话

## 使用范围

`repair` 是默认关闭的可选插件，依赖 `projects`、`files` 和 `sandbox`。启用后，实例的“开发”页提供“AI 修复会话”。`complete` 插件包包含此插件。

首版每次修改 1 个现有 UTF-8 文件，可选择最多 7 个上下文文件。所选文件总内容最多 16 KB。文件必须位于当前项目目录内，项目账号需要相应读写权限。源实例需要系统 Python 3，以及已经准备好的持久项目身份。

模型只接收明确选中的文本。补丁采用目标文件的完整新内容，界面并列展示原文和修改后内容。首版不支持创建、删除或重命名文件，也不支持多文件补丁。

## 操作步骤

1. 在设置中启用本地助手，选择本机 Ollama 服务中已有的模型。模型服务地址只接受回环地址；发送前核对模型声明的本地权重信息。
2. 启动项目实例，填写目标文件、上下文文件和修复要求，选择“选择文件并预览发送内容”。此时只读取项目文件，尚未发送模型请求。
3. 审阅脱敏后的内容，再选择“确认发送并生成补丁”。发送预览使用一次性令牌。模型失败、返回越界路径或结果截断时，不生成可应用补丁。
4. 审阅原文、补丁和验证命令，勾选确认后，在新建的隔离沙箱验证。验证完成后可查看退出码、日志和沙箱清理结果。
5. 验证通过后选择“接受补丁并更新原文件”。应用前再次核对项目配置、运行代次和全部所选文件摘要。

会话打开期间，目标文件、上下文和修复要求保持锁定。需要更换时，先选择“关闭会话并重新选择”。新会话需要重新审阅验证命令。关闭会话不撤销已经接受的文件变更。

## 隔离验证的含义

验证沙箱使用源实例对应发行版的基础镜像，网络为 `isolated`，存储为 `discard-on-stop`。沙箱在同一次启动内重建所选文本文件，并执行用户审阅的命令。文件位于 `/workspace/sakura-input`，新建目录权限为 `0700`，文件权限为 `0600`。输入路径拒绝越界、符号链接和已有节点覆盖。

验证只覆盖所选文本和这条命令。完整项目、依赖目录、原实例中安装的运行时和环境变量都不会复制。基础镜像缺少命令所需工具时，验证会失败；插件不会自动联网安装工具。默认 Alpine 镜像可使用 `sh -n` 等已有命令核对适用的文件。

只有真实任务状态为成功、退出码为 `0`、沙箱清理完成，才允许接受同一 SHA-256 摘要的补丁。退出码未知、清理待确认或清理失败均不算通过。当前命令必须与最近成功验证的命令一致，并重新勾选审阅确认；使用新命令需重新验证。沙箱每次停机都会丢弃写入，下次验证会重新创建输入文件。

## 权限和并发边界

源项目文件操作复用项目准备租约和持久项目 UID。固定文件程序不执行模型代码，拒绝符号链接、硬链接、非普通文件、NUL 内容和越界路径。客户机根路径逐级使用禁止跟随链接的目录描述符打开。

会话绑定实例配置、项目配置版本、项目身份和客户机运行代次。读取、生成、验证及应用均核对这些信息。应用同时持有实例操作锁和文件工作台的变更锁，拒绝覆盖已由编辑器锁定的文件。目标文件先写入同目录临时文件，核对原摘要和节点身份后替换，并保留文件权限及所有者。

文件工作台的锁只能协调遵守该锁的 Sakura 操作。客户机中的其他进程仍可能在最后核对与替换之间写入文件，插件不提供针对这些进程的原子比较交换保证。接受补丁前，应停止会改写所选文件的客户机进程。

如果替换已经开始，后续同步或任务清理失败，界面显示“应用结果待核对”。此时原文件可能已经改变，应在文件工作台检查内容及补丁摘要。本会话禁止自动重放。模型生成失败和验证失败不会写入原项目。

## 会话与接口

会话仅保存在内存中，有效期为 30 分钟，最多保留 8 个。关闭会话会取消在途生成或验证并释放沙箱。已应用会话和已完成沙箱清理的过期会话可回收。插件停用时会重试清理；清理失败保留原资源身份，后续重试仍需核对同一沙箱。

`GET /api/vms/{vmId}/repair?sessionId=…` 返回会话。`POST /api/vms/{vmId}/repair` 接收 `preview`、`generate`、`validate`、`apply` 或 `cancel`。路由要求实例所有者权限，并遵守当前项目范围。请求、会话及响应均有公开 Schema；`RepairSessionsV1` 纳入官方服务契约。

## 验证记录

本地定向验证覆盖运行代次变化、配置及上下文变化、编辑器锁、路径拒绝、取消、验证失败、清理失败重试、已应用会话回收和写入后结果不确定。

独立临时 QEMU 验证已核对输入文件重建、文件权限、真实 shell 退出码、整机停止、COW 基线不变及下次启动无旧输入。夹具复制基础镜像到临时数据目录，不读取现有用户实例。模型协议使用本机 HTTP 夹具；这类验证不代表真实模型的修复质量。

新建源实例的实际项目测试已覆盖正式项目 UID 读取、发送确认、模型协议响应、隔离验证和受控替换。写入后读回内容与补丁一致，文件保留非 root 所有者。上下文摘要变化和符号链接目标均被拒绝。

开发期的一次真实测试遇到 `PROJECT_IDENTITY_CLEANUP_FAILED`，原生账号运行回执读取未确认，流程在应用前停止。后续全新实例的完整测试通过，但该次回执失败的底层原因尚未确认。插件保留既有清理检查；遇到此错误时，不把生成或验证结果当作可应用状态。
