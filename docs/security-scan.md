# 镜像与软件包安全扫描

启动实例后，在“工作空间 → 安全扫描”点击“开始扫描”。Sakura 会在客户机只读检查 SSH 认证设置、待更新系统软件包和可写系统文件，同时读取已安装软件包的源包名称与版本，并向 [OSV 批量查询接口](https://google.github.io/osv.dev/post-v1-querybatch/)发送这些名称、版本及发行版标识。界面展示匹配的包和漏洞编号，可打开 OSV 详情。

扫描使用实际客户机的版本：Alpine 取 APK 源包和 `Alpine:v<主次版本>`，Debian 取 dpkg 源包和 `Debian:<版本>`，Ubuntu 24.04 取 dpkg 源包和 `Ubuntu:24.04:LTS`。OSV 分页会继续查询，直到取完结果。扫描失败、网络不可达或发行版无法识别时，页面明确标为“漏洞匹配未完成”，不会把零结果当成无漏洞。

结果只覆盖这次读取到的系统软件包及 [OSV 收录的数据源](https://google.github.io/osv.dev/data/)；不包括项目级 npm/pip、容器内容、尚未收录的漏洞或运行时配置利用条件。界面最多展示 20 个受影响源包和每包 5 个漏洞编号，原始结果保留至多 200 个源包和每包 30 个编号，统计数量覆盖完整扫描。客户机镜像安装了新软件或更新后需重新扫描。

`npm run test:security-scan` 在真实 Alpine、Debian、Ubuntu/QEMU 客户机中核对清单和 OSV 查询。单元测试还验证源包映射、批量结果对应、分页和异常响应。
