# 第七批二十个完整插件包设计

## 1. 版本、范围与交付物

设计系列 **6.0.0 → 7.0.0**，日期 2026-10-26。当前检出应用保持 **2.8.1 → 2.8.1**，基线为 `4afb3b9a`，分支为 `codex/plugin-management`，宿主插件 API 为 5。本轮交付 20 个新插件包、285 个内部插件及 285 个领域服务的产品与实施设计。

本地其他分支已保留第六批设计标签 `design/plugin-packs-v6.0.0`，对应提交 `d1a07ca0`；另有应用标签 `v2.10.0` 和 `v2.11.0`。本轮将这些历史设计与当前源码一起核对。历史标签存在不表示当前工作区已升级，也不把旧批次重新计入这 20 个包。

设计系列沿用按批次递增的版本习惯。7.0.0 表示新增设计批次，不表示应用兼容性变化或可安装包版本。运行实现均待开始；本轮不登记运行插件，不修改选择、API 或应用依赖。实施开工时另定应用版本及依赖的精确发行版本。

每包覆盖输入、编辑、核心处理、结果判断、复核、固定版本、交接和清理。包只声明成员集合；内部插件按独立对象、数据所有权和生命周期划分。工作台组合公共服务，不能越过服务接口读取其他插件的数据目录。

## 4. 内部插件和对象契约

详情成员表使用完整插件 ID 和完整直接依赖，不用星号展开。每行列出唯一拟议领域服务及主要方法。实现时把每条依赖落实为精确版本的 `pin()`，把成员落实为 `member()`；设计版本不能填入运行清单。

每包首个插件拥有工作空间根账本、许可修订和包级容量，其余插件直接依赖它。字节、定义、执行、判断和人工决定归各表声明的所有者。工作台只保存视图偏好，不复制领域事实；交接插件拥有交接意图与回执，不接管源对象的删除权。

共同对象记录 `workspaceId`、`id`、`revision`、`schemaVersion`、`contentDigest` 和 `createdAt`。引用固定提供者、ID、修订及摘要，不自动追随最新版本。服务端绑定真实 actor 和插件 generation；输入中的作者、负责人或审阅人标签不授予访问权限。

定义服务支持分页查询、按 `expectedRevision` 保存、封存和归档。结果服务发布新固定结果，复核不会覆盖旧运行事实。所有持久存储者须支持引用查询、清理预览和按原修订提交。共享字节去重只由原存储者完成，逻辑引用和历史保护仍保留。

| 状态类别 | 语义 |
| --- | --- |
| 定义 | `draft → sealed → archived`，封存正文不可覆盖 |
| 计划 | `ready → consumed`，另有 `expired` 和 `invalidated` |
| 处理 | `queued → preparing → running → finalizing → completed`，失败、取消和中断单列 |
| 判断 | `passed`、`failed`、`inconclusive`、`not-supported`，附适用输入与覆盖范围 |
| 清理 | `pending`、`confirmed`、`unknown`，与处理状态分开 |

人工接受可以承认例外，不能改写机器失败或缺失证据。抽样通过不推导总体通过；模拟轨迹不作为真实外部观察；收到第三方报告不代表完成了本地复算。

## 6. 页面、HTTP、CLI 与执行授权

详情所有接口都是拟议设计。HTTP 采用 `POST /api/<完整插件ID>/<明确方法>`，逐项声明严格请求、响应、权限和副作用策略。只读方法也须鉴权。上传和下载使用独立有界二进制路径，不经一个任意服务名或命令分发接口调用。

CLI 使用各包指定别名，支持 JSON 输出、分页、固定版本、preview、提交、status、wait、cancel 和 reconcile。离线 `verify` 在纯 Node 安装产物运行，不启动宿主、不联网、不执行导入内容。缺少必需原工具的重算显示未验证，不能退化成只检查摘要后宣称业务通过。

沿用退出码：0 表示当前命令完成；1 为已知业务失败；2 为输入或传输错误；3 为不确定或不支持；4 为清理待确认。并存时按 2、4、3、1、0 报告优先级，JSON 保留全部状态。异步提交的 0 仅表示已接收，等待命令以最终状态退出。

计划固定完整输入、目标、参数、工具摘要、权限修订、资源上限、输出范围和绝对截止，默认 5 分钟内可提交。分页不缩小授权范围。授权绑定完整计划，改变输入或目标即失效；有效授权不重复确认。重复提交查询原回执，不新建相同副作用。

需要真实执行的包使用固定受管工具。专属 VM 默认无外部网络、宿主目录挂载和公开端口；所需内部连接在固定工具档案中声明。控制器退出后仍要有独立截止与原资源核销证据，未经验证的平台明确显示不支持。

社区扩展开发沿用社区 WASM 协议，官方包自身仍遵守 API 5。候选编译成功、离线检查、受限试运行、签名、安装分别记录；不能以一个“成功”覆盖全部阶段。私钥由原秘密提供者或外部签名者持有，本包只保存公开结果和签名请求。

## 7. 本体复用与新增能力

现有[插件契约](plugin-design-contract.md)、[计算运行时](compute-runtime.md)、[固定工具执行](suite-execution.md)、[共同容量](suite-capacity.md)提供接入原则。新包不能把通用计算入口、旧工具 profile 或 API 5 当成任意运行代码的授权。

详情的新增本体接口只定义能力缺口，尚未登记、实现或验证。实施时复用无权限的纯解析代码；工具注册、许可、进程/连接/磁盘所有权和取消仍由原领域承担。新公共方法须有独立版本契约、直接消费者和逐操作策略。

## 8. 容量、交换、升级与恢复

详情中的容量和时间均为待实测的设计上限。准入同时受单对象、空间、包、工具和宿主约束，取最严格者。当前 8 GiB 共同容量只覆盖已登记范围，本批 20 包尚未纳入；不得直接把各包额度相加当作可用容量。

每包至少为控制账本预留 32 MiB，包含在包总额中。普通写入不能消耗取消、撤权与恢复保留。材料、派生字节、索引、导入隔离、导出暂存、模型、工具资产和未知资源均计费；虚拟磁盘按声明容量预留并另报实际占用。首版模板须能在明确公布的可用额度下完成；超限前说明所需空间和可调整项。

默认控制 JSON 上限 1 MiB、上传块 512 KiB、读租约最长 15 分钟；详情可收紧。字节上传与元数据请求分离，分页结果不能绕过总预算。解析、计算、导出各有绝对截止；截止到达不等于原资源已退出。

普通交接格式为 `sakura-<包ID>/1` 的有界 ZIP STORE，单封套默认最多 256 MiB，详情若另设大小须在实现时单独验证。该目标不由旧封套的 16 MiB 实测保证。拒绝压缩条目、ZIP64、路径穿越、符号链接、设备、重复路径和大小写碰撞。

大于单封套的空间可选择完整引用子图分批导出，每批独立核验，不隐式拼接为多卷事务。若只交付报告或局部证据，清单须列明外部缺失引用，并按只读参考档案接收；此类档案不能成为可执行定义、完整数据版本或本地通过证据。需要完整复算时补齐输入后建立新的本地计划。

清单固定长度、摘要、对象关系及来源。原始、校正、脱敏及派生字节分别保留摘要。导出只包含明确选择且许可仍有效的对象，不自动携带所有祖先、秘密、活动运行票据或宿主路径。缺少有效发布者签名时来源标为未认证，摘要一致只证明内容一致。

接收先检查限额、结构、字节、关系和领域规则，再隔离审阅并接受到新空间。旧 ID 映射为新 ID；旧批准、秘密引用、运行身份和路径不生效。导入的源码、模板、脚本、HTML 或 WASM 均不因接收而执行。

跨插件发布先持久化意图与预留，再由各所有者写入并确认，完整对象图发布后开放读取。中断根据原意图和实际回执核对，不凭“记录不存在”推断失败或重发。未知状态保持占用；仅原领域证明释放后归还容量。

升级先检查对象模式、活动执行和引用，保存可恢复副本并预览迁移。全部验证通过后提交新模式；失败保留原版本和原字节。无法解释新模式的降级拒绝写入。停用先停准入，再关闭原资源，保留正式对象和未核销入口；归档、停用和到期均不自动删除数据。
