# 备份文件级恢复

启用“备份策略”插件，在停止实例的“快照 → 备份文件恢复”中选择一份备份、文件系统分区和要提取的文件。支持普通实例包、加密备份、外部目录备份及内容块去重备份。恢复结果供下载，不覆盖当前实例中的文件，也不注册新的永久实例。

## 使用方式

1. 选择备份。加密备份需要对应密码；如果备份记录已有密钥引用，可以留空使用该引用。密码提交后从表单清除，不进入任务日志、恢复记录或结果报告。
2. 填写分区编号。默认 `0` 为整盘文件系统，适用于默认 Alpine 镜像；其他镜像可能需要 `1` 或其他分区编号。支持 ext2/ext3/ext4，以只读方式挂载，不重放日志。加密文件系统、LVM 或其他文件系统不会自动解锁、组装或修复。
3. 每行填写一个相对文件系统根目录的文件路径，例如 `workspace/README.md`、`etc/os-release`。最多 8 个普通文件，合计 8 MiB；拒绝绝对路径、`..`、重复路径，以及解析后位于所挂载文件系统之外的链接。
4. 点击“提取备份文件”，等待任务完成后下载文件或导出恢复记录。后台先核对备份完整性、解密或重组内容块，再校验并展开独立磁盘；临时 Alpine 系统只读连接该磁盘后提取指定内容。每个下载文件再次核对大小与 SHA-256。

缺失文件、路径越界、超限、错误密码或损坏备份会使任务失败。失败前已经保存的文件仍可下载，界面不会将部分成功标为全部完成。任务保留备份标识、原文件路径、大小、哈希和耗时；请在删除源实例前下载所需文件。

## 生命周期与空间

任务期间所选备份受到操作锁保护，不能同时删除或改变其保留策略；进入救援阶段后源实例也被锁定，保持停止。临时系统网络隔离，使用 512 MiB 内存、1 vCPU、4 GiB 临时根盘，需要本机 Alpine 镜像和一个空余运行名额。

提取文件本身最多 8 MiB，但准备过程要读取完整备份并展开磁盘；加密、内容块重组和磁盘临时文件可能同时存在，应预留相应宿主空间。整个任务最多 30 分钟，单次文件收集最多 120 秒。取消、应急锁定或关闭服务会终止工作，先退出临时虚拟机，再移除解密、重组和展开文件。关闭网页不会取消已提交任务。

产物保存在本机数据目录中，沿用任务历史的保留与清理规则，不自动加密；加密备份提取出的文件是明文。此功能验证备份及指定文件能够读取，不代表已验证备份系统能够启动，也不是灾备演练功能。

执行接口为 `GET/POST /api/vms/:vmId/backup-recovery`，文件下载为 `GET /api/vms/:vmId/backup-recovery/artifact?run=...&artifact=...`，已纳入 OpenAPI 和生成 SDK。真实验证命令：`npm run test:backup-recovery`。
