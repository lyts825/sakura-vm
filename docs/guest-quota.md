# 客户机用户与目录配额

先在当前项目启用[项目磁盘配额](project-quota.md)。该配额卷限制整个项目目录的容量；“客户机目录配额”再按 Linux UID 设置卷内的用户硬上限。能力中心的 `status` 显示用户配额是否启用及客户机的 `repquota` 报告；`set` 输入 `uid` 和 `hardMiB`，`clear` 清除所选 UID 的限制。UID 必须是非 root 的现有用户，用户上限须小于项目上限。只有写入这个项目卷的文件计入用户配额，卷外文件不计入。

客户机需要配额工具：Alpine 安装 `quota-tools`，Debian/Ubuntu 安装 `quota`。当前 Ubuntu 云镜像还需安装与运行内核匹配的 `linux-modules-extra-$(uname -r)`；能力检查会在缺少模块时报告。设置操作会加载模块，启用 ext4 用户配额并保存开机挂载选项。Alpine 会注册 OpenRC 启动脚本，Debian/Ubuntu 由系统启动流程恢复配额。缺少工具或内核模块时不宣称配额已生效。

`clear` 只清除所选 UID 的限制，不关闭同一卷中其他用户的限制。移除项目配额卷时，Sakura 将项目内容迁回普通目录并保留镜像归档；配额元数据文件 `aquota.user` 也作为目录内容保留，需要时可在确认不再使用后自行清理。客户机采用 ext4 外置配额文件，工具可能提示该格式已弃用；能力会按实际内核状态和写入结果报告，不把仅有配置文件视为生效。

真实 Alpine、Debian、Ubuntu/QEMU 测试均验证了 UID 超额写入被拒绝、重启后继续拒绝、清除限制后可写入，以及随后移除项目配额卷。
