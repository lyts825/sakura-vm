# 可靠性演练工作台插件包设计

## 1. 版本、读者与交付边界

设计版本：**2.0.0**。应用版本保持 **2.6.0**，源码基线为 `86f589a`，宿主插件 API 为 `5`。运行实现状态：**待开始**。本文中的插件、服务、命令和路径均为拟议设计，尚未注册或发布。当前运行目录仍为 69 个插件、13 个包。

本文面向插件开发者、应用维护者和验收人员。目标是让维护者在受管隔离副本中复现故障，核对恢复后的业务结果，并把可复核的演练记录交给其他人。第二批设计的共同规则见[总览](plugin-pack-expansion-design.md)。

拟议包 ID 为 `resilience-lab`，包含 10 个插件。完整流程为：固定来源 → 创建隔离副本 → 验证正常基线 → 注入有期限的故障 → 观测影响 → 验证恢复 → 封存报告 → 清理资源。包内只处理自己创建且归属已确认的演练资源。

首版不注入生产 VM、原项目、宿主网卡、宿主磁盘、真实电源控制器或跨主机网络故障。不接管用户已有 VM，不开放任意 root 命令，不运行生产自动修复规则。真实 BMC（Baseboard Management Controller，基板管理控制器）、第三节点和生产流量演练继续采用[独立部署流程](ha-external-drill.md)，不会因本包报告通过而变成已验证。

“恢复成功”限于本次固定副本、场景和断言。没有实际写入与读取证据时，不报告业务恢复成功；本地故障耗时不能推算生产可用性或真实灾备时间。

依赖图无环。`projects` 是唯一外部必需插件。本包不依赖整个 `foundry`、`delivery`、`app-runtime`，也不依赖本批另外两个新包。包声明仅组合精确版本成员，不拥有另一套资源或执行入口。

可选提供者缺席时，本地固定镜像与合成业务数据流程仍完整可用。`app-targets` 只提供来源选择和修订说明；原应用不接受故障指令。`metrics` 的额外宿主采样仅供诊断，不替代业务探针。报告将来可由交付或知识插件消费，但当前没有假定 `delivery-reports` 已支持接收外部演练证据。

`foundry-catalog` 来源每次使用都须核对 `authorizeUse` 的当前结果与撤回状态。已运行的副本若发现来源撤回，停止下一步注入并安全收尾。提供者停用后，不继续使用需要重新核验的来源；已封存报告仍可读取。

## 4. 本体边界与待补接口

本包沿用[插件设计契约](plugin-design-contract.md)。可信插件仍与宿主共用进程，类型和源码门禁不等于操作系统沙箱。故障执行不得通过动态 Shell、私有 `Machines`、另一插件实现类或裸进程句柄绕过公共边界。

| 边界 | 当前状态 | 本轮拟议补充及责任 |
| --- | --- | --- |
| ImageAssetsV1 | 已有 | 自有 VM 创建、镜像引用、停机捕获、精确销毁仍由本体持有原回执；插件不复制账本 |
| WorkspacesV1.runPrepared | 已有 | 仅运行准备好的项目；缺少工具拒绝，禁止在演练执行时下载、安装或运行 setup |
| 元数据、Jobs、执行能力、RecoveryCatalog | 已有 | 复用修订串行提交、取消、原领域恢复目录；任务状态不代替进程退出或资源释放证明 |
| DrillSupervisionV1 | **拟议新增本体公共服务** | 建立独立监管、固定副本授权、故障执行与收尾回执；只暴露预定义动作，不提供任意宿主命令 |
| 演练副本使用票据 | **拟议新增本体授权协议** | 由创建副本的原 fixtures 消费者签发请求，本体核验后授予指定插件实例有限操作；不转移 VM 所有权 |
| 演练互斥租约 | **拟议扩展本体准入** | 持久绑定原 VM、项目、网卡与卷，协调准备、故障、恢复和捕获；人工紧急停止可抢占并使演练失效，不与安全收尾互相等待 |
| 演练副本恢复交接 | **拟议增强本体回执协议** | 在同一演练 owner 内，证明旧副本已停止、新副本独立且来源固定，再绑定新的项目和 boot 代次；现有 ImageAssetsV1 没有该事务语义 |
| 备份副本来源桥接 | **拟议兼容扩展** | `BackupsV1` 当前有验证文件租约与恢复操作，但没有面向本包的不透明镜像移交回执；需新增验证、脱敏确认、只读导入桥接，不能直接调用 restore 后按 VM ID 接管 |

`DrillSupervisionV1` 的最小操作面如下。签名细节在实施阶段冻结为严格类型，表中动作不代表已经存在。

| 操作 | 输入约束 | 输出与权限 |
| --- | --- | --- |
| preview | 原消费者、固定副本、项目修订、故障目录版本、全部预算、绝对截止 | 返回不可变计划摘要、能力缺口和预计清理对象；无副作用 |
| arm | 单次批准、计划摘要、原副本回执、由 fixtures 请求签发的有限授权 | 建立监管与互斥，先保存收尾责任，再向 guard 发放不可转让的管理租约；不注入故障 |
| authorizeStep | guard 原管理租约、计划中已登记的步骤和消费者身份 | 本体从原 fixtures 授权派生绑定 faults、probes 或 recovery 实际实例的动作票据；不能扩大动作、参数或期限 |
| inject | faults 原动作票据、预批准步骤序号、幂等键 | 固定适配器核对真实调用者与代次，先持久化意图，再执行；返回 observed、absent 或 unknown |
| observe | 原故障回执 | 读取原命名空间、规则句柄、cgroup 或卷的实际状态；不能扩展授权 |
| contain | 原租约与取消或到期原因 | 先封锁新注入，再撤回原故障；必要时停止原副本，不启动恢复业务 |
| reconcile | 原意图和身份回执 | 只核对未知副作用、监管存活和收尾证据；不重放 inject |
| release | 原租约及完整清理证明 | 原资源域确认后归还额度，缺证据时保留 cleanup-pending |

独立监管必须由本体受管进程与真实句柄实现。插件只持有不透明回执。监管进程不能与普通业务取消信号一起提前终止；原责任未确认时，插件停用仍须留下本体收尾入口。未来若需要修改既有服务的不兼容语义，应另建版本，不能偷偷改变 V1。

副本使用票据绑定原 `OwnedImageVm`、演练 ID、计划摘要、被授权插件实例及 generation、允许动作与截止时间。faults 只能注入已批准故障，probes 只能执行固定探针，recovery 只能执行已批准恢复。本体逐次核对真实调用者，拒绝仅凭 owner 字符串、VM ID 或调用方传入的 `OwnedImageVm` 取得控制权。停止须有明确的有限授权；捕获与销毁始终由 fixtures 原消费者调用。批准不能授权任意消费者，同包插件也不共享资源所有权。跨服务保持原消费者身份，不假扮 fixtures 所有者。

具体发放顺序为：guard 调用 fixtures 的拟议 `authorizeDrill`；fixtures 核对原副本、已批准计划及受允许的消费者后，请求本体记录有限委派；guard 使用该委派执行 `arm`；本体按预批准步骤派生各消费者自己的动作票据。guard 的管理租约只能用于编排准入、封锁与安全收尾，不能交给 faults 使用。runs 只编排插件公共服务，不直接持有可绕过原服务的故障票据。`authorizeStep` 不开放客户端 HTTP；客户端不能任意指定被授权实例或增加步骤。

期限分为不可延长的 `faultDeadline`、覆盖正常恢复和观察的 `runDeadline`，以及仅用于核销原资源的清理权限。故障票据到期后禁止新注入并触发撤回；故障已确认撤回、原场景未取消且仍在 `runDeadline` 内时，本体才允许签发计划内 recovery/probes 的后续动作票据。后续票据不延长旧故障期限。取消、演练总到期、权限撤销或身份变化撤销业务动作，只保留原资源的安全收尾。清理权限不允许重新启动业务或创建副本。

## 5. 首次使用与来源固定

### 5.1 零 VM 首次使用

启用 `resilience-lab` 后，服务重启才激活。顶级“可靠性演练”页面无需选择 VM。空态显示模板、镜像与工具要求、预计资源和离线导入入口；不自动下载镜像、创建 VM、联网、采样或执行故障。

用户先登记本地镜像，或者显式准备本体内置镜像。准备动作可能下载文件，必须单独展示来源和下载规模。故障运行阶段只使用固定摘要的本地资产。镜像缺少工具时，页面列出缺项，并提供镜像准备说明；不会自动补装。

选择模板后，用户上传或选择本地合成业务样本，固定启动定义、探针和恢复断言。预览显示新建副本、镜像摘要、业务样本摘要、磁盘和内存预算、网络隔离、故障强度及到期后的停止动作。批准后才创建和准备副本。

### 5.2 来源与副本

TargetRevision 记录来源种类、来源修订、镜像摘要和业务样本清单。来源可以是本地固定镜像、已授权工坊资产或经可选桥接导入的已验证备份。应用来源选择仅附加应用标识、当前修订和人工说明，不复制应用 secrets、生产网络策略或流量入口。

首版默认使用合成数据。导入真实备份须先停留在隔离预检阶段，检查启动项、挂载、外部连接配置和秘密文件，列出无法判断的内容。自动扫描不能证明全部数据已脱敏；用户须审阅数据清单。未审阅来源不得进入故障步骤。

每个副本由本包的 fixtures 消费者通过 ImageAssetsV1 创建，保存 `OwnedImageVm` 原回执。首版不支持把已有 VM 标为本包所有。目标说明中的原 VM 与演练副本分开存储；任何销毁请求只能引用演练副本回执。

副本默认持久隔离，无共享宿主目录、外网出站或公开入口。管理连接由本体提供。项目只使用已准备工具，不包含仓库初始化、运行时准备或安装脚本。基线完成后可停止自有副本并封存检查点，再按受管启动交接取得新 boot 身份。

### 5.3 首版模板

| 模板 | 正常基线 | 故障与恢复 | 验收输出 |
| --- | --- | --- | --- |
| HTTP 延迟与重试 | 合成服务按请求 ID 返回固定业务结果，记录正常耗时和错误数 | 在专用测试网卡增加延迟或丢包，到期撤回并验证恢复 | 各阶段样本、超时与重复提交计数、恢复窗口 |
| 工作进程重启 | 队列样本可读取，已确认任务有固定结果摘要 | 停止一个受管工作进程，按计划重启同一固定版本 | 处理中任务的结果、重复执行检测、未完成项 |
| CPU 争用 | 固定负载下记录业务请求和任务完成时间 | 在有硬配额的独立 cgroup 运行有限工作器，到期清理 | 故障强度实测、业务结果、配额和进程退出证明 |
| 数据卷写满 | 在专用测试卷写入带序号样本并读回 | 只填满该测试卷的保留区域，验证写入失败和恢复后写入 | 已确认写入集合、恢复后集合、缺失或重复项 |
| 检查点恢复 | 固定检查点中包含已确认数据集 | 停止当前副本，恢复独立新副本并验证数据及业务 | 检查点摘要、旧新身份交接、实际恢复耗时 |

模板是可编辑的结构化场景。编辑后必须生成新修订，重新跑正常基线和审批。不能把模板中的演示结果当作本机验证证据。

## 6. 身份、预算与互斥

### 6.1 固定身份

每次演练同时绑定控制器运行代次、插件实例与 generation、目标修订、来源摘要、VM ID 与 createdAt、原磁盘身份、宿主 VM 进程创建身份、客户机 boot ID、项目 ID 与配置修订。项目进程另绑定启动票据、进程组或 cgroup 标识和启动时刻。PID 不能单独用作终止依据。

预览和执行之间任一字段变化，计划失效。普通 VM 重启也会失效；本包不因 VM ID 相同自动续接旧演练。原进程存活状态未知时，不能复用该副本执行新步骤。

恢复副本的交接有明确前后条件。交接前锁定原 Run、旧 ReplicaBinding 和新 ReplicaReceipt，确认新副本来自固定检查点且归同一 fixtures 消费者。先停止旧副本并取得原执行权的撤销证明，再验证新项目及 boot 身份，最后以修订比较提交新绑定。提交丢失响应时可查询同一交接回执，不重复创建副本。

交接后，旧故障令牌、探针票据和恢复命令全部失效。历史记录保留旧身份；不把旧 VM 的清理权限转移到新 VM。停止旧副本不等于删除其磁盘，删除仍须核对原回执及证据保存策略。

### 6.2 预算

下表是**首版拟定硬上限，实施前资源实测可收紧，不是当前性能保证**。宿主已有更低预算时以更低值为准。超限拒绝或等待，不创建无界队列。

| 项目 | 首版上限与规则 |
| --- | --- |
| 同时执行 | 每宿主 1 个演练、1 个活动故障；恢复期间最多保留 2 个本包副本 |
| 故障期限 | 单次最多 120 秒；固定截止不可续期；提前取消先撤回故障 |
| 演练期限 | 总共 20 分钟，准备最多 10 分钟；副本最长保留 60 分钟后停止，磁盘按保留策略处理 |
| VM 资源 | 每副本最多 2 vCPU、2 GiB 内存、32 GiB 虚拟磁盘；须同时预留新旧副本与导入临时空间 |
| 数据样本 | 每场景 2 GiB、10,000 个文件；单文件 256 MiB；拒绝设备、链接逃逸与特殊文件 |
| 网络故障 | 延迟最多 500 ms、抖动最多 100 ms 且不大于延迟、丢包最多 10%；只作用于专用测试接口 |
| CPU 故障 | 仅一个压力工作器，专用 cgroup 最多占一个 vCPU 的 50%；不得提高 VM 总配置 |
| 写满故障 | 专用测试文件系统最多 128 MiB；只填固定保留目录，监管和验证记录空间位于故障卷之外 |
| 探针 | 每阶段最多 4 个探针；HTTP 合计最多 10 请求/秒、并发 2；单响应最多 64 KiB，超时最多 3 秒 |
| 采样与报告 | 单演练最多 20,000 条样本、50 MiB 日志、200 MiB 报告；超限标记证据缺失，不截断后仍报告通过 |
| 包内持久容量 | 报告及样本共 5 GiB，输入库共 8 GiB，本包引用的检查点逻辑大小共 64 GiB；另计活动 VM 和临时空间，不以共享去重降低准入预留 |
| 离线包 | 压缩文件最多 2 GiB，展开总计 3 GiB，最多 10,000 个条目，单条目最多 256 MiB，主清单最多 10 MiB；上传、导出与解压逐段计数，超过即中止 |
| 排队 | 最多 5 个待运行计划；到期计划离开队列，运行时重新核对身份和资源 |

这些风险预算独立于业务可用性阈值。不能用“错误预算尚有余量”延长故障或绕过宿主资源预算。

互斥同时覆盖副本、项目、测试网卡、测试卷和原进程票据。注入、恢复、关机捕获、清理不得并发；观测只能在原租约下只读。普通项目编辑、核心启停或镜像操作造成身份漂移时，演练封锁后续步骤。实施时必须将这些冲突接入本体准入；仅在 UI 禁用按钮不算互斥完成。

## 7. 故障执行与截止保证

### 7.1 首版故障边界

| 故障 | 固定实现方向 | 执行前条件 | 明确不支持 |
| --- | --- | --- | --- |
| 网络延迟、抖动、丢包 | 在副本专用网络命名空间与 veth 上设置带独占句柄的 `netem` | 规则位置为空、监管管理通道不经过测试接口、内核与工具能力通过预检 | 修改管理 `eth0`、宿主网卡或已有根队列；改变 DNS、互联网路由或真实对端 |
| 工作进程中断 | 停止本包以普通项目账户启动的指定进程组 | 精确启动票据、父子关系、原 cgroup 和进程创建身份一致 | 按名称杀进程、任意 PID、停止数据库宿主或未归属进程 |
| CPU 争用 | 固定压力程序运行在独立 cgroup v2 中 | 硬 CPU 和进程数配额已经生效，压力程序摘要固定 | 宿主压力、无限 fork、内存耗尽、模拟任意 CPU 硬件故障 |
| 数据卷写满 | 在专用有上限文件系统中填充固定保留文件 | 卷身份、容量上限、挂载边界和可释放空间已经验证 | 填满根盘或宿主盘、随机磁盘损坏、真实 I/O 控制器故障 |
| 检查点恢复 | 停止本包副本后从固定镜像创建新副本 | 旧副本停止回执、检查点完整、恢复预算已预留 | 宣称已验证停电一致性、在线复制一致性或跨主机自动接管 |

CPU 配额与测试卷容量须读取内核实际值。预览容量或定时采样不能充当硬限制。网络恢复只删除本次规则，不能按“当前是 netem”删除其他规则；规则漂移时封锁该副本，必要时停止副本，保留未知状态。

### 7.2 截止与独立监管

故障注入前必须先启动客户机监管和独立宿主监管，并取得双方的真实就绪回执。故障目录固定每种动作的撤回方案与停止后果。监管收到的授权只允许结束原故障、撤销演练入口或停止原副本，不允许启动业务、接通外网或扩展故障。

客户机监管持有不可延长的单调时限和固定故障句柄。宿主监管独立于主 Node 控制器，持有精确 VM 进程句柄与停止权限。主进程被冻结时，故障到期不能依赖其事件循环或经它转发的 QMP（QEMU Machine Protocol，QEMU 控制协议）请求。这个能力是待实现的本体缺口；现有网络 worker 的父进程转发路径不足以直接承担它。

截止到达后立即禁止注入或续约。正常目标是先撤回故障，再观察原规则或压力进程确实不存在；无法确认时由独立监管停止原副本。首版验收窗口拟定为到期后 5 秒内取得撤回或停止的实际证据，超出即记为截止验收失败并禁止该适配器继续使用。

这一窗口只针对已验证的本机运行环境，不是任意操作系统故障下的实时保证。宿主休眠、整个内核冻结、监管与客户机同时失去调度、硬件失效均可能阻止及时观测或执行。复苏后先保持演练封锁并核验旧副作用；记录期限违规，不补写准时清理证明。不能把进程定时器、计划到期字段或操作超时当成故障已经停止。

主进程退出和冻结须分别验证。进程退出时的父子生命周期回收不能证明父进程冻结时仍能收尾。插件卸载不得先杀死唯一监管者；所有监管者退出前，原资源域必须确认本次故障已撤回或副本已停止。无法证明监管独立性时，故障按钮不可用，只提供计划编辑和离线报告。

## 8. 场景、基线与恢复判定

ScenarioRevision 固定有序步骤、故障参数、探针修订、业务成功条件、数据断言、恢复动作、全部期限和预算。首版每场景最多 8 步，不支持循环、条件动态生成命令或故障叠加。保存草稿不产生执行授权。

正常基线至少运行 60 秒，要求最小样本数、错误数上限和固定业务断言通过。无样本、超时、缺少探针工具和日志读取失败分别记录。不能把无数据视为零错误。分位数报告必须显示样本数、观察窗口和算法版本；样本不足时显示不足，不使用孤立数值比较恢复效果。

故障生效须同时有适配器观察回执和业务样本。未观察到预期影响可以形成“故障无效”结果，不能用注入命令退出码替代。请求以唯一 ID 关联，避免重复提交被误算为两次成功。演练时钟记录阶段单调耗时和墙钟时间；跨重启失去单调连续性时，不输出精确总恢复时间。

恢复策略仅有三类：撤回故障后观察；重启原受管工作进程；从固定检查点创建新副本。每类策略绑定完整参数、原身份和恢复后断言。首版不接受任意修复 Shell，也不自动修改生产 Runbook。

安全收尾与业务恢复分开授权。取消、到期或失联允许监管撤回原故障、关闭入口和停止原副本。这不会自动批准重启业务、恢复磁盘或创建新副本。完整场景批准可包含明确恢复策略；如果场景被取消或身份变化，恢复批准失效，须另行预览。

恢复至少经过 60 秒稳定窗口，确认实际服务响应与预定义数据集合。检查点恢复报告区分“检查点已有数据”“检查点后确认写入”和“恢复后读回数据”。数据丢失必须据此逐项计算；缺少确认记录时报告未知，不能给出零数据丢失。恢复时间起止事件固定在场景中，不使用宿主估算替代实测。

## 9. 状态机与中断处理

### 9.1 计划与运行

计划状态为 `draft → previewed → approved → consumed`；旁路终态为 `expired`、`revoked` 或 `stale`。预览有效期 5 分钟，批准单次消费并绑定当前 owner 会话、计划摘要及全部修订。仅修改标题或附件说明可不改变执行修订；修改参数、样本或断言必须重新预览。

运行状态为 `queued → preparing → baselining → armed → injecting → observing → recovering → verifying → cleaning → completed`。失败或取消都先进入 `containing`，再进入 `cleaning`。控制器重启后，非终态统一进入 `reconcile-required`，不重放故障、恢复、数据写入或待运行队列。

运行分别保存 `outcome`、`containment` 和 `cleanup`。`outcome` 可为 passed、failed、cancelled 或 inconclusive；收尾和清理分别为 confirmed、pending 或 unknown。只有断言通过、故障实际撤回、资源清理确认且证据完整，才允许封存为 `passed`。

每步执行前先提交 StepIntent，包含幂等键、预期前态、租约与目标身份。响应丢失时查询原回执。无可靠查询或无法辨别是否发生副作用时，记录 unknown，封锁后续写入，不自动重试注入或恢复。

### 9.2 并发、取消与核销

| 事件 | 行为 | 需要保留的证据 |
| --- | --- | --- |
| 同时编辑或重复批准 | 以修订比较拒绝后到者；单次批准只能消费一次 | 原修订、请求幂等键与冲突结果 |
| 注入中取消 | 先取消后续步骤，再由监管核验或撤回原故障；不因请求已取消跳过清理 | 注入意图、实际故障回执、取消时刻 |
| 控制器重启 | 封锁并核销原运行；监管继续只收尾 | 原运行代次、监管身份、故障截止与回执 |
| VM 重启或同 ID 重建 | 旧票据全部失效；不得向新 boot 或新创建实例执行旧指令 | 原 createdAt、磁盘、boot 与当前差异 |
| 监管丢失 | 停止准入，由剩余监管封锁原副本；无法确认停止时显示 unknown | 原句柄及失联记录，不按裸 PID 清理 |
| 清理权限或磁盘访问丢失 | 保留资源、额度及 RecoveryCatalog 记录 | 原 owner、路径边界、失败原因和可重试动作 |
| 清理成功但提交失败 | 查询同一销毁或撤回回执，确认后补交状态 | 原资源域完成证明；不重复删除新资源 |

核销只读观察和安全收尾可重复请求，但每次只能作用于原票据。人工填写“已处理”不能释放额度或抹去 unknown。需要新恢复操作时，先核销旧故障，再生成绑定当前身份的新计划。

## 10. UI、HTTP 与 CLI

顶级页面按“来源与样本、场景、运行、报告、待处理资源”组织。运行详情显示阶段、固定目标、实际故障、截止、恢复状态和清理状态，不能用一个绿色任务状态覆盖其他未知项。取消按钮始终指向原运行；页面刷新只恢复查看，不恢复执行。

所有入口使用相同的公共服务、严格请求契约和 owner 会话。读取需要来源范围权限，导出另核对内容权限。写入在服务端复核维护状态、锁、固定身份和审批；不能从 HTTP 方法或 URL 推断权限。

下表中的路由及 CLI 为拟议命名，当前不可执行。实现不得只提供一个绕过领域校验的通用 `act` 命令。

## 11. 证据、离线交接与数据生命周期

### 11.1 报告与比较

报告保存场景及模板版本、固定来源、各阶段身份、批准摘要、故障实测、探针样本、数据断言、时间区间、未知项、恢复和清理回执。原始样本与汇总算法版本同时保留。用户可另加说明，不能改写原始结果。

比较只在来源、业务样本、探针和场景参数兼容时提供直接差值。镜像、CPU 配额或负载变化必须显示差异。来自不同宿主或未认证导入的结果可并排查看，但不自动判定性能改善或生成发布许可。

已封存报告及已接受的外部报告依靠自身引用快照读取，不要求原 VM 仍存在。授权以报告归属与当前读取权限核对；删除原 VM 不扩大读取权限，也不会使报告无法查看。可执行的重新演练仍须另建本地目标。

封存分为通过、未通过和不完整三类，均可导出。尚有资源未清理的报告可导出草稿，必须包含剩余责任；后续清理形成新的补充回执，不能覆盖旧导出物。

### 11.2 导出与隔离导入

导出包默认只包含报告、结构化样本、脱敏日志、场景定义及引用清单，不包含镜像、磁盘、秘密、账户会话、审批令牌或可用执行票据。用户可显式选择附带已经审阅的合成业务样本，界面先显示新增文件和总字节数。

清单使用固定格式版本，记录每个条目的规范相对路径、大小、摘要、内容类型和用途。离线 verify 核对清单、所有条目、报告引用和汇总一致性，拒绝路径穿越、绝对路径、符号链接、重复路径、大小写碰撞、未声明文件、超量解压和嵌套压缩包。离线解析不渲染脚本或活动 HTML。

首版导出物默认无发布者签名。摘要只能检查文件一致性，不能证明报告真实发生或发布者身份。校验结果必须同时显示 `integrity` 和 `sourceTrust`，无签名内容标记“来源未认证”。即使全部摘要正确，也不能自动授予执行权限或视为本机验收通过。

import 先保存到独立隔离区，展示来源、版本、完整性和敏感字段扫描结果。accept 只接受为外部参考报告或场景草稿，并分配新的本地 ID。导入的 VM、项目、PID、boot、租约、审批和恢复令牌全部保留为不可执行的来源文字，不映射为本机权威身份。重新演练须重新选择本地来源、预览、批准和验证。

### 11.3 凭据、保留与清理

首版模板不使用生产凭据。测试服务的认证令牌由每次副本临时生成，只注入已授权进程，不写入模板、计划、日志或导出物。日志先遮蔽已知令牌，仍允许用户在导出前预览并排除字段；自动遮蔽不能保证发现任意秘密。

默认保留最近 30 次演练报告及其样本，最长 30 天；用户固定的报告仍受 5 GiB 总容量预算约束，固定操作不能无限扩容。副本成功清理后保留元数据回执。报告引用的输入摘要、检查点和样本不能提前回收；创建导出任务时先持有读租约，导出完成或取消后释放。

这些输入及检查点引用由 fixtures 原服务提供拟议的 `retainInput/releaseInput/openInputRead/closeInputRead`，reports 通过直接依赖调用。读取只返回获准样本或只读引用信息，不返回副本控制票据。先登记保留，再封存报告；取消或崩溃导致保留结果不明时，核对原幂等回执，不能先删输入。报告归档且没有活动导出后才允许释放相应引用，释放不等于授权删除底层内容。

未核销运行、待清理资源和有效引用不因保留期到期自动删除。报告、输入、检查点、VM 或临时空间任一额度不足时，拒绝新任务并显示实际占用。用户可导出并解除已结束报告的固定或引用，再审阅清理；不得为新任务强删仍受保护的内容。副本创建、检查点捕获和离线包展开均按峰值同时预留，不能只检查最终文件大小。

清理先生成包含精确 owner、修订、引用和资源列表的短时计划，再执行。先停止探针和业务进程，撤回原故障，确认监管不再需要，销毁自有副本，最后释放镜像引用。清理失败保留原资源租约和待处理入口，不能因为任务终态、插件停用或保留期到期而删除证据或释放额度。

本包产生的正式模板与说明可纳入 Git。实际演练数据、日志、报告、截图和本地验收脚本属于测试材料，使用精确忽略规则保留在本地，不纳入 Git。不能按“未跟踪”或“已忽略”无差别删除用户文件。

发布必须同时满足以下正常与故障条件。测试材料保留本地，Git 只记录简短验证结论。

| 验收场景 | 必须观察到的结果 |
| --- | --- |
| 独立启用、零 VM、可选插件全部缺席 | 仅启用本包及 projects，使用本地镜像和合成数据跑完 5 个模板；无隐式下载或联网 |
| 基线缺工具、无样本或断言失败 | 不注入故障，显示具体缺项，资源收尾可核验 |
| 网络、CPU、卷与进程故障 | 观测真实变化；不影响管理网卡、根盘、其他进程或其他 VM；撤回与恢复均有实际证据 |
| 主控制器冻结超过故障截止 | 独立监管在指定窗口内撤回故障或停止原 VM；不依赖父进程 QMP 转发；窗口不达标就禁止该故障发布 |
| 控制器强制退出、监管退出、VM 卡死 | 分别验证，不以其中一种替代其他情况；未确认资源显示 unknown 并阻止继续演练 |
| 宿主休眠与恢复 | 记录是否超期；恢复后先封锁及核销，不补造准时清理或自动恢复业务 |
| VM 同 ID 重建、boot 改变、项目修订变化 | 拒绝旧计划和旧停止票据；不能作用于新资源 |
| 重复批准、并发执行、注入时取消 | 至多一次副作用，禁止故障叠加；取消仍完成原收尾或保留明确待清理责任 |
| 故障写入后响应丢失、元数据提交失败 | 查询原回执；无法确认时停止推进，不盲目重试 |
| 新旧副本恢复交接中断 | 原身份和来源可重查，旧执行权已撤销后才授权新副本；无双运行、无旧票据越权 |
| 检查点恢复的数据检查 | 能检出丢失、重复和未知写入；缺证据不能报告零丢失 |
| 来源撤回、提供者停用、报告引用保留 | 新操作拒绝；旧报告可读；引用中资产不会提前删除 |
| 导出篡改、恶意路径、解压超限与令牌检查 | 离线拒绝不合格包；有效无签名包标来源未认证；导入不执行、不映射控制权限 |
| 清理失败及服务重启 | 原资源、额度、监管责任与恢复入口仍在；确认原域回执后才释放 |
| 独立运行包 | 不依赖源码或开发加载器，监管和探针资产摘要可核验；默认包仍不自动启用 |

首版验收以实际支持并测试的宿主和客户机组合列明范围。尚未通过的操作系统、内核能力、监管故障组合与真实生产演练必须标记未验证，不能从本地模板通过推导为支持。
