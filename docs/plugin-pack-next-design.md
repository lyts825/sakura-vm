# 第四批十个完整插件包设计

## 1. 版本、范围与完成标准

插件包设计系列：**3.0.0 → 4.0.0**。日期：2026-10-25。应用版本保持 **2.7.0**，核对提交为 `237d7bc`，宿主插件 API 为 5。本文面向产品维护者、各领域实现者和验收人员。

本轮增加 10 个完整插件包，共 **114 个拟议插件**，承接[第三批设计](plugin-pack-suite-design.md)。4.0.0 沿用现有设计批次版本习惯，代表新增一批设计，不是应用主版本升级，也不替换前三批的定义。

当前分支为 `codex/plugin-management`，工作区有事件复盘等 2.8.0 实施改动。读取工作区声明得到 130 个插件、19 个整合包，其中包含尚未提交的登记；这个数字只表示声明目录，不代表运行就绪或功能验收。本轮不修改这些实现，不把本批插件加入目录或 `complete`。

每个包都须支持首次配置、独立输入、核心处理、人工复核或结果判断、版本保存、离线交接和原资源清理。插件按独立对象和生命周期拆分，数量随职责确定。只提供页面入口、名称列表或一个可运行命令，不能作为完整包交付。

## 4. 独立使用与跨包协作

十个新包之间没有必需依赖。每个包提供可本地输入的模板和固定材料格式，支持缺少在线适配器时完成明确范围内的流程。模拟报告、人工记录、外来声明和本机真实执行必须分别标识。

| 使用模式 | 必须可完成的工作 | 完整包验收的额外条件 |
| --- | --- | --- |
| 需求、架构、权限、容量、发布审查 | 导入、编辑、检查、复核、封存、交换和清理 | 完整业务用例及旧修订/撤权/导入异常通过 |
| 代码改造、性能、测试数据 | 输入与定义可独立编辑，缺少执行条件显示准确原因 | 使用固定工具真实生成或执行，取得原始证据并核销资源 |
| 集群基线 | 离线观察、漂移、例外、变更建议和交接 | 拟议在线采集与支持动作须经原提供者实测；缺席时不能标为已应用 |
| 恢复验证 | 目标与计划、历史档案审阅、固定材料核验 | 实际独立恢复、业务探针和全部原资源清理通过 |

跨包使用以显式导入固定材料为基础。例如，需求基线可以作为发布范围来源；测试数据可以作为性能实验输入；容量方案可以引用恢复副本的资源要求。接收方必须检查对象类型、修订、摘要、适用范围和缺项，不能只读取另一包的“通过”标签。

一个包的审阅结果不授予另一个包的执行权限。依赖发生变化时，原结果保留，新的引用显示过期或不可比。首版不自动订阅其他包的“最新版本”，不因打开页面而启动后台任务。

## 5. 插件与服务契约

沿用[插件设计契约](plugin-design-contract.md)及[协议](plugin-protocol.md)。详情中的每行是一个独立插件，列出专属对象、服务名、业务方法、直接必需依赖和直接可选依赖。服务名均为接口草案，不代表当前可调用。

所有持久定义服务还须提供分页 `list/get`、带 `expectedRevision` 的 `save`、固定版本 `seal` 和 `archive`。结果服务提供按固定 ID/修订读取、来源及覆盖查询。存储者提供引用查询、清理预览及原修订提交；聚合服务不能替原存储者删除数据。

共同对象至少包含 `workspaceId/id/revision/schemaVersion/contentDigest/createdAt`。`SourceRef` 另存来源类型、来源修订、许可和固定字节摘要；`Result` 保存输入引用、工具/规则版本、覆盖范围及证据性质。授权主体由服务端绑定，客户端传入的 owner 不生效。

定义状态为 `draft → sealed → archived`。封存后修改产生新修订；人工决定记录审阅时的输入和主体。任务状态为 `queued → preparing → running → finalizing → completed`，失败、取消和中断分别保存。`completed` 只表示处理结束，业务结论与 `pending/confirmed/unknown` 清理状态另列。

实现者不得把任意 `permissions`、`sandbox` 或脚本执行字段写进现有 manifest，宣称宿主已支持。新增本体能力使用显式版本服务，原有 API 5 与冻结契约的含义保持不变。社区 WASM 插件不因此获得可信源码插件的权限。

## 6. 页面、接口和命令的一致体验

每个工作台提供总览、输入、核心对象、结果、审阅、交接和清理入口，详情可按任务调整命名。空状态有模板和缺项说明；模板只生成草稿。列表支持分页和筛选，长正文分段读取，错误保留用户输入并提供恢复入口。

计划确认页显示全部输入总数、固定版本、完整目标范围、工具、预算、输出和潜在外部动作。展示分页不减少批准范围；批准绑定服务端完整计划。不能在预览后静默补入其他材料、主机或检查规则。

详情中的命名操作统一采用 `POST /api/<插件ID>/<方法>`，读操作也逐项声明只读策略。上传、下载和分块读取另设严格二进制路由。每条路径对应固定请求、响应和操作策略，不提供任意服务名或方法名分发。

提交响应包含 `operationId`、适用的 `jobId/runId` 和查询入口。业务冲突、旧修订、来源撤权、不支持、容量不足和清理待确认使用稳定错误码。分页查询返回游标、固定查询修订及总量/截断说明；导出不能把第一页当成全量对象。

CLI 统一以 `sakura <包别名>` 开头，提供 JSON 输出、固定 ID 读取、预览、提交、状态、等待、取消和核销。普通查询成功返回 0；执行命令按最终结果返回 0/1/2/3/4，分别表示完成、已知业务失败、输入或传输错误、不确定或不支持、清理待确认。异步提交的 0 只表示接收。

离线 `verify` 是本地命令，不启动宿主、联网或执行导入材料。所有包都要在独立安装产物中验证 CLI 和离线核验，不能依赖开发目录内的 TypeScript 加载器。页面同时复用亮色、夜间、窄屏和键盘操作约定；锁定及账号切换后清除私有页面数据。

## 7. 授权、执行和恢复

创建空间、读取来源、外部动作前及输出提交前都复核当前授权。业务中的负责人、复核人和决策人是记录字段，不自动创建宿主新角色。单人完成多个阶段时如实记录，不能表示多人独立批准。

执行计划固定输入、目标、当前权限修订、工具摘要、资源上限和截止。默认有效期 5 分钟，批准只消费一次。同一计划重复提交返回原回执；输入改变、过期或身份改变须重新预览。已有授权仍有效且计划未变化时，无需重复确认。

所有有副作用动作先保存意图和原查询入口，再交给原执行者。网络断开、控制器退出或服务换代后只核对原回执，不推断成功、不自动重放。清理只针对原租约、原进程和原 VM 身份，不能借恢复新建资源或扩大业务范围。

新增执行包均使用固定工具协议和受管副本。工具镜像、版本、动作集合和支持平台必须经实际验证。任意上传脚本、测试钩子和项目启动代码如果确需运行，必须在计划明示的隔离执行域内，不能转成宿主命令。

原副本核对创建回执、运行寿命、boot 身份、项目及配置摘要。独立截止机制必须在控制器退出后仍能终止执行；未证明这一点的工具模式不得标为可用。取消先停止新调度，再等待原执行域退出，释放资源须有原提供者证明。

包含运行清理结论的最终报告，必须在原执行资源核销后封存。提前保存的中间报告明确标为清理待确认；取得新回执后生成新修订。导出传输租约由后续交接账本核销，封套不能声称包含自身尚未发生的传输完成证明。

## 9. 交换、容量和清理

继承[第三批总览](plugin-pack-suite-design.md)的有界封套规则：格式为 `sakura-<包ID>/1`，使用 ZIP STORE，拒绝路径穿越、链接、压缩、ZIP64、重复路径和大小写碰撞。清单固定条目长度与摘要，原字节和派生字节分别记录。

导出预览列出完整材料及缺项，默认不携带秘密、原凭据、活动租约、未审阅私人字段或整份备份。导入依次完成大小、结构、摘要、引用、模式和业务约束检查，在隔离空间审阅后显式接受。接收生成新 ID，保留来源映射；旧批准、路径、运行回执和权限都不成为本地授权。

离线核验分别说明字节完整性、来源认证、可重算范围和缺项。摘要一致不等于来源真实，也不等于业务结论可靠。没有配置并验证签名时，来源为未认证；本轮不承诺已实现新的签名基础设施。

详情里的容量和时限均为待实测的拟定硬上限。实际准入取单对象、空间、包和宿主共同额度中最严格者，十个包的额度不能简单相加。当前共同总额默认 8 GiB，覆盖范围见[容量说明](suite-capacity.md)；第四批尚未接入，设计大额度不自动修改配置。

源字节、派生字节、导入隔离、导出暂存、解密暂存和未确认资源都计费。VM 按声明的虚拟磁盘容量预留，同时报告实际分配字节。每包预留 32 MiB 控制账本；控制 JSON 默认 1 MiB，分块默认 512 KiB，短期读租约最长 15 分钟。

保留策略先生成候选，清理前展示对象、字节和保护引用。停用保留正式材料；活动任务、导出或无法核对的占用阻止删除。仅清理本插件确认拥有且无人保护的材料。旧版本仍被报告引用时不能因“已归档”而删除。

执行型包允许先实现可审阅的输入和计划，但只有工具实测通过后才能计为完整包。各包可以独立实施；第三批尚未完成的工具服务不能成为隐含前置，也不能用静态示例替代执行证据。

## 11. 本轮设计验收

设计验收检查 10 个包与 114 个插件的数量和唯一性，与当前目录及前三批拟议 ID 比对；检查全部直接依赖存在、必需依赖图无环、单包闭包不含另一个新包，并检查拟议服务名、HTTP 命名空间、文档链接和版本一致性。

逐包核对独立输入、领域处理、唯一对象所有者、输出、页面与 CLI、预算、失败恢复、离线交接和可判定验收。涉及外部动作的包必须区分原提供者已实现能力与拟议服务，涉及统计或推演的包必须保留假设和不确定性。

本轮仅交付设计，运行实现全部待开始。设计验证不运行构建、功能测试、浏览器或 VM，也不引用旧版运行结果作为本批实现证据。最终设计检查、提交及本地标签记录在[项目状态](../PROJECT_STATUS.md)。
