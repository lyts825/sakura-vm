# 事件与队列实验

## 用途与准备

`event-lab` 包含 11 个插件，提供消息模式、样例、生产和消费声明、隔离测试代理、运行、断言、报告、交接及工作台。插件包保持实验性，默认不启用。

首版固定代理在独立虚拟机内使用 SQLite WAL 队列和一个消费者。它适合观察应用结果去重、确认丢失后的重投和慢消费者，不提供外部消息产品的兼容性或生产性能结论。

先启用插件包并按提示重启，再准备含 Python 3、SQLite 和 multiprocessing 标准库的 x86_64 镜像。执行不会安装依赖。每次虚拟机至少预留 8 GiB 磁盘，另计镜像、材料和恢复额度；默认 8 GiB 总额不足，请按[容量说明](suite-capacity.md)明确配置宿主预算。

## 完成一次实验

1. 进入事件工作台，选择已准备镜像和“重复消息去重”“确认丢失后重投”或“慢消费者积压”。创建样例只保存声明。
2. 核对消息模式及样例。也可上传经过人工审阅的 JSON 消息，按模式检查后固定。
3. 固定生产顺序、去重规则、消费延迟、拒绝消息列表和重试次数，再固定场景。
4. 预览原执行计划，核对输入、镜像、预算和截止后批准。重复提交返回原运行，关闭未执行预览会释放其输入额度。
5. 读取原运行和逐消息轨迹。需要停止时取消原运行；清理未确认时使用“核销原资源”。核销不重放消息。
6. 重算消息断言，核对重复应用结果、死信、剩余消息和顺序范围，再封存报告。

`passed` 表示选定实验中的观测满足固定规则。`failed` 保留已确认的重复应用结果、死信或规则不符。缺少完整观测、授权撤回或执行中断时保留 `inconclusive`。报告不会把未知项转换为通过。

## 额度与执行边界

每次最多 1000 条消息，单条正文最多 8 KiB，完整输入最多 2 MiB，完整轨迹最多 12,000 条。场景按复制和重试策略计算轨迹及延迟上限，超限时在执行前拒绝。消费延迟最多 500 ms，重试最多 3 次。

工具固定为 1 vCPU、1 GiB 内存，最长 900 秒。没有外网、宿主共享目录、端口映射、任意脚本或外部回调。每次使用新队列。宿主重启保留中断记录，用户可以核销原资源，再建立新的实验。

执行身份、64 KiB 分块运输、原资源清理及宿主总容量见[固定工具执行底座](suite-execution.md)。

## 报告交接与清理

在交接页逐项允许原始消息材料导出，再预览、批准并下载封存报告的引用图。每次下载都会重查来源许可。撤销导出许可后，旧包也无法继续从本机接口下载。

接收先核验封套、材料摘要、声明关联、轨迹计数和报告关系，然后保存到新的隔离空间。导入内容不携带执行批准、虚拟机票据或本机通过记录。离线结果始终标注 `executionVerified=false`，它只能核对声明是否一致。

历史页支持归档、预览物理清理及原发布恢复。被报告或其他修订引用的对象会继续保留。活动资源或未确认的材料不释放预算。

## CLI 与接口

CLI 帮助为 `npm run event -- help`。普通调用使用 `event <领域> <动作> <输入.json>`，HTTP 使用相同严格契约。离线核验命令为 `event verify <交接包>`，完整安装包可以用纯 Node 执行。

接口字段以生成帮助和 `shared/contracts/event-http.ts` 为准。插件归属、实际预算和验证记录见[实现说明](event-lab-pack-design.md)。
