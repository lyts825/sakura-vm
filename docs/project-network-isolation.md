# 项目网络隔离

在项目设置的“项目网络”中选择“独立命名空间”，保存后启动项目。Sakura 为每个项目在 Linux 客户机内建立独立的网络命名空间，只启用回环接口，不创建到客户机主网络的连接或 IPv4/IPv6 路由。项目初始化脚本、主启动命令、托管服务、就绪及健康检查、流水线步骤、收藏命令、工程执行器、代码诊断、语言服务、调试适配器、开发工具任务、运行时与开发工具版本检查、项目运行时选择及 Git 工作台命令会在该命名空间内运行。托管命令和显式项目终端进入命名空间前会复核接口与路由；若有额外接口或路由，或项目尚未启动，会拒绝执行，不会退回共享网络。切换模式前必须停止这些托管会话；停止整个项目后，命名空间中没有残留进程时才会删除。

私有模式不开放 Windows 预览端口。Notebook 和浏览器 IDE 可以在项目命名空间内启动，只监听该命名空间的回环地址，通过宿主 `127.0.0.1` 上的 SSH TCP 桥接访问；桥接不添加客户机网络接口或路由，每次连接都复核项目网络。Notebook 使用系统 Python 在共享网络预取二进制依赖包，再在私有命名空间内创建项目虚拟环境并离线安装；不提供二进制包的依赖会明确失败。浏览器 IDE 在共享网络下载并校验固定发布包，加载项目、IDE 子进程和集成终端在私有命名空间内运行。实例停止、暂停、应急锁定或控制服务关闭时桥接关闭；控制服务重启后可通过会话状态、启动或访问入口恢复桥接。

Envoy 服务网格及数据库容器仍依赖客户机共享网络，因此会拒绝在私有项目中启动。容器模板查询与容器安装、镜像拉取、模板应用、Compose 命令等共享网络操作同样拒绝；已有容器可按 ID 停止或移除，清理命令不继承项目环境变量。一个实例只要含有私有项目，Sakura 就不生成该实例的 VS Code Remote-SSH 主机别名，并拒绝编辑器项目入口；项目设置变更后同步更新已生成的别名。按锁文件安装依赖及其安装脚本在私有命名空间中运行，需要联网下载时会失败；可先在共享网络预取固定依赖（npm 禁用脚本，pip 只下载二进制包），再从项目缓存离线安装。仓库数据通过客户机共享网络获取，但私有项目使用无工作树检出下载，检出及 Git 过滤器在项目命名空间内执行。项目环境变量也只在托管项目命令内设置，不传给共享网络中的准备步骤。安装运行时及其他准备工作仍使用客户机共享网络，以便获取依赖。

网页普通终端与可恢复 tmux 会话也按当前工作项目进入相同的网络空间，准备阶段可自动创建命名空间。恢复和只读分享会复核项目、目录、网络模式、运行会话标识及所有窗格的实际网络空间。运行中的连接、断开后仍在运行的 tmux 会话及暂停中的实例会阻止修改项目目录或网络模式；“停止项目终端”按项目清理并保留停止状态和布局，刷新不会重建会话。停用项目插件后仍遵守已保存的活动项目配置，见 [项目终端与只读分享](project-terminals.md)。

基础 `/exec` API、生成的 SDK 和 CLI 也默认按活动项目执行，支持显式选择其他项目。命令进入项目目录，在命名空间内加载环境，遮盖输出中的私密配置；请求断开或超时会清理独立进程组。执行期间实例和项目绑定受到操作保护。实例管理需明确指定 `scope: "instance"` 或 CLI `--instance`，见 [项目命令执行](project-execution.md)。

构建农场也使用项目网络。登记节点时选择项目，未指定时绑定该实例已保存的活动项目；以后切换活动项目或重载服务不会改变节点绑定。旧节点首次升级时完成同样的持久绑定。工作目录留空使用节点项目目录，显式目录必须位于该项目内。每个构建独立准备并复核项目网络，在命名空间内加载环境和密钥，日志与结果遮盖密钥；超时或取消清理它自己的进程组，不影响同节点其他槽位。构建运行时保护项目目录及网络模式，并阻止更换节点绑定。项目已删除或密钥服务未加载时拒绝执行，不退回默认项目或缺失值。

单次 SSH/GPG Agent 转发命令同样进入所选项目的网络空间，加载项目目录和环境并遮盖密钥。转发套接字通过客户机文件系统访问，私有网络不添加接口或路由；取消和超时结束命令进程组、关闭 Agent 连接，GPG 另清理临时目录。运行和清理期间阻止实例操作及项目修改。

系统调用隔离工具的受限命令也在所选项目中运行，先进入项目网络空间，再加载 seccomp 过滤器。`restricted` 可创建网络套接字，但仍受私有项目的接口与路由限制；`networkless` 另拒绝创建套接字等系统调用。目录、环境、输出遮盖、配置保护及取消清理沿用项目执行规则。火焰图和 eBPF 运行固定的实例诊断脚本，采集范围仍为整个实例。

临时 TCP 隧道按项目保存运行状态，私有入口经 SSH 连接该项目网络空间内的指定回环端口，每次连接复核绑定、接口及路由。不同项目可使用同一客户机端口，各自拥有独立宿主入口；查询和关闭按所选项目执行。运行中的入口保护项目目录和网络模式，实例暂停、停止或应急锁定时撤销。用法见 [临时反向隧道](reverse-tunnel.md)。

KDE 桌面也会持久绑定所选项目，私有项目中的 Xvnc、Plasma、Konsole 及其子进程进入同一网络空间，图形状态探测和 SSH 连接复核该绑定。每个实例只有一个 KDE 会话；切换绑定须先保存工作并点“停止桌面”，停止会关闭连接并清理桌面用户的全部进程，包括另建会话的子进程。桌面运行或实例暂停时不能修改绑定项目的目录和网络模式。控制服务在每次客户机启动后重新核对配置，重建私有网络，再恢复已启用的绑定；停机时修改这些设置会关闭旧绑定的自动恢复。克隆和导出包保留绑定元数据，控制服务重载不重启仍在运行的有效桌面。首次安装及升级的软件包下载使用共享网络，不加载项目环境或密钥。旧版桌面须重新安装或启动升级到第 4 版启动脚本，见 [Linux 图形桌面](linux-desktop.md)。

这是一项针对 **Sakura 托管项目进程、图形桌面、单应用窗口与项目终端及命令** 的网络分段功能，当前仍标为部分实现。独立 SSH、显式实例管理命令、自行启动的进程及其他扩展不受该模式限制；客户机 root 也能自行变更网络命名空间。不能把它当作抵御客户机管理员或恶意代码的安全边界，也不能用它承诺实例级无外网。需要整个实例断网时，应使用实例级网络策略。

单应用图形窗口也沿用启动项目的网络模式。私有窗口的 Xvnc、Openbox、应用及其子进程在项目网络空间内运行，已有 SSH 连接桥接进入同一空间并复核网络；运行和暂停中的窗口会阻止该项目切换模式或目录。每个窗口还使用独立 Linux 用户、受保护的 X11/VNC 凭据和按用户限制的图形端口，见 [单应用窗口](single-app-windows.md)。自行在这些托管会话外启动的图形程序仍不受项目网络设置约束。

`npm run test:project-network-isolation` 在真实 Alpine 虚拟机中验证两个项目使用不同的命名空间、没有路由，且初始化、环境变量、服务、仓库下载阶段（测试桩）与真实 Git 检出、Git 工作台、收藏命令、流水线、交互式项目终端、运行时版本与开发工具检查处于预期的命名空间，人工添加路由后托管命令拒绝执行，并验证停止后的清理。`npx tsx scripts/smoke-project-network-isolation.ts debian` 和 `npx tsx scripts/smoke-project-network-isolation.ts ubuntu` 可在真实 Debian、Ubuntu 客户机中复核同一流程。设置 `SAKURA_LSP_PRIVATE=1` 运行 `npm run test:language-services`、设置 `SAKURA_DAP_PRIVATE=1` 运行 `npm run test:debug-adapter` 可额外验证私有项目中的语言服务与调试器。独立 SSH、显式实例管理命令和自行启动进程仍不受项目命名空间约束。

设置 `SAKURA_NOTEBOOK_PRIVATE=1` 运行 `npm run test:notebook` 验证私有 Notebook 的二进制包预取、离线安装、认证、桥接恢复和 Jupyter WebSocket 内核的实际命名空间及拒绝外网。设置 `SAKURA_BROWSER_IDE_PRIVATE=1` 运行 `npm run test:browser-ide` 验证私有浏览器 IDE 的认证、进程命名空间、桥接恢复和到期清理；同时设置 `SAKURA_BROWSER_IDE_TERMINAL=1` 验证真实浏览器中的集成终端也进入同一命名空间。

设置 `SAKURA_SINGLE_APP_PRIVATE=1` 运行 `npm run test:single-app-windows` 验证私有图形窗口的进程命名空间、共享网络中没有 RFB 监听、既有会话绑定与停止清理；设置 `SAKURA_SINGLE_APP_BROWSER=1` 额外验证真实浏览器中的 noVNC 认证。

`npm run test:project-desktop -- alpine`、`-- debian`、`-- ubuntu` 在真实客户机和 Chromium 中验证完整 KDE、图形方式启动的 Konsole 的命名空间、保留的显示身份、跨项目连接拒绝、只读连接、停止与脱离会话子进程清理、双屏、实例及控制服务重启、停机修改配置和切换项目。测试使用独立数据目录，需要联网安装 KDE。

`npm run test:build-farm -- alpine`、`-- debian`、`-- ubuntu` 在真实客户机验证构建目录、环境、私有网络、Windows DPAPI 密钥输出遮盖、节点重载及活动项目切换后的绑定、子目录和越界目录拒绝、同节点两槽并发与分别取消后的子进程清理。测试使用独立数据目录，不同步源码。
