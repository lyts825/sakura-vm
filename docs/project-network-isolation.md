# 项目网络隔离

在项目设置的“项目网络”中选择“独立命名空间”，保存后启动项目。Sakura 为每个项目在 Linux 客户机内建立独立的网络命名空间，只启用回环接口，不创建到客户机主网络的连接或 IPv4/IPv6 路由。项目初始化脚本、主启动命令、托管服务、就绪及健康检查、流水线步骤、收藏命令、工程执行器、代码诊断、语言服务、调试适配器、开发工具任务、运行时与开发工具版本检查、项目运行时选择及 Git 工作台命令会在该命名空间内运行。托管命令和显式项目终端进入命名空间前会复核接口与路由；若有额外接口或路由，或项目尚未启动，会拒绝执行，不会退回共享网络。切换模式前必须停止这些托管会话；停止整个项目后，命名空间中没有残留进程时才会删除。

私有模式不开放 Windows 预览端口。Notebook、浏览器 IDE、Envoy 服务网格及数据库容器依赖客户机共享网络，因此会拒绝在私有项目中启动；Notebook 与浏览器 IDE 的安装入口也会拒绝执行。容器模板查询与容器安装、镜像拉取、模板应用、Compose 命令等共享网络操作同样拒绝；已有容器可按 ID 停止或移除，清理命令不继承项目环境变量。一个实例只要含有私有项目，Sakura 就不生成该实例的 VS Code Remote-SSH 主机别名，并拒绝编辑器项目入口；项目设置变更后同步更新已生成的别名。按锁文件安装依赖及其安装脚本在私有命名空间中运行，需要联网下载时会失败；可先在共享网络预取固定依赖（npm 禁用脚本，pip 只下载二进制包），再从项目缓存离线安装。仓库数据通过客户机共享网络获取，但私有项目使用无工作树检出下载，检出及 Git 过滤器在项目命名空间内执行。项目环境变量也只在托管项目命令内设置，不传给共享网络中的准备步骤。安装运行时及其他准备工作仍使用客户机共享网络，以便获取依赖。

这是一项针对 **Sakura 托管项目进程与显式项目终端** 的网络分段功能，当前仍标为部分实现。普通管理员终端、独立 SSH、客户机自行启动的进程、图形应用及其他扩展不受该模式限制；客户机 root 也能自行变更网络命名空间。不能把它当作抵御客户机管理员或恶意代码的安全边界，也不能用它承诺实例级无外网。需要整个实例断网时，应使用实例级网络策略。

`npm run test:project-network-isolation` 在真实 Alpine 虚拟机中验证两个项目使用不同的命名空间、没有路由，且初始化、环境变量、服务、仓库下载阶段（测试桩）与真实 Git 检出、Git 工作台、收藏命令、流水线、交互式项目终端、运行时版本与开发工具检查处于预期的命名空间，人工添加路由后托管命令拒绝执行，并验证停止后的清理。`npx tsx scripts/smoke-project-network-isolation.ts debian` 和 `npx tsx scripts/smoke-project-network-isolation.ts ubuntu` 可在真实 Debian、Ubuntu 客户机中复核同一流程。设置 `SAKURA_LSP_PRIVATE=1` 运行 `npm run test:language-services`、设置 `SAKURA_DAP_PRIVATE=1` 运行 `npm run test:debug-adapter` 可额外验证私有项目中的语言服务与调试器。普通管理员终端和自行启动进程仍不受项目命名空间约束。
