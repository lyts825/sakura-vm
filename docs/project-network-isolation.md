# 项目网络隔离

默认项目 `/exec`、初始化、主命令、普通服务、就绪和命令式健康检查、运行时版本的显式探测与选择验证，以及构建农场和单次 SSH Agent 命令已使用持久项目 UID/GID 与独立 home，正文通过受保护输入运输。既有 root 目录需要管理员明确核对并应用 [目录迁移](project-directory-migration.md)。下述其他入口中的命名空间约束仍各有范围，普通终端、GPG Agent 及全部扩展尚未全部迁移为同一项目账号，不能据此声称所有入口都有跨 UID 权限边界。

在项目设置的“项目网络”中选择“独立命名空间”，保存后启动项目。Sakura 为每个项目在 Linux 客户机内建立独立的网络命名空间，只启用回环接口，不创建到客户机主网络的连接或 IPv4/IPv6 路由。项目初始化脚本、主启动命令、托管服务、就绪及健康检查、流水线步骤、收藏命令、工程执行器、代码诊断、语言服务、调试适配器、开发工具任务、运行时与开发工具版本检查、项目运行时选择及 Git 工作台命令会在该命名空间内运行。托管命令和显式项目终端进入命名空间前会复核接口与路由；若有额外接口或路由，或项目尚未启动，会拒绝执行，不会退回共享网络。切换模式前必须停止这些托管会话；停止整个项目后，命名空间中没有残留进程时才会删除。

私有模式不开放 Windows 预览端口。Notebook 和浏览器 IDE 可以在项目命名空间内启动，只监听该命名空间的回环地址，通过宿主 `127.0.0.1` 上的 SSH TCP 桥接访问；桥接不添加客户机网络接口或路由，每次连接都复核项目网络。Notebook 使用系统 Python 在共享网络预取二进制依赖包，再在私有命名空间内创建项目虚拟环境并离线安装；不提供二进制包的依赖会明确失败。浏览器 IDE 在共享网络下载并校验固定发布包，加载项目、IDE 子进程和集成终端在私有命名空间内运行。实例停止、暂停、应急锁定或控制服务关闭时桥接关闭；控制服务重启后可通过会话状态、启动或访问入口恢复桥接。

Envoy 服务网格边车进入所选项目的网络空间，验证与运行时加载项目目录、环境和密钥。私有项目的监听及上游只在本项目回环内；不同项目可复用相同端口，共享网络项目间仍检查冲突。控制服务重载后重新核对会话、配置摘要、实际代理程序、参数、目录、网络和监听；旧版或失去会话的代理须先停止。运行时保护绑定设置，暂停实例须先恢复再修改策略或禁用能力。停止通过 pidfd 清理本项目的遗留代理；启动取消只清理本次尝试，不影响其他项目。客户机重启后仍需手动启动。使用和兼容性要求见 [项目 Envoy 边车](service-mesh.md)。

Debian、Ubuntu 私有项目使用独立的 Docker 与 containerd，容器 `host` 网络为本项目的仅回环空间；镜像先通过共享网络预取，再导入项目，工作负载不退回共享 Docker。支持 Dockerfile、符合条件的 Compose、官方 Dev Container CLI 与数据库预设；容器、镜像和数据卷按项目分开，暂停、运行与停止后的容器记录保护目录及网络绑定，停用容器插件仍保留保护。使用条件、重启恢复及验证范围见 [私有项目容器](private-containers.md)。容器安装、CLI 安装、模板元数据与模板应用属于不加载项目密钥的共享网络准备步骤。

含私有项目的 Debian、Ubuntu 实例撤销原有共享 SSH 名称别名，改用专属项目 SSH 服务和密钥。VS Code、普通 SSH 命令、SFTP 与其后台子进程进入所选项目网络，编辑器缓存也按项目分开；共享项目使用独立服务而保持共享网络。能力中心的 VS Code、JetBrains 与 Neovim 档案也只导出经过核对的项目入口，未配置项目 SSH 或 IDE 插件未启用时拒绝导出。桥接只转送至本项目回环，每次新连接核对服务与实际网络；停止清理整个所属 cgroup，核心绑定保护不依赖 IDE 插件。私有模式需由本机下载 VS Code 服务端并传入，不能使用 Unix 套接字转发。Windows 桌面 Remote-SSH 的真实远程扩展、编辑、集成终端及 ShellExecution 任务已在 Debian、Ubuntu 各自的双项目验证；重载与重启、环境和密钥变更及验证范围见 [项目 SSH 与 Remote-SSH](project-ssh.md)。

按锁文件安装依赖及其安装脚本在私有命名空间中运行，需要联网下载时会失败；可先在共享网络预取固定依赖，再从项目缓存离线安装。预取不解析项目私密配置、不加载项目运行时或环境，在清空环境后的系统工具与独立临时目录中执行；项目 npmrc、Python 导入路径和包管理器配置不进入下载器。npm 使用去除脚本与可执行配置的清单、带完整版本和摘要的 registry 锁文件及空 npm 配置，保持 `--ignore-scripts`；Git、URL、路径、工作区链接和未完整锁定的来源先拒绝。pip 使用隔离系统 Python，只接受固定版本的普通包并下载二进制 wheels。下载后复核原始清单摘要，项目文件变化则拒绝发布缓存。单独保存的实例镜像与 HTTP(S) 代理配置可用于下载，不接受 URL 中的凭证或令牌参数；需要认证的 npm/pip 仓库可在实例网络档案另行保存固定端点与只读凭证名称，以临时回环镜像进行 Bearer/Basic 下载，不加载项目令牌、npmrc 或其他可执行配置，见 [离线软件包缓存](package-cache.md)。离线安装仍进入项目网络并加载项目环境。主命令与普通服务的新账号入口由项目 UID 执行 Git 检出及过滤器；私有项目目标尚无 `.git` 时明确拒绝启动，不借共享网络执行项目 Git，固定认证预取代理尚未接通此路径。安装运行时及其他准备工作仍使用客户机共享网络，以便获取依赖。

运行时面板刷新只读取宿主配置和最近完成的样本，不执行客户机命令。主动探测才在固定项目账户与项目环境中读取有界声明文件、执行版本命令；选择版本须核对 root 管理的 ready 回执，再通过项目 UID 验证所选绝对路径，不能依赖缓存跳过验证。安装共享运行时在干净管理员环境与共享网络中进行，任务全域清理确认后才能发布 ready，详见 [运行时版本](runtime-versions.md)。

网页普通终端与可恢复 tmux 会话也按当前工作项目进入相同的网络空间，准备阶段可自动创建命名空间。恢复和只读分享会复核项目、目录、网络模式、运行会话标识及所有窗格的实际网络空间。运行中的连接、断开后仍在运行的 tmux 会话及暂停中的实例会阻止修改项目目录或网络模式；“停止项目终端”按项目清理并保留停止状态和布局，刷新不会重建会话。停用项目插件后仍遵守已保存的活动项目配置，见 [项目终端与只读分享](project-terminals.md)。

基础 `/exec` API、生成的 SDK 和 CLI 也默认按活动项目执行，支持显式选择其他项目。命令进入项目目录，在命名空间内加载环境，遮盖输出中的私密配置；请求断开或超时会清理独立 cgroup，包括普通另建会话和双重 fork 的子进程。执行期间实例和项目绑定受到操作保护。实例管理需明确指定 `scope: "instance"` 或 CLI `--instance`，见 [项目命令执行](project-execution.md)。

构建农场使用节点绑定项目的持久账号与网络。登记节点时选择项目，未指定时绑定该实例已保存的活动项目；以后切换活动项目或重载服务不会改变节点绑定。旧节点首次升级时完成同样的持久绑定。每次准备捕获一份配置，后续环境、运行时与密钥仅由该份配置解析。工作目录留空使用原项目目录；显式子目录在降权正文中相对切换，原账号目录身份保持不变。每个槽位具有独立完整票据与 cgroup，超时或取消清理自己的全部后代，不影响另一槽位；准确域停止后才核销账号票据。清理失败保留 503、错误码与原记录，关闭或重载也不改成普通取消。运行和清理期间保护项目目录与网络模式，并阻止更换节点绑定。项目已删除或密钥服务未加载时拒绝执行。路径条件、准备租约和恢复范围见 [构建农场](build-farm.md)。

单次 SSH Agent 转发使用所选项目的持久账号、独立 home、原目录和网络；准备固定当前项目与配置，正文仍通过受保护帧降权执行。每条任务有独立入口、宿主流及不可变资源归属，核对直接连接的 UID/GID、进程创建身份、boot 和完整 cgroup。同项目多任务可以并行，撤销一条不关闭另一条的连接。确认完整域和准确资源清理后才核销账号票据，未确认时保留错误码、票据与资源，后续准备先恢复原归属，见 [SSH Agent 转发](ssh-agent-forward.md)。转发套接字通过客户机文件系统访问，私有网络不添加接口或路由；运行与清理期间保护项目绑定。

单次 GPG Agent 命令同样进入所选项目的网络空间，加载目录和环境并遮盖密钥，但尚未接入上述项目账号和固定 broker。取消或超时清理命令 cgroup 并关闭桥接，确认域已释放后才清理临时目录；独立 SSH 重试仍未确认时保留原归属及目录并报告错误。

普通托管服务使用每次运行独立的持久 cgroup，停止、启动回滚与自动重启同样核对 boot、run、inode、实际 pane 身份和固定账号票据，再清理整个运行并核销票据。清理或账号入口未确认时暂停自动检查与重启。旧版没有归属的 tmux 服务须手动核查迁移，见 [服务运行归属](project-service-lifecycle.md)。

单主命令项目也使用独立的持久 cgroup 和主运行记录，启动前持久保存完整身份，主进程退出后保留后台后代归属。停止整个私有项目先冻结固定 generation 和 release ID，再清理全部运行和账号票据，最后核销准确原命名空间。确认丢失时保留原请求，同 boot 新启动具有新 generation；即使 inode 复用，旧停止请求也不能删除新代。待清理或状态未确认时拒绝修改启动配置，面板支持停止重试。取消任务时仍未确认的清理记录为失败并保留具体错误码。旧主项目 tmux 会话需要明确核查迁移，见 [主命令运行归属](project-main-lifecycle.md)。

系统调用隔离工具的受限命令也在所选项目中运行，先进入项目网络空间，再加载 seccomp 过滤器。`restricted` 可创建网络套接字，但仍受私有项目的接口与路由限制；`networkless` 另拒绝创建套接字等系统调用。目录、环境、输出遮盖、配置保护及取消清理沿用项目执行规则。火焰图和 eBPF 运行固定的实例诊断脚本，采集范围仍为整个实例。

临时 TCP 隧道按项目保存运行状态，私有入口经 SSH 连接该项目网络空间内的指定回环端口，每次连接复核绑定、接口及路由。不同项目可使用同一客户机端口，各自拥有独立宿主入口；查询和关闭按所选项目执行。运行中的入口保护项目目录和网络模式，实例暂停、停止或应急锁定时撤销。用法见 [临时反向隧道](reverse-tunnel.md)。

KDE 桌面也会持久绑定所选项目，私有项目中的 Xvnc、Plasma、Konsole 及其子进程进入同一网络空间，图形状态探测和 SSH 连接复核该绑定。每个实例只有一个 KDE 会话；切换绑定须先保存工作并点“停止桌面”，停止会关闭连接并清理桌面用户的全部进程，包括另建会话的子进程。桌面运行或实例暂停时不能修改绑定项目的目录和网络模式。控制服务在每次客户机启动后重新核对配置，重建私有网络，再恢复已启用的绑定；停机时修改这些设置会关闭旧绑定的自动恢复。克隆和导出包保留绑定元数据，控制服务重载不重启仍在运行的有效桌面。首次安装及升级的软件包下载使用共享网络，不加载项目环境或密钥。旧版桌面须重新安装或启动升级到当前第 5 版启动脚本，见 [Linux 图形桌面](linux-desktop.md)。

这是一项针对 **Sakura 托管项目进程、项目 SSH、图形桌面、单应用窗口与项目终端及命令** 的网络分段功能，当前仍标为部分实现。非 Sakura 生成的系统 SSH、显式实例管理命令、自行启动的进程及其他扩展不受该模式限制；客户机 root 也能自行变更网络命名空间。不能把它当作抵御客户机管理员或恶意代码的安全边界，也不能用它承诺实例级无外网。需要整个实例断网时，应使用实例级网络策略。

单应用图形窗口也沿用启动项目的网络模式。私有窗口的 Xvnc、Openbox、应用及其子进程在项目网络空间内运行，已有 SSH 连接桥接进入同一空间并复核网络；运行和暂停中的窗口会阻止该项目切换模式或目录。每个窗口还使用独立 Linux 用户、受保护的 X11/VNC 凭据和按用户限制的图形端口，见 [单应用窗口](single-app-windows.md)。自行在这些托管会话外启动的图形程序仍不受项目网络设置约束。

`npm run test:project-network-isolation` 在真实 Alpine 虚拟机中验证两个项目使用不同的命名空间、没有路由，且初始化、环境变量、服务、仓库下载阶段（测试桩）与真实 Git 检出、Git 工作台、收藏命令、流水线、交互式项目终端、运行时版本与开发工具检查处于预期的命名空间，人工添加路由后托管命令拒绝执行，并验证停止后的清理。`npx tsx scripts/smoke-project-network-isolation.ts debian` 和 `npx tsx scripts/smoke-project-network-isolation.ts ubuntu` 可在真实 Debian、Ubuntu 客户机中复核同一流程。设置 `SAKURA_LSP_PRIVATE=1` 运行 `npm run test:language-services`、设置 `SAKURA_DAP_PRIVATE=1` 运行 `npm run test:debug-adapter` 可额外验证私有项目中的语言服务与调试器。非 Sakura 生成的系统 SSH、显式实例管理命令和自行启动进程仍不受项目命名空间约束。

设置 `SAKURA_NOTEBOOK_PRIVATE=1` 运行 `npm run test:notebook` 验证私有 Notebook 的二进制包预取、离线安装、认证、桥接恢复和 Jupyter WebSocket 内核的实际命名空间及拒绝外网。设置 `SAKURA_BROWSER_IDE_PRIVATE=1` 运行 `npm run test:browser-ide` 验证私有浏览器 IDE 的认证、进程命名空间、桥接恢复和到期清理；同时设置 `SAKURA_BROWSER_IDE_TERMINAL=1` 验证真实浏览器中的集成终端也进入同一命名空间。

`npm run test:project-cache -- alpine|debian|ubuntu` 使用独立真实客户机验证正常 npm registry 依赖和二进制 Python wheels 的下载与私有离线安装，检查预取忽略项目 `NODE_OPTIONS`、`PYTHONPATH`、npmrc、pip.conf、环境与未解析的私密引用，以及离线导入钩子只在项目网络执行；另验证清单变更、URL 与 Git prepare 依赖拒绝。设置 `SAKURA_KEEP_CACHE_SMOKE=1` 可保留所属目录中的 `prefetch-evidence.json`。

设置 `SAKURA_SINGLE_APP_PRIVATE=1` 运行 `npm run test:single-app-windows` 验证私有图形窗口的进程命名空间、共享网络中没有 RFB 监听、既有会话绑定与停止清理；设置 `SAKURA_SINGLE_APP_BROWSER=1` 额外验证真实浏览器中的 noVNC 认证。

`npm run test:project-desktop -- alpine`、`-- debian`、`-- ubuntu` 在真实客户机和 Chromium 中验证完整 KDE、图形方式启动的 Konsole 的命名空间、保留的显示身份、跨项目连接拒绝、只读连接、停止与脱离会话子进程清理、双屏、实例及控制服务重启、停机修改配置和切换项目。测试使用独立数据目录，需要联网安装 KDE。

`npm run test:build-farm -- alpine`、`-- debian`、`-- ubuntu` 在真实客户机验证构建目录、环境、私有网络、Windows DPAPI 密钥输出遮盖、节点重载及活动项目切换后的绑定、子目录和越界目录拒绝、同节点两槽并发与分别取消后的子进程清理。测试使用独立数据目录，不同步源码。

`npm run test:service-mesh -- debian`、`-- ubuntu` 验证真实 Envoy 的并行代理流量、命名空间与相同端口、环境及密钥加载、宿主桥接、绑定保护、旧代理及遗留进程清理、取消、额外路由拒绝和实例重启后恢复。`-- alpine` 当前只验证官方二进制不兼容时被拒绝，未完成 Alpine 真实代理流量验证。
