# 项目网络隔离

在项目设置的“项目网络”中选择“独立命名空间”，保存后启动项目。Sakura 为每个项目在 Linux 客户机内建立独立的网络命名空间，只启用回环接口，不创建到客户机主网络的连接或 IPv4/IPv6 路由。项目初始化脚本、主启动命令、托管服务、就绪及健康检查、流水线步骤、收藏命令和工程执行器会在该命名空间内运行。项目页的“打开项目隔离终端”会连接到已保存项目的同一命名空间，启动前复核接口和路由；未启动项目时不会退回共享网络。切换模式前必须停止这些托管会话；停止整个项目后，命名空间中没有残留进程时才会删除。

私有模式不开放 Windows 预览端口。Notebook、浏览器 IDE、Envoy 服务网格和容器启动依赖客户机共享网络，因此会拒绝在私有项目中启动。克隆仓库、安装运行时及其他准备工作仍使用客户机共享网络，以便获取依赖。

这是一项针对 **Sakura 托管项目进程与显式项目终端** 的网络分段功能，当前仍标为部分实现。普通管理员终端、独立 SSH、客户机自行启动的进程、图形应用及其他扩展不受该模式限制；客户机 root 也能自行变更网络命名空间。不能把它当作抵御客户机管理员或恶意代码的安全边界，也不能用它承诺实例级无外网。需要整个实例断网时，应使用实例级网络策略。

`npm run test:project-network-isolation` 在真实 Alpine 虚拟机中验证两个项目使用不同的命名空间、没有路由，且初始化、服务、收藏命令、流水线与交互式项目终端进入相应命名空间，并验证停止后的清理。`npx tsx scripts/smoke-project-network-isolation.ts debian` 和 `npx tsx scripts/smoke-project-network-isolation.ts ubuntu` 可在真实 Debian、Ubuntu 客户机中复核同一流程。普通管理员终端和自行启动进程仍不受项目命名空间约束。
