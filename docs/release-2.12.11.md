# 2.12.11 · CI 安装与跨平台检查修复

日期：2026-11-03。版本：2.12.10 → 2.12.11。状态：待验收。

## 问题与修复

GitHub Actions 的 Windows 和 Ubuntu 安装任务在克隆 PosixLoom 时收到 HTTP 407，后续验证没有执行。受管代理拒绝未认证请求时，没有返回 `Proxy-Authenticate`，Git 无法协商认证方式。

HTTP 与 CONNECT 的 407 响应现在声明 Basic 认证；CONNECT 响应明确标记空正文和连接关闭。每次代理租约仍使用独立随机凭证，缺失和错误凭证继续拒绝，认证信息不转发到目标服务。没有关闭认证、绕过受管网络或跳过 CI 步骤。

公开接口、宿主插件 API 5 和持久数据格式保持兼容，没有新增依赖。实现提交：`d9ea1b50`。

代理修复后，Ubuntu 安装通过，架构扫描在 JSON 资源后尝试 `index.ts` 候选路径时遇到 `ENOTDIR`。扫描器现在将这一情况与不存在的候选路径同样处理，其他文件读取错误仍然抛出。

## 验证

专项回归在修改前因缺少认证挑战头失败，修改后通过。覆盖 HTTP 与 CONNECT、缺失和错误凭证、curl 自动协商认证，以及认证信息不转发。既有网络运行时和适配器回归共 20 项全部通过。

TypeScript 检查和 2,569 个模块的本地架构检查通过。本地完整构建因环境缺少 `g++.exe` 停止，尚未通过；未跳过原生编译步骤。

专项脚本和失败日志保存在忽略目录 `artifacts/ci-proxy-fix/`，不纳入 Git。双平台 CI 的结果待核对，版本标签在验收后创建。
