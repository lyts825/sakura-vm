# JupyterLab 与 Marimo 环境

启动实例并选择项目后，在“能力中心”选择“Jupyter/Marimo 环境”。`provider` 可设为 `jupyter` 或 `marimo`；`mode` 支持 `status`、`install`、`start` 和 `stop`。`start` 会安装缺失的环境，完成后使用“打开 Notebook”取得当前会话链接。每个实例的每个项目同时管理一个会话；更换提供者、端口或项目配置前先停止原会话。

虚拟环境保存在项目目录的 `.sakura/notebooks/<provider>/venv`，由原项目持久 UID/GID 创建。Notebook、内核与其子进程使用同一项目账号、独立 home、目录和网络。请求固定原项目、捕获配置与客户机运行身份，环境只解析这份配置，密码令牌和项目环境经有界保护帧降权执行，不进入管理员启动参数。历史 root 目录需先明确核对并应用 [目录迁移](project-directory-migration.md)，入口不自动建立项目目录或递归改属主。

所有网络模式都先由固定系统 Python 在共享网络下载二进制 wheels，再由项目账号创建虚拟环境并离线安装。下载只接受固定提供者与系统工具，不加载项目 Python、环境、密钥、pip 配置或钩子；系统依赖及下载需要访问软件源。源中缺少适配系统的二进制包时安装失败，不改为联网编译。缓存固定原 boot、UUID、目录与文件身份、大小和摘要；最多 512 个 wheels、合计 1 GiB。完整安装任务域确认清理后才精确退休缓存，失败或回执丢失保留原记录供复核。

`guestPort` 是客户机监听端口，`hostPort` 是本机回环端口，默认均为 8888。共享和私有项目都只监听原网络中的 `127.0.0.1`，通过宿主回环 SSH 桥接访问 HTTP 与 WebSocket，不建立 QEMU 端口映射。已用于实例转发的本机端口会拒绝复用；请选择另一个端口。JupyterLab 与 Marimo 使用随机令牌，链接经授权的控制接口单独取得，普通状态与任务记录不含令牌。结束使用后执行 `stop`。

打开入口前核对原账号、boot、完整运行票据、cgroup inode、窗格创建身份、保护帧摘要，以及该 UID 实际持有的监听。每次桥接连接都复核，SSH 连接完成后再次检查。读取状态、重载或取得链接不安装环境、不发行新票据，也不把同名新进程当作原会话。

停止先保存待复核状态并关闭桥接，然后按原完整归属清理整个 cgroup，包括内核和脱离终端的子进程；准确资源与账号票据核销后才移除会话记录。虚拟环境和项目文件保留。清理未确认返回 503，原记录与具体错误码保留，取消不会把清理失败记为正常结束。实例暂停时先恢复再停止；冷重启后先执行 `stop` 核对并退休旧记录，再执行 `start`，旧停止不会发往新 boot。

控制服务关闭会撤销桥接，已运行 Notebook 继续保留；重新加载后，状态检查或取得链接可在原完整归属核对成功后恢复入口。旧 root 会话没有上述票据，继续显示待复核，不自动接管或删除未知进程、缓存及记录，需要管理员明确处理。此功能不恢复内核任务或自动更新 Python 依赖。项目网络范围见 [项目网络隔离](project-network-isolation.md)，账号合约见 [项目账号](project-identities.md)。

`npm run test:notebook` 使用新的临时实例安装、启动两种提供者，检查认证、UID/GID、home、环境、完整运行票据、桥接重载及停止核销。设置 `SAKURA_NOTEBOOK_PRIVATE=1` 检查私有网络及 Jupyter WebSocket 内核；脚本也接受 `debian` 或 `ubuntu` 参数。当前脚本已适配上述账号入口并完成类型及静态 Python 语法检查；这次尚未执行新的客户机实测，历史 root 结果不替代新的 UID 验证。
