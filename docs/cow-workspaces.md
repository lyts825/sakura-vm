# 临时 COW 工作区

启用“沙箱工作台”插件后，创建沙箱时将“磁盘写入策略”改为“临时 COW：停止即丢弃”。沙箱默认仍使用原来的保留写入模式，旧实例的行为不变。策略创建后固定，不能把已有保留数据的实例直接改成丢弃模式。

临时模式为根磁盘启用 QEMU 的 `snapshot=on` 写时复制层。客户机看到完整可写磁盘，修改只进入本次进程的临时层；沙箱停止后，下次启动从创建时的基础环境开始。只对根磁盘启用该选项，初始化种子仍为只读。原理见 [QEMU 磁盘参数](https://www.qemu.org/docs/master/system/invocation.html) 与 [snapshot mode](https://www.qemu.org/docs/master/system/images.html#snapshot-mode)。

沙箱任务每次结束都会停止整个虚拟机，因此任务成功、失败、超时、取消或到期后都不依靠这次磁盘写入继续下一次任务。需要跨命令共享修改时，可把连续命令写在同一个任务里，或选择保留写入模式。单纯关闭网页不等于停止手动启动的沙箱；到期策略仍会由宿主服务执行。

任务日志和明确填写的产物保存在 Sakura 数据目录。产物在虚拟机停止前提取，仍按原有路径、大小和数量限制检查；如果命令超时或取消发生在提取前，未提取的文件无法恢复。即使选择到期保留实例记录，临时磁盘改动也会丢弃。重新启动到期实例仍会被拒绝。

这是磁盘状态隔离，不是加密或安全擦除：临时写入可能实际落在宿主临时存储，强制断电后是否遗留临时文件取决于 QEMU 和宿主文件系统。网络权限单独选择，默认隔离，允许 NAT 后仍可主动访问可达网络。公开接口增加可选 `storage: "persistent" | "discard-on-stop"`，省略时保留旧行为；普通实例创建接口不接受这个字段。

`npm run test:sandbox` 同时验证原来的保留模式、宿主/互联网/DNS 隔离、NAT 正向对照、超时、取消与到期，再验证临时模式的三次真实 Alpine/QEMU 启动。已确认每次停止后基础 QCOW2 的 SHA-256 不变，成功及取消任务写入的文件在后续启动中消失，明确提取的文件和任务日志仍然可用。
