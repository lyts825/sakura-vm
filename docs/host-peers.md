# 主机配对与多主机状态

在“系统设置 → 主机配对与多主机状态”中，先在被访问主机启用独立的 HTTPS 同伴入口，选择监听地址和端口，然后重启 Sakura 服务。默认只监听 `127.0.0.1`，可经 SSH 隧道连接；选择 `0.0.0.0` 才向局域网网卡开放。控制面仍只监听本机回环地址，不通过同伴入口开放控制 API。

被访问主机显示 TLS 证书指纹。生成的一次性 10 位十六进制配对码有效 5 分钟，重启后失效，也可主动撤销。在另一台主机输入 `https://主机地址:端口/`、该指纹和配对码。客户端在发送配对码前核对 TLS 证书指纹；配对成功后保存独立的长随机读取凭证。被访问主机只保存凭证摘要，可在“允许读取本机状态的主机”中撤销。加入方可以移除远端主机。配对是单向的：要双向查看，需要在两边分别配对。

已配对主机每 30 秒读取一次只读状态，也可手动检查。总览显示主机平台、架构、CPU 数、空闲与总内存、运行与总实例数，以及最近检查时间和连接错误。远端接口不发送实例名称、命令、任务日志、文件路径或控制凭证。远端请求超时为 10 秒；连接失败时保留上一次观测，但明确显示当前错误。短码接口按来源限制尝试次数。

“资源评分调度”按计划实例需要的 CPU 数和内存刷新本机及已配对主机的观测。读取失败、观测超过 90 秒、CPU 数或空闲内存不足的主机明确列为不可选；其他主机按内存余量（45%）、1 分钟负载（45%）和运行实例密度（10%）排序，显示总分与分项得分。实例能力中心的 `resource-scheduler` 也使用当前实例的 CPU/内存配置执行同一评分。结果是基于瞬时资源的放置建议，不代表目标主机已经通过镜像、架构、网络或磁盘兼容性检查，也不会迁移或启动实例。

本机控制 API 为 `GET/POST /api/host-peers`，受控制面会话与本机凭证保护；请求结构在 OpenAPI/SDK 中。同伴 HTTPS 入口提供 `POST /peer/pair` 和经配对凭证认证的 `GET /peer/status`。仅当目标主机为指定入站配对单独开启导入权限后，`GET /peer/import-status` 与 `POST /peer/import` 才允许查询回执和流式导入完整实例包。另有独立的策略发布授权，允许该入站主机通过 `GET/POST /peer/rollouts` 读取和保存插件灰度策略，不包含其他控制操作。迁移流程见 [跨主机冷迁移](cold-migration.md)和[主机维护排空](maintenance-drain.md)；策略发布见[集群策略发布](fleet-policy-rollout.md)。

同一授权通道还支持[跨主机快照复制](snapshot-replications.md)，将指定历史快照校验后导入为远端独立实例。

故障副本接管使用独立的入站 `allow-failover` 权限，同时需要导入权限。`/peer/replica-activate-check`、`/peer/replica-activate` 与 `/peer/replica-retire` 均核对传输 ID、实例 ID、来源实例、快照 ID 和磁盘 SHA-256；目标退出接管时必须已停机，随后被持久封锁。详见[故障接管策略与健康检查](ha-failover-check.md)。
