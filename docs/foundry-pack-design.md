# 环境镜像工坊插件包设计

## 1. 版本、目标与边界

设计版本：1.0.0。核对基线：Sakura 2.5.0，提交 `6fb9115`。本文保留设计时的方案；`2.6.0` 实施后的使用方式与实际边界见 [工坊指南](foundry-workbench.md)，验收状态见 [项目状态](../PROJECT_STATUS.md)。

`foundry` 把“先手工准备一台 VM”整理为可审阅的镜像制作流程：固定基础来源和安装材料，在专用实例构建，清理身份，再断网启动验收。合格镜像可供交付构建、应用运行和数据任务显式选取。

现有 [`environment`](../plugins/packs/environment.ts) 包由 `recipes`、`ide` 组成，处理项目配置与编辑器接入。工坊管理可复用的磁盘内容、制作证据和镜像引用。两者保留独立入口和启用方式；`foundry` 不覆盖 `environment`。

整包包含 9 个新插件。每个插件有独立服务、页面、数据所有权和停用规则。`delivery`、`app-runtime`、`data-lab` 均为可选消费者，整包之间没有必需依赖。

**固定来源不等于逐位可重现。** 相同软件包与命令仍可能产生不同时间戳、文件顺序或随机值。首版分别记录来源一致性、软件清单一致性、功能验收和磁盘摘要；只有两次独立构建的完整字节相同，才报告逐位一致。

## 2. 已有能力与真实缺口

以下公共接口以 [`v1.ts`](../server/service-contracts/v1.ts) 和插件 `services.ts` 为准。内部类可供本体实现复用，不能当作第三方插件 SDK。

| 需求 | 2.5.0 的可复用能力 | 仍须实现的边界 |
| --- | --- | --- |
| 获取基础镜像 | [`ImagesV1`](../plugins/images/services.ts) 的 `list/prepare` 下载既有发行版镜像 | 没有任意内容摘要查询、来源锁定清单或持久镜像引用；不能把 `prepare(id)` 当作指定版本下载 |
| 保存磁盘副本 | [`GoldenImagesV1`](../plugins/snapshots/services.ts) 的 `view/action` 制作、校验、实例化和删除模板 | 没有供交付执行器选取的镜像句柄、引用阻删或清理身份的证明 |
| 保存项目配方 | [`RecipesV1`](../plugins/recipes/services.ts) 导入、预览差异和应用项目配置 | 配方不是系统依赖锁，也不证明安装材料已取得；工坊导入须生成新蓝图并重新审阅 |
| 探测运行时 | [`RuntimeVersionsV1`](../plugins/runtimes/services.ts) 探测、选择和安装项目运行时 | 工坊需要可离线复用的精确版本、材料摘要与全局工具清单；不能直接复用项目安装作为镜像制作证明 |
| 缓存软件包 | [`package-cache.ts`](../server/package-cache.ts) 和 [`package-cache.md`](package-cache.md) 已实现系统包与项目依赖缓存 | `packageCacheScript` 是内部脚本，未形成镜像材料锁与导出协议；现有项目缓存不能冒充可搬迁的镜像材料库 |
| 隔离交付 | [`DeliveryExecutor`](../server/delivery-executor.ts) 创建专用实例，检查 `python3/cc/ip/openssl/useradd/groupadd/nft` | 默认基础镜像缺工具时返回 `DELIVERY_IMAGE_NOT_READY`；当前通过内部 `distroInfo` 找固定路径，没有任意镜像选择 |
| 固定交付输入 | [`DeliveryInputs`](../server/delivery-inputs.ts) 对默认及矩阵镜像计算 SHA-256 | 摘要只检测替换，未使原镜像持久保留；需要显式内容引用、消费租约和兼容的环境字段 |
| 清理启动身份 | [`黄金镜像说明`](golden-images.md) 说明克隆会更新控制密钥与主机名 | 现有模板保留客体私钥、应用账户、机器标识和数据；不能声明黄金镜像已经脱敏 |

当前内置镜像组合为 Alpine/x86_64、Debian/x86_64、Debian/aarch64、Ubuntu/x86_64，见 [`images.ts`](../server/images.ts)。首版按此组合声明支持；其他发行版和架构必须新增适配器及启动验收。

## 3. 插件成员与职责

表内 `F-*` 指本包插件，完整 ID 为 `foundry-*`。“可选”缺席时只隐藏对应接入，不改变基础流程。任务中心、存储预算和宿主授权属于本体能力，不作为插件依赖边。

| 插件 | 用户操作与输入 → 输出 | 必需依赖 / 可选依赖 | 独立价值与生命周期 |
| --- | --- | --- | --- |
| `foundry-sources` | 登记发行版源或本地磁盘；预览下载、取得并固定材料；来源声明 → `SourceLock`、校验后的基础资产 | 无 / `images`、`snapshots` | 单独保存可核验的基础镜像来源；原始内容只读，取消保留可恢复下载，停用后引用仍保护字节 |
| `foundry-blueprints` | 选择隔离构建、Node、Python 或自定义模板；编辑、比较、复制、冻结；配方 → `BlueprintRevision` | F-sources / `recipes`、`runtimes` | 单独编写和交换环境定义；草稿可改，冻结修订不可改，归档不删除已用修订 |
| `foundry-depot` | 预览软件解析、显式联网预取、导入材料、校验离线完整性；蓝图和源锁 → `MaterialLock` | F-sources、F-blueprints / `secrets` | 单独准备离线材料；私有凭据按任务注入，取消只处置本任务暂存，完整材料按引用回收 |
| `foundry-builders` | 审阅资源与网络计划后制作、取消、恢复清理、创建新尝试；三个锁定对象 → `BuildRun`、未发布磁盘 | F-sources、F-blueprints、F-depot / 无 | 有自己的制作页和日志；仅修改新建实例，终态保存实际退出与清理回执，未知清理禁止重试 |
| `foundry-sanitizers` | 选择清理策略、预览受影响路径、执行封存前清理；制作磁盘 → `SanitizedCandidate`、清理证据 | F-builders / 无 | 单独检查本包制作结果的身份与残留；仅处理私有副本，清理后不得回到安装阶段，修改须新建候选 |
| `foundry-checks` | 选择验收配置、断网启动、运行工具及身份检查、比较两次构建；候选 → `CheckReport` | F-sanitizers / 无 | 单独复验旧候选并显示过期证据；每次用全新实例，失败保留有界证据并回收实例 |
| `foundry-catalog` | 发布合格镜像、查看引用、创建独立实例、撤回、退役、预览清理；候选和证据 → `ImageRevision` | F-sources、F-builders、F-sanitizers、F-checks / 无 | 独立镜像库与消费者入口；版本内容不可改，撤回禁新消费，已有引用保留，清理复核引用修订 |
| `foundry-exchange` | 导出交接包、分块导入隔离区、验证来源、审阅接收、提交本机验收；镜像 → 交接文件或导入记录 | F-sources、F-catalog、F-checks / `secrets` | 独立离线交接入口；接收不等于本机合格，签名密钥可选，导入失败不覆盖已有镜像 |
| `foundry-workbench` | 在“来源—蓝图—材料—制作—清理—验收—镜像—交接”之间导航，选模板并恢复中断步骤 | 上述 8 个插件 / `command-palette` | 聚合已声明服务，不拥有另一份镜像状态；页面关闭不取消已接受任务，停用不影响子插件数据 |

所有后台插件必须声明实际使用的 `jobs`、`job-retry` 等受管贡献。重试入口只能创建经审阅的新尝试，不能自动重放网络下载、安装或实例创建。

### 3.1 无环依赖与按需启用

依赖顺序为 `sources → blueprints → depot → builders → sanitizers → checks → catalog → exchange`；`workbench` 位于末端，直接读取所需服务。箭头表示后者依赖前者，表中额外向前引用不形成回边。

`catalog` 不调用 `exchange`；`exchange` 通过 `catalog.stageImport` 登记隔离资产，接收后进入清理和验收。`sanitizers` 接受本地制作回执或本体签发的导入回执，不反向查询 `catalog`。`checks` 不要求伪造本地 `BuildRun`，发布按两类来源分别检查证据链。

只启用来源与蓝图即可管理定义；启用材料库即可制作离线材料包；完整包一次提供全部 9 个插件。可选的配方、运行时或密钥插件不会被完整包隐式强制安装。

## 4. 用户流程与验收结果

### 4.1 制作供 delivery 使用的隔离镜像

1. 选择基础发行版和架构，查看实际来源 URL、摘要算法、预期摘要和取得方式。只有主动点击“取得来源”才联网。
2. 选择“隔离交付基础”蓝图，预览系统工具及 Node/Python 版本。检查按发行版映射的包名，冻结蓝图修订。
3. 解析依赖后查看完整材料清单、版本、摘要、字节数和下载端点。审阅后预取；离线机器可导入同一清单的材料包。
4. 预览制作计划，包括新实例资源、可写空间、时限、离线安装命令和预计磁盘占用。点击制作后只使用已取得材料。
5. 运行清理策略，封存磁盘。页面分别显示已清理、保留并解释、无法判断的项目；任何必需项不明都阻止发布。
6. 从封存磁盘创建两台独立实例，断网验证工具可用、项目 UID 隔离、启动身份更新和文件互不影响，然后核销实例。
7. 发布不可变镜像修订，创建用途为 `delivery` 的引用。用户在交付定义中选取 `imageRef`，交付输入同时固定镜像摘要和验收配置版本。
8. 原构建实例与来源 VM 删除后，镜像仍能用于新交付。撤回只阻止新授权；正在执行的构建由既有租约保护。

现有 delivery 仍按原定义运行。新字段和消费者适配完成前，界面只能导出镜像描述，不能显示“已接入交付”。禁止通过覆盖基础镜像文件或修改 `SAKURA_IMAGE_DIR` 实现接入。

### 4.2 完全离线交接与升级

发送方选择具体镜像修订和包含材料的范围，查看大小及敏感项说明，再导出。接收方校验完整内容后进入隔离区；审阅签名来源、蓝图、工具清单和网络要求，再创建本机候选。

接收方先在独立副本重新执行适用清理策略，再完成断网启动及身份验收，才能发布本机可消费修订。没有材料时仍可使用已合格的磁盘，但页面明确“不能离线重建”。缺失基础镜像或依赖时保持待补齐，禁止后台联网补足。

升级复制蓝图产生新修订，生成差异并重新取材、制作和验收。用户显式切换消费者引用；失败时仍可选择未撤回的旧修订，已有任务不随别名变化。

## 5. 数据身份、公共契约与状态机

### 5.1 不可变身份和引用责任

| 对象 | 必需身份与内容 | 变更规则 |
| --- | --- | --- |
| `SourceLock` | `sourceId/revision/digest`，发行版、架构、原始 URL、最终 URL、取得时间、字节摘要、校验来源 | 固定内容摘要；URL 与版本名只是来源信息，不能替代字节校验 |
| `BlueprintRevision` | `blueprintId/revision/digest`，基础源锁、系统包约束、运行时、安装步骤、清理与检查配置、网络计划 | 冻结后仅复制生成新修订；来源或命令变化使原审阅令牌失效 |
| `MaterialLock` | `digest`，精确包版本、架构、仓库元数据摘要、每个材料摘要及长度、许可证声明来源 | 记录完整依赖解析结果；不含凭据、带凭据 URL 或机器绝对路径 |
| `BuildRun` | `runId/attemptId`，蓝图和材料摘要、引擎版本、VM 创建与启动身份、资源回执、退出与清理状态 | 一次尝试一份记录；崩溃恢复只对原资源核销，不能改写成成功 |
| `SanitizedCandidate` | `candidateDigest`，独立磁盘摘要、格式、虚拟容量、清理策略摘要和来源类型 | 磁盘或清理策略变化生成新候选；外部导入保留外部来源，禁止冒充本地构建 |
| `CheckReport` | `reportId/digest`，候选摘要、检查器和策略版本、架构、两个启动身份、证据摘要、结果 | 结果为 `pass/fail/unknown`；缺证据、探测异常和跳过必需项均不能算通过 |
| `ImageRevision` | `imageId/version/revisionDigest`，候选、报告与来源摘要，用途配置、撤回状态 | 版本内容不可覆盖；显示名可改，消费时固定 `revisionDigest` |
| `ImageReference` | 内容摘要、宿主授权范围、消费者插件与对象 ID、用途、创建与释放回执 | 仅所属消费者能释放；持久引用保护任务输入，执行租约保护正在使用的磁盘 |

内容摘要使用版本化的规范 JSON 与 SHA-256。摘要包含安全策略和材料身份，排除自身 `digest`、签名信封、显示名、生成时间及撤回等可变状态；磁盘摘要独立计算完整字节。签名覆盖内容摘要与信任域，避免摘要自引用。引用不能仅使用可变版本别名。

### 5.2 本体必须补充的窄能力

拟新增 `ImageAssetsV1`，由本体管理不可变磁盘、持久引用和运行租约。插件只获得有权限的资产 ID；宿主路径、QEMU 参数和挂载句柄不进入通用插件响应。

| 拟增方法 | 约定与失败行为 |
| --- | --- |
| `stage/append/finish` | 预留限额，按精确偏移写入有界分块，完成时核对全长摘要与磁盘结构；返回不可变 `assetId` |
| `inspect/verify` | 返回格式、架构、物理与虚拟容量及校验状态；拒绝外部 backing file、链接、特殊文件和摘要漂移 |
| `retain/references/release` | 建立具备消费者身份的持久引用，幂等释放；引用账本在插件停用后仍可用 |
| `acquire/renew/close` | 签发受期限和任务身份约束的读或创建租约；实际活动实例另有本体引用，不能仅靠租约时间判定可删 |
| `createOwnedVm` | 从核验资产创建独立可写副本，登记网络、原资源回执和临时或持久生命周期；临时实例绑定审阅过的绝对期限，持久实例在创建成功时移交消费者归属并保留资产引用；不替换全局基础镜像 |
| `cleanupPlan/cleanup` | 返回保护原因和引用修订；执行时重新验证身份、预算与引用，部分清理保留未确认记录 |

[`VmAccess`](../server/vm-access.ts) 和 [`vm-ports.ts`](../server/vm-ports.ts) 是本体适配的起点；不能直接把 `Machines`、文件系统路径或全部 VM 方法暴露给新插件。制作、封存、断网克隆及失联回收须逐项核定受管能力。

`ImageAssetsV1` 只管理资源事实，不决定发布资格。`foundry-catalog` 判断候选与验收证据；消费者负责检查所需用途、撤回与新授权，再申请本体租约。关闭工坊后禁止新增工坊消费，已运行实例仍由本体核销。

### 5.3 插件公共服务

以下均为拟增契约，实施时进入独立 V1 接口、描述符和兼容性基线。方法写入均包含授权上下文、预期修订与幂等键，返回已提交对象或明确失败；耗时动作返回任务 ID。

| 服务 | 必须覆盖的方法与返回 |
| --- | --- |
| `FoundrySourcesV1` | `list/previewAcquire/acquire/import/verify/archive`，返回源锁、联网计划或任务 |
| `FoundryBlueprintsV1` | `list/get/save/compare/importPreview/freeze/archive`，返回修订、差异或冲突 |
| `FoundryDepotV1` | `plan/fetch/verify/export/import/retain/release/cleanupPlan/cleanup`，返回材料锁、缺件清单或清理回执 |
| `FoundryBuildersV1` | `plan/start/list/get/cancel/recover`，返回尝试、实际退出和资源清理状态 |
| `FoundrySanitizersV1` | `plan/apply/get`，返回受影响项目、候选及逐项清理证据 |
| `FoundryChecksV1` | `profiles/start/get/compare`，返回验收配置、报告或构建差异 |
| `FoundryCatalogV1` | `list/get/publish/stageImport/previewUse/authorizeUse/withdraw/retire/cleanupPlan/cleanup`，返回修订与本体可核验授权；不返回磁盘路径 |
| `FoundryExchangeV1` | `previewExport/export/beginImport/appendImport/finishImport/review/accept/reject`，返回交接任务、隔离记录或接收回执 |
| `FoundryWorkbenchV1` | `templates/capabilities/resume`，只聚合可用模板、能力与下一可执行步骤 |

delivery 的 [`DeliveryEnvironment`](../shared/contracts/delivery-common.ts) 拟增加可选的版本化 `imageRef`。无该字段时保持旧行为；有字段时要求对应供应者及能力存在，固定摘要、用途证据与持久引用，失败不回退到默认镜像。`app-runtime`、`data-lab` 使用同一显式引用约定。

### 5.4 状态转换和中断恢复

制作主状态为 `planned → fetching → ready → building → sanitizing → verifying → eligible → published`。下载独立完成后也可直接从 `ready` 开始；只允许明确动作推进下一步，页面刷新不触发执行。

每个尝试单独记录 `queued/running/succeeded/failed/cancelled/interrupted`，清理状态单独记录 `pending/confirmed/unknown`。执行成功且清理确认才能进入 `eligible`；任务取消不等于实例已经停止。

导入状态为 `receiving → quarantined → reviewed → accepted → sanitizing → verifying → eligible`，可转 `rejected`。`accepted` 只授权专用副本清理和本机验收；外部报告不替代本机启动身份检查。

镜像发布后可转 `withdrawn` 或 `retired`，回收仅发生于无引用且无租约时。撤回原因与时间不可抹除；恢复供新任务使用必须重新审阅，保留历史。

服务重启先对照任务日志和本体资源账本。创建回执已存在时恢复同一任务；无法证明 VM、进程或文件归属时保留并显示人工处理入口，禁止按名称猜测删除。

## 6. 界面、HTTP 与 CLI

主入口为侧栏“镜像工坊”。窄屏使用阶段选择器，阶段页保留“当前修订、缺少条件、下一动作”；来源 URL、安装脚本和清理路径在对应审阅页展开，不要求用户手写内部 ID。

镜像详情显示可用用途、架构、材料完整性、实际验证时间、来源信任和引用者。清理页同时列出可回收内容与阻止删除的具体任务。失败页提供原日志、缺少材料、清理状态和允许的恢复动作。

各插件使用与 ID 对应的平坦路由，例如 `GET/POST /api/foundry-sources`、`GET/POST /api/foundry-catalog`；写入动作使用严格判别联合。二进制传输路由另行声明，禁止将磁盘塞进单次 JSON 或浏览器内存。

所有业务端点要求宿主会话与 owner 权限；使用宿主身份并显式携带 `workspaceId`，不能依靠“当前选中 VM”。读操作不补写修复记录；修改在提交前再次检查会话、维护状态、修订及插件生命周期。

拟提供 `sakura foundry source/blueprint/material/build/check/image/exchange` 命令组。`plan` 输出可保存的 JSON；`apply --plan <id>` 仅消费未过期计划。CLI 使用同一 HTTP 契约，支持任务等待、取消、范围错误和非零退出码，不提供直接修改数据目录的旁路。

网络取得、制作、清理、发布、接收和消费者切换均有独立计划。计划有效期拟为 5 分钟，绑定对象摘要、授权主体、资源预算和修订；任一变化要求重新预览。重复提交同一幂等键返回原任务，不能多建实例。

## 7. 安全、预算与交接格式

### 7.1 网络与凭据

默认“离线安装”。显式联网只用于来源与材料取得，计划列出协议、域名、端口和路径范围；重定向越界拒绝，认证信息不得转发到新端点。只下载材料，不执行上游脚本。

需要联网构建的自定义蓝图必须独立选择并审阅。其结果标记“联网制作”，不得取得“离线重建已验证”证明；验证阶段始终断网。实现不能将缺包、镜像启动失败或超时解释为授权开启 NAT。

私有来源仅引用 `secrets` 中的凭据名称。代理在独占临时目录读取凭据，任务结束后核销；凭据不写入镜像、蓝图、材料锁、日志或命令参数。密钥插件缺席时仅支持公开来源和本地导入。

### 7.2 身份清理与首次启动验收

清理在专用副本中完成，内容包括构建账号凭据、下载认证文件、shell 历史、临时日志、Sakura 控制密钥、SSH 主机私钥、机器标识和 cloud-init 已消费状态。按发行版适配，未知路径或初始化方式必须报告不支持。

封存后不再启动母盘。首次启动生成新控制连接身份、机器标识及 SSH 主机密钥；验证两台克隆彼此不同，也不同于构建实例，且旧公钥不能连接。生成失败时隔离实例，不能复用旧身份继续运行。

关键文件清单和适配器规则提供可检查的清理证据；扫描结果不能证明整块磁盘绝无秘密。自定义安装脚本写入未知敏感路径时须补充清理规则并重验，否则只能保留未合格候选。

清理进程需要临时控制身份，但临时私钥只存在本体密钥存储。清理计划最后安排关机前删除客体控制授权；宿主收到关机回执后只读封存。若正常关机或删除无法确认，候选保持未合格，不能依靠扫描结果推断已完成。

验收还检查所需命令版本、普通项目 UID 的实际执行、UID 与宿主控制身份隔离、包管理器离线拒绝联网、文件系统可写范围和实例停止回执。只检验命令是否存在不足以取得 `delivery-isolated` 用途资格。

断网证据来自本体实际网络配置与探测结果，不能只读客体环境变量或接受脚本自报。控制通道与工作负载联网权限分别记录；DNS、TCP、UDP 外连失败不影响受管控制通道。

### 7.3 存储、并发与保留

首版拟采用与现有黄金镜像相近的发布预算：单镜像物理内容最多 32 GiB，虚拟容量最多 128 GiB，最多 16 个已发布镜像，总物理预算 128 GiB。工坊自己的源、材料、候选和暂存计入同一预算，导入隔离区不能绕过限额。

单次材料预取默认最多 2 GiB、4 个并发下载；默认每宿主同时制作 1 台、验收 2 台。可提高软限额，但仍受本体 CPU、内存、磁盘预算及硬上限约束；排队中的任务不得预先启动 VM。

预检按基础复制、虚拟磁盘增长、封存转换和两台验收实例计算最坏空间并预留。实际写入继续计量；空间不足停下本次任务，已发布镜像和用户实例不能作为自动腾挪对象。

创建与活动读取租约拟为 15 分钟，可按原任务身份续租；下载租约按范围关闭。创建任务超时后，只能按原资源身份清理尚未移交的实例。创建成功须持久记录消费者归属并另保留资产引用，再关闭创建租约。

临时制作、验收和试运行实例仍遵守事先审阅的绝对期限。`app-runtime` 的长期应用实例不因创建、消费或下载租约到期而停机；其停止和恢复由持久应用策略管理。未释放持久引用不自动过期，失联消费者须显示归属并经明确退役流程处理，不能以插件已停用为由删除。

### 7.4 离线交接和来源信任

拟定义 `sakura-image-v1` 交接容器：版本化头、清单及按摘要排序的原始内容段。只允许已声明类型的磁盘与材料段，不接受任意路径、链接或压缩包自动展开。所有段与全包都须校验长度和摘要；存在签名时再按指定用途验签，完成后才发布隔离记录。

每个传输块最多 1 MiB，可按精确偏移续传；导入总量不得超过工坊剩余预算，单镜像仍限 32 GiB。导出流式写入用户选定的新文件，失败保留明确标记的部分文件，不覆盖既有文件。

签名采用独立的 `sakura-foundry` 信任域。有效签名只说明指定内容由对应密钥签署；未知发布者仍在隔离区，已撤销密钥拒绝自动接收。信任配置不与 Sakura 更新中心或 delivery 发布者列表混用。

未签名内容标为“来源未认证”。独立的接收策略决定是否允许用户显式接收；接收不改变来源标记，也不跳过清理与本机验收。错误签名、内容摘要不符和类型不符一律拒绝，不能用“允许未签名”绕过。

## 8. 停用、升级与实施验收

停用按反向依赖排空：阻止新任务，撤销尚未消费的计划，等待或取消本包任务，再处理原身份清理。引用账本和已发布字节保留；撤销 UI 不释放消费者引用。强制退出留下 `interrupted/unknown`，重启后仅恢复核销。

卸载与清数据分开处理。工坊数据归对应服务所有，源锁、材料锁、尝试和报告由镜像修订持久引用；未发布失败记录有明确保留期，过期后仍须生成清理计划。消费者释放引用后，才能逐层回收依赖材料，不能直接清空插件目录。

升级采用元数据版本迁移预览，先验证旧记录和引用一致性，再原子提交。未知高版本只读或明确拒绝写入；迁移失败保留旧状态。新检查策略使旧证据显示待复验，不静默将既有镜像改为已通过。

最小关键验证覆盖中途断网、取消、宿主重启、磁盘写满、旧启动身份、并发引用与删除、下载中撤回、摘要篡改、旧凭据残留、插件停用和导入重复提交。对应本体与插件契约必须通过生成及兼容性检查。

delivery 的 `imageRef` 适配与实际构建属于可选组合验收，不阻塞 foundry 独立包交付。组合启用时须证明选择、固定、保留和释放一致；`app-runtime`、`data-lab` 的镜像消费遵循同一规则。

架构验收要求：完整包及各独立前缀组合可启停、依赖无环、可选服务缺席行为明确；运行代码只经声明的契约访问资源。测试脚本、镜像、证据和截图保留在本地忽略路径，Git 仅记录正式实现与简短验证结论。

完成标准为 F0～F5 全部通过，并提供实际实现提交、契约基线、版本标签与已知限制。设计版本 1.0.0 仅表示设计范围冻结；应用发布版本和排期另行确定。
